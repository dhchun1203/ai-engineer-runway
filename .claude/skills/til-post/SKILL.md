# TIL 쓰고 올리기

2026-11-25 사용자 결정: TIL은 언제나 이 포맷으로 일관되게 쓴다. 본보기는 같은 폴더의 `example-23.md`(23회차, 사용자가 "좋아"라고 한 글).

## 포맷 (여섯 칸, 이 순서와 제목 그대로)

```
## 1. 오늘의 흐름
## 2. 구조
## 3. 코드
## 4. 핵심 정리
## 5. 헷갈린 점, 고친 점
## 6. 실행 예시
```

1. **오늘의 흐름**: 그날 한 일을 2~3문장으로(무엇을 했고 왜 그 순서인지). 아래에 번호 목록 3~6개로 순서를 적는다. 화살표(→)로 결과 숫자를 붙여도 좋다.
2. **구조**: `txt` 코드 블록 하나로 그날의 큰 그림. 데이터, 입력과 출력, 단계, 파일 구조, 명령 흐름 같은 것을 왼쪽 이름, 오른쪽 내용으로 정렬한다.
3. **코드**: 주제마다 `### 소제목`. 수업에서 친 핵심 코드를 짧게 다듬어 넣는다(전부 붙이지 않는다). 설명 주석은 코드 위 줄에, `;`로 붙이지 않고 한 줄에 한 문장, 인자가 많은 호출은 쉼표 뒤에서 줄바꿈. 명령어 회차(Git, Docker, SQL)는 `bash`, `sql` 블록.
4. **핵심 정리**: `| 개념 | 내 말로 |` 표(개념 5~9개, 한 줄씩 내 말로). 그 아래 글머리표 3~6개로 그날의 "왜"와 실제 숫자(손계산, 비교 결과, 함정)를 적는다.
5. **헷갈린 점, 고친 점**: 글머리표. 실제 오류 메시지는 백틱으로 그대로, 원인, 고친 방법. 수업 노트와 실제 결과가 다른 곳, 수업 코드에서 고칠 곳, 다시 실행할 때의 주의.
6. **실행 예시**: 실제 출력만 `txt` 블록으로(표, print 결과, 명령 결과). 한 블록에 너무 길면 나눈다.

**문체**: 나를 위한 정리 노트라 "~다", "~한다" 체, 짧은 문장. 가운데점(·), 긴 하이픈(—), 이모지 금지. 명령, 함수, 파일, 열 이름은 백틱. 분량은 5,000~9,000자 정도(본보기 6,200자). 7번 이후 칸을 따로 만들지 않는다(과제, 챌린지, 오후 실습 같은 것은 3번의 `###`와 4~6번에 녹인다). 사용자가 빼라고 한 것(예: 미니 과제)은 넣지 않는다.

**맥 기준**: 2026-11-21부터 사용자는 맥을 쓴다. 명령은 맥 기준(brew, `source .venv/bin/activate`, `uv run`, Colima, Cmd/Option). 윈도우 전용 명령(winget, Git Bash, Docker Desktop, PowerShell)은 수업 복습 레슨(`src/content/class-lessons/`)이 바꿔 둔 맥 명령으로 쓴다.

## 숫자와 출력은 실제 값만

- 출처는 그날 수업 자료(커밋 노트북, 사용자가 준 정리)와 같은 날의 수업 복습 레슨(`src/content/class-lessons/NN-*/index.mdx`, 이미 맥에서 실행해 검증한 값)이다.
- 새로 적는 출력과 숫자는 레슨에 있는 값이거나 직접 실행해 본 값만 쓴다. 파이썬은 `uv run --python 3.14 --with ...`로 돌려 본다.
- `3. 코드`의 파이썬 블록은 모아서 실행해 오류가 없는지 확인한다(그래프는 `matplotlib.use("Agg")`).

## 올리기

```bash
node --env-file=.env.local scripts/til-upsert.mjs <본문.md> --slug <slug> \
  --title "Linear Regression & Gradient Descent" \
  --summary "한 줄 요약" --tags "python,머신러닝" --series "Python" --date 2026-11-25
```

- 새 글: `--title`, `--date`(학습한 날) 필수. 제목은 앞 글들처럼 영어로 짧게(`NumPy & Pandas Basics`), slug는 제목을 소문자 kebab으로. 시리즈는 기존 것(`Git`, `Python`, `Database`, `SQL`) 중 맞는 것, 태그는 기존 태그(`python`, `pandas`, `머신러닝`, `Database`, `SQL`, `Docker`, `git`)를 먼저 쓴다.
- 기존 글: `--slug`만 주면 본문만 바꾼다. 이해도, 셀프 체크, 막힌 곳, 요약은 사용자가 직접 쓴 칸이라 건드리지 않는다.
- 고치기 전에 원본을 백업한다(`.til-backup/`, git에 안 올라감).
- 글 화면은 로그인이 필요하다. 저장 뒤 DB에서 `body_md` 길이와 제목을 확인하고, 사용자에게 주소 `https://ai-engineer-hub-kr.vercel.app/til/<slug>`를 알려 확인을 부탁한다.
