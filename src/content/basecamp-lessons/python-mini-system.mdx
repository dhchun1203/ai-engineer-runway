지금까지 배운 함수들을 하나로 모으면 작은 프로그램이 돼요. 큰 시스템도 사실은 작은 함수 여러 개가 손을 잡은 거예요.

함수 하나는 딱 한 가지 일만 해요. 그런데 이 함수들이 같은 데이터를 함께 다루기 시작하면, 갑자기 "관리 시스템"처럼 보이기 시작해요.

이 레슨에서는 재고(창고에 있는 물건 개수)를 예로 들어 볼게요. 물건을 넣고, 빼고, 개수를 고치고, 순위를 매기고, 통계를 내는 흐름을 하나씩 만들어 봐요.

이 레슨은 심화 과제 5번(작은 시스템 만들기)을 스스로 풀 수 있게 준비시켜요. 여러 함수를 조합하는 법, 표준편차를 직접 계산하는 법, 어떤 자료구조를 쓸지 생각하는 법을 함께 익혀요.

## 1. 하나의 데이터, 여러 개의 함수

작은 시스템은 어렵지 않아요. "하나의 데이터 뭉치"를 두고, 그걸 다루는 함수 몇 개를 만드는 거예요.

재고를 딕셔너리로 표현해 볼게요. 물건 이름을 열쇠(key)로, 개수를 값(value)으로 두는 거예요.

```python
# 재고: 물건 이름 -> 개수
stock = {"사과": 12, "바나나": 5}

# 물건을 넣는 함수 (이미 있으면 개수를 더해요)
def add_item(stock, name, qty):
    if name in stock:
        stock[name] = stock[name] + qty
    else:
        stock[name] = qty

# 물건을 아예 빼는 함수 (열쇠 자체를 지워요)
def remove_item(stock, name):
    if name in stock:
        del stock[name]

# 개수를 새 값으로 고치는 함수
def update_qty(stock, name, qty):
    if name in stock:
        stock[name] = qty
```

이제 이 함수들을 짧은 이야기처럼 이어서 불러 볼게요.

```python
add_item(stock, "오렌지", 8)      # 새 물건 추가
add_item(stock, "사과", 3)        # 사과는 이미 있으니 12 + 3
update_qty(stock, "바나나", 20)   # 바나나 개수를 20으로 교체
remove_item(stock, "오렌지")      # 오렌지는 다 팔려서 제거

print(stock)
# 예상 출력: {'사과': 15, '바나나': 20}
```

여기서 중요한 점이 하나 있어요. 위 함수들은 값을 돌려주지(return) 않고, 받은 `stock`을 직접 바꿔요(mutate).

딕셔너리는 함수 안으로 "주소"가 전달돼서, 함수 안에서 바꾸면 바깥의 `stock`도 같이 바뀌어요. 그래서 `return` 없이도 결과가 남는 거예요.

반대로 "바꾸지 말고 새 결과만 알려줘" 하고 싶을 때는 값을 return 하게 만들면 돼요. 다음 절에서 그런 함수를 만들어 볼게요.

## 2. 조회하고 순위 매기기

이번엔 데이터를 바꾸지 않고 "보기만" 하는 함수를 만들어요. 개수가 많은 순서대로 순위를 뽑아 볼게요.

```python
# 개수가 많은 순서대로 (이름, 개수) 목록을 돌려줘요
def get_ranking(stock):
    # stock.items()는 (이름, 개수) 짝들의 모음이에요
    # key=lambda x: x[1] 는 "짝의 두 번째 값(개수)으로 정렬" 이라는 뜻이에요
    return sorted(stock.items(), key=lambda x: x[1], reverse=True)

stock = {"사과": 15, "바나나": 20, "포도": 7}
print(get_ranking(stock))
# 예상 출력: [('바나나', 20), ('사과', 15), ('포도', 7)]
```

`sorted(...)`는 원래 `stock`을 건드리지 않고, 정렬된 새 목록을 만들어서 돌려줘요. 그래서 return이 필요해요.

`reverse=True`를 빼면 개수가 적은 순서(오름차순)가 돼요. 반대로 순위를 매기고 싶을 때 이렇게 바꿔요.

참고로 정렬은 꼭 `sorted`를 써야 하는 건 아니에요. 알고리즘 레슨에서 손으로 짠 선택 정렬(selection sort)을 그대로 가져와 순위를 매길 수도 있어요. 지금은 편하게 `sorted`를 쓰지만, "직접 정렬하는 길도 있다"는 걸 기억해 두세요.

## 3. 통계를 직접 계산하기 (핵심)

이제 이 레슨의 가장 중요한 부분이에요. 평균, 최댓값, 최솟값, 그리고 표준편차를 라이브러리 없이 직접 구해 볼게요.

먼저 평균, 최댓값, 최솟값은 간단해요.

```python
numbers = [10, 20, 30, 40]

total = sum(numbers)          # 전부 더하기: 100
count = len(numbers)          # 개수: 4
mean = total / count          # 평균: 25.0

print(mean)          # 예상 출력: 25.0
print(max(numbers))  # 예상 출력: 40 (최댓값)
print(min(numbers))  # 예상 출력: 10 (최솟값)
```

이제 표준편차예요. 말이 어렵지, 순서를 따라가면 쉬워요.

표준편차는 "값들이 평균에서 얼마나 흩어져 있는지"를 나타내는 숫자예요. 모두 평균 근처면 작아지고, 멀리 퍼져 있으면 커져요.

계산 순서는 이래요. 먼저 각 값에서 평균을 뺀 차이를 구해요. 그 차이를 제곱해요(음수를 없애고 큰 차이를 더 크게 보려고요).

그 제곱한 값들의 평균이 분산(variance)이에요. 분산의 제곱근이 표준편차(standard deviation)예요.

제곱근은 특별한 도구 없이 `값 ** 0.5`로 구할 수 있어요. 어떤 수의 0.5제곱이 곧 제곱근이거든요.

```python
numbers = [10, 20, 30, 40]

mean = sum(numbers) / len(numbers)   # 평균 = 25.0

# 각 값에서 평균을 뺀 뒤 제곱한 값들
squared_diffs = []
for x in numbers:
    diff = x - mean          # 평균과의 차이
    squared_diffs.append(diff ** 2)   # 차이를 제곱

# 분산 = 제곱한 값들의 평균
variance = sum(squared_diffs) / len(squared_diffs)

# 표준편차 = 분산의 제곱근
std_dev = variance ** 0.5

print(variance)   # 예상 출력: 125.0
print(std_dev)    # 예상 출력: 11.180339887498949
```

한 줄씩 손으로 확인해 볼게요. 차이는 각각 -15, -5, 5, 15예요. 이걸 제곱하면 225, 25, 25, 225가 돼요.

이 넷을 더하면 500, 나누면(4로) 분산은 125예요. 마지막으로 125의 제곱근이 약 11.18, 그게 표준편차예요.

이 계산을 함수로 묶어 두면 어디서든 재사용할 수 있어요.

```python
def get_stats(numbers):
    mean = sum(numbers) / len(numbers)
    variance = sum((x - mean) ** 2 for x in numbers) / len(numbers)
    std_dev = variance ** 0.5
    return {
        "평균": mean,
        "최댓값": max(numbers),
        "최솟값": min(numbers),
        "표준편차": std_dev,
    }

print(get_stats([10, 20, 30, 40]))
# 예상 출력: {'평균': 25.0, '최댓값': 40, '최솟값': 10, '표준편차': 11.180339887498949}
```

이제 심화 과제에서는 학생 성적 데이터로 같은 구조를 직접 만들어 보세요. 여기서 익힌 표준편차 계산 순서(차이 제곱 -> 평균 -> 제곱근)는 숫자 목록이면 무엇에나 똑같이 쓸 수 있어요.

## 4. 설계로 생각하기: 자료구조와 한계

시스템을 만들 때는 "어떤 모양으로 데이터를 담을까"를 먼저 정해야 해요. 지금은 `이름 -> 개수`처럼 값 하나만 담았지만, 물건마다 정보가 여러 개면 어떻게 할까요.

이럴 때 딕셔너리 안에 딕셔너리를 넣는 중첩 딕셔너리를 쓸 수 있어요.

```python
# 물건마다 개수와 가격을 함께 담기
stock = {
    "사과": {"개수": 15, "가격": 1000},
    "바나나": {"개수": 20, "가격": 500},
}

print(stock["사과"]["가격"])   # 예상 출력: 1000
```

중첩 딕셔너리의 장점은, 한 물건에 대한 정보를 깔끔하게 한 곳에 모을 수 있다는 거예요. 이름으로 찾으면 그 물건의 모든 정보가 딸려 나와요.

단점도 있어요. 안으로 들어갈수록 `stock["사과"]["가격"]`처럼 대괄호가 길어져 읽기 어렵고, 없는 열쇠를 잘못 건드리면 오류가 나기 쉬워요.

여기서 한 걸음 더 생각해 볼게요. 만약 물건이 수백만 개로 늘어나면 어떤 일이 벌어질까요.

첫째, 모든 데이터가 컴퓨터 메모리(잠깐 쓰는 작업 공간)에 올라가 있어서 메모리 부담이 커져요. 둘째, 프로그램을 끄면 딕셔너리는 통째로 사라져서 다음에 다시 켜면 데이터가 없어요.

셋째, "가격이 1000원 넘는 물건만 빠르게 찾아줘" 같은 조건 검색이 어려워요. 전부 하나씩 훑어야 하니 개수가 많아질수록 느려져요.

이런 문제들 때문에 실무에서는 데이터베이스(database)를 써요. 데이터를 껐다 켜도 안전하게 보관하고, 조건으로 빠르게 찾고, 큰 데이터를 다루도록 만들어진 도구예요.

지금 이 세 가지 생각(메모리 부담, 끄면 사라짐, 조건 검색이 느림, 그래서 데이터베이스가 필요함)은 심화 과제의 서술형 질문에 답할 때 그대로 재료가 돼요. 답을 통째로 외우기보다, 왜 그런지를 자기 말로 설명해 보세요.

## 한 줄 정리

작은 시스템은 하나의 데이터 뭉치를 여러 함수가 나눠 맡는 것이고, 평균이나 표준편차 같은 통계도 (차이 제곱, 평균, 제곱근의 순서만 알면) 라이브러리 없이 직접 만들 수 있어요.
