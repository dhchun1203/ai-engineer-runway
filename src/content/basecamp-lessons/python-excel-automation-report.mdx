1편에서 흩어져 있던 지점 파일을 하나로 모았어요. 광주점 파일이 깨져 있어도 멈추지 않았고, 신촌점의 지저분한 값도 깔끔하게 정리했죠.

2편에서는 모은 기록으로 보고서를 만들어요. 그다음이 진짜 재미있는 부분이에요. 다음 주에 새 파일이 오면 어떻게 되는지, AI에게 기능을 부탁하면 어떻게 되는지 직접 겪어 봐요.

> 이 편은 공식 STEP 4 최종 과제의 후반부(합계 내고 결과 파일 만들기, 종합 미니 과제)에 대응해요. 우리는 서점 예시로 끝까지 가 보고, 공식 과제는 카페 데이터로 같은 흐름을 여러분이 직접 완성하면 돼요.

1편의 칸들을 모두 실행한 상태에서 이어 가세요. Colab 연결이 끊겼다면 준비 칸부터 1편의 칸을 차례로 다시 실행하면 돼요.

## 4단계. 지점별 매출 합계 구하기 (5번 일)

`all_rows`를 한 줄씩 보며 지점별 매출 합계를 `branch_total` 딕셔너리에 담아요. [첫 번째 레슨](/basecamp/python-excel-data-basics)의 SUMIF 패턴 그대로예요.

```python
branch_total = {}
for row in all_rows:
    branch = row["지점"]
    branch_total[branch] = branch_total.get(branch, 0) + row["매출"]   # 처음 보는 지점은 0부터

print(branch_total)
# {'신촌점': 666000, '종로점': 444000, '해운대점': 451000}
```

`.get(branch, 0)`의 `0`이 중요해요. 처음 보는 지점이면 합계가 아직 없으니 0에서 시작해야 하죠. 여기를 비워 두거나 다른 값을 넣으면 첫 매출부터 계산이 어긋나요.

신촌점 숫자를 손으로 한번 확인해 볼까요? 소설 20권 × 15000원, 에세이 6권 × 13000원, IT 9권 × 32000원을 더하면 300000 + 78000 + 288000 = 666000이에요. 맞네요.

## 5단계. 결과 엑셀 파일로 저장하기 (6번 일)

시트 세 개짜리 보고용 엑셀 파일을 만들어요.

- 전체데이터: 정리된 판매 기록 전부
- 지점별합계: 지점마다 총매출
- 확인필요: 열지 못한 파일 목록

```python
wb = Workbook()

# 시트 1: 전체데이터
sheet1 = wb.active
sheet1.title = "전체데이터"
sheet1.append(["날짜", "지점", "분야", "권수", "가격", "매출"])
for row in all_rows:
    sheet1.append(list(row.values()))

# 시트 2: 지점별합계
sheet2 = wb.create_sheet("지점별합계")
sheet2.append(["지점", "총매출"])
for branch, total in branch_total.items():
    sheet2.append([branch, total])

# 시트 3: 확인필요
sheet3 = wb.create_sheet("확인필요")
sheet3.append(["열지 못한 파일"])
for name in errors:
    sheet3.append([name])

# ▼▼▼ AI에게 받은 '분야별합계' 시트 코드를 여기에 넣어요 ▼▼▼

# ▲▲▲ 여기까지 ▲▲▲

wb.save(RESULT_FILE)                                   # 파일로 저장
print(f"완료! 총 {len(all_rows)}줄 → {RESULT_FILE}")
# 완료! 총 9줄 → 주간판매_정리.xlsx
```

처음 보는 것 두 가지만 짚을게요.

`list(row.values())`는 한 줄의 값들을 넣은 순서대로 리스트로 만들어요. 1편에서 정리한 한 줄을 날짜, 지점, 분야, 권수, 가격, 매출 순으로 만들었죠. 그래서 제목 줄과 순서가 딱 맞아요.

마지막 줄의 `f"..."`는 f-string이에요. 따옴표 앞에 `f`를 붙이면, 중괄호 `{ }` 안에 쓴 변수나 계산 결과가 그 자리에 채워져요. `{len(all_rows)}` 자리에 `9`가 들어간 거예요.

`▼▼▼`와 `▲▲▲` 사이의 빈자리는 잠시 뒤 AI에게 받은 코드를 넣을 곳이에요. `wb.save(...)`보다 위에 있어야 해요. 저장한 다음에 시트를 추가하면 파일에는 반영되지 않거든요.

이제 코드는 한 글자도 고치지 말고, 이 세 칸만 순서대로 다시 실행하세요. 칸을 클릭한 뒤 Ctrl + Enter를 누르면 그 칸이 실행돼요.

코드는 그대로인데 대구점이 자동으로 들어왔어요. `iterdir()`가 실행할 때마다 폴더를 새로 들여다보기 때문이에요. 파일만 넣고 다시 실행하면 끝, 이게 자동화의 가치예요.

> 합치기 칸을 다시 실행해도 기록이 두 번 쌓이지 않는 이유가 있어요. 그 칸 맨 위의 `all_rows = []`가 매번 빈 리스트로 새로 시작하기 때문이에요. 만약 `all_rows = []`를 다른 칸에 따로 뒀다면, 다시 실행할 때마다 같은 기록이 계속 쌓여 합계가 부풀었을 거예요. "다시 실행해도 같은 결과"가 나오게 만드는 것도 자동화 툴의 중요한 조건이에요.

## 종합 체험 2. AI에게 요청해서 기능 더하기

본부장님이 분야별 합계도 보고 싶다고 하셨어요. 이번에는 코드를 직접 짜는 대신 AI에게 요청해 기능을 붙여 봐요. ChatGPT, Claude, Gemini 무엇이든 괜찮아요.

### 요청문 쓰기: AI는 내 코드를 모른다

AI는 우리 Colab 화면을 볼 수 없어요. 그래서 "분야별 합계 시트 추가해 줘"라고만 하면, AI는 변수 이름도 데이터 모양도 모른 채 짐작으로 코드를 짜요. 그러면 우리 코드와 맞지 않는 코드가 나오기 쉬워요.

좋은 요청문에는 네 가지가 들어가요. [AI 리터러시 레슨](/basecamp/ai-literacy-prompt)에서 배운 프롬프트 구성 요소와 같은 이야기예요.

| 부분 | 무엇을 쓰나요 | 우리 예시 |
| --- | --- | --- |
| 역할 | AI가 맡을 역할 | 파이썬 업무 자동화 조수 |
| 지금 상황 | 이미 있는 변수와 데이터 모양 | `all_rows`의 한 줄 모양, `wb`에 시트 3개 |
| 요청 | 원하는 결과를 구체적으로 | 분야별 매출 합계 시트, 열 이름 두 개 |
| 조건 | 하지 말아야 할 것, 스타일 | 새로 만들거나 저장하지 말 것, 줄마다 주석 |

우리 서점 예시로는 이렇게 보내면 돼요.

```text
너는 파이썬 업무 자동화를 도와주는 조수야.
나는 Google Colab에서 주간 판매 엑셀을 정리하는 파이썬 코드를 쓰고 있어.

[지금 상황]
- all_rows : 판매 기록을 담은 리스트야. 한 줄은 이런 딕셔너리야.
  {'날짜': '2026-10-05', '지점': '종로점', '분야': '소설', '권수': 12, '가격': 15000, '매출': 180000}
- wb : openpyxl로 만든 결과 엑셀(Workbook)이야. 이미 시트 3개가 들어 있어.
- 네가 짜 준 코드는 wb.save(...) 바로 위에 넣을 거야.

[요청]
wb에 '분야별합계' 시트를 추가하는 코드를 짜 줘.
- 분야별로 '매출'을 모두 더해서 category_total 이라는 딕셔너리에 담아 줘
- 시트의 열은 '분야', '총매출' 두 개로 해 줘

[조건]
- wb를 새로 만들거나 저장하는 코드는 넣지 마
- 파이썬 초보자도 이해할 수 있게 짧게 짜고, 줄마다 주석을 달아 줘
```

조건의 첫 줄이 특히 중요해요. AI가 친절하게 `wb = Workbook()`부터 새로 써 주면, 앞에서 만든 시트 세 개가 날아간 빈 파일에 분야별합계만 담겨요. 저장 코드를 넣으면 저장이 두 번 일어나고요.

> 공식 과제에도 이런 요청문이 준비돼 있어요. 거기서는 품목별 합계를 요청해요. 요청문이 어떤 부분으로 나뉘어 있는지, 왜 그 조건이 들어갔는지 생각하며 보내 보세요.

### 받은 코드 붙이기

AI의 답은 매번 조금씩 달라요. 대략 이런 모양의 코드가 올 거예요.

```python
# 시트 4: 분야별합계
category_total = {}                               # 분야별 매출 합계를 담을 빈 딕셔너리
for row in all_rows:                              # 판매 기록을 한 줄씩 보면서
    category = row["분야"]                         # 이 줄의 분야 이름
    category_total[category] = category_total.get(category, 0) + row["매출"]   # 분야별로 매출 더하기

sheet4 = wb.create_sheet("분야별합계")              # '분야별합계' 시트 만들기
sheet4.append(["분야", "총매출"])                   # 제목 줄
for category, total in category_total.items():   # 분야마다
    sheet4.append([category, total])              # 한 줄씩 적기
```

받은 코드를 5단계 칸의 `▼▼▼`와 `▲▲▲` 사이에 붙여 넣고, 그 칸을 다시 실행하세요.

붙여 넣기 전에 한 번은 읽어 보세요. `Workbook()`이나 `save`가 들어 있지 않은지, `all_rows`와 `"매출"`처럼 우리 코드의 이름을 그대로 쓰는지요. 지금까지 배운 문법이라 충분히 읽을 수 있어요. SUMIF 패턴이 그대로 보이죠?

> 회사의 실제 데이터(고객 정보, 매출 자료 등)는 AI 채팅에 붙여 넣지 않아요. 위 요청문처럼 데이터의 모양만 알려 주고, 예시 한 줄은 가짜 값으로 보여 주면 충분해요.

## 종합 체험 3. 결과를 코드로 검증하기

에러 없이 돌아갔다고 결과가 맞는 건 아니에요. 그래서 결과를 코드로 확인해요. 무엇을 확인하면 좋을지부터 정해 볼게요.

1. 결과 파일에 시트가 정말 4개 생겼나?
2. 분야는 몇 개인가? (소설, 에세이, IT로 3개여야 해요)
3. 지점별 합계를 다 더한 값과 분야별 합계를 다 더한 값이 같은가?

세 번째가 핵심이에요. 같은 판매 기록을 지점으로 나눠 더하든 분야로 나눠 더하든, 전체 합은 같아야 하잖아요. 둘이 다르다면 어딘가에서 빠지거나 잘못 더해진 거예요.

```python
check = load_workbook(RESULT_FILE)                  # 저장된 파일을 다시 열어서
print("시트 이름:", check.sheetnames)                # 1. 시트 목록
print("분야 수:", len(category_total))              # 2. 분야 개수

branch_sum = sum(branch_total.values())             # 3. 지점별 합계를 모두 더한 값
category_sum = sum(category_total.values())         #    분야별 합계를 모두 더한 값
print("지점별 총합:", branch_sum)
print("분야별 총합:", category_sum)

if branch_sum == category_sum:                      # 4. 두 총합 비교
    print("[검증 통과]")
else:
    print("[확인 필요]")
# 시트 이름: ['전체데이터', '지점별합계', '확인필요', '분야별합계']
# 분야 수: 3
# 지점별 총합: 1937000
# 분야별 총합: 1937000
# [검증 통과]
```

시트 이름을 `wb.sheetnames`가 아니라 저장된 파일을 다시 열어서 확인한 이유가 있어요. 코드 안의 `wb`에 시트가 있어도, 저장 전에 추가된 게 아니면 파일에는 없을 수 있거든요. 보고받는 사람이 여는 건 파일이니까, 파일을 확인해야 해요.

`sum(딕셔너리.values())`는 딕셔너리의 값만 모두 더해요. 지점별 합계 `{'대구점': 376000, ...}`에서 숫자만 모아 더하는 거예요.

### 검증이 잡아내는 실수

AI가 이렇게 짜 줬다고 해 볼게요. 한 군데만 달라요.

```python
category_total[category] = category_total.get(category, 0) + row["권수"]   # "매출" 대신 "권수"!
```

에러는 전혀 안 나요. 시트도 잘 생기고, 숫자도 그럴듯하게 들어가요. 그런데 검증 칸을 돌리면 이렇게 나와요.

```text
지점별 총합: 1937000
분야별 총합: 110
[확인 필요]
```

매출이 아니라 권수를 더해 버린 거예요. 눈으로 표만 봤다면 놓쳤을지도 몰라요. 이런 실수를 잡으려고 검증을 하는 거예요.

> 공식 과제 5-3은 이 검증 코드를 직접 짜는 문제예요. 공식 데이터의 변수 이름(품목별 합계를 담은 딕셔너리 이름 등)에 맞춰 여러분 코드로 써 보세요.

## 종합 체험 4. 생각해 보기
