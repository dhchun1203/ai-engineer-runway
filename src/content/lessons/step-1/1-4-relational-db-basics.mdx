## 1. 학습 목표

이 레슨을 마치면 다음을 할 수 있습니다.

- 테이블 · 행 · 열이 각각 무엇에 해당하는지 설명할 수 있다
- 기본키가 왜 필요한지 말할 수 있다
- 외래키로 두 테이블을 연결해 만들 수 있다
- 만든 테이블에 데이터를 넣고 조회해 확인할 수 있다

## 2. 왜 배우나

앞 레슨에서 파일에 데이터를 저장해봤다면, 데이터가 많아질수록 찾기 어렵고 중복이 쌓이고 여러 사람이 동시에 고치면 꼬인다는 걸 느꼈을 겁니다. 관계형 데이터베이스(relational database, 표들을 서로 연결해 데이터를 정리해 두는 저장소)는 이 문제를 표 여러 개로 나누고 서로 잇는 방식으로 풉니다.

이 커리큘럼에서 만들 서비스는 결국 전부 이 구조 위에 데이터를 쌓습니다. 이 레슨은 Supabase SQL 에디터라는 브라우저 화면에서 전부 실습하므로 아이패드만 있어도 됩니다.

## 3. 개념 설명

### 📊 표 하나 = 테이블

테이블(table, 같은 종류의 데이터를 모아두는 표)을 엑셀 시트라고 생각하면 쉽습니다.

시트 하나가 테이블 하나, 시트의 한 줄이 행(row, 표의 한 줄 — 레코드 하나) 하나, 시트의 세로 칸이 열(column, 표의 세로 칸 — 정해진 자료형을 가짐) 하나입니다. 다른 점은, 열마다 어떤 자료형(`text`, `int`, `serial` 등)만 들어갈지 미리 정해둔다는 것입니다.

| 엑셀 | 데이터베이스 | 예시 |
|------|--------------|------|
| 시트 | 테이블 | `students` 표 |
| 줄(행) | 행(레코드) | 학생 한 명 |
| 칸(열) | 열(컬럼) | `name`(이름), `grade`(학년) |

### 🧵 외래키 — 두 표를 잇는 실

<TwistBox>

학생을 표에서 지우면 그 학생의 수강 기록도 자동으로 같이 사라질 것 같지만, 실제로 시도하면 어떤 일이 일어날까요?

```sql
-- 김지현(id=1)이 이미 수강 기록을 갖고 있는 상태에서 삭제를 시도
DELETE FROM practice.students WHERE id = 1;
-- update or delete on table "students" violates foreign key constraint
```

외래키는 "가리키는 대상이 사라지면 안 된다"는 규칙도 함께 강제합니다. `enrollments`가 `student_id`로 그 학생을 계속 가리키는 한, 삭제 자체가 거부됩니다.

먼저 관련 수강 기록을 지우거나, 표를 설계할 때 `ON DELETE CASCADE` 같은 규칙을 미리 정해둬야 이런 삭제가 가능해집니다.

</TwistBox>

## 5. 실무 팁

- 테이블 · 열 이름은 소문자와 밑줄(snake_case)로 짓는 관례를 따릅니다 — `student_name`처럼.
- `NOT NULL`은 처음부터 걸어두는 편이 나중에 빈 값을 찾아 다시 채우는 것보다 쉽습니다.
- 연습은 반드시 `practice` 스키마 안에서만 합니다 — 실수로 다른 서랍을 건드리면 되돌릴 수 없습니다.
- 실습이 끝나면(또는 처음부터 다시 하고 싶으면) 아래 "실습 되돌리기" 블록을 실행해 연습용 서랍을 치웁니다 — 이걸 실행한 뒤 맨 위 블록부터 다시 누르면 깨끗한 상태에서 다시 시작합니다.

## 6. 핵심 정리 및 스스로 점검

**핵심 정리**

- 테이블 하나는 같은 종류의 데이터를 모아두는 표이고, 행은 한 건, 열은 항목이다
- 기본키는 각 행을 유일하게 구분하는 값이다
- 외래키는 다른 표의 기본키를 가리켜 두 표를 연결하는 값이다
- 스키마는 여러 테이블을 묶어 담는 서랍이며, 연습은 별도 서랍(`practice`)에서만 한다
- 실습은 Supabase SQL 에디터라는 브라우저 화면에서 이뤄지므로 아이패드에서도 그대로 할 수 있다

**이 레슨의 단어**

| 단어 | 뜻 |
|------|-----|
| 테이블 | 같은 종류의 데이터를 모아두는 표 |
| 행 | 표의 한 줄 — 레코드 하나 |
| 열 | 표의 세로 칸 — 정해진 자료형을 가짐 |
| 기본키 | 표 안에서 각 행을 유일하게 구분하는 값 |
| 외래키 | 다른 표의 기본키를 가리켜 두 표를 연결하는 값 |
| 스키마 | 여러 테이블을 묶어 담는 이름 붙은 서랍 |
| 제약조건 | 표에 넣을 수 있는 값의 규칙(`NOT NULL`, 기본키 등) |
