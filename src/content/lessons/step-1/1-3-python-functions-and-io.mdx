## 1. 학습 목표

이 레슨을 마치면 다음을 할 수 있습니다.

- 반복되는 처리를 함수로 묶어 이름을 붙일 수 있다
- 함수에 값을 넘기고 결과를 돌려받는 흐름을 설명할 수 있다
- 예상 가능한 실패를 `try`/`except`로 감싸 프로그램이 멈추지 않게 할 수 있다
- 결과를 파일에 저장하고 다시 읽어 확인할 수 있다

## 2. 왜 배우나

앞 레슨에서 변수·자료형·조건문·반복문으로 한 덩어리 스크립트를 짰다면, 이번엔 그 덩어리를 이름 붙은 조각으로 나눌 차례입니다. 코드가 길어질수록 같은 처리를 여러 번 복사-붙여넣기 하게 되는데, 함수는 이 반복을 한 곳에 모아줍니다.

그리고 프로그램은 늘 바깥 세계(사용자 입력, 파일, 나중엔 API)와 만나고, 바깥 세계는 항상 예상과 다르게 굴 수 있습니다. 실패를 감당하고 결과를 남기는 법을 배우면 다음 Step의 API 호출·데이터 처리로 자연스럽게 이어집니다.

## 3. 개념 설명

### 🥤 함수는 자판기

자판기(function, 반복되는 처리를 이름 붙여 묶어 두는 코드 조각)에 동전을 넣으면 정해진 음료가 나옵니다. 넣는 동전이 다르면 나오는 음료도 다르지만, 자판기 내부 작동 방식은 항상 같습니다.

함수도 똑같습니다 — `def`로 한 번 정의해두면, 넣는 값(입력)만 바꿔가며 같은 처리를 계속 재사용할 수 있습니다. 함수를 "정의할 때" 괄호 안에 적는 이름은 매개변수(parameter, 함수가 입력을 받기 위해 미리 정해둔 이름)이고, 함수를 "호출할 때" 실제로 넣는 값은 인자(argument, 함수를 호출할 때 실제로 넘기는 값)라고 부릅니다.

| 자판기 비유 | 함수 개념 | 예시 |
|---|---|---|
| 동전 넣는 자리 | 매개변수 — 입력을 받기로 미리 정해둔 이름 | `def summarize_member(name, age, height):` |
| 실제로 넣는 동전 | 인자 — 호출할 때 실제로 넘기는 값 | `summarize_member("김지현", 27, 168.3)` |
| 나오는 음료 | 반환값(return value, 함수가 돌려주는 결과) | `return f"{name} - 나이 {age}세"` |

### 🛟 예외는 안전망

줄타기 곡예사 밑에 안전망이 있으면, 발을 헛디뎌도 바닥까지 떨어지지 않고 그 자리에서 다시 시작할 수 있습니다. 예외(exception, 코드 실행 중 발생하는 예상 가능한 오류 상황)를 처리하지 않으면 프로그램은 그 줄에서 곧바로 멈춰버립니다.

`try:` 블록 안에서 실패할 수 있는 코드를 실행하다가, 실제로 실패하면 `except 예외이름:` 블록이 대신 실행되고 프로그램은 계속 이어집니다.

이때 반드시 잡을 예외를 이름으로 지정해야 합니다 — 이름 없이 `except:`만 쓰면 무엇이 잘못됐는지 알 수 없는 채로 온갖 종류의 오류를 전부 삼켜버려서, 나중에 진짜 버그를 찾을 때 실마리가 사라집니다.

### ✉️ 파일은 편지

편지를 쓰고 봉투에 넣어 두면 내가 컴퓨터를 꺼도 그 내용은 그대로 남아 있다가, 나중에 다시 열어 읽을 수 있습니다. 변수에 담긴 값은 프로그램이 끝나면 사라지지만, 파일(file, 프로그램이 끝난 뒤에도 내용이 남는 저장 단위)에 쓴 내용은 남습니다.

`open(파일명, "w")`는 쓰기 모드로, `open(파일명, "r")`는 읽기 모드로 파일을 엽니다. `with open(...) as f:` 블록을 쓰면 블록이 끝나는 순간 파일이 자동으로 닫혀서, 닫는 것을 깜박할 걱정이 없습니다.

한글을 쓰거나 읽을 때는 `encoding="utf-8"`을 반드시 지정해야 합니다 — Windows의 기본 인코딩은 `utf-8`이 아니라서, 지정하지 않으면 한글이 깨질 수 있습니다.

## 4. 실무 예제

앞 레슨의 회원 정보(`name`, `age`, `height`)를 이어받아, 요약 문자열을 돌려주는 함수를 만들고, 나이 값이 잘못된 회원은 예외로 방어하고, 정상 처리된 결과만 파일에 저장했다가 다시 읽는 완결된 예제입니다.

<PredictPrompt />

<RunPython>

```python
# members_io.py
# 함수로 회원 요약을 만들고, 잘못된 나이 값은 예외로 방어하고, 결과를 파일에 남긴다

def summarize_member(name, age, height):
    """회원 정보를 받아 한 줄 요약 문자열을 돌려준다."""
    return f"{name} - 나이 {age}세, 키 {height}cm"


# 회원 원본 데이터 - 세 번째 회원의 나이 값이 숫자가 아니다 (일부러 잘못된 값을 섞었다)
raw_members = [
    ("김지현", "27", 168.3),
    ("이민준", "34", 175.5),
    ("박서연", "스물아홉", 162.0),  # 잘못된 나이 값
]

summaries = []

for name, age_text, height in raw_members:
    try:
        age = int(age_text)
    except ValueError:
        print(f"'{name}'의 나이 값이 잘못되었습니다: '{age_text}' - 건너뜁니다.")
        continue
    summaries.append(summarize_member(name, age, height))

print("---")

# 정상 처리된 요약을 파일에 저장한다 (같은 폴더의 상대 경로, UTF-8 인코딩)
with open("members.txt", "w", encoding="utf-8") as f:
    for line in summaries:
        f.write(line + "\n")

# 저장한 파일을 다시 열어 읽고 출력한다
with open("members.txt", "r", encoding="utf-8") as f:
    print("members.txt 내용:")
    print(f.read())
```

</RunPython>

위 "실행" 버튼을 누르면 이 코드가 브라우저 안에서 바로 돌아갑니다 — 파일에 쓰고 다시 읽는 부분까지 브라우저 안 임시 공간에서 그대로 동작합니다. `try`/`except`로 잘못된 나이 값이 한 번 걸러지는 것도 출력으로 확인할 수 있습니다.

**실행 방법:** 위 코드를 `members_io.py` 파일로 저장한 뒤, PowerShell에서 아래 명령을 실행합니다.

```powershell
# members_io.py 실행 — python 대신 py 런처를 씁니다
py members_io.py
```

macOS는 `python3 members_io.py`로 실행합니다.

실행하면 먼저 "박서연"의 나이 값이 잘못되었다는 경고 메시지가 한 줄 출력됩니다(예외가 실제로 한 번 잡힌 것입니다). 이어서 정상 처리된 "김지현"·"이민준" 두 명의 요약이 `members.txt`에 저장되고, 바로 다시 읽어 그 내용이 화면에 출력됩니다.

실행이 끝나면 `members_io.py`와 같은 폴더에 `members.txt` 파일이 실제로 생겼는지 직접 열어서 확인해보세요.

경고 메시지가 두 번 출력되고, `summaries`에는 여전히 정상 처리된 회원만 담깁니다. `try`/`except`가 반복문 **안**에 있어서, 한 번의 실패가 `continue`로 그 회원만 건너뛰고 다음 회원으로 넘어가기 때문입니다 — `try`/`except`가 없었다면 첫 번째 잘못된 값에서 프로그램 전체가 멈췄을 것입니다.

</details>

### 해보기 (선택)

저장 파일명을 `members.txt` 대신 `members2.txt`로 바꿔보세요. 쓰기와 읽기 두 곳의 파일명을 모두 고쳐야 실행 후 폴더에 `members2.txt`가 생깁니다.

<details>
<summary>정답 보기</summary>

`with open("members.txt", ...)` 두 줄을 모두 `with open("members2.txt", ...)`로 바꾸면 됩니다. 한 곳만 고치면 쓰기와 읽기가 서로 다른 파일을 가리켜 `FileNotFoundError`(읽으려는 파일이 아직 없음)가 발생할 수 있습니다.

</details>

## 5. 실무 팁

- **함수는 하나의 일만 하게 짓습니다.** 이름만 보고도 무슨 일을 하는지 알 수 있게(`summarize_member`처럼) 짓습니다.
- **예외를 잡을 때는 잡을 예외를 이름으로 지정합니다.** `except ValueError:`처럼 구체적으로 적어야, 나중에 다른 종류의 오류가 났을 때 그걸 놓치지 않고 알아챌 수 있습니다.
- **파일을 열 때는 `with`를 씁니다.** 블록이 끝나면 자동으로 닫혀서, 닫는 것을 잊어버릴 수가 없습니다.
- **한글을 다루는 파일은 `encoding="utf-8"`을 꼭 지정합니다.** Windows 환경에서 특히 이 지정을 빠뜨리면 한글이 깨지는 문제를 자주 겪습니다.

## 6. 핵심 정리 및 스스로 점검

**핵심 정리**

- 함수는 `def`로 정의하고, 매개변수로 입력을 받아 `return`으로 결과를 돌려준다
- `try`/`except`는 예상 가능한 실패를 감싸는 안전망이고, 잡을 예외는 반드시 이름으로 지정한다
- `with open(...) as f:`는 파일을 자동으로 닫아주는 안전한 파일 열기 방식이다
- 한글이 담긴 파일은 `encoding="utf-8"`을 지정해야 깨지지 않는다
- 예외 하나를 처리해도 반복문의 나머지 항목은 계속 처리된다

**이 레슨의 단어**

| 단어 | 뜻 |
|------|-----|
| 함수 | 반복되는 처리를 이름 붙여 묶어 두는 코드 조각 |
| 매개변수 | 함수가 입력을 받기 위해 미리 정해둔 이름 |
| 인자 | 함수를 호출할 때 실제로 넘기는 값 |
| 반환값 | 함수가 처리를 마치고 돌려주는 결과 |
| 예외 | 코드 실행 중 발생하는 예상 가능한 오류 상황 |
| 파일 | 프로그램이 끝난 뒤에도 내용이 남는 저장 단위 |
| 인코딩 | 글자를 컴퓨터가 저장할 수 있는 형태로 바꾸는 규칙 |

**스스로 점검**

1. 잡을 예외 이름을 지정하지 않고 모든 예외를 조용히 삼키는 `except:` 형태로 코드를 짜면 무엇이 문제일까요?

<details>
<summary>힌트 보기</summary>

`except` 뒤에 이름을 적지 않으면, 정말로 예상했던 실패와 코드 자체의 진짜 실수를 프로그램이 서로 구분할 수 있을지 생각해보세요.

</details>

<details>
<summary>정답 보기</summary>

어떤 종류의 오류든 상관없이 전부 잡아버려서, 정말 예상했던 실패(`ValueError` 같은)와 코드에 진짜 버그가 있어서 나는 오류(오타, 잘못된 로직 등)를 구분할 수 없게 됩니다. 문제가 조용히 숨겨진 채로 프로그램은 계속 돌아가지만, 나중에 왜 결과가 이상한지 원인을 찾기가 훨씬 어려워집니다.

</details>

2. `with open("members.txt", "w", encoding="utf-8") as f:` 대신 `with`를 빼고 `f = open("members.txt", "w", encoding="utf-8")`만 썼다면, 파일을 다 쓴 뒤 무엇을 직접 해줘야 할까요?

<details>
<summary>힌트 보기</summary>

`with` 블록이 끝나는 순간 파이썬이 자동으로 해주던 일이 무엇이었는지 3장 내용을 떠올려보세요. `with` 없이는 그 일을 누가 대신 해줄까요.

</details>

<details>
<summary>정답 보기</summary>

`f.close()`를 직접 호출해서 파일을 닫아야 합니다. `with`를 쓰지 않으면 Python이 자동으로 닫아주지 않으므로, 만약 `close()` 호출 전에 예외가 발생하면 파일이 열린 채로 남아 다음 실행에서 문제가 생길 수 있습니다.

</details>
