## 1. 학습 목표

이 레슨을 마치면 다음을 알아듣습니다.

- 파인튜닝(fine-tuning, 모델을 특정 목적에 맞게 다시 학습시키는 것)이 무엇을 하는 작업인지 한 문장으로 말할 수 있다
- PEFT·LoRA·QLoRA가 각각 무엇이고 왜 등장했는지 말할 수 있다
- 언제 프롬프트·RAG 대신 튜닝을 고려하는지 말할 수 있다
- 튜닝이 전체 파이프라인에서 어느 자리에 놓이는지 안다

## 2. 왜 배우나

프롬프트와 RAG로 대부분의 문제가 풀리지만, 조직 특유의 말투나 형식을 모델이 전혀 모르는 경우처럼 남는 문제가 있습니다.

튜닝은 이럴 때 쓰는 마지막 카드이며, 비용과 시간이 많이 듭니다. 그래서 먼저 알아야 할 것은 언제 튜닝을 쓰지 않아야 하는가입니다.

## 3. 개념 설명

### 🧭 언제 튜닝 대신 프롬프트·RAG로 푸는가

| 상황 | 권장 접근 |
|------|---------|
| 모델이 이미 아는 지식이고 지시만 명확히 하면 되는 경우 | 프롬프트 |
| 모델이 모르는 최신·사내 정보를 찾아 붙여줘야 하는 경우 | RAG |
| 프롬프트·RAG로도 조직 특유의 말투·형식을 못 맞추는 경우 | PEFT 튜닝 |

파이프라인에서의 자리는 다음과 같습니다.

`문제 정의 → 프롬프트로 해결 시도 → RAG로 지식 보강 → 그래도 안 되면 PEFT 튜닝 → 평가`

## 5. 실무 팁

- 튜닝 전에 평가셋부터 만들어 둡니다. 무엇이 좋아졌는지 판단할 기준이 없으면 튜닝 여부를 결정할 수 없습니다(다음 편에서 다룹니다).
- 기법 선택보다 데이터 품질이 결과를 더 크게 좌우합니다.
- 어댑터는 크기가 작아서 용도별로 여러 개를 만들어 갈아 끼울 수 있습니다.
- 학습 데이터에 개인정보가 섞이면 모델이 그것을 그대로 기억할 수 있습니다.

## 6. 핵심 정리 및 스스로 점검

**핵심 정리**

- 전체 파인튜닝은 모델 전체를 다시 학습시키는 것이고, PEFT는 일부만 손대는 방식이다
- LoRA는 원본 가중치를 얼리고 작은 어댑터 층만 학습하는 PEFT 기법이다
- QLoRA는 모델을 압축한 뒤 LoRA를 적용해 더 적은 자원으로 튜닝하는 방식이다
- 튜닝은 프롬프트·RAG로 안 되는 경우에 쓰는 마지막 카드다
- 이 레슨의 코드는 읽기용이며, 실제로 다뤄보는 것은 개강 후 본 과정에서다

**이 레슨의 단어**

| 단어 | 뜻 |
|------|-----|
| 파인튜닝 | 모델을 특정 목적에 맞게 다시 학습시키는 것 |
| PEFT | 모델 전체가 아니라 일부만 학습하는 효율적인 튜닝 방식 |
| LoRA | 원본 가중치는 얼려두고 작은 어댑터 층만 학습하는 PEFT 기법 |
| QLoRA | 모델을 압축한 뒤 LoRA를 적용하는 방식 |
| 어댑터 | 원본 모델 위에 덧붙여 학습하는 작은 층 |
| 양자화 | 모델의 숫자 표현을 더 작은 크기로 압축하는 것 |
| 베이스 모델 | 튜닝하기 전 원본 모델 |

**스스로 점검**

1. 전체 파인튜닝 대신 LoRA를 쓰는 이유는 무엇일까요?

<details>
<summary>힌트 보기</summary>

전체 파인튜닝과 LoRA가 각각 모델의 얼마나 많은 부분을 새로 학습시키는지 떠올려보세요. 손대는 부분의 크기가 다르면 걸리는 시간과 자원에 어떤 차이가 생길지 생각해봅니다.

</details>

<details>
<summary>정답 보기</summary>

전체 파인튜닝은 모델 전체를 다시 학습시켜야 해서 시간과 비용이 많이 듭니다. LoRA는 원본 가중치를 그대로 두고 작은 어댑터 층만 학습하므로, 훨씬 적은 자원으로 비슷한 효과를 낼 수 있습니다.

</details>

2. 프롬프트로 안 풀리는 문제를 만났을 때, 곧바로 튜닝으로 건너뛰지 않고 먼저 시도해야 할 것은 무엇이고 왜 그 순서일까요?

<details>
<summary>힌트 보기</summary>

모델이 지시만으로 안 되는 게 아니라 "모르는 지식"이 부족한 경우인지부터 구분해보세요. 프롬프트와 튜닝 사이에, 비용이 훨씬 덜 들면서도 모델에게 정보를 보태줄 방법이 있었다는 것을 떠올려봅니다.

</details>

<details>
<summary>정답 보기</summary>

먼저 RAG로 모델이 모르는 지식을 검색해 붙여주는 방법을 시도합니다. 프롬프트 → RAG → 튜닝 순서인 이유는 뒤로 갈수록 비용과 시간이 커지기 때문입니다.

튜닝은 데이터 준비와 학습 부담이 커서, 프롬프트와 RAG로도 조직 특유의 말투·형식을 못 맞출 때만 마지막 카드로 씁니다.

</details>
