## 1. 학습 목표

이 레슨을 마치면 다음을 알아듣습니다.

- 키워드 검색(BM25)과 벡터 검색을 각각 한 문장으로 설명할 수 있다
- 왜 실무 RAG가 이 둘을 함께 쓰는지 말할 수 있다
- re-ranking이 검색 파이프라인의 어느 자리에서 무슨 역할을 하는지 안다

## 2. 왜 배우나

앞 레슨에서 벡터 검색은 "뜻이 비슷한 것"을 찾는다고 배웠습니다. 하지만 제품 코드나 사람 이름처럼 정확히 일치해야 하는 단어는 오히려 놓치기 쉽습니다. 그래서 실무 RAG는 키워드 검색과 벡터 검색을 함께 쓰는 경우가 많습니다.

## 4. 실무 예제

### 실무에서 이게 어떻게 쓰이나

사내 문서 검색이나 법률·의료 문서 검색에서 하이브리드 검색이 특히 필요합니다. "제3조" 같은 조문 번호나 사번, 약품명처럼 정확히 일치해야 하는 토큰이 자주 등장하기 때문입니다.

벡터 검색만 쓰면 뜻이 비슷한 조문끼리 헷갈릴 수 있지만, 키워드 검색을 함께 쓰면 정확한 번호가 있는 문서가 우선순위를 지킵니다.

> 아래 코드는 개념을 눈으로 보기 위한 예시입니다 — 지금 실행할 필요는 없습니다.
> 개강 후 본 과정에서 실제로 돌려보게 됩니다.

<PredictPrompt />

```typescript
// 개념 예시 — 두 검색 결과를 합쳐 re-ranking에 넘기는 흐름
const keywordResults = await bm25Search(query); // 키워드 검색 결과
const vectorResults = await vectorSearch(query); // 벡터 검색 결과
const merged = mergeRankings(keywordResults, vectorResults); // 두 순위를 합친 후보군
const reranked = await rerank(query, merged); // 후보를 다시 정교하게 줄 세운다
```

## 5. 실무 팁

- top-k 값과 re-ranking 대상 수는 실무에서 팀이 속도·비용·정확도를 보며 정하는 결정 지점입니다 — 정답이 하나로 고정되어 있지 않습니다.
- 개강 후 실습에서 "왜 이 정도만 다시 순위를 매길까" 같은 질문이 나오면, 오늘 본 하이브리드 검색·re-ranking 개념이 그 답의 재료라는 것을 알아채는 정도면 충분합니다.

## 6. 핵심 정리 및 스스로 점검

**핵심 정리**

- 키워드 검색은 같은 단어가 있는지를 보고, 벡터 검색은 뜻이 비슷한지를 본다
- 하이브리드 검색은 두 결과를 합쳐 더 정확한 후보군을 만든다
- re-ranking은 후보군을 더 정교한 모델로 다시 줄 세우는 단계다
- top-k와 re-ranking 대상 수는 속도·비용과 맞물린 실무 결정 지점이다
- 이 레슨의 코드는 읽기용이며, 실제로 손으로 돌려보는 것은 개강 후 본 과정에서 다룬다

**이 레슨의 단어**

| 단어 | 뜻 |
|------|-----|
| 키워드 검색 | 문서에 같은 단어가 실제로 들어 있는지를 보는 검색 방식 |
| BM25 | 키워드 검색에서 널리 쓰이는 대표 알고리즘 |
| 하이브리드 검색 | 키워드 검색과 벡터 검색 결과를 합치는 방식 |
| re-ranking | 후보군을 더 정교한 모델로 다시 줄 세우는 단계 |
| top-k | 검색에서 상위 몇 개까지 가져올지 나타내는 값 |
| 후보군 | re-ranking이 다시 정렬하기 전, 미리 넉넉히 뽑아둔 결과 묶음 |
| 지연 | 검색부터 답변까지 걸리는 시간(latency) |

**스스로 점검**

1. "제3조" 같은 정확한 조문 번호를 찾을 때, 벡터 검색만 쓰면 왜 아쉬운 결과가 나올 수 있을까요?

<details>
<summary>힌트 보기</summary>

벡터 검색이 문서를 고를 때 "같은 단어인가"가 아니라 무엇을 기준으로 가까움을 따졌는지 떠올려보세요. 조문 번호처럼 형태는 조금 다르지만 뜻은 비슷해 보이는 두 표현을, 이 기준으로 정확히 구별할 수 있을지 생각해봅니다.

</details>

<details>
<summary>정답 보기</summary>

벡터 검색은 "뜻이 비슷한가"를 보기 때문에 "제3조"와 "제5조"처럼 형태는 다르지만 뜻은 비슷해 보이는 문서를 구별하기 어려울 수 있습니다. 정확한 번호 일치가 중요할 때는 키워드 검색이 함께 있어야 이런 문서를 놓치지 않습니다.

</details>

2. re-ranking은 왜 처음부터 모든 문서에 정교한 모델을 돌리지 않고, 하이브리드 검색으로 후보를 먼저 좁힌 뒤에만 사용할까요?

<details>
<summary>힌트 보기</summary>

re-ranking에 쓰이는 모델과 하이브리드 검색에 쓰이는 방식 중 어느 쪽이 더 정교하고 어느 쪽이 더 빠른지 비교해보세요. 정교할수록 문서 하나를 처리하는 데 무엇을 더 많이 쓰게 될지도 함께 생각해봅니다.

</details>

<details>
<summary>정답 보기</summary>

정교한 re-ranking 모델은 빠른 검색 방식보다 느리고 비용이 더 듭니다. 그래서 먼저 빠른 하이브리드 검색으로 후보를 넉넉히 추린 다음, 그 안에서만 정교한 모델을 써서 전체 속도와 비용을 감당할 수 있는 수준으로 유지합니다.

</details>
