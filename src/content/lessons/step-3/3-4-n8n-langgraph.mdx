## 1. 학습 목표

이 레슨을 마치면 다음을 알아듣습니다.

- n8n과 LangGraph가 각각 무엇인지 한 문장으로 말할 수 있다
- 어떤 자동화에 노코드가 맞고 어떤 자동화에 코드가 맞는지 판단 기준을 말할 수 있다
- 두 도구가 전체 자동화 파이프라인에서 어디에 놓이는지 안다

## 2. 왜 배우나

개강 후 실습에서 이 두 도구로 직접 자동화를 만들게 됩니다. 도구 이름과 성격을 그때 처음 만나면 배울 게 두 배가 됩니다.

이 편은 도구를 설치해 돌려 보는 편이 아니라, 개강 후 실습할 두 도구가 무엇이고 언제 어느 쪽을 고르는지 미리 알아 두는 편입니다. **지금은 설치하지 않습니다.**

## 3. 개념 설명

### 🔗 공통 개념 — 노드와 연결

두 도구 모두 "무엇을 하는 상자(노드)"와 "다음으로 가는 선(연결)"으로 자동화를 표현합니다. 이는 앞 편에서 본 여러 AI 구조의 노드·연결 개념과 같습니다.

### ⚖️ 언제 어느 쪽을 고르나

두 도구 중 무엇을 쓸지는 상황에 따라 팀이 판단하는 결정 지점입니다.

| 상황 | 어느 쪽이 맞나 |
|---|---|
| 변경이 잦고 비개발자도 손대야 함 | 노코드(n8n) |
| 조건 분기가 복잡하고 테스트가 필요함 | 코드(LangGraph) |
| 화면 구성은 노코드로, 복잡한 판단만 코드로 | 둘을 섞어서 사용 |

어느 쪽을 쓰든 무엇이 바뀌었는지 기록(버전 관리)하고, 실패했을 때 무엇이 잘못됐는지 알 수 있어야 합니다.

## 5. 실무 팁

- 노코드도 결국 버전 관리가 필요합니다. 화면에서 고친 내용을 기록으로 남겨두어야 나중에 무엇이 바뀌었는지 알 수 있습니다.
- 워크플로가 커지면 하나로 몰아넣지 않고 여러 개로 쪼갭니다.
- 도구가 무엇이든 실패했을 때 어디까지 처리됐는지 알 수 있어야 합니다.

## 6. 핵심 정리 및 스스로 점검

**핵심 정리**

- n8n은 화면에서 블록을 이어 붙이는 노코드 워크플로 도구다
- LangGraph는 코드로 그래프를 선언하는 프레임워크다
- 두 도구 모두 노드와 연결로 자동화를 표현한다는 공통점이 있다
- 변경이 잦고 비개발자도 손대야 하면 노코드, 조건 분기가 복잡하고 테스트가 필요하면 코드가 어울린다
- 이 레슨의 코드는 읽기용이며, 실제로 손으로 돌려보는 것은 개강 후 본 과정에서 다룬다

**이 레슨의 단어**

| 단어 | 뜻 |
|------|-----|
| 노코드 | 화면에서 블록을 이어 붙여 만드는 방식, 코드를 직접 쓰지 않음 |
| 워크플로 | 자동화가 실행되는 전체 흐름 |
| 노드 | 워크플로에서 하나의 작업을 나타내는 상자 |
| 연결 | 한 노드에서 다음 노드로 가는 선 |
| 그래프 | 노드와 연결로 이루어진 전체 구조 |
| 분기 | 조건에 따라 다른 노드로 갈라지는 지점 |
| 실행 이력 | 워크플로가 언제 어디까지 실행됐는지 남긴 기록 |
