## 1. 학습 목표

이 레슨을 마치면 다음을 알아듣습니다.

- 구조화 출력이 서비스 규모에서 실패했을 때 무엇을 선택할 수 있는지 말할 수 있다
- 카나리 배포(canary deployment)가 무엇을 가리키는지, 왜 전체에 한 번에 올리지 않는지 말할 수 있다
- 비용·지연·성공률 세 지표가 서로 어떻게 맞바꿔지는지 안다
- 롤백 조건을 배포 전에 정해 두는 이유를 알아듣는다

## 2. 왜 배우나

`2-7-prompt-patterns`에서 만든 구조화 출력은 하루 수천 번 돌면 실패가 반드시 섞입니다. 한 번도 안 깨지는 파이프라인은 없습니다.

프롬프트나 모델을 바꿀 때 전체 요청에 한 번에 적용하면 잘못됐을 때 되돌리기 어렵습니다. 이 레슨은 그 두 문제를 서비스가 어떻게 다루는지 다룹니다.

## 3. 개념 설명

### 🔀 구조화 출력 파이프라인 — 검증 실패는 반드시 일어난다

### ⏪ 롤백 조건을 미리 정해 두는 이유

롤백(rollback)은 문제가 생긴 버전을 이전 버전으로 되돌리는 것입니다. 사고가 벌어지는 중에는 판단이 흐려지므로, 어떤 상황이면 롤백할지를 배포 전에 미리 정해 둡니다.

### ⚖️ 비용·지연·성공률 — 서로 맞바꿔지는 세 지표

더 정확한 모델은 대체로 더 느리고 더 비쌉니다. 비용·지연·성공률 중 무엇을 우선할지는 서비스 성격에 따라 다르며, 그 우선순위는 서비스가 직접 정합니다.

## 4. 실무 예제

### 실무에서 이게 어떻게 쓰이나

새 프롬프트를 전체 요청에 한 번에 적용했다가 특정 입력에서 형식이 깨져 화면이 빈 채로 나간 적이 있었습니다. 원인을 찾아 되돌리는 동안 이미 많은 사용자가 빈 화면을 보고 난 뒤였습니다.

만약 카나리로 10%에만 먼저 태웠다면 문제를 훨씬 적은 사용자에게서, 훨씬 빨리 발견했을 것입니다. 이 경험 이후 이 팀은 새 버전을 항상 일부 요청에만 먼저 태우는 방식으로 바꿨습니다.

> 아래 코드는 개념을 눈으로 보기 위한 예시입니다 — 지금 실행할 필요는 없습니다.
> 개강 후 본 과정에서 실제로 다뤄보게 됩니다.

```typescript
// 카나리 비율에 따라 어느 버전을 쓸지 고르고 결과 지표를 기록하는 개념 예시
function pickVersion(canaryRatio: number): "canary" | "stable" {
  return Math.random() < canaryRatio ? "canary" : "stable";
}

async function handleRequest(input: string) {
  const version = pickVersion(0.1); // 요청의 10%만 카나리 버전으로
  const raw = await callModel(version, input);
  const parsed = ProductCopySchema.safeParse(JSON.parse(raw));

  if (!parsed.success) {
    // 검증 실패 — 세 선택지 중 하나를 고른다(여기서는 기본값 대체)
    recordMetric({ version, success: false });
    return DEFAULT_COPY;
  }

  recordMetric({ version, success: true }); // 성공률 지표로 쌓인다
  return parsed.data;
}
```

## 5. 실무 팁

- 롤백 조건은 배포 전에 숫자로 정해 둡니다. 사고 중에는 판단이 흐려지기 때문입니다.
- 검증 실패도 지표로 남깁니다. 조용히 재시도만 하면 문제가 얼마나 자주 나는지 보이지 않습니다.
- 비용은 요청 한 건이 아니라 하루 총액으로도 함께 봅니다.

## 6. 핵심 정리 및 스스로 점검

**핵심 정리**

- 구조화 출력 검증 실패에는 재시도·기본값 대체·사람에게 넘기기 세 선택지가 있다
- 카나리 배포는 새 버전을 일부 요청에만 먼저 태워 문제를 적게, 빨리 발견하게 한다
- 롤백 조건은 사고가 나기 전에 미리 숫자로 정해 둔다
- 비용·지연·성공률은 서로 맞바꿔지며 우선순위는 서비스가 정한다
- 이 레슨을 마지막으로 Step 3의 개요 레슨 13편이 모두 끝났다

**이 레슨의 단어**

| 단어 | 뜻 |
|------|-----|
| 구조화 출력 | 자연어 대신 정해진 형식(JSON 등)으로 응답을 받는 것 |
| 스키마 검증 | 응답이 정해진 형식을 지켰는지 코드로 확인하는 것 |
| 카나리 배포 | 새 버전을 일부 요청에만 먼저 적용해 보는 배포 방식 |
| 롤백 | 문제가 생긴 버전을 이전 버전으로 되돌리는 것 |
| 성공률 | 요청 중 검증을 통과한 응답의 비율 |
| 지연(latency) | 요청부터 응답까지 걸리는 시간 |
| 토큰 비용 | 모델 호출에 드는 비용, 토큰 사용량으로 계산됨 |
