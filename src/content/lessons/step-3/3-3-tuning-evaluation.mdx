## 1. 학습 목표

이 레슨을 마치면 다음을 알아듣습니다.

- 베이스라인(baseline, 비교 기준이 되는 튜닝 전 모델)이 왜 필요한지 한 문장으로 말할 수 있다
- 튜닝 전후 결과 표를 읽고 좋아졌는지 판단하는 근거를 말할 수 있다
- 평가셋을 학습 데이터와 왜 분리해야 하는지 말할 수 있다
- LLM 평가가 전체 파이프라인의 어느 자리에서 이뤄지는지 안다

## 2. 왜 배우나

튜닝한 모델이 "좋아 보인다"와 "실제로 좋아졌다"는 다릅니다. 눈으로 보기에 그럴듯한 답이 실제 지표로는 나빠진 경우가 흔합니다.

개강 후 프로젝트에서 결과 표를 앞에 두고 배포할지 말지 판단해야 할 사람은 강사가 아니라 여러분 자신입니다.

## 3. 개념 설명

### 📊 평가 지표의 종류

LLM 평가는 성격이 다른 몇 가지 방식을 섞어서 씁니다.

| 종류 | 무엇을 보는가 | 한계 |
|------|-------------|------|
| 형식 통과율 | 응답이 정해진 형식(JSON 등)을 지켰는가 | 형식만 맞고 내용이 틀려도 통과한다 |
| 정답 일치도 | 정해진 정답과 얼마나 일치하는가 | 정답이 하나로 정해지지 않는 질문에는 못 쓴다 |
| 사람 평가 | 사람이 직접 답을 읽고 채점한다 | 정확하지만 느리고 비용이 든다 |
| 모델 채점 | 다른 모델이 답을 읽고 채점한다 | 빠르지만 채점하는 모델도 실수할 수 있다 |

## 5. 실무 팁

- 평가셋은 이상적인 케이스가 아니라 실제로 문제가 났던 입력부터 채웁니다(2-7-promptops의 골든셋과 같은 원칙입니다).
- 지표 하나만 보고 배포를 결정하지 않습니다. 형식·정답 일치도·사람 평가를 함께 봅니다.
- 튜닝 전후 비교는 같은 평가셋·같은 조건에서만 의미가 있습니다.

## 6. 핵심 정리 및 스스로 점검

**핵심 정리**

- 베이스라인은 튜닝 전 점수이며, 이것 없이는 튜닝 효과를 판단할 수 없다
- 평가셋은 학습 데이터와 분리해야 실제 실력을 잴 수 있다
- 지표는 형식 통과율·정답 일치도·사람 평가·모델 채점처럼 성격이 다른 것을 함께 봐야 한다
- 형식 지표만 오르고 사람 평가가 떨어지는 경우가 실제로 있다
- 튜닝 전후 비교는 같은 평가셋·같은 조건에서만 의미가 있다

**이 레슨의 단어**

| 단어 | 뜻 |
|------|-----|
| 베이스라인 | 비교 기준이 되는 튜닝 전 모델의 점수 |
| 평가셋 | 학습 데이터와 분리해서 성능을 재는 데 쓰는 입력·정답 목록 |
| 과적합 | 학습 데이터에만 잘 맞고 새 입력에는 약해지는 상태 |
| 형식 통과율 | 응답이 정해진 형식을 지킨 비율 |
| 사람 평가 | 사람이 직접 답을 읽고 채점하는 방식 |
| 모델 채점 | 다른 모델이 답을 읽고 채점하는 방식 |
| 회귀 | 이전에는 되던 것이 다시 안 되게 된 상태 |

**스스로 점검**

1. 4장 결과 표처럼 튜닝 후 형식 통과율은 올랐는데 사람 평가 점수는 떨어졌습니다. 이대로 배포하면 무슨 일이 일어날까요?
