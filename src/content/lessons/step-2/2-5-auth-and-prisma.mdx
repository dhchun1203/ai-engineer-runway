### 🪪 인증과 인가는 다른 질문이다

인증(authentication)은 "당신이 누구인가"를 확인하는 절차입니다. 인가(authorization)는 "확인된 당신이 이걸 해도 되는가"를 확인하는 절차입니다.

신분증 확인과 출입 등급의 관계와 같습니다. 신분증으로 누구인지 확인한 뒤에도, 등급이 낮으면 특정 구역에는 들어갈 수 없습니다.

### 🔒 비밀번호는 그대로 저장하지 않는다

비밀번호를 원문(평문) 그대로 저장하면, 저장소가 유출되는 순간 모든 사용자의 비밀번호가 그대로 드러납니다. 그래서 해시(hash, 원래 값을 복원할 수 없게 바꾼 값)로 바꿔서 저장합니다.

솔트(salt, 해시 전에 섞는 무작위 값)를 더하면 같은 비밀번호라도 사용자마다 다른 해시가 나와 더 안전해집니다. `bcryptjs` 라이브러리가 해시 생성과 솔트 처리를 함께 해줍니다.

<TwistBox>

솔트를 직접 만들어서 데이터베이스 컬럼에 따로 저장해야 할 것 같은데, 아래 코드 어디에도 그런 부분이 없습니다.

```typescript
const passwordHash = await bcrypt.hash(password, 10); // 솔트를 넘긴 적이 없다
```

`bcrypt.hash`는 호출될 때마다 내부에서 솔트를 무작위로 만들고, 그 솔트를 결과 문자열 안에 함께 담아 돌려줍니다. 그래서 `User` 모델에 `passwordHash` 컬럼 하나만 있어도 됩니다 — 솔트를 위한 별도 컬럼이 필요 없다는 것이 이 라이브러리를 처음 쓸 때 흔히 놓치는 부분입니다.

</TwistBox>

### 🎫 JWT는 서명된 출입증

JWT(JSON Web Token, 서명된 출입증)는 로그인에 성공했을 때 서버가 발급하는 토큰입니다. 이후 요청마다 이 토큰을 제시하면 서버는 다시 로그인하지 않고도 사용자를 확인할 수 있습니다.

토큰에는 만료 시간이 있어 일정 시간이 지나면 무효가 됩니다. 서버가 서명했기 때문에 내용이 조작되면 검증에 실패합니다.

### 🗄️ ORM과 Prisma의 세 단계

ORM(Object-Relational Mapping, 테이블을 코드 객체처럼 다루는 방식)은 SQL 문을 직접 쓰지 않고 함수 호출로 데이터베이스를 다루게 해줍니다. Prisma는 이 방식을 세 단계로 나눕니다.

스키마 정의(테이블 모양을 파일로 적기) → 마이그레이션(실제 데이터베이스에 반영하기) → 타입이 붙은 클라이언트(코드에서 자동완성과 함께 안전하게 호출하기) 순서입니다.

Prisma는 메이저 버전을 명시적으로 고정해 설치합니다.

Prisma 프로젝트를 초기화합니다. 외부 데이터베이스 서버 없이 끝까지 돌아가도록 로컬 파일 데이터베이스(SQLite)를 씁니다.

```powershell
npx prisma init --datasource-provider sqlite
```

생성된 `prisma/schema.prisma`를 아래처럼 채웁니다. `User` 모델 하나면 충분합니다.

```text
// prisma/schema.prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "sqlite"
  url      = env("DATABASE_URL")
}

model User {
  id           Int      @id @default(autoincrement())
  email        String   @unique
  passwordHash String
  createdAt    DateTime @default(now())
}
```

`.env` 파일에는 아래 두 키가 필요합니다. 실제 값 자리에는 자리표시자를 넣었습니다 — 이 값들은 저장소에 커밋하지 않습니다.

```text
DATABASE_URL=<Prisma가 만든 SQLite 파일 경로>
JWT_SECRET=<32자 이상의 무작위 문자열>
```

스키마를 실제 데이터베이스에 반영합니다.

```powershell
npx prisma migrate dev --name init
```

`src/auth.ts` 파일을 만들고 아래 코드를 그대로 붙여 넣습니다.

```typescript
// src/auth.ts
import express from "express";
import bcrypt from "bcryptjs";
import jwt from "jsonwebtoken";
import { PrismaClient } from "@prisma/client";

const app = express();
app.use(express.json());
const prisma = new PrismaClient();

const jwtSecret = process.env.JWT_SECRET;
if (!jwtSecret) {
  throw new Error("JWT_SECRET 환경변수가 설정되지 않았습니다");
}

app.post("/signup", async (req, res) => {
  const { email, password } = req.body;
  const existing = await prisma.user.findUnique({ where: { email } });
  if (existing) {
    res.status(409).json({ error: "이미 가입된 이메일입니다" });
    return;
  }
  const passwordHash = await bcrypt.hash(password, 10);
  const user = await prisma.user.create({
    data: { email, passwordHash },
  });
  res.status(201).json({ id: user.id, email: user.email });
});

app.post("/login", async (req, res) => {
  const { email, password } = req.body;
  const user = await prisma.user.findUnique({ where: { email } });
  if (!user) {
    res.status(401).json({ error: "이메일 또는 비밀번호가 올바르지 않습니다" });
    return;
  }
  const isValid = await bcrypt.compare(password, user.passwordHash);
  if (!isValid) {
    res.status(401).json({ error: "이메일 또는 비밀번호가 올바르지 않습니다" });
    return;
  }
  const token = jwt.sign({ userId: user.id }, jwtSecret, { expiresIn: "1h" });
  res.status(200).json({ token });
});

function requireAuth(
  req: express.Request,
  res: express.Response,
  next: express.NextFunction,
) {
  const header = req.headers.authorization;
  if (!header || !header.startsWith("Bearer ")) {
    res.status(401).json({ error: "인증 토큰이 필요합니다" });
    return;
  }
  try {
    const payload = jwt.verify(header.slice(7), jwtSecret) as { userId: number };
    (req as express.Request & { userId: number }).userId = payload.userId;
    next();
  } catch {
    res.status(401).json({ error: "유효하지 않은 토큰입니다" });
  }
}

app.get("/me", requireAuth, async (req, res) => {
  const userId = (req as express.Request & { userId: number }).userId;
  const user = await prisma.user.findUnique({ where: { id: userId } });
  res.status(200).json({ id: user?.id, email: user?.email });
});

const port = process.env.PORT ?? 3001;
app.listen(port, () => {
  console.log(`인증 서버 실행 중: http://localhost:${port}`);
});
```

function requireAdmin(req: express.Request, res: express.Response, next: express.NextFunction) {
  const userId = (req as express.Request & { userId: number }).userId;
  prisma.user.findUnique({ where: { id: userId } }).then((user) => {

## 5. 실무 팁

- **시크릿과 접속 정보는 절대 저장소에 올리지 않습니다.** `.env` 파일은 `.gitignore`에 넣어 커밋 대상에서 제외합니다.
- **해싱과 토큰 서명을 직접 구현하지 않습니다.** `bcryptjs`·`jsonwebtoken`처럼 검증된 라이브러리를 씁니다. 직접 만든 알고리즘은 눈에 보이지 않는 취약점을 남기기 쉽습니다.
- **토큰에 개인정보를 담지 않습니다.** JWT의 내용은 암호화가 아니라 서명만 되어 있어, 누구나 내용을 열어 볼 수 있습니다. API 문서화(예: Swagger)는 엔드포인트가 늘어나면 함께 검토할 만한 다음 단계입니다.

## 6. 핵심 정리 및 스스로 점검

**핵심 정리**

- 인증은 "누구인가", 인가는 "무엇을 해도 되는가"를 확인하는 서로 다른 절차다
- 비밀번호는 `bcryptjs` 해시를 거쳐야만 저장할 수 있다 — 평문 저장·평문 비교는 금지다
- JWT는 만료 시간이 있는 서명된 토큰으로, 매 요청마다 다시 로그인하지 않게 해준다
- Prisma는 스키마 정의 → 마이그레이션 → 타입 있는 클라이언트 순서로 데이터베이스를 다룬다
- 시크릿과 접속 정보는 코드가 아니라 `process.env`로만 읽는다

**이 레슨의 단어**

| 단어 | 뜻 |
|------|-----|
| 인증 | 사용자가 누구인지 확인하는 절차 |
| 인가 | 확인된 사용자가 무엇을 해도 되는지 확인하는 절차 |
| 해시 | 원래 값을 복원할 수 없게 바꾼 값 |
| 솔트 | 해시 전에 섞는 무작위 값 |
| JWT | 서명이 붙은 토큰, 만료 시간을 가진다 |
| ORM | 테이블을 코드 객체처럼 다루는 방식 |
| 마이그레이션 | 스키마 정의를 실제 데이터베이스에 반영하는 작업 |

**스스로 점검**

1. 비밀번호를 `bcrypt.hash`로 저장한 뒤에는 왜 로그인할 때 원문끼리 비교하지 않고 `bcrypt.compare`를 쓸까요?

<details>
<summary>힌트 보기</summary>

해시라는 값이 원래대로 되돌릴 수 있는 값인지 아닌지 떠올려 보세요. 저장된 값과 로그인 시 입력한 값을 비교하려면 두 값을 같은 형태로 맞춰야 하지 않을지 생각해봅니다.

</details>

<details>
<summary>정답 보기</summary>

해시는 원래 값으로 되돌릴 수 없도록 설계된 값입니다. 저장된 값은 이미 해시라서 로그인 시 입력한 원문과 직접 비교할 수 없고, `bcrypt.compare`가 입력값을 같은 방식으로 해시해 저장된 해시와 맞는지 확인해줍니다.

</details>

2. JWT 토큰에 사용자의 이메일이나 이름을 그대로 넣으면 왜 문제가 될 수 있을까요?

<details>
<summary>힌트 보기</summary>

JWT에서 "서명"과 "암호화"가 같은 개념인지 떠올려 보세요. 토큰 문자열을 가로챈 사람이 그 안의 내용을 눈으로 읽을 수 있는지 없는지를 생각해봅니다.

</details>

<details>
<summary>정답 보기</summary>

JWT는 서명만 되어 있을 뿐 암호화되어 있지 않습니다. 토큰 문자열을 복사해 디코더에 붙여넣으면 누구나 내용을 그대로 읽을 수 있으므로, 개인정보를 담으면 토큰을 가로챈 사람에게 그대로 노출됩니다.

</details>
