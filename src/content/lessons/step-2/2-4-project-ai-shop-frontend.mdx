## 1. 학습 목표

이 프로젝트에서 무엇을 만들고 무엇을 증명하는지 먼저 짚고 넘어갑니다.

- **무엇을 만드나:** Supabase에 저장된 상품 데이터를 화면에 보여주고, LLM API가 생성한 추천 문구를 함께 띄우는 AI 쇼핑몰의 프론트엔드 화면입니다.
- **무엇을 증명하나:** 지금까지 배운 데이터베이스·화면 기초·컴포넌트가 실제로 하나의 서비스로 이어붙는다는 것을 확인합니다. 구현 방법을 통째로 외우는 것이 아니라, "무엇이 어디에 필요한지" 감을 잡는 것이 이 레슨의 목표입니다.
- 개강 후 팀 프로젝트에서 이 화면을 실제로 만들 때, 오늘 준비해둔 것들이 그대로 출발점이 됩니다.

## 2. 왜 배우나

이 프로젝트는 지금까지 배운 여러 모듈이 처음으로 한 화면에 합쳐지는 자리입니다.

`2-1-postgres-and-supabase`·`2-1-ai-data-modeling`에서 다진 데이터 구조, `2-2-html-css-js`·`2-2-browser-and-ui`에서 다진 화면 기초, `2-3-typescript-setup`·`2-3-react-components`에서 다진 컴포넌트 작성법이 전부 여기서 필요합니다.

아직 이 레슨들을 보지 않았어도 slug만 기억해뒀다가, 프로젝트를 실제로 시작할 때 막히는 부분이 있으면 해당 레슨으로 돌아가 복습하면 됩니다.

## 4. 실무 예제

### 사전 준비 체크리스트

이 프로젝트를 개강 첫날 바로 시작하려면 아래를 미리 준비해둡니다.

| 준비물 | 왜 필요한가 | 지금 할 일 |
|--------|-------------|-----------|
| Supabase 프로젝트 | 상품 데이터를 저장할 데이터베이스가 필요합니다 | 새 프로젝트를 만들고 상품 정보를 담을 테이블 1개를 생성해보기 |
| LLM API 키 | 상품 추천 문구를 AI가 생성하려면 API 호출 권한이 필요합니다 | 발급받아 `.env.local`에 저장해두기(코드에 직접 쓰지 않기) |
| 샘플 상품 데이터 | 화면에 표시할 데이터가 있어야 UI를 눈으로 확인할 수 있습니다 | 팔고 싶은 상품 3~5개를 이름·가격·설명으로 표에 정리해두기 |
| Node·VS Code 환경 | `2-3-typescript-setup`에서 설치한 환경이 이 프로젝트의 실행 기반입니다 | `node --version`으로 설치가 살아있는지 확인해두기 |

> ⚠️ 이 체크리스트는 "무엇을 준비할지"만 알려줍니다. 실제 구현 방법은 개강 후
> 본 과정에서 팀과 함께 설계합니다.

```text
# .env.local — 키 이름만 적어둡니다. 실제 값은 각자 발급받은 것을 넣습니다.
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
LLM_API_KEY=
```

## 5. 실무 팁

- **팀 프로젝트에서 자주 막히는 지점 1 — 환경변수 공유.** 디스코드나 카카오톡에 API 키를 평문으로 보내지 않습니다. 팀 노션의 비공개 페이지나 1Password 같은 도구로 공유하는 습관을 미리 들여둡니다.
- **팀 프로젝트에서 자주 막히는 지점 2 — 디자인 합의 지연.** 디자인이 확정될 때까지 화면 작업을 미루지 말고, 구조(어떤 컴포넌트가 어디 들어가는지)부터 먼저 잡아둡니다.
- **팀 프로젝트에서 자주 막히는 지점 3 — 키 노출 사고.** `.env.local`이 `.gitignore`에 포함되어 있는지 프로젝트를 시작하자마자 확인합니다.
- **시간 배분·역할 분담.** 오늘 60분은 준비까지만입니다. 실제 구현은 팀 프로젝트 시간에 별도로 배정되며, 화면 담당·데이터 담당·API 연동 담당처럼 미리 역할을 나눠두면 개강 첫날 회의가 짧아집니다.

## 6. 핵심 정리 및 스스로 점검

**핵심 정리**

- [ ] Supabase 프로젝트를 만들고 테이블 1개를 생성했다
- [ ] LLM API 키를 발급받아 `.env.local`에 저장했다(코드에는 쓰지 않았다)
- [ ] 판매할 상품 3~5개를 표로 정리해뒀다
- [ ] `node --version`으로 Node 환경이 살아있는지 확인했다
- [ ] 팀원과 화면·데이터·API 역할을 나눠봤다(선택)

**이 레슨의 단어**

| 단어 | 뜻 |
|------|-----|
| 프론트엔드 | 사용자가 직접 보고 만지는 화면 쪽 코드 |
| 환경변수 | 코드에 직접 적지 않고 실행 환경에 따로 저장해두는 값(API 키 등) |
| 시드 데이터 | 화면 확인용으로 미리 넣어두는 샘플 데이터 |
| 목업 | 실제 데이터 없이 화면 모양만 먼저 확인하기 위한 가짜 데이터 |
| 상태 관리 | 장바구니처럼 화면 여러 곳에서 함께 써야 하는 값을 관리하는 방식 |
| API 연동 | 화면 코드가 외부 서비스(LLM API 등)를 호출해 응답을 받아오는 것 |

**스스로 점검**

1. 왜 API 키를 코드에 직접 쓰지 않고 `.env.local`에 저장해야 할까요?

<details>
<summary>정답 보기</summary>

코드는 깃 저장소에 올라가고, 저장소가 공개되면 키가 그대로 노출되어 누구나 그 키로 API를 호출(과금)할 수 있게 됩니다. `.env.local`은 기본적으로 `.gitignore`에 포함되어 저장소에 올라가지 않으므로 키를 안전하게 분리할 수 있습니다.

</details>

2. 샘플 상품 데이터를 지금 미리 준비해두면 개강 후 어떤 점이 편해질까요?

<details>
<summary>정답 보기</summary>

화면 작업은 보여줄 데이터가 있어야 눈으로 확인하며 진행할 수 있습니다. 데이터가 없으면 화면 작업과 데이터 준비를 동시에 하느라 시간이 분산되는데, 데이터를 미리 준비해두면 개강 첫날부터 화면 작업에 바로 집중할 수 있습니다.

</details>
