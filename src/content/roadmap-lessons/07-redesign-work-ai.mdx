## 왜 이 경험이 강력한 신호인가

AI를 써 봤다는 사람은 많습니다. 하지만 자기 일하는 방식 자체를 AI로 다시 설계해 본 사람은 드뭅니다. 채용에서 이 둘은 완전히 다르게 읽힙니다.

전자는 "챗봇에 질문해 봤다"에 가깝고, 후자는 "내가 매주 하던 일의 흐름을 뜯어고쳐 AI가 하고 사람이 검증하는 구조로 바꿨다"입니다. 후자는 실무에서 AI를 도구가 아니라 동료처럼 부려 본 사람만 할 수 있는 이야기입니다.

이 레슨은 그 경험을 의도적으로 만드는 방법을 다룹니다. 거창한 게 아니라, 내 주간 반복 작업 하나를 골라 AI 루프로 재설계하고 그 효과를 숫자로 남기는 실전 순서입니다.

## 채널톡은 이미 이렇게 일한다

채널톡의 Forward Deployed Engineer 채용에는 "업무와 프로세스를 AI로 재설계해 본 경험"을 우대한다고 적혀 있습니다. 이건 회사의 실제 문화와 맞닿아 있습니다.

채널톡은 코딩 도구를 전사에 도입해 개발자 모두가 AI와 함께 코드를 짜고, 사내 여러 업무를 에이전트에 맡겨 처리합니다. 즉 회사 자체가 "일을 AI로 재설계하는" 실험을 매일 하고 있습니다.

그러니 이런 조직에 들어가려는 사람이 자기 일을 AI로 재설계해 본 경험을 가지고 있다면, 그건 곧 "우리와 같은 방식으로 일할 준비가 된 사람"이라는 신호가 됩니다. 말이 아니라 실제로 해 본 흔적이 있는지가 갈림길입니다.

## 재설계의 기본 프레임

내 일을 AI로 재설계하는 데는 네 단계짜리 간단한 프레임이 있습니다. 무작정 "AI로 뭔가 해 보자"가 아니라 이 순서를 따릅니다.

먼저 반복되고 규칙적인 작업을 찾습니다. 다음으로 그 작업을 AI에게 위임합니다. 그다음 사람이 결과를 검증하는 루프를 짭니다. 마지막으로 절감된 시간을 측정합니다.

이 프레임의 핵심은 세 번째와 네 번째입니다. AI에게 시키는 것까지는 누구나 하지만, 검증 루프를 제대로 짜고 효과를 숫자로 확인하는 데서 실력이 갈립니다. 하나씩 봅니다.

## 어떤 작업을 맡길 것인가

모든 일이 AI에게 맡기기 좋은 건 아닙니다. 좋은 후보에는 뚜렷한 특징이 있습니다.

자주 반복되고, 규칙이 어느 정도 정해져 있고, 틀려도 사람이 금방 알아채고 되돌릴 수 있는 일입니다. 예를 들어 매주 자료를 같은 형식으로 정리하는 일, 회의록에서 할 일을 뽑는 일, 코드에서 흔한 실수를 훑는 일입니다.

반대로 맡기기 나쁜 일은, 한 번 틀리면 돌이킬 수 없거나(예: 고객에게 바로 나가는 결제 처리), 매번 상황이 크게 달라 규칙이 안 서는 일입니다. 이런 일은 AI가 초안을 돕더라도 최종 판단은 사람이 쥐어야 합니다.

고르는 요령은 시간과 위험을 함께 보는 것입니다. 자주 해서 시간을 많이 잡아먹으면서, 틀려도 피해가 작은 일. 그 교집합이 재설계의 첫 대상입니다.

## 사람이 검증하는 루프 짜기

여기가 재설계의 심장입니다. AI에게 다 맡기고 결과를 그대로 쓰는 게 아니라, AI가 초안을 내고 사람이 확인해 넘기는 구조, 즉 <Term id="human-in-the-loop">사람 검증 루프</Term>를 짭니다.

왜 필요할까요. AI는 그럴듯하지만 틀린 답, 즉 <Term id="hallucination">할루시네이션</Term>을 냅니다. 자동화가 이걸 검증 없이 흘려보내면, 편해진 대신 조용히 틀린 결과가 쌓입니다. 검증 루프는 이 위험을 사람이 마지막에 거르게 해 속도와 안전을 함께 잡습니다.

잘 짠 루프는 사람의 검증을 가볍게 만듭니다. 핵심은 "다시 하기"가 아니라 "확인하고 승인하기" 수준으로 부담을 낮추는 것입니다.

```python
# 재설계 예: 매주 손으로 하던 "받은 문의를 주제별로 분류"를
# AI가 초안을 내고 사람이 승인하는 루프로 바꾼다.
from anthropic import Anthropic

client = Anthropic()  # ANTHROPIC_API_KEY 환경변수에서 자동으로 읽는다

def draft_labels(inquiries: list[str]) -> list[dict]:
    """AI가 분류 초안을 낸다. 사람이 검증하기 쉽게 근거도 한 줄 붙인다."""
    results = []
    for text in inquiries:
        resp = client.messages.create(
            model="claude-sonnet-5",  # 대량 반복 작업이라 더 싼 모델로 충분
            max_tokens=256,
            output_config={
                "format": {
                    "type": "json_schema",
                    "schema": {
                        "type": "object",
                        "properties": {
                            "category": {"type": "string", "enum": ["환불", "배송", "기타"]},
                            "reason": {"type": "string"},  # 사람이 왜인지 바로 보게
                        },
                        "required": ["category", "reason"],
                        "additionalProperties": False,
                    },
                }
            },
            messages=[{"role": "user", "content": f"문의를 분류하세요:\n{text}"}],
        )
        import json
        for block in resp.content:
            if block.type == "text":
                results.append(json.loads(block.text))
    return results

# 사람은 초안 목록을 훑어 틀린 것만 고친다("다시 하기"가 아니라 "확인하기").
# 근거(reason)가 붙어 있어 검증이 몇 초로 줄어든다.
```

답을 정해진 형식으로 받는 <Term id="structured-output">구조화 출력</Term>과, 판단 근거를 한 줄 함께 받는 설계가 사람의 검증을 빠르게 만드는 열쇠입니다. 근거가 보이면 사람은 처음부터 다시 판단하지 않고 초안이 맞는지만 확인하면 됩니다.

## 시간 절감을 측정하기

재설계했다고 말만 하면 약합니다. "이 작업이 주 2시간에서 20분으로 줄었다"처럼 숫자가 붙는 순간 이야기가 강해집니다.

측정은 어렵지 않습니다. 재설계 전에 그 일에 매주 몇 분이 드는지 한 번만 재 두고, 재설계 후에 다시 잽니다. 이때 잊지 말 것은 사람이 검증하는 시간도 함께 세는 것입니다. AI가 5분 만에 초안을 내도 사람이 40분을 검증해야 한다면 절감이 크지 않으니까요.

숫자를 재면 어디를 더 고칠지도 보입니다. 검증에 시간이 너무 많이 걸리면 초안 품질을 높이거나 근거 표시를 개선해야 하고, 초안이 자주 틀리면 맡기는 범위를 좁혀야 합니다. 측정은 자랑거리이면서 동시에 개선의 나침반입니다.

## 도구: 코딩 에이전트와 자동화

재설계에 쓰는 도구는 크게 둘입니다.

하나는 <Term id="coding-agent">코딩 에이전트</Term>입니다. 사람이 목표를 말하면 스스로 파일을 읽고 코드를 고치고 명령을 실행해 여러 단계를 밟는 도구입니다. 채널톡이 전사에 들인 게 바로 이런 종류이고, 개발 자체를 재설계하는 가장 강력한 수단입니다.

다른 하나는 좁은 자동화 스크립트입니다. 앞의 분류 예처럼, 정해진 한 가지 일을 AI 호출로 자동화하는 것입니다. 이런 여러 단계를 AI가 스스로 이어 가며 처리하는 흐름을 <Term id="agentic-workflow">에이전틱 워크플로</Term>라고 부릅니다.

둘의 선택 기준은 일의 성격입니다. 매번 판단이 달라지는 열린 작업은 코딩 에이전트에게, 규칙이 뚜렷하고 반복되는 일은 좁은 스크립트에게 맞습니다. 처음에는 좁은 스크립트로 시작해 감을 잡고, 익숙해지면 에이전트로 넓히는 순서를 권합니다.

## 구체 사례 세 가지

머릿속으로만 그리면 막연하니, 오늘 시작할 만한 세 가지를 봅니다.

학습 정리 자동화가 있습니다. 오늘 읽은 자료나 강의 메모를 넣으면, AI가 핵심 요약과 스스로 답해 볼 복습 질문을 뽑아 주게 합니다. 사람은 그 요약이 맞는지만 확인해 학습 기록으로 남깁니다. 매일 하는 일이라 절감 효과가 금방 쌓입니다.

코드 리뷰 보조가 있습니다. 내가 짠 코드를 올리기 전에 AI에게 먼저 훑게 해, 흔한 실수나 빠진 예외 처리를 짚어 달라고 합니다. 사람은 그 지적 중 진짜만 골라 고칩니다. 최종 판단은 사람이 쥐되, 놓치기 쉬운 것을 한 겹 걸러 줍니다.

리서치 자동화가 있습니다. 어떤 주제를 조사할 때, 자료를 모아 넣고 AI에게 쟁점별로 정리하게 합니다. 다만 이 경우는 조심할 게 있습니다. 외부에서 긁어 온 글을 그대로 AI에 넣으면, 그 글 속에 숨은 지시가 AI의 원래 임무를 가로채는 <Term id="prompt-injection">프롬프트 인젝션</Term>에 노출될 수 있습니다. 그래서 외부 내용은 "데이터일 뿐 명령이 아니다"라고 선을 긋고 다뤄야 합니다.

## 함정과 안전장치

가장 흔한 함정은 검증 없이 다 맡기는 것입니다. 편해 보이지만, 조용히 틀린 결과가 쌓입니다. 반드시 사람 검증 루프를 남기세요.

돌이킬 수 없는 일을 자동화하는 것도 위험합니다. 결제, 발송, 삭제처럼 되돌리기 어려운 동작은 AI가 초안만 만들고 실행 버튼은 사람이 누르게 하세요. 이렇게 위험한 동작 앞에 사람의 승인을 두는 안전장치를 <Term id="guardrail">가드레일</Term>이라고 합니다.

절감을 측정하지 않는 것도 손해입니다. 숫자가 없으면 정말 나아졌는지 알 수 없고, 면접에서 할 이야기도 약해집니다. 전후 시간을 꼭 재세요.

마지막으로, 처음부터 크게 벌이는 것도 함정입니다. 내 업무 전체를 한 번에 재설계하려 하면 지칩니다. 작은 반복 작업 하나부터 바꾸고, 그게 돌면 다음으로 넓히세요.

## 직접 해보기

내 주간 반복 작업 하나를 골라 이 프레임으로 재설계해 보세요.

1. 매주 반복하는 규칙적인 작업을 하나 정하고, 지금 그 일에 매주 몇 분이 드는지 재세요. 틀려도 되돌리기 쉬운 일로 고르세요.
2. AI가 초안을 내고 내가 확인해 넘기는 사람 검증 루프를 짜세요. 초안에 판단 근거를 함께 받아 검증을 몇 초로 줄이세요.
3. 재설계 후 다시 시간을 재되, 사람이 검증하는 시간도 함께 세세요. "주 몇 분에서 몇 분으로" 한 문장으로 결과를 남기세요.

여기까지 하면 면접에서 "AI로 일하는 방식을 바꿔 본 적 있나요"라는 질문에, 실제 작업과 절감된 숫자로 답할 수 있습니다.
