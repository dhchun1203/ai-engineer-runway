## 02. AI Agent 개발자는 실제로 어떤 일을 하나

**모델을 만드는 사람이 아니라, 모델이 일을 끝내도록 판을 짜는 사람이에요.**

STEP 3 챗봇에서는 검색 결과를 프롬프트에 넣어 Gemini에게 답하게 했어요. 이때 "무엇을 검색할지"는 우리가 정했죠.

에이전트는 이 결정을 모델에게 맡겨요. 모델이 상황을 보고 검색, DB 조회, 메일 보내기 같은 도구를 스스로 골라 여러 단계를 거쳐 일을 끝내요. 이렇게 여러 단계를 이어 일을 처리하는 흐름을 <Term id="agentic-workflow">에이전트 워크플로</Term>라고 불러요.

실제 업무는 대략 이래요.

- **일 쪼개기**: 업무 흐름 중 어디를 LLM에게 맡기고, 어디를 정해진 코드로 처리할지 나눠요. STEP 4에서 "규칙"과 "판단"을 나눴던 것과 같은 일이에요.
- **도구 만들기와 연결**: 에이전트가 쓸 API, DB 조회, 검색 같은 도구를 만들고 설명을 달아 붙여요. MCP가 이 연결 방식의 표준이에요.
- **흐름 설계**: 단계와 분기, 상태를 관리해요(LangGraph 같은 도구).
- **지식 붙이기**: 사내 문서를 검색해 답의 근거로 쓰게 해요(<Term id="rag">RAG</Term>).
- **실패 다루기**: 엉뚱한 도구 호출, 지어낸 답, 끝없이 도는 반복을 잡아요. 위험한 행동을 막는 <Term id="guardrail">가드레일</Term>도 여기에 들어가요. 실제 시간은 여기에 가장 많이 들어요.
- **평가와 개선**: 정답 세트(<Term id="golden-set">골든셋</Term>)로 성능을 재고, 로그를 보며 고치고, 비용과 응답 속도를 관리해요.

> **핵심**: 데모는 하루면 만들어요. 실제 사용자가 써도 무너지지 않게 만드는 데는 몇 주가 걸려요. 이 차이를 메우는 게 이 직무의 진짜 일이에요.

## 03. 비슷해 보이는 직무들은 어떻게 다른가

| 직무 | 한마디로 | 주로 만드는 것 |
| --- | --- | --- |
| LLM 개발자 | 모델 자체를 다루거나, LLM 기능을 서비스에 넣는 사람 | 파인튜닝된 모델, LLM API를 쓰는 기능 |
| AI Agent 개발자 | 모델이 도구를 써서 일을 끝내게 만드는 사람 | 에이전트, 워크플로, 도구 연결 |
| AX 자동화 | 회사의 일하는 방식을 AI로 바꾸는 사람 | 사내 업무 자동화, n8n 같은 워크플로 |
| LLMOps | 만든 AI가 안정적으로 굴러가게 지키는 사람 | 배포, 모니터링, 평가 파이프라인, 비용 관리 |
| AI PM | 무엇을 만들지 정하고 성공을 재는 사람 | 기획, 요구사항, 지표, 평가 기준 |

> **"LLM 개발자"는 회사마다 뜻이 달라요.** 모델을 직접 학습시키는(<Term id="fine-tuning">파인튜닝</Term> 포함) 자리라면 석사나 연구 경력을 보는 경우가 많고, LLM으로 기능을 만드는 자리라면 AI Agent 개발자나 응용 AI 엔지니어와 거의 겹쳐요. 공고를 볼 때는 직무 이름보다 하는 일 목록을 보세요.

선을 하나 그어 보면 이렇게 나뉘어요.

- LLM 개발자와 Agent 개발자는 **만드는 쪽**이에요.
- AX 자동화는 **현장에 적용하는 쪽**이에요.
- LLMOps는 **굴러가게 지키는 쪽**이에요.
- AI PM은 **방향을 정하는 쪽**이에요.

## 04. 직무마다 필요한 역량

### AI Agent 개발자

- Python과 백엔드 기초(API, DB)
- 프롬프트와 컨텍스트 설계, RAG, 도구 연결(MCP)
- 실패를 상정하는 습관과 평가(eval) 감각

### AX 자동화

- 업무를 단계로 쪼개는 능력
- 자동화 도구, 현업 담당자와 대화하는 능력
- "이 일을 자동화하면 얼마가 줄어드나"를 재는 감각

### LLMOps

- 클라우드, 배포, 모니터링, 로그 분석
- 평가 자동화와 비용 최적화
- 서비스 운영 경험이 크게 작용

### AI PM

- 문제 정의, 지표 설계, 사용자 이해
- LLM이 잘하는 것과 못하는 것에 대한 감

### 모든 직무의 공통 바닥

결과를 그대로 믿지 않고 검증하는 습관, 그리고 내가 만든 걸 설명하는 힘이에요. AI 리터러시 STEP의 "5가지 관점"이 사실 모든 직무의 공통 역량이에요.

## 05. 교육과정 내용이 실제 업무 어디에 연결되나

| 교육과정 단계 | 실제 업무에서는 |
| --- | --- |
| 기초 (Python, SQL, ML 기초, 생성형 AI) | 모든 직무의 바닥. 데이터 다루기, 모델이 무엇을 하는지 이해하기 |
| 빌드 (풀스택, API, DB, 프롬프트) | 에이전트가 쓸 도구와, 사람이 쓰는 서비스 화면 만들기 |
| 심화 (에이전트 설계, RAG, MCP, 오케스트레이션, LLMOps) | AI Agent 개발자와 LLMOps의 핵심 업무 그대로 |
| 기업 연계 AX 프로젝트 | AX 자동화 실무와 포트폴리오 |

베이스캠프에서 이미 맛보기를 했어요.

- **STEP 3 Q&A 챗봇**은 아주 작은 RAG예요. 검색해서 프롬프트에 넣고, 데이터에 근거해 답하게 했죠.
- **STEP 4~5 엑셀 자동화**는 아주 작은 AX 자동화예요. 업무를 규칙과 판단으로 나누고, 깨진 파일에도 멈추지 않게 만들고, 결과를 검증했죠.

## 06. 비전공자는 어떤 직무부터 접근할 수 있나

현실적으로 문이 넓은 순서는 대략 이래요.

1. **AX 자동화**: 업무 이해와 문제 정의가 코드 깊이만큼 중요해서, 현업 경험이 있는 전환자에게 유리해요.
2. **응용 AI / AI Agent 개발자(신입)**: 교육과정이 직접 길러 주는 영역이에요. 실제로 배포하고 운영해 본 포트폴리오가 있으면 비전공 핸디캡이 크게 줄어요.
3. **FDE(고객사에 붙어 구축하는 엔지니어)**: 기술과 고객 대화를 둘 다 하는 자리예요. 영업과 구축 경험이 있는 사람에게 잘 맞아요.

상대적으로 문이 좁은 곳도 있어요.

- 모델을 직접 학습시키는 LLM 연구 개발은 석사나 연구 경력의 벽이 있어요.
- LLMOps는 운영 경력을 보는 경우가 많아요.
- AI PM은 비개발 출신도 가능하지만 신입 자리 자체가 적어요.

## 07. 수료 후 신입으로 바라볼 수 있는 포지션

- **응용 AI 엔지니어 / AI 서비스 개발자**: 백엔드와 LLM을 함께 다뤄요. 스타트업에 많아요.
- **AI Agent 개발자**: 에이전트와 RAG 기반 기능을 만들어요.
- **AX 엔지니어 / AX 컨설턴트**: 대기업 AX 조직이나 SI 쪽에 자리가 많아요.
- **FDE / 솔루션 엔지니어**: 고객사에 AI를 붙여 주는 역할이에요.

> AX 쪽 신입 자리는 SI와 대기업 계열에 많아요. "닫힌 솔루션, 보수적인 조직은 피한다"는 기준과 부딪힐 수 있으니, 세션에서 자리의 성격을 구분하는 법을 물어보면 좋아요.
