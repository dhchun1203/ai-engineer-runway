## 2. NumPy 배열은 곱하기 한 번이 모든 칸에 들어간다

리스트에 `* 2`를 하면 두 번 이어 붙고, `* 1.1`은 `TypeError`예요. `np.array`로 바꾸면 반복문 없이 칸마다 계산돼요.

```python
arr = np.array(amounts)
print(arr * 2)          # [ 6400  3000 30000 13000 64000 ...]
print("합계:", arr.sum())   # 106600
print("모양: ", arr.shape, " 데이터 타입: ", arr.dtype)   # (12,)  int64
```

### NumPy 배열: 곱하기 한 번이 모든 칸에 들어간다

먼저 지출 12건을 리스트에 적어요. 파이썬에서 배운 리스트 그대로예요.

amounts = [3200, 1500, 15000, 6500, 32000, 4800,

## 3. 조건을 대괄호에 넣으면 True 칸만 남는다, 대신 배열은 한 종류만 담는다

```python
arr[arr >= 10000]   # array([15000, 32000, 10900, 18500])
```

배열에 글자가 하나라도 섞이면 숫자까지 전부 글자(`<U21`)가 되고, 칸에 이름표도 없어요. 그래서 열마다 종류가 따로인 pandas 표로 옮겨요.

<details>
<summary>자세히 보기</summary>

### 조건으로 고르기: True/False 줄을 대괄호에 넣으면 True 칸만 남는다

"만 원 이상인 지출은 어느 칸일까?"를 배열에 물으면 칸마다 답한 True/False 12개가 나와요. 그 줄을 대괄호 안에 넣으면 True인 칸만 남아요. 이것을 불리언 인덱싱(Boolean indexing)이라고 해요.

### 배열의 한계: 한 가지 종류만 담고, 이름표가 없다

가게 이름도 같이 넣고 싶어요. 그런데 배열은 한 가지 종류만 담을 수 있어서, 글자가 하나라도 섞이면 숫자까지 전부 글자로 바뀌어요.

```python
mixed = np.array([["편의점", 3200],
                  ["버스",   1500]])
print(mixed)
print("값의 종류:", mixed.dtype)
```

```text
[['편의점' '3200']
 ['버스' '1500']]
값의 종류: <U21
```

`3200`이 `'3200'`이라는 글자가 됐어요. `<U21`은 "최대 21글자짜리 문자열"이에요. 이제 금액을 더할 수 없고, 어느 칸이 가게이고 어느 칸이 금액인지 이름표도 없어요.

그래서 일단 리스트 세 개로 따로 두고 식비 합계를 반복문으로 구해 봤어요.

```python
shops = ["편의점", "버스", "영화관", "분식집", "온라인쇼핑", "카페",
         "음원앱", "버스", "편의점", "웹툰", "온라인쇼핑", "분식집"]

categories = ["식비", "교통", "문화", "식비", "쇼핑", "식비",
              "문화", "교통", "식비", "문화", "쇼핑", "식비"]

food = 0
for c, a in zip(categories, amounts):
    if c == '식비':
        food += a

print(food)
```

```text
24200
```

식비 하나에 반복문 다섯 줄이에요. 교통, 문화, 쇼핑까지 하려면 네 번 써야 하고, 리스트 순서가 하나만 어긋나도 엉뚱한 답이 나와요.

## 4. DataFrame은 `{열 이름: 리스트}` 딕셔너리로 만들고 shape, head, info로 본다

```python
spend = pd.DataFrame({
    "day": [2, 3, 4, 5, 7, 9, 12, 14, 16, 19, 20, 25],
    "shop": shops,
    "category": categories,
    "amount": amounts
})
print(spend.shape)   # (12, 4)
```

`spend.info()`를 보면 숫자 열은 `int64`, 글자 열은 pandas 3부터 `str`이에요. 노트북은 셀의 마지막 줄 결과만 보여 줘서, 중간 결과는 `print()`로 감싸요.

#### 크기, 앞부분, 칸의 종류 보기

실제 거래 내역은 수천 줄이라 한 번에 다 볼 수 없어요. `shape`로 크기를, `head(n)`으로 앞 n줄을, `info()`로 열마다 빈칸과 종류를 봐요.

```python
print(spend.shape)
spend.head(3)
```

```text
(12, 4)
   day shop category  amount
0    2  편의점       식비    3200
1    3   버스       교통    1500
2    4  영화관       문화   15000
```

`(12, 4)`는 12행 4열이에요. `head()`의 괄호를 비우면 5줄을 보여 주고, 뒤쪽은 `tail(3)`으로 봐요. `shape`는 괄호 없이, `head()`는 괄호와 함께 써요.

숫자 열은 `int64`, 글자 열은 `str`이에요. 배열과 달리 열마다 종류가 따로라서 글자 열이 있어도 금액은 숫자 그대로예요. `12 non-null`은 빈칸이 없다는 뜻이에요.

<Note title="pandas 3에서 달라진 두 가지">
- 글자 열의 종류가 `object` 대신 `str`로 나와요. 인터넷의 옛 자료(pandas 2)에는 `object`로 보여요.
- `spend["amount"][2] = 값`처럼 이어 붙인 대입은 원래 표를 바꾸지 못해요. 7절에서 `loc`로 고쳐요.
</Note>

## 6. 행 거르기: 조건은 &로 잇고 조건마다 괄호로 감싼다

### 오늘 만난 두 오류

**`and`를 쓴 경우.** 파이썬의 `and`는 양쪽을 True 하나, False 하나로 보려고 해요. 그런데 조건의 결과는 12칸짜리 줄이라 하나로 정할 수 없어요.

```python
spend[(spend["category"] == '식비') and (spend["amount"] >= 5000)]
```

```text
ValueError: The truth value of a Series is ambiguous. Use a.empty, a.item(), a.any() or a.all().
```

**괄호를 뺀 경우.** 파이썬은 `&`를 `==`, `>=`보다 먼저 계산해요. 그래서 `'식비' & spend["amount"]`부터 하려다 막혀요.

```python
spend[spend["category"] == '식비' & spend["amount"] >= 5000]
```

```text
TypeError: Cannot perform 'rand_' with a dtyped [int64] array and scalar of type [bool]
```

두 경우 모두 `&`와 괄호로 고치면 위의 분식집 두 행이 나와요. 오류 문장은 어렵지만 마지막 줄부터 읽는 습관을 들이면 돼요.

<Hint>
`=`(넣기)와 `==`(같은가?)를 헷갈려 `spend[spend["category"] = "문화"]`로 쓰면 `SyntaxError`가 나요. 숫자를 따옴표로 감싸 `spend["amount"] >= "10000"`처럼 글자와 비교하면 `TypeError: Invalid comparison between dtype=int64 and str`이 나요.
</Hint>

## 8. groupby는 SQL의 GROUP BY, 분류별 합계가 한 줄이다

```python
spend.groupby('category')['amount'].sum().sort_values(ascending=False)
# 쇼핑 50500, 문화 27900, 식비 24200, 교통 3000
```

`value_counts()`로 세면 식비가 5번으로 1위예요. 어제 배운 SQL과는 모양만 달라요.

| 하고 싶은 것 | SQL | pandas |
| --- | --- | --- |
| 열 고르기 | `SELECT shop, amount` | `spend[['shop', 'amount']]` |
| 행 거르기 | `WHERE amount >= 10000` | `spend[spend['amount'] >= 10000]` |
| 두 조건 | `WHERE a AND b` | `spend[(a) & (b)]` |
| 정렬 | `ORDER BY amount DESC` | `sort_values('amount', ascending=False)` |
| 개수 제한 | `LIMIT 3` | `.head(3)` |
| 그룹별 합계 | `GROUP BY category`와 `SUM(amount)` | `groupby('category')['amount'].sum()` |
| 값 하나 고치기 | `UPDATE ... SET amount = 14000 WHERE ...` | `spend.loc[2, 'amount'] = 14000` |

### 어제 배운 SQL과 나란히 놓기

하고 싶은 일은 같고 쓰는 모양만 달라요.

### 미션: 내 플레이리스트를 혼자 분석하기

교안의 마지막 미션이에요. 새 데이터에 오늘 배운 순서(표 만들기, 계산, 거르기, 정렬, 묶기)를 혼자 적용해요. 노래 제목과 장르는 가상이에요.

1. 노래 8곡으로 `playlist` 표 만들기
2. 이번 달 총 재생 수
3. 재생 수 20 이상인 곡
4. 가장 많이 들은 Top 3
5. 장르별 재생 수 합계(큰 순)
6. 보너스: 발라드이면서 10번 이상 들은 곡

먼저 직접 풀어 본 뒤 아래와 비교해 보세요.

```python

    "title": ["봄바람", "Run Up", "새벽 감성", "Neon City", "첫눈", "Jump!", "바다 소리", "Fire Dance"],
    "genre": ["발라드", "댄스", "발라드", "힙합", "발라드", "댄스", "인디", "댄스"],
    "plays": [12, 35, 8, 22, 15, 28, 5, 19],
})

print("이번 달 총 재생 수:", playlist["plays"].sum())
print(playlist[playlist["plays"] >= 20])
print(playlist.sort_values("plays", ascending=False).head(3))
print(playlist.groupby("genre")["plays"].sum().sort_values(ascending=False))
print(playlist[(playlist["genre"] == "발라드") & (playlist["plays"] >= 10)])
```

## 오늘 꼭 기억할 주의점

- 리스트에 `* 2`를 하면 이어 붙고 `* 1.1`은 `TypeError`예요. 칸마다 계산하려면 `np.array`로 바꿔요.
- NumPy 배열은 한 가지 종류만 담아요. 글자가 섞이면 숫자도 글자가 돼요. 열마다 종류가 다른 표는 pandas로 만들어요.
- `pd.DataFrame({열 이름: 리스트})`의 리스트들은 길이가 같아야 해요.
- 열 하나는 `spend["열"]`(Series), 여러 개는 `spend[["열1", "열2"]]`(표, 대괄호 두 겹)로 꺼내요.
- 조건 두 개는 `and`가 아니라 `&`, `|`로 잇고 조건마다 괄호로 감싸요.
- 정렬과 거르기의 결과는 새 표예요. 행 번호는 원래 번호를 들고 가고, 남기려면 변수에 담아요.
- 한 칸은 `spend.loc[행, 열] = 값`으로 고쳐요. `spend["열"][행] = 값`은 pandas 3에서 원래 표를 바꾸지 못해요.
- 계산해 둔 열은 원래 열을 고쳐도 저절로 바뀌지 않아요. 계산 줄을 다시 실행해요.
- 노트북은 셀의 마지막 줄 결과만 보여 줘요. 중간 결과는 `print()`로 감싸요.
