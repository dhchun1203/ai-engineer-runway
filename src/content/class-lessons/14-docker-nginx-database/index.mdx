## 1. 도커가 왜 필요할까

TIL 셀프 체크에 "도커가 왜 필요해?"라고 적었죠. 이 절이 그 답이에요.

### "제 PC에서는 잘 되는데요?"

개발자 PC, 동료 PC, 테스트 서버, 운영 서버는 OS 버전도 설치된 라이브러리도 설정도 조금씩 달라요. 그래서 같은 코드가 어디서는 돌고 어디서는 안 돌아요.

도커는 앱과 실행에 필요한 모든 것(라이브러리, 설정, 런타임)을 **이미지** 하나로 포장해요. 그리고 어디서든 똑같은 **컨테이너**로 실행해요.

화물을 규격 컨테이너에 담으면 배든 기차든 트럭이든 똑같이 다룰 수 있잖아요. 도커 로고의 고래가 컨테이너를 싣고 있는 이유예요.

| 효과 | 설명 |
| --- | --- |
| 환경 일치 | 개발, 테스트, 운영 환경을 같은 이미지로 맞춰요 |
| 빠른 설치 | MySQL, Redis 같은 서버를 설치 과정 없이 명령 한 줄로 실행해요 |
| 깔끔한 정리 | 컨테이너를 지우면 끝이라 내 PC에 흔적이 남지 않아요 |
| 가벼움 | VM보다 훨씬 작고 빠르게 실행돼요(다음 절) |

### 도커는 언제 나왔을까

| 시기 | 사건 |
| --- | --- |
| 2000년대 | FreeBSD Jail, Solaris Zones 같은 컨테이너 기술의 원형이 나와요. 도커가 컨테이너를 처음 발명한 건 아니에요 |
| 2008 | 리눅스 커널 기능(namespaces, cgroups)을 쓰는 LXC(Linux Containers)가 나와요 |
| 2010 | Solomon Hykes가 PaaS 회사 dotCloud를 세우고, 내부 도구로 컨테이너 기술을 만들어요 |
| 2013년 3월 | 미국 산타클라라 PyCon에서 도커를 처음 공개하고, Apache 2.0 라이선스 오픈소스로 풀어요 |
| 2013년 10월 | dotCloud가 회사 이름을 Docker Inc.로 바꿔요 |
| 2014년 6월 | 첫 안정 버전 Docker 1.0과 이미지 저장소 Docker Hub가 나와요 |
| 2015 | Docker, Google, CoreOS 등이 리눅스 재단 아래 OCI(Open Container Initiative)를 세워 이미지와 런타임을 표준으로 맞춰요 |
| 2017 | 핵심 런타임 containerd를 CNCF에 기증하고, 오픈소스 프로젝트를 Moby로 나눠요 |
| 2020년 이후 | Go로 다시 쓴 Compose v2가 나와 `docker-compose`가 `docker compose`로 합쳐져요 |
| 지금 | 컨테이너는 클라우드와 쿠버네티스(Kubernetes)에서 표준 배포 단위예요 |

재미있는 건 도커를 처음 공개한 자리가 **파이썬 컨퍼런스**(PyCon)의 5분짜리 라이트닝 토크였다는 점이에요.

## 2. VM과 컨테이너는 뭐가 다를까

VM(가상 머신)도 "다른 환경을 흉내 내서 프로그램을 돌린다"는 점은 같아요. 차이는 **무엇을 흉내 내느냐**예요.

```txt
가상 머신 (VM)                         도커 컨테이너
[앱 A] [앱 B] [앱 C]                    [앱 A] [앱 B] [앱 C]
[라이브러리] x 3                         [라이브러리] x 3
[게스트 OS, 커널 포함, 수 GB] x 3          (게스트 OS 없음)
[하이퍼바이저: VirtualBox, VMware, Hyper-V]  [도커 엔진]
[호스트 OS]                             [호스트 OS, 리눅스 커널을 모두가 함께 씀]
[하드웨어]                              [하드웨어]
```

| 비교 | 가상 머신 (VM) | 도커 컨테이너 |
| --- | --- | --- |
| 가상화 대상 | 하드웨어. 컴퓨터 한 대를 통째로 흉내 | 프로세스. 격리된 프로그램 실행 |
| OS | VM마다 게스트 OS(커널 포함)를 설치 | 호스트 OS의 커널을 함께 씀 |
| 크기 | 수 GB | 수 MB에서 수백 MB |
| 시작 시간 | 수십 초에서 수 분(OS 부팅) | 1초 안팎(프로세스 시작) |
| 격리 수준 | 강함(OS 단위로 완전히 분리) | 상대적으로 약함(커널을 함께 씀) |
| 핵심 기술 | 하이퍼바이저 | 리눅스 커널의 namespaces(격리) + cgroups(자원 제한) |
| 비유 | 단지 안에 단독주택을 여러 채 짓기 | 건물 하나를 원룸 여러 개로 나누기 |

컨테이너는 "가벼운 VM"이 아니라 **격리된 프로세스**예요. 컨테이너 안에서는 자기만의 파일, 네트워크, 프로세스 목록이 보여요. 하지만 실제로는 호스트 커널 위에서 도는 평범한 프로그램이라 OS 부팅이 없고 빨라요.

<TwistBox title="Windows에서는 리눅스 커널이 어디 있을까">

컨테이너는 리눅스 커널이 있어야 돌아요. 그래서 Windows와 macOS의 Docker Desktop은 안에 작은 리눅스 VM을 하나 띄워요(Windows는 WSL 2). 컨테이너는 그 VM 안에서 돌아요.

정리하면 Windows에서는 **VM 한 개 위에 컨테이너 여러 개**가 올라가는 구조예요. 그래서 Docker Desktop이 꺼져 있으면 `docker` 명령이 일을 시킬 곳이 없어 실패해요(19절 첫 오류).

</TwistBox>

## 3. 도커는 누가 일을 할까

`docker` 명령을 치면 그 명령이 직접 일을 하는 게 아니에요. 세 쪽이 나눠서 일해요.

```txt
[클라이언트: 내 터미널]  docker pull / run / ps / compose
        | 명령 전달
        v
[도커 호스트: 내 PC]
  도커 데몬(dockerd)이 실제 작업을 해요
  이미지(읽기 전용 틀): nginx, postgres:18, redis
  컨테이너(실행 중인 프로세스): my-nginx, my-pg, my-redis
        ^
        | (1) pull: 이미지 내려받기
[레지스트리: Docker Hub]  ubuntu, nginx, mysql, postgres ... 수많은 공식 이미지
```

| 구성 요소 | 역할 |
| --- | --- |
| 클라이언트(`docker` 명령) | 내가 친 명령을 데몬에 전달해요 |
| 도커 데몬(`dockerd`) | 이미지 받기, 컨테이너 만들기, 실행, 삭제 같은 실제 작업을 해요. daemon은 뒤에서 계속 도는 프로그램이에요 |
| 레지스트리(Docker Hub) | 이미지를 저장하고 나누는 원격 저장소예요. registry는 등록소라는 뜻이에요 |

`docker run`을 할 때 이미지가 내 PC에 없으면 데몬이 알아서 pull해요. 오늘 실습에서는 흐름을 익히려고 `pull`을 먼저 따로 쳤어요.

Git 수업의 `git clone`과 GitHub를 떠올리면 쉬워요. Docker Hub는 이미지의 GitHub이고, `docker pull`은 내려받기예요.

## 4. 이미지, 컨테이너, 볼륨

오늘 배운 것 중 가장 중요한 세 가지예요.

| 이름 | 비유 | 만드는 명령 | 지우는 명령 |
| --- | --- | --- | --- |
| 이미지 | 붕어빵 틀(바뀌지 않음) | `docker pull`, `docker build -t 이름 .` | `docker rmi` |
| 컨테이너 | 붕어빵(틀 하나로 여러 개) | `docker run` | `docker rm` |
| 볼륨 | 붕어빵 밖 보관함 | `-v 이름:경로` | `docker volume rm` |

```txt
Docker Hub --docker pull--> 내 PC의 이미지 --docker run--> 컨테이너
                                                            |  -v
                                                            v
                                                     볼륨 (컨테이너를 지워도 남음)
```

### 이미지 (Image)

이미지는 컨테이너를 만드는 **읽기 전용 틀**(템플릿)이에요. 앱 실행에 필요한 파일(최소한의 OS 파일, 라이브러리, 실행 파일, 설정)과 "켜지면 무엇을 실행할지"가 들어 있어요.

| 특징 | 설명 |
| --- | --- |
| 읽기 전용 | 한 번 만든 이미지는 바뀌지 않아요 |
| 레이어 구조 | 여러 겹을 쌓아 만들어요. 같은 레이어는 이미지끼리 함께 쓰고, 이미 받은 레이어는 다시 받지 않아요 |
| 이름:태그 | `postgres:18`, `ubuntu:24.04`처럼 써요. 태그를 빼면 `latest`예요 |
| 저장 위치 | Docker Hub에서 `pull`로 받아 내 PC에 저장해요. `docker images`로 봐요 |

`docker pull`을 치면 줄마다 `Pull complete`가 찍혀요. 레이어를 하나씩 받는 과정이에요. 이미 받은 레이어는 `Already exists`로 나와요.

### 컨테이너 (Container)

컨테이너는 이미지를 **실행한 것**(실행 인스턴스)이에요. 이미지 위에 쓰기 가능한 얇은 레이어를 한 장 덧붙여서, 격리된 프로세스로 돌려요.

```txt
컨테이너 A [쓰기 레이어]   컨테이너 B [쓰기 레이어]   컨테이너 C [쓰기 레이어]
              \                    |                    /
               이미지 postgres:18 (읽기 전용, 셋이 함께 씀)
                 레이어 3: PostgreSQL 실행 파일과 설정
                 레이어 2: 필요한 라이브러리
                 레이어 1: 베이스 OS 파일(Debian)
```

| 특징 | 설명 |
| --- | --- |
| 이미지의 실행 인스턴스 | 이미지 하나로 컨테이너를 여러 개 만들 수 있어요(서로 격리) |
| 격리된 프로세스 | 자기만의 파일, 네트워크, 프로세스 공간을 가져요 |
| 쓰기 레이어 | 컨테이너 안에서 만든 파일과 데이터는 여기 저장돼요. 컨테이너를 지우면 함께 사라져요 |
| 생명주기 | 생성, 실행, 정지, 삭제 |

```txt
이미지 --docker run--> 실행 중(Up) --docker stop 또는 exit--> 정지(Exited) --docker rm--> 삭제
                          ^                                   |
                          +------------ docker start ---------+
              실행 중에서 바로 지우기: docker rm -f (정지 + 삭제)
```

정지(`Exited`)된 컨테이너는 `docker ps`에는 안 보이고 `docker ps -a`에만 보여요. 할 일을 끝낸 컨테이너는 스스로 `Exited (0)`이 돼요.

### 한 줄 정리와 파이썬 비유

| | 이미지 | 컨테이너 |
| --- | --- | --- |
| 정체 | 실행에 필요한 것을 담은 틀 | 그 틀로 만든 실행 중인 프로세스 |
| 상태 | 읽기 전용(변하지 않음) | 쓰기 가능(실행 중 데이터가 생김) |
| 개수 관계 | 1개 | 같은 이미지로 N개 |
| 만드는 법 | `docker pull`(또는 직접 빌드) | `docker run` |
| 확인 | `docker images` | `docker ps -a` |
| 삭제 | `docker rmi` | `docker rm` |

지난주에 배운 클래스가 여기서 쓰여요. **이미지는 클래스, 컨테이너는 그 클래스로 만든 객체**(인스턴스)예요. 클래스 하나로 객체를 여러 개 만들고 객체마다 자기 데이터를 갖듯이, `postgres:18` 이미지 하나로 컨테이너를 여러 개 만들고 컨테이너마다 자기 데이터를 가져요.

## 5. 첫 컨테이너: hello-world

### 설치 확인

```bash
docker --version
docker compose version
docker info
```

`docker info`에서 오류가 나면 Docker Desktop(또는 Docker 데몬)이 켜져 있는지 확인해요.

### 오늘 쓰는 명령과 옵션

| 명령 | 역할 |
| --- | --- |
| `docker pull 이미지:태그` | 이미지 내려받기(pull: 끌어오다) |
| `docker images` | 내려받은 이미지 목록 |
| `docker run [옵션] 이미지` | 컨테이너 만들기 + 실행 |
| `docker ps` / `docker ps -a` | 실행 중 / 전체 컨테이너 목록(ps: process status, -a: --all) |
| `docker exec -it 컨테이너 명령` | 실행 중인 컨테이너에 들어가기(exec: execute) |
| `docker logs 컨테이너` | 컨테이너 로그 보기 |
| `docker cp 원본 대상` | 내 PC와 컨테이너 사이 파일 복사(cp: copy) |
| `docker stop` / `docker start` | 컨테이너 정지 / 다시 시작 |
| `docker rm` / `docker rmi` | 컨테이너 삭제 / 이미지 삭제(rm: remove, rmi: remove image) |

`docker run` 옵션은 이것만 기억하면 돼요.

| 옵션 | 풀네임 | 의미 | 예시 |
| --- | --- | --- | --- |
| `-it` | `-i`: `--interactive`, `-t`: `--tty` | 터미널을 붙여 대화형으로 실행. `-i`는 키보드 입력을 열어 두고, `-t`는 가상 터미널(TTY)을 붙여 프롬프트가 보이게 해요 | `-it ubuntu bash` |
| `-d` | `--detach` | 터미널에서 떼어 뒤에서 실행 | `-d nginx` |
| `--name` | | 컨테이너 이름 정하기 | `--name my-nginx` |
| `-p 호스트:컨테이너` | `--publish` | 포트 잇기(컨테이너 포트를 밖에 공개) | `-p 8080:80` |
| `-e 키=값` | `--env` | 환경 변수 전달(environment variable) | `-e MYSQL_ROOT_PASSWORD=1234` |
| `-v 볼륨:경로` | `--volume` | 볼륨 잇기(데이터 보존) | `-v pgdata:/var/lib/postgresql` |

한 글자 옵션은 `-i -t`를 `-it`처럼 붙여 쓸 수 있어요. 풀네임은 `--interactive --tty`처럼 하이픈 두 개로 써요.

### 이미지 받고 실행하기

`hello-world`는 도커가 잘 도는지 확인하는 공식 테스트 이미지예요. 메시지를 한 번 찍고 끝나는 아주 작은 이미지예요.

```bash
docker pull hello-world
docker images
```

목록에 `hello-world`가 보이면 내 PC에 저장된 거예요. 크기가 수십 KB로 아주 작아요.

```bash
docker run hello-world
```

```txt
Hello from Docker!
This message shows that your installation appears to be working correctly.
...
```

메시지 아래에는 방금 도커가 한 일이 4단계로 찍혀요. 3절 그림과 그대로 맞아요.

| 단계 | 의미 |
| --- | --- |
| 1 | 클라이언트(`docker` 명령)가 데몬에 요청 |
| 2 | 데몬이 Docker Hub에서 `hello-world` 이미지를 pull(이미 받았으면 건너뜀) |
| 3 | 데몬이 이미지로 새 컨테이너를 만들어 실행하고 메시지를 찍음 |
| 4 | 데몬이 결과를 클라이언트(내 터미널)로 보냄 |

<PredictPrompt />

`docker run hello-world`가 끝난 직후 `docker ps`를 치면 hello-world 컨테이너가 보일지 예측해 보세요.

```bash
docker ps
docker ps -a
```

`docker ps`에는 아무것도 없어요. 메시지를 찍고 할 일을 마쳐서 바로 정지(Exited)했기 때문이에요. `docker ps -a`에는 `Exited (0)` 상태의 컨테이너가 보여요. `Exited (0)`은 정상 종료라는 뜻이에요.

`--name`을 안 줬기 때문에 `NAMES` 칸에는 도커가 아무렇게나 지은 이름(예: `happy_turing`)이 붙어 있어요.

### 한 번 더 실행하면

```bash
docker run hello-world
docker ps -a
```

이번에는 pull 과정 없이 바로 실행되고, `docker ps -a`에 컨테이너가 **2개**가 돼요. `run`은 칠 때마다 이미지 하나로 **새 컨테이너**를 만들어요. 클래스로 객체를 또 만든 것과 같아요.

### 정리하기

컨테이너는 `docker ps -a`의 CONTAINER ID(앞 몇 글자만 써도 돼요)나 NAMES로 지정해 지워요. 여러 개를 한 번에 써도 돼요.

```bash
docker rm <컨테이너ID 또는 이름> <컨테이너ID 또는 이름>
docker rmi hello-world
docker images
```

그 이미지를 쓰는 컨테이너가 남아 있으면 `docker rmi`가 실패해요. **컨테이너를 먼저 지우고 이미지를 지워요.** 다음부터는 `--name`으로 이름을 직접 정해서 ID를 찾지 않고 이름으로 다뤄요.

## 6. Ubuntu: 컨테이너 안으로 들어가기

`-it`로 컨테이너 셸에 들어가서, 실행부터 종료, 재시작, 삭제까지 한 바퀴 돌아봐요.

```bash
docker pull ubuntu:24.04
docker images
docker run -it --name my-ubuntu ubuntu:24.04 bash
```

- `-it`: 대화형 터미널로 실행
- `bash`: 컨테이너가 켜지면 실행할 명령(Bourne Again SHell)

프롬프트가 `root@<컨테이너ID>:/#` 모양으로 바뀌면 컨테이너 안에 들어온 거예요.

`-it` 없이 `docker run ubuntu:24.04 bash`로 켜면 bash가 입력을 받지 못해 곧바로 끝나요. 직접 비교해 보세요.

### 안에서 해 보기

```bash
cat /etc/os-release
whoami
ls /
apt update
apt install -y curl
curl --version
echo "hello docker" > /root/hello.txt
cat /root/hello.txt
exit
```

| 명령 | 뜻 |
| --- | --- |
| `apt` | Ubuntu 패키지 관리자(Advanced Package Tool) |
| `apt update` | 설치할 수 있는 패키지 목록을 최신으로 받기 |
| `apt install -y` | 설치 중 "계속할까요?"에 자동으로 예(`-y`: `--yes`) |
| `curl` | URL로 요청을 보내는 도구(Client URL) |

컨테이너용 이미지는 최소한만 담아서 `curl`, `vim` 같은 도구가 없어요. 필요하면 `apt`로 깔아요.

<TwistBox title="apt update를 건너뛰면 curl을 못 찾아요">

`E: Unable to locate package curl`이 나오면 `apt update`를 건너뛴 거예요. Docker의 Ubuntu 이미지는 용량을 줄이려고 패키지 목록(`/var/lib/apt/lists`)을 비워 둔 채로 나와요. 그래서 컨테이너를 처음 켜면 꼭 `apt update`로 목록부터 받아야 `apt install`이 패키지를 찾아요.

`apt update` 자체가 실패하면(`Temporary failure resolving ...`) 컨테이너의 인터넷 연결 문제예요. 회사나 학원 네트워크의 프록시, 방화벽, Docker Desktop 네트워크 설정을 확인해요.

</TwistBox>

### 생명주기 확인

`exit`로 나오면 컨테이너의 주인 프로그램(bash)이 끝났으니 컨테이너도 정지(Exited)돼요.

```bash
docker ps
docker ps -a
```

정지된 컨테이너를 다시 켜고 붙어서, 아까 만든 파일이 남았는지 봐요.

```bash
docker start -ai my-ubuntu
cat /root/hello.txt
exit
```

`-ai`는 켜면서 터미널에 붙고(`-a`: `--attach`) 입력도 잇는다(`-i`: `--interactive`)는 뜻이에요.

컨테이너를 **정지해도 안의 데이터는 남아요.** 하지만 컨테이너를 **삭제하면 함께 사라져요.** 이 문제를 15절에서 볼륨으로 풀어요.

```bash
docker rm my-ubuntu
docker ps -a
```

## 7. nginx: 포트 잇기와 뒤에서 켜기

`-d`, `-p`로 웹 서버를 띄우고, 실행 중인 컨테이너에 `exec`로 들어가 첫 페이지를 바꿔 봐요.

```bash
docker pull nginx
```

태그를 빼서 `nginx:latest`를 받아요.

### 웹 기본 상식: IP 주소와 포트

웹 서버를 띄우기 전에, 주소창의 `http://localhost:8080/index.html`이 무슨 뜻인지 짚고 가요.

| 부분 | 이름 | 묻는 것 |
| --- | --- | --- |
| `http://` | 프로토콜 | 어떤 규칙으로? |
| `localhost` | IP 주소(호스트) | 어느 컴퓨터로? |
| `:8080` | 포트 | 어느 프로그램으로? |
| `/index.html` | 경로 | 어떤 파일을? |

| 용어 | 의미 | 비유 |
| --- | --- | --- |
| IP 주소(Internet Protocol address) | 네트워크에서 컴퓨터를 찾는 주소(예: `192.168.0.10`) | 아파트 건물 주소 |
| 포트(port: 항구, 출입구) | 그 컴퓨터 안에서 프로그램을 찾는 번호(0에서 65535) | 아파트 호수 |
| localhost | 내 컴퓨터 자신을 가리키는 이름. `127.0.0.1`과 같아요 | 우리 집 |

한 컴퓨터 안에서 여러 프로그램이 각자 다른 번호의 문으로 요청을 받아요. **한 번호는 한 프로그램만** 쓸 수 있어요. 포트를 빼면 기본값을 써요. http는 80, https는 443이에요.

| 포트 | 쓰는 프로그램 |
| --- | --- |
| 80 | 웹 서버(HTTP) |
| 443 | 웹 서버(HTTPS) |
| 22 | SSH 원격 접속 |
| 3306 | MySQL |
| 5432 | PostgreSQL |
| 6379 | Redis |

오늘 띄우는 컨테이너는 모두 `-p` 오른쪽에 이 번호들이 들어가요.

### 컨테이너 켜기

```bash
docker run -d --name my-nginx -p 8080:80 nginx
docker ps
```

TIL에 남긴 `docker ps` 결과예요. `PORTS` 칸에 `0.0.0.0:8080->80/tcp`가 보여요. 내 PC 8080번이 컨테이너 80번으로 이어졌다는 뜻이에요.

```txt
CONTAINER ID   IMAGE     COMMAND                  CREATED                  STATUS                  PORTS                  NAMES
ba5cd077165e   nginx     "/docker-entrypoint.…"   Less than a second ago   Up Less than a second   0.0.0.0:8080->80/tcp   web
```

- `-d`: 뒤에서 실행(터미널을 붙잡지 않음)
- `-p 8080:80`: 내 PC의 8080 포트를 컨테이너의 80 포트로

브라우저에서 `http://localhost:8080`에 들어가면 "Welcome to nginx!" 페이지가 보여요. 터미널에서는 이렇게 확인해요.

```bash
curl http://localhost:8080
```

### 포트는 이렇게 이어져요

```txt
브라우저 localhost:8080 --> 내 PC 8080 --(-p 8080:80)--> my-nginx  80번에서 대기
브라우저 localhost:8081 --> 내 PC 8081 --(-p 8081:80)--> my-nginx2 80번에서 대기
```

컨테이너는 격리된 네트워크 안에 있어서, `-p` 없이 켜면 내 PC 브라우저로 들어갈 수 없어요. `-p 8080:80`은 "내 PC 8080번으로 온 요청을 컨테이너 80번으로 넘겨라"라는 뜻이에요(포트 포워딩).

왼쪽이 **바깥**(내 PC), 오른쪽이 **안쪽**(컨테이너)이에요. 컨테이너 포트(80)는 nginx 이미지가 정해 둔 값이고, 호스트 포트(8080)는 비어 있는 번호 중에 내가 골라요.

- **컨테이너 포트는 같아도 돼요.** 컨테이너마다 네트워크가 따로 격리돼 있어서예요.
- **호스트 포트는 겹치면 안 돼요.** 같은 8080을 또 쓰면 `port is already allocated`가 나요.

같은 이미지로 하나 더 띄우고 호스트 포트만 바꿔 보세요.

```bash
docker run -d --name my-nginx2 -p 8081:80 nginx
```

`http://localhost:8081`에서도 같은 nginx 페이지가 보여요. 확인했으면 `docker rm -f my-nginx2`로 정리해요.

<TwistBox title="포트는 나중에 붙일 수 없어요">

포트는 **컨테이너를 만들 때만** 정할 수 있어요. 이미 만든 컨테이너에 나중에 `-p`를 붙이는 명령은 없어요. 포트를 바꾸려면 컨테이너를 지우고 새로 만들어요.

</TwistBox>

### 실행 중인 컨테이너에 들어가기

```bash
docker exec -it my-nginx bash
```

`exec`는 실행 중인 컨테이너 안에서 명령을 실행해요(execute). `run`은 **새 컨테이너를 만들고**, `exec`는 **이미 켜진 컨테이너 안에서** 명령을 돌려요.

6절의 Ubuntu는 `exit`하면 꺼졌죠. `exec`로 들어간 bash는 주인 프로그램이 아니라 덤으로 띄운 것이라, **`exit`해도 컨테이너는 계속 돌아요.** nginx가 주인 프로그램이기 때문이에요.

### 첫 페이지 바꾸기

```bash
cd /usr/share/nginx/html
ls
echo "<h1>Hello from Docker Nginx!</h1>" > index.html
cat index.html
exit
```

`cd`는 change directory, `ls`는 list, `cat`은 concatenate(파일 내용 출력)예요. 브라우저를 새로고침하면 바뀐 페이지가 보여요.

### 로그 보기

```bash
docker logs my-nginx
docker logs -f my-nginx
```

`-f`는 새로 찍히는 로그를 실시간으로 따라가요(`--follow`). 브라우저를 몇 번 새로고침해서 접속 기록이 찍히는 걸 보고, `Ctrl + C`로 빠져나와요.

TIL에 남긴 로그예요. 한 줄에 보낸 주소, 시각, 요청, 결과 번호가 들어 있어요. 404는 파일 없음, 200은 성공이에요. 처음엔 `event.html`이 없어서 404, 파일을 만든 뒤엔 200이 나왔어요.

```txt
172.17.0.1 - - [12/Nov/2026:02:02:30 +0000] "GET /event.html HTTP/1.1" 404 153 "-" "curl/8.5.0" "-"
172.17.0.1 - - [12/Nov/2026:02:02:30 +0000] "GET /event.html HTTP/1.1" 200 53 "-" "curl/8.5.0" "-"
```

### 정리하기

```bash
docker stop my-nginx
docker rm my-nginx
```

`docker rm -f my-nginx` 한 줄로 정지와 삭제를 한 번에 할 수도 있어요(`-f`: `--force`, 강제).

## 8. 볼륨과 내 폴더 잇기

7절에서 `index.html`을 컨테이너 안에서 고쳤죠. 그 컨테이너를 지우면 고친 파일도 함께 지워져요. 남겨야 하는 파일은 **컨테이너 밖**에 둬요. 방법은 두 가지예요.

```bash
# 1) 도커가 관리하는 볼륨에 두기
docker run -d --name web -p 8080:80 -v cafe-html:/usr/share/nginx/html nginx

# 2) 내 PC 폴더를 그대로 잇기
docker run -d --name web -p 8080:80 -v ./site:/usr/share/nginx/html nginx
```

| 쓰는 법 | 왼쪽에 오는 것 | 언제 |
| --- | --- | --- |
| `-v 이름:경로` | 볼륨 이름(도커가 관리) | DB 데이터처럼 도커가 알아서 지켜 주면 될 때 |
| `-v ./폴더:경로` | 내 PC 폴더 경로 | 내가 VS Code로 직접 고칠 파일(웹 페이지, 설정)일 때 |

내 폴더를 이으면 `site/index.html`을 VS Code에서 고치고 저장만 해도 컨테이너가 바로 그 파일을 봐요.

<TwistBox title="./를 빼면 오류 없이 엉뚱한 볼륨이 생겨요">

`-v site:/usr/share/nginx/html`처럼 `./`를 빼면, 도커는 이걸 내 폴더가 아니라 **site라는 이름의 볼륨**으로 읽어요. 오류도 없이 빈 볼륨이 새로 생겨서, 내 `site` 폴더의 파일은 하나도 안 보여요.

내 폴더를 이을 때는 꼭 `./`나 전체 경로로 시작해요.

</TwistBox>

<TwistBox title="Git Bash에서 경로가 이상하게 바뀔 때">

Git Bash는 `/usr/...`처럼 `/`로 시작하는 글자를 Windows 경로로 바꿔 버려요. 그래서 컨테이너 안 경로 앞에 `C:/Program Files/Git`이 붙어 엉뚱한 곳을 가리켜요.

이럴 때는 이 줄을 먼저 치고 다시 실행해요.

```bash
export MSYS_NO_PATHCONV=1
```

</TwistBox>

## 9. Dockerfile: 장바구니를 이미지로

지금까지는 남이 만든 이미지(nginx, ubuntu)를 받아 썼어요. 이번에는 어제 만든 장바구니 프로그램을 **내 이미지**로 만들어요. 어제 만든 장바구니가 여기서 쓰여요.

이미지 만드는 법을 적은 파일이 `Dockerfile`이에요. 장바구니 폴더에 확장자 없이 이 이름으로 만들어요.

```dockerfile
FROM astral/uv:python3.14-bookworm-slim
WORKDIR /app
COPY . .
RUN uv sync
CMD ["uv", "run", "main.py"]
```

| 줄 | 하는 일 | 언제 실행 |
| --- | --- | --- |
| `FROM` | 바탕 이미지 고르기(여기선 파이썬 3.14와 uv가 든 이미지) | build할 때 |
| `WORKDIR /app` | 컨테이너 안 작업 폴더를 `/app`으로(없으면 만들어요) | build할 때 |
| `COPY . .` | 내 폴더(왼쪽 `.`)를 작업 폴더(오른쪽 `.`)로 복사 | build할 때 |
| `RUN uv sync` | 패키지 설치. 결과가 이미지에 담겨요 | build할 때 |
| `CMD [...]` | 컨테이너가 켜질 때 실행할 명령 | **run할 때마다** |

```bash
docker build -t cart .
docker run --rm cart
```

- `docker build -t cart .`: 현재 폴더(`.`)의 Dockerfile로 `cart`라는 이름의 이미지를 만들어요(`-t`: tag).
- `docker run --rm cart`: 실행하고, 끝나면 컨테이너를 자동으로 지워요. 한 번 돌리고 끝나는 프로그램이라 `Exited` 컨테이너가 쌓이지 않게 해요.

<TwistBox title="코드를 고쳤는데 옛날 코드가 돌아요">

이미지에는 **build한 순간의 코드**가 복사돼 들어 있어요. 그래서 `main.py`를 고친 뒤 `docker run`만 다시 하면 옛날 코드가 돌아요.

코드를 고치면 **`docker build`부터 다시** 해요. build할 때 `COPY`가 새 코드를 다시 담아요.

</TwistBox>

### .dockerignore로 빼기

`COPY . .`는 폴더를 통째로 복사해요. 그러면 내 PC의 `.venv`, `__pycache__`, `.git`까지 이미지에 들어가요. 이미지가 커지고, 내 PC용 가상환경이 리눅스 컨테이너에 섞여 들어가요.

`.gitignore`처럼 `.dockerignore` 파일에 빼고 싶은 것을 적어요.

```txt
.venv
__pycache__
.git
```

`.venv`는 이미지 안에서 `RUN uv sync`가 새로 만들어요. 5회차에서 `.venv`는 저장소에 안 올리고 `uv sync`로 다시 만든다고 배웠죠. 같은 원리예요.

<TwistBox title="input()을 받는 메뉴는 -it가 필요해요">

장바구니 메뉴처럼 `input()`으로 키보드 입력을 받는 프로그램은 `docker run --rm cart`만으로는 입력할 수 없어요. 6절에서 본 것처럼 입력을 열어 두는 `-i`와 터미널을 붙이는 `-t`가 필요해요.

```bash
docker run --rm -it cart
```

</TwistBox>

## 10. Docker Compose 기초: 긴 명령을 파일로

`docker run` 옵션이 점점 길어졌죠. 컨테이너가 두세 개가 되면 매번 치기 힘들어요. **Compose**는 이 옵션들을 `compose.yaml` 파일에 적어 두고 명령 한 줄로 켜고 꺼요. compose는 구성하다, YAML은 "YAML Ain't Markup Language"의 줄임이에요.

| `docker run` 옵션 | `compose.yaml` 키 |
| --- | --- |
| `--name my-pg` | `container_name: my-pg` |
| `postgres:18` | `image: postgres:18` |
| `-e POSTGRES_PASSWORD=1234`(`--env`) | `environment:` |
| `-p 5432:5432`(`--publish`) | `ports:` |
| `-v pgdata:/var/lib/postgresql`(`--volume`) | `volumes:` |

### 기초 문법

```yaml
services:                 # 실행할 컨테이너(서비스) 목록. 꼭 있어야 해요
  서비스이름:              # 예: db, cache, web (서비스끼리 부를 때 이 이름을 써요)
    image: 이미지:태그      # 쓸 이미지
    container_name: 이름   # 컨테이너 이름 (빼면 자동으로 지어요)
    environment:           # 환경 변수 (-e)
      KEY: value
    ports:                 # 포트 잇기 (-p). 따옴표로 감싸기를 권해요
      - "호스트:컨테이너"
    volumes:               # 볼륨 잇기 (-v)
      - 볼륨이름:컨테이너경로
volumes:                  # 쓸 볼륨 선언 (맨 바깥)
  볼륨이름:
```

YAML 규칙은 세 가지예요.

- 들여쓰기는 **스페이스 2칸**이에요. 탭은 안 돼요.
- `키: 값`에서 콜론 뒤에 **공백 한 칸**이 꼭 있어야 해요.
- 목록은 `- 항목` 모양이에요.

예전 자료에 있는 `version: "3.8"` 같은 맨 위 `version`은 이제 쓰지 않아요. 넣어도 obsolete 경고만 찍히고 무시돼요.

<TwistBox title="포트를 따옴표로 감싸는 이유">

YAML의 옛 규칙에서는 `22:22`처럼 콜론 뒤 숫자가 60보다 작으면 **60진수 숫자**로 읽힐 수 있어요(시:분처럼). 파이썬 YAML 라이브러리로 직접 읽어 봤어요.

```txt
- 22:22     -> 1342       (숫자가 돼 버림)
- 8080:80   -> '8080:80'  (글자)
- "22:22"   -> '22:22'    (글자)
```

어떤 포트에서 이런 일이 생길지 따지기보다, 늘 `"5432:5432"`처럼 따옴표로 감싸면 걱정이 없어요.

</TwistBox>

### 켜고 끄기

`compose.yaml`이 있는 폴더에서 쳐요.

```bash
docker compose up -d
docker compose down
```

- `up -d`: 파일에 적힌 서비스를 만들고 뒤에서 켜요.
- `down`: 컨테이너와 네트워크를 지워요. **볼륨은 남겨요.**
- `down -v`: 볼륨까지 지워요(`--volumes`).

16절에서 PostgreSQL과 Redis를 Compose로 함께 켜 보며 자세히 다뤄요.

## 11. nginx: 웹 서버와 리버스 프록시

### 웹 서버와 앱 서버

| | 웹 서버(nginx) | 앱 서버 |
| --- | --- | --- |
| 하는 일 | 폴더의 파일(html, 그림)을 **그대로** 내줘요 | **코드를 실행해서** 답을 만들어 내줘요 |
| 예 | `site/index.html`을 보여 주기 | 주문을 받아 계산하는 파이썬 앱 |

### 리버스 프록시

**리버스 프록시**는 nginx가 요청을 **대신 받아** 뒤에 있는 앱에 넘기고, 앱의 답을 그대로 돌려주는 거예요. 식당 카운터 직원이 주문을 받아 주방에 넘기고 음식을 손님에게 건네주는 것과 같아요.

```txt
브라우저 --localhost/menu/--> nginx (80번) --proxy_pass--> menu 앱
                                |
                                +-- 파일은 바로 줌 (site/index.html)
```

이렇게 하면 밖으로 여는 포트는 **nginx의 80번 하나**로 둬요. 앱이 여러 개여도 `/menu/`, `/order/`처럼 **경로로** 골라 보내요. 앱마다 8081, 8082 같은 포트를 따로 열지 않아도 돼요.

### 설정 파일

`conf/default.conf`에 이렇게 적었어요.

```nginx
server {
    listen 80;

    location / {
        root /usr/share/nginx/html;
        index index.html;
    }

    location /menu/ {
        proxy_pass http://menu/;
    }
}
```

| 줄 | 뜻 |
| --- | --- |
| `listen 80;` | 80번 문에서 기다려요 |
| `location / { root ...; index index.html; }` | 나머지 주소는 이 폴더의 파일을 그대로 줘요. 주소에 파일이 없으면 `index.html`을 줘요 |
| `location /menu/ { proxy_pass http://menu/; }` | `/menu/`로 시작하는 요청은 `menu` 서비스로 넘겨요 |

nginx 설정은 줄마다 `;`로 끝나요. 빠뜨리면 설정 검사에서 걸려요.

<TwistBox title="proxy_pass에 localhost를 쓰면 502가 나요">

`proxy_pass http://localhost:8000/`처럼 쓰고 싶어지죠. 그런데 **컨테이너 안의 localhost는 nginx 컨테이너 자신**이에요. nginx 안에는 menu 앱이 없으니 연결에 실패하고 `502 Bad Gateway`가 나요.

Compose로 함께 켠 서비스끼리는 **서비스 이름이 곧 주소**예요. 그래서 `http://menu/`처럼 서비스 이름을 적어요(16절에서 직접 확인해요).

</TwistBox>

### 끝의 `/` 하나가 하는 일

`proxy_pass http://menu/;`처럼 **끝에 `/`가 있으면** 요청 주소에서 `/menu/`를 떼고 넘겨요.

| 브라우저 요청 | menu 앱이 받는 주소 |
| --- | --- |
| `localhost/menu/` | `/` |
| `localhost/menu/list` | `/list` |

menu 앱 입장에서는 자기가 `/menu/` 아래에 붙어 있는지 몰라도 돼요.

### 설정을 고친 뒤

```bash
docker exec cafe-web-1 nginx -t           # 설정 검사
docker exec cafe-web-1 nginx -s reload    # 끄지 않고 설정 다시 읽기
```

설정을 고치면 `nginx -t`로 먼저 검사하고, 통과하면 `nginx -s reload`로 반영해요. 컨테이너를 끄지 않아도 돼요.

`cafe-web-1`은 Compose가 지어 준 컨테이너 이름이에요. `container_name`을 안 주면 **프로젝트(폴더) 이름, 서비스 이름, 번호**를 이어서 지어요. `cafe` 폴더의 `web` 서비스 첫 번째 컨테이너라는 뜻이에요.

## 12. 데이터베이스 기초

### 왜 데이터베이스일까

어제 장바구니는 프로그램을 끄면 담은 게 다 사라졌죠. 변수는 메모리에 있어서예요. 데이터베이스는 이걸 해결해요.

- **꺼도 남아요.** 프로그램을 꺼도 데이터가 디스크에 남아요.
- **여러 프로그램의 요청을 차례로 받아 지켜 줘요.** 여러 사람이 동시에 주문해도 데이터가 엉키지 않아요.
- **조건으로 바로 찾아요.** "1번 주문", "재고 20개 미만"처럼 원하는 것만 꺼내요.

### 구조

```txt
DB 컨테이너 > 데이터베이스 서버(DBMS) > 데이터베이스 cafe > 표 orders (id, menu, qty)
```

| 용어 | 뜻 | 엑셀로 치면 |
| --- | --- | --- |
| DBMS | 데이터베이스를 관리하는 프로그램(MySQL, PostgreSQL) | 엑셀 프로그램 |
| 데이터베이스 | 표를 모아 두는 단위(`cafe`, `shop`) | 엑셀 파일 하나 |
| 표(테이블) | 같은 모양의 데이터를 모은 것(`orders`) | 시트 하나 |
| 열(컬럼) | 데이터의 항목. 열마다 **타입**이 정해져 있어요 | 머리줄의 칸 |
| 행(로우) | 데이터 한 건(주문 하나) | 한 줄 |

| 타입 | 뜻 |
| --- | --- |
| `INT` | 정수(integer) |
| `VARCHAR(20)` | 최대 20자까지의 글자(variable character). 넘치면 오류예요 |

### 기본 키 (Primary Key)

**기본 키**는 행마다 **겹치지 않고, 비울 수도 없는** 값이에요. 주문 번호처럼 그 행 하나를 콕 집는 이름표예요. Git의 커밋 해시가 커밋마다 하나뿐인 것과 비슷해요.

### SQL 네 문장

SQL(Structured Query Language)은 데이터베이스에 일을 시키는 언어예요.

```sql
CREATE DATABASE cafe;
CREATE TABLE orders (id INT PRIMARY KEY, menu VARCHAR(20), qty INT);
INSERT INTO orders VALUES (1, 'latte', 2);
SELECT * FROM orders WHERE id = 1;
```

| 문장 | 하는 일 |
| --- | --- |
| `CREATE DATABASE cafe;` | `cafe` 데이터베이스 만들기 |
| `CREATE TABLE orders (...);` | 열 이름과 타입을 정해 표 만들기. `id`가 기본 키 |
| `INSERT INTO orders VALUES (...);` | 행 하나 넣기 |
| `SELECT * FROM orders WHERE id = 1;` | `id`가 1인 행의 모든 열(`*`) 꺼내기 |

문법에서 헷갈리는 세 가지예요.

- SQL은 **`;`로 끝나요.**
- 글자 값은 **작은따옴표**(`'latte'`)로 감싸요.
- `WHERE`에서 같다는 **`=` 하나**예요. 파이썬처럼 `==`가 아니에요.

<TwistBox title="규칙을 어기면 DB가 바로 막아요">

PostgreSQL 엔진으로 직접 넣어 봤어요. 기본 키와 타입이 데이터를 지켜 주는 게 보여요.

```sql
INSERT INTO orders VALUES (1, 'mocha', 1);
-- ERROR: duplicate key value violates unique constraint "orders_pkey"

INSERT INTO orders VALUES (NULL, 'mocha', 1);
-- ERROR: null value in column "id" of relation "orders" violates not-null constraint

SELECT * FROM orders WHERE menu = "latte";
-- ERROR: column "latte" does not exist

SELECT * FROM orders WHERE id == 1;
-- ERROR: operator does not exist: integer == integer
```

1번 주문이 이미 있어서 같은 번호를 또 못 넣고, 번호를 비워 둘 수도 없어요. 큰따옴표로 감싼 `"latte"`는 글자가 아니라 **열 이름**으로 읽혀서 "latte라는 열이 없다"고 나와요. `==`는 SQL에 없는 연산자예요.

</TwistBox>

<TwistBox title="프롬프트가 -> 로 바뀌었다면">

MySQL에서 Enter를 쳤는데 결과 대신 프롬프트가 `->`(PostgreSQL은 `-#`)로 바뀌면 끝의 `;`가 빠진 거예요. DB는 문장이 아직 안 끝났다고 보고 다음 줄을 기다려요.

당황하지 말고 `;`만 치고 Enter를 누르면 돼요.

</TwistBox>

## 13. MySQL 컨테이너

`-e`로 꼭 필요한 환경 변수를 줘서 DB를 띄우고, 컨테이너 안의 `mysql` 클라이언트로 SQL을 실행해요.

```bash
docker pull mysql:8.4
```

8.4는 MySQL의 LTS(Long Term Support, 장기 지원) 버전이에요.

### 켜기

```bash
docker run -d --name my-mysql -e MYSQL_ROOT_PASSWORD=1234 -p 3306:3306 mysql:8.4
```

`-e MYSQL_ROOT_PASSWORD=1234`는 관리자(root) 비밀번호를 정해요. **꼭 있어야 하는** 환경 변수라, 빠뜨리면 컨테이너가 바로 꺼져요. `docker ps -a`와 `docker logs my-mysql`로 확인해 보세요.

처음 켤 때 준비에 수십 초가 걸려서 로그로 준비가 끝났는지 봐요.

```bash
docker logs -f my-mysql
```

`ready for connections`가 보이면 `Ctrl + C`로 빠져나와요.

내 PC에 MySQL이 이미 깔려 있어서 3306을 쓰고 있다면 `-p 3307:3306`처럼 호스트 포트를 바꿔요.

### 들어가기

```bash
docker exec -it my-mysql mysql -uroot -p
```

- `-uroot`: root 사용자로 접속(`-u`: `--user`, 값을 붙여 써도 돼요)
- `-p`: 비밀번호를 물어보게 해요(`--password`). docker의 `-p`(포트)와 **뜻이 달라요.** 여기 `-p`는 `mysql` 명령의 옵션이에요

비밀번호 `1234`를 치면 `mysql>` 프롬프트가 나와요.

`exec`로 꼭 DB 클라이언트를 바로 띄울 필요는 없어요. `docker exec -it my-mysql bash`로 셸에 먼저 들어간 뒤 `mysql -uroot -p`를 쳐도 같아요.

### 안에서 SQL 실행

```sql
SHOW DATABASES;
CREATE DATABASE shop;
USE shop;
CREATE TABLE product (id INT AUTO_INCREMENT PRIMARY KEY, name VARCHAR(50), price INT);
INSERT INTO product (name, price) VALUES ('키보드', 35000), ('마우스', 18000);
SELECT * FROM product;
exit
```

- `USE shop;`: 이제부터 `shop` 데이터베이스에서 일해요
- `AUTO_INCREMENT`: 값을 안 넣으면 1씩 늘려 자동으로 채워요. 그래서 `INSERT`에 `id`를 안 적었어요
- `INSERT ... VALUES (...), (...)`: 괄호를 쉼표로 이어 여러 행을 한 번에 넣어요
- `VARCHAR(50)`: 최대 50자 글자

```bash
docker rm -f my-mysql
```

### 수업에서 한 cafe 버전

수업에서는 데이터베이스와 볼륨까지 한 번에 줬어요.

```bash
docker run -d --name db -e MYSQL_ROOT_PASSWORD=cafe1234 -e MYSQL_DATABASE=cafe -p 3306:3306 -v cafe-data:/var/lib/mysql mysql:8.4
docker exec -it db mysql -u root -p cafe
```

- `-e MYSQL_DATABASE=cafe`: 처음 켤 때 `cafe` 데이터베이스를 만들어 줘요
- `-v cafe-data:/var/lib/mysql`: MySQL이 데이터를 두는 폴더를 볼륨에 이어요
- `mysql -u root -p cafe`: 맨 끝 `cafe`는 들어가자마자 쓸 데이터베이스예요(`USE cafe;`를 대신해요)

12절의 네 문장으로 주문을 넣고 `SELECT * FROM orders;`를 친 결과예요(TIL).

```txt
+----+-----------+------+
| id | menu      | qty  |
+----+-----------+------+
|  1 | latte     |    2 |
|  2 | americano |    1 |
+----+-----------+------+
2 rows in set (0.00 sec)
```

## 14. Redis 컨테이너: 메모리 속 키와 값

Redis(REmote DIctionary Server)는 데이터를 **메모리**에 키와 값으로 두는 저장소예요. 파이썬 딕셔너리를 서버로 만든 것과 비슷해서 아주 빨라요. 로그인 세션, 캐시, 점수판에 많이 써요.

```bash
docker pull redis
docker run -d --name my-redis -p 6379:6379 redis
docker ps
```

Redis 공식 이미지는 꼭 필요한 환경 변수가 없어서 기본 설정만으로 바로 켜져요.

```bash
docker exec -it my-redis redis-cli
```

`redis-cli`는 Redis 명령줄 클라이언트예요(CLI: Command Line Interface).

```txt
PING
SET player:1:name "재현"
GET player:1:name
SET score 100
INCR score
INCRBY score 50
GET score
SET session:abc "login" EX 30
TTL session:abc
LPUSH ranking "A" "B" "C"
LRANGE ranking 0 -1
KEYS *
exit
```

| 명령 | 설명 |
| --- | --- |
| `PING` | 연결 확인. `PONG`이 돌아와요 |
| `SET` / `GET` | 글자 저장 / 꺼내기 |
| `INCR` / `INCRBY` | 숫자 늘리기(increment / increment by). 점수, 조회수처럼 여럿이 동시에 늘려도 안전해요 |
| `EX 30` / `TTL` | 30초 뒤 자동 삭제(expire) / 남은 시간 확인(Time To Live). 세션, 캐시에 써요 |
| `LPUSH` / `LRANGE` | 리스트 왼쪽(앞)에 넣기 / 범위 꺼내기. `0 -1`은 처음부터 끝까지 |
| `KEYS *` | 모든 키 보기 |

Redis와 같은 동작을 하는 파이썬 흉내 라이브러리로 결과를 확인해 봤어요.

| 명령 | 결과 |
| --- | --- |
| `INCR score` | 101 |
| `INCRBY score 50` | 151 |
| `TTL session:abc` | 30(바로 쳤을 때) |
| `LRANGE ranking 0 -1` | C, B, A |

`LPUSH`는 **앞에** 넣어서, A, B, C 순서로 넣으면 꺼낼 때는 C, B, A로 뒤집혀 나와요. 30초가 지난 뒤 `TTL session:abc`를 다시 치면 `-2`(키 없음)가 나와요.

```bash
docker rm -f my-redis
```

## 15. PostgreSQL과 볼륨: 지워도 데이터가 남을까

먼저 볼륨 **없이** 데이터를 넣고 컨테이너를 지워서 데이터가 사라지는 걸 봐요. 그다음 볼륨을 만들어 같은 과정을 반복하며 데이터가 남는 걸 봐요. 데이터는 밖에서 만든 SQL 파일을 가져오는(임포트) 방식으로 넣어요.

```bash
docker pull postgres:18
```

### 가져올 SQL 파일 준비 (내 PC에서)

실습 폴더를 만들고 들어가요. 이 절의 명령은 모두 이 폴더에서 쳐요.

```bash
mkdir pg-lab
cd pg-lab
```

`pg-lab` 폴더에 `products.sql`을 만들고 아래 내용을 저장해요. VS Code 같은 편집기로 만들고 **인코딩은 UTF-8**로 해요.

```sql
INSERT INTO product (name, price, stock) VALUES
('무선 키보드', 35000, 120),
('게이밍 마우스', 28000, 85),
('27인치 모니터', 259000, 15),
('USB-C 허브', 19900, 200),
('노트북 거치대', 24000, 7);
```

실무에서도 처음 넣을 데이터나 테스트 데이터는 이렇게 SQL 파일로 관리하고 DB에 가져오는 경우가 많아요. 파일이라 Git으로 버전 관리도 돼요.

### 1단계: 볼륨 없이

```bash
docker run -d --name my-pg -e POSTGRES_PASSWORD=1234 -p 5432:5432 postgres:18
docker logs my-pg
```

`POSTGRES_PASSWORD`는 기본 사용자 `postgres`의 비밀번호예요. 꼭 있어야 해요. 로그 끝에 `database system is ready to accept connections`가 보이면 준비 끝이에요.

```bash
docker exec -it my-pg psql -U postgres
```

`psql`은 PostgreSQL 명령줄 클라이언트(PostgreSQL interactive terminal)이고, `-U postgres`는 postgres 사용자로 접속한다는 뜻이에요(`--username`).

```sql
CREATE TABLE product (id SERIAL PRIMARY KEY, name VARCHAR(100) NOT NULL, price INT NOT NULL, stock INT NOT NULL DEFAULT 0);
\dt
\d product
\q
```

| 컬럼 | 타입 | 의미 |
| --- | --- | --- |
| `id` | `SERIAL` | 상품 번호. 자동으로 늘어나는 정수(MySQL의 `AUTO_INCREMENT`와 같은 역할) |
| `name` | `VARCHAR(100)` | 상품 이름 |
| `price` | `INT` | 가격 |
| `stock` | `INT` | 재고 수량. 값을 안 넣으면 `DEFAULT 0` |

`NOT NULL`은 비워 둘 수 없다는 뜻이에요. PostgreSQL 엔진으로 확인해 보니, `stock`을 빼고 넣으면 0이 들어가고, `price`를 비우면 `null value in column "price" ... violates not-null constraint` 오류가 났어요.

| psql 명령 | 설명 |
| --- | --- |
| `\l` | 데이터베이스 목록(list) |
| `\dt` | 표 목록(describe tables) |
| `\d 테이블명` | 표 구조(describe) |
| `\i 파일경로` | 컨테이너 안의 SQL 파일 실행(include) |
| `\q` | 나가기(quit) |

### 밖의 SQL 파일 가져오기

`products.sql`은 내 PC에 있고 `psql`은 컨테이너 안에 있어요. 그래서 파일을 컨테이너로 복사한 뒤 실행해요.

```bash
docker cp products.sql my-pg:/tmp/products.sql
docker exec -it my-pg psql -U postgres -f /tmp/products.sql
```

- `docker cp 원본 대상`: 내 PC와 컨테이너 사이 파일 복사. 컨테이너 쪽은 `컨테이너이름:경로`로 써요
- `-f 파일`: SQL 파일을 읽어 실행해요(`--file`)

`INSERT 0 5`가 찍히면 5건이 들어간 거예요.

<TwistBox title="파일을 복사하지 않고 흘려 넣는 방법도 있어요">

표준 입력(STDIN)으로 파일 내용을 바로 흘려 넣을 수도 있어요. 이때는 터미널이 아니라 파일에서 입력이 오니까 `-t` 없이 `-i`만 써요.

```bash
docker exec -i my-pg psql -U postgres < products.sql
```

macOS와 Linux 터미널, Windows 명령 프롬프트(cmd)에서 동작해요. PowerShell은 `<` 리디렉션을 지원하지 않고, 파이프(`|`)로 넘기면 한글이 깨질 수 있어요. PowerShell에서는 위의 `docker cp` 방식을 써요.

</TwistBox>

### 꺼내 보기

```bash
docker exec -it my-pg psql -U postgres
```

```sql
SELECT * FROM product;
SELECT name, stock FROM product WHERE stock < 20;
SELECT name, price * stock AS stock_value FROM product ORDER BY stock_value DESC;
\q
```

세 문장을 PostgreSQL 엔진으로 돌려 본 결과예요.

**1) 전부 꺼내기**

| id | name | price | stock |
| --- | --- | --- | --- |
| 1 | 무선 키보드 | 35000 | 120 |
| 2 | 게이밍 마우스 | 28000 | 85 |
| 3 | 27인치 모니터 | 259000 | 15 |
| 4 | USB-C 허브 | 19900 | 200 |
| 5 | 노트북 거치대 | 24000 | 7 |

**2) 재고가 20개 미만인 상품(재고 부족 알림)**

| name | stock |
| --- | --- |
| 27인치 모니터 | 15 |
| 노트북 거치대 | 7 |

**3) 상품별 재고 금액(가격 x 재고) 큰 순서**

| name | stock_value |
| --- | --- |
| 무선 키보드 | 4200000 |
| USB-C 허브 | 3980000 |
| 27인치 모니터 | 3885000 |
| 게이밍 마우스 | 2380000 |
| 노트북 거치대 | 168000 |

`AS`는 계산한 열에 이름(별칭, alias)을 붙여요. `ORDER BY ... DESC`는 큰 것부터(descending, 내림차순) 정렬해요. 모니터는 한 대가 비싸도 재고가 15개뿐이라 3등이에요.

### 지우고 다시 켜면

<PredictPrompt />

컨테이너를 지우고 **똑같은 명령**으로 다시 켠 뒤 `SELECT * FROM product;`를 치면 상품 5개가 보일지 예측해 보세요.

```bash
docker rm -f my-pg
docker run -d --name my-pg -e POSTGRES_PASSWORD=1234 -p 5432:5432 postgres:18
docker exec -it my-pg psql -U postgres -c "SELECT * FROM product;"
```

`-c "SQL"`은 psql 안에 들어가지 않고 SQL 한 줄만 실행해요(`--command`).

```txt
ERROR:  relation "product" does not exist
```

표도 데이터도 없어요. 새 컨테이너는 **빈 DB로** 시작해요. 컨테이너를 지우면 그 안에 쌓인 데이터도 함께 사라져요. relation은 PostgreSQL에서 표를 부르는 말이에요.

<TwistBox title="이름 없는 볼륨이 몰래 생겨 있어요">

`docker volume ls`를 쳐 보면 긴 해시 이름의 볼륨이 보여요. postgres 이미지는 데이터 경로를 볼륨으로 쓰겠다고 정해 둬서, `-v`를 안 주면 도커가 **이름 없는 볼륨**(anonymous volume)을 알아서 만들어요.

하지만 새 컨테이너는 또 새 익명 볼륨을 만들어서 이전 데이터를 찾아 잇지 못해요. 그래서 **이름 있는 볼륨**이 필요해요.

</TwistBox>

1단계 정리예요. 컨테이너를 지울 때 `-v`를 붙이면 이어진 익명 볼륨까지 함께 지워요(`--volumes`).

```bash
docker rm -f -v my-pg
docker volume prune
```

`docker volume prune`은 어떤 컨테이너도 안 쓰는 익명 볼륨을 정리해요. 확인 질문에 `y`를 쳐요. prune은 가지치기라는 뜻이에요.

### 2단계: 볼륨을 쓰면

```bash
docker volume create pgdata
docker volume ls
docker volume inspect pgdata
```

`ls`는 목록, `inspect`는 상세 정보예요. 실제 저장 위치(`Mountpoint`) 같은 걸 보여 줘요. 볼륨은 **도커가 관리하는 컨테이너 바깥 저장 공간**이라, 컨테이너가 지워져도 남아요.

```bash
docker run -d --name my-pg -e POSTGRES_PASSWORD=1234 -p 5432:5432 -v pgdata:/var/lib/postgresql postgres:18
```

`-v pgdata:/var/lib/postgresql`은 `pgdata` 볼륨을 컨테이너의 데이터 경로에 이어요.

<TwistBox title="PostgreSQL 18부터 경로가 바뀌었어요">

| 버전 | 볼륨을 이을 경로 |
| --- | --- |
| `postgres:18` 이상 | `/var/lib/postgresql` |
| `postgres:17` 이하 | `/var/lib/postgresql/data` |

인터넷의 예전 자료처럼 18 이미지에 `/var/lib/postgresql/data`를 이으면 컨테이너가 안 켜지거나 데이터가 안 남을 수 있어요.

</TwistBox>

이번에는 psql 안에 들어가지 않고 `-c`로 바로 실행해요. 표 만들기, 가져오기, 꺼내기는 1단계와 같아요.

```bash
docker exec -it my-pg psql -U postgres -c "CREATE TABLE product (id SERIAL PRIMARY KEY, name VARCHAR(100) NOT NULL, price INT NOT NULL, stock INT NOT NULL DEFAULT 0);"
docker cp products.sql my-pg:/tmp/products.sql
docker exec -it my-pg psql -U postgres -f /tmp/products.sql
docker exec -it my-pg psql -U postgres -c "SELECT * FROM product;"
```

이제 컨테이너를 완전히 지워요.

```bash
docker rm -f my-pg
docker ps -a
docker volume ls
```

컨테이너는 사라졌지만 `pgdata` 볼륨은 남아 있어요. 같은 볼륨을 이어서 **새 이름**의 컨테이너를 만들어요.

```bash
docker run -d --name my-pg2 -e POSTGRES_PASSWORD=1234 -p 5432:5432 -v pgdata:/var/lib/postgresql postgres:18
docker exec -it my-pg2 psql -U postgres -c "SELECT * FROM product;"
```

상품 5개가 그대로 나와요. 데이터는 컨테이너가 아니라 **볼륨에** 있었던 거예요.

| | 1단계(볼륨 없음) | 2단계(`-v pgdata:...`) |
| --- | --- | --- |
| 데이터 위치 | 컨테이너마다 새로 생기는 익명 볼륨 | 이름 있는 볼륨 `pgdata` |
| 지우고 새 컨테이너 | 빈 DB | 데이터 그대로 |

```bash
docker rm -f my-pg2
```

`pgdata` 볼륨은 지우지 마세요. 다음 절 Compose 실습에서 다시 써요.

<TwistBox title="새 비밀번호로 켰는데 접속이 안 돼요">

`-e`로 준 비밀번호와 처음 실행할 SQL을 넣는 init 폴더(`/docker-entrypoint-initdb.d`)는 **데이터 폴더가 비어 있을 때 처음 한 번만** 읽어요. DB를 처음 만들 때만 쓰는 설정이에요.

그래서 볼륨이 남아 있으면 `-e POSTGRES_PASSWORD=새비번`으로 켜도 **예전 비밀번호가 그대로**예요. 예전 비밀번호로 접속하거나, 정말 새로 시작하려면 볼륨을 지우고 켜요. 볼륨을 지우면 데이터도 사라진다는 걸 잊지 마세요.

</TwistBox>

## 16. Compose로 DB와 Redis 함께 켜기

10절에서 배운 Compose로 PostgreSQL과 Redis를 함께 켜요. 15절의 `pg-lab` 폴더에서 나와 새 실습 폴더를 만들어요.

```bash
cd ..
mkdir compose-lab
cd compose-lab
```

`cd ..`는 한 단계 위 폴더로, `mkdir`는 폴더 만들기(make directory)예요. `compose-lab` 폴더에 `compose.yaml`을 만들어요.

```yaml
services:
  db:
    image: postgres:18
    container_name: lab-pg
    environment:
      POSTGRES_PASSWORD: 1234
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql
  cache:
    image: redis
    container_name: lab-redis
    ports:
      - "6379:6379"
volumes:
  pgdata:
    external: true
```

`external: true`는 "Compose가 새로 만들지 말고 15절에서 만든 **기존 `pgdata` 볼륨**을 그대로 써라"라는 뜻이에요. 이 줄이 없으면 Compose는 `compose-lab_pgdata`처럼 폴더 이름이 붙은 **새 볼륨**을 만들어요. 그러면 상품 5개가 안 보여요.

### 검사하고 켜기

```bash
docker compose config
```

YAML에 틀린 곳이 있으면 여기서 알려 줘요. 문제가 없으면 최종으로 적용될 설정을 찍어 줘요(config: configuration). 하지 않아도 되는 단계예요.

```bash
docker compose up -d
docker compose ps
docker compose logs db
```

`docker run` 두 번 대신 명령 한 줄로 PostgreSQL과 Redis가 함께 켜져요.

### 들어가 보기

Compose에서는 컨테이너 이름 대신 **서비스 이름**(`db`, `cache`)으로 들어가요.

```bash
docker compose exec db psql -U postgres -c "SELECT * FROM product;"
```

`docker compose exec`는 기본으로 터미널이 붙어 있어서 `-it`를 안 써도 돼요. 15절에서 가져온 상품 5개가 그대로 보여요. Compose로 띄운 새 컨테이너도 같은 볼륨을 쓰기 때문이에요.

```bash
docker compose exec cache redis-cli PING
```

같은 Compose 프로젝트 안의 서비스는 **서비스 이름이 곧 주소**(호스트 이름)예요. Redis 컨테이너에서 `db`라는 이름으로 PostgreSQL을 찾을 수 있는지 봐요.

```bash
docker compose exec cache getent hosts db
```

`getent hosts`는 호스트 이름을 IP로 바꿔 보여 줘요(get entries). `db`의 IP가 나오면 서로 이름으로 찾을 수 있다는 뜻이에요. 11절의 `proxy_pass http://menu/`가 동작하는 이유가 바로 이거예요.

### 내리기

```bash
docker compose down
docker compose ps
docker volume ls
```

`down`은 컨테이너와 네트워크를 지우지만 **볼륨은 남겨요.** 다시 `docker compose up -d`를 하면 데이터가 그대로 이어져요.

| 명령 | 설명 |
| --- | --- |
| `docker compose up -d` | 서비스 만들기 + 뒤에서 켜기(`--detach`) |
| `docker compose ps` | 서비스 상태(process status) |
| `docker compose logs [서비스]` | 로그(`-f`는 실시간, `--follow`) |
| `docker compose exec 서비스 명령` | 서비스 컨테이너에 들어가기(execute) |
| `docker compose stop` / `start` | 정지 / 다시 시작 |
| `docker compose down` | 컨테이너 + 네트워크 삭제(볼륨은 남김) |
| `docker compose down -v` | 볼륨까지 삭제(`--volumes`). 단, `external` 볼륨은 안 지워요 |

## 17. MySQL과 PostgreSQL 한눈에

둘 다 같은 일을 하는 데이터베이스인데 명령이 조금씩 달라요.

| | MySQL | PostgreSQL |
| --- | --- | --- |
| 이미지, 포트 | `mysql:8.4`, 3306 | `postgres:18`, 5432 |
| 관리자, 비밀번호 `-e` | `root`, `MYSQL_ROOT_PASSWORD` | `postgres`, `POSTGRES_PASSWORD` |
| 들어가기 | `mysql -u root -p` | `psql -U postgres`(컨테이너 안에서는 비밀번호를 안 물어요) |
| DB 목록, 옮기기 | `SHOW DATABASES;`, `USE shop;` | `\l`, `\c shop` |
| 표 목록, 표 모양 | `SHOW TABLES;`, `DESCRIBE orders;` | `\dt`, `\d orders` |
| 나가기 | `exit` | `\q` |
| 볼륨 자리 | `/var/lib/mysql` | `/var/lib/postgresql`(18부터) |
| 자동 번호 | `AUTO_INCREMENT` | `SERIAL` |
| 앱 계정 `-e` | `MYSQL_USER`: 일반 계정을 **하나 더** 만들어요 | `POSTGRES_USER`: 관리자 **이름이 바뀌어요** |

마지막 줄이 헷갈려요. `MYSQL_USER=app`은 root 말고 `app` 계정을 하나 더 만들어요. `POSTGRES_USER=app`은 계정을 더 만드는 게 아니라 관리자 이름 자체가 `postgres`에서 `app`으로 바뀌어요. 그때는 `psql -U app`으로 들어가야 해요.

`docker compose` 명령은 `compose.yaml`이 있는 `compose-lab` 폴더에서 쳐야 해요.

```bash
docker compose down

docker ps -a

```

이미지까지 지우려면 이름을 여러 개 이어 써요.

```bash
docker rmi ubuntu:24.04 nginx mysql:8.4 redis postgres:18
```

`docker system prune -a --volumes`는 안 쓰는 컨테이너, 이미지, 볼륨을 **모두** 지워요. 다른 프로젝트의 데이터도 사라질 수 있으니 조심해요(`-a`: `--all`).

## 19. 자주 나는 오류

| 메시지 | 원인 | 해결 |
| --- | --- | --- |
| `failed to connect to the docker API` | Docker Desktop 엔진이 꺼져 있어요 | Docker Desktop을 열고 Engine running을 기다려요 |
| `The container name "/web" is already in use` | 같은 이름의 컨테이너가 남아 있어요(꺼져 있어도) | `docker ps -a`로 보고 `docker rm`(켜져 있으면 `docker rm -f`) |
| `port is already allocated` | 그 호스트 포트를 다른 컨테이너나 프로그램이 써요 | `docker ps`로 보고 정리하거나 `-p 8081:80`처럼 바꿔요 |
| `container is running: stop the container before removing` | 켜진 컨테이너를 `rm`했어요 | `docker stop` 뒤 `docker rm` |
| `E: Unable to locate package ...` | 컨테이너 안에서 `apt update`를 안 했어요 | `apt update`부터 |
| `bash: executable file not found` | 셸(bash)이 없는 이미지예요(alpine 등) | `sh`를 써요 |
| Git Bash에서 경로 앞에 `C:/Program Files/Git`이 붙어요 | Git Bash가 `/usr/...` 경로를 바꿔요 | `export MSYS_NO_PATHCONV=1` |
| `502 Bad Gateway` | `proxy_pass`에 `localhost`를 적었어요 | 서비스 이름(`http://menu/`)으로 |
| MySQL/PostgreSQL 컨테이너가 바로 꺼져요 | 꼭 필요한 환경 변수(`MYSQL_ROOT_PASSWORD`, `POSTGRES_PASSWORD`)가 없어요 | `docker logs`로 확인하고 `-e`로 줘요 |
| MySQL 접속 때 `Can't connect` | 아직 처음 준비 중이에요 | `docker logs -f`로 `ready for connections`를 보고 다시 |
| 새 비밀번호로 켰는데 접속 거부 | 볼륨에 예전 데이터가 남아 `-e`를 안 읽어요 | 예전 비밀번호로. 새로 하려면 볼륨 삭제 |
| PostgreSQL 18 컨테이너가 안 켜지거나 데이터가 안 남아요 | 볼륨 경로가 예전 것이에요 | `/var/lib/postgresql`로 이어요 |
| SQL 가져올 때 `No such file` / `could not find` | 다른 폴더에서 쳤거나 `docker cp` 경로가 틀렸어요 | `pg-lab` 폴더에서 쳤는지, 경로가 맞는지 확인 |
| 가져온 한글이 깨져요 | 파일이 UTF-8이 아니거나 PowerShell 파이프로 넘겼어요 | UTF-8로 저장하고 `docker cp` 방식을 써요 |
| 프롬프트가 `->` 또는 `-#` | SQL 끝의 `;`가 빠졌어요 | `;`만 치고 Enter |
| `external volume "pgdata" not found` | 15절의 볼륨이 없어요 | `docker volume create pgdata` |

## 오늘 꼭 기억할 주의점

- **이미지는 틀, 컨테이너는 붕어빵, 볼륨은 보관함.** `docker run`은 칠 때마다 새 컨테이너를 만들어요.
- **꺼진 컨테이너는 `docker ps -a`에만** 보여요. 이름이 남아 있으면 같은 이름으로 못 만들어요.
- **`-p 바깥:안`.** 왼쪽이 내 PC, 오른쪽이 컨테이너예요. 호스트 포트는 겹치면 안 되고, 포트는 만들 때만 정할 수 있어요.
- **컨테이너를 지우면 안의 파일도 사라져요.** 남길 것은 `-v 이름:경로`(볼륨)나 `-v ./폴더:경로`(내 폴더)에 둬요. `./`를 빼면 엉뚱한 볼륨이 생겨요.
- **지우는 순서는 컨테이너 먼저, 이미지는 나중.** 켜진 컨테이너는 `stop` 뒤 `rm`, 또는 `rm -f`.
- **Dockerfile은 build 때 코드를 복사해요.** 코드를 고치면 build부터 다시 하고, `.dockerignore`로 `.venv`, `__pycache__`, `.git`을 빼요.
- **`compose down`은 볼륨을 남기고, `down -v`는 지워요.** `external` 볼륨은 `down -v`로도 안 지워져요.
- **컨테이너 안의 localhost는 그 컨테이너 자신.** 다른 서비스는 서비스 이름으로 불러요. nginx 설정을 고치면 `nginx -t` 뒤 `nginx -s reload`.
- **SQL은 `;`로 끝, 글자는 작은따옴표, 같다는 `=` 하나.** 기본 키는 겹칠 수도 비울 수도 없어요.
- **DB 비밀번호 `-e`는 처음 한 번만 읽어요.** 볼륨이 남아 있으면 예전 비밀번호 그대로예요.
- **PostgreSQL 18의 볼륨 경로는 `/var/lib/postgresql`.** 예전 자료의 `/data`를 그대로 따라 하지 않아요.
