어제는 생활체육센터 DB에 표를 만들고 행을 한두 개씩 손으로 넣었어요. 그런데 회원이 두 명뿐이면 "마포구 회원만", "이메일이 없는 회원만" 같은 조회를 해 봐도 결과가 늘 시시해요.

그래서 먼저 **시드 파일**로 연습용 데이터를 한 번에 채워요. 그다음 `SELECT`로 보고 싶은 열만, `WHERE`로 보고 싶은 행만 꺼내요. 오늘의 한 줄은 이거예요. **`SELECT`는 세로(열)를 고르고, `WHERE`는 가로(행)를 고른다.**

수업 정리와 교안 2장 1강을 함께 따라가요. 레슨 끝에 확인 퀴즈가 있고, 문항을 모두 풀면 [수업 복습](/class) 목록에 완료로 표시돼요.

**시드(seed) 파일**은 표를 처음 상태로 되돌리고 연습용 데이터를 채우는 SQL 파일이에요. 씨앗을 심듯 "처음 데이터"를 심는다는 뜻이에요. 몇 번을 실행해도 같은 상태로 돌아오니, 실습하다 데이터가 꼬여도 다시 돌리면 돼요.

## 2. 돈 칸은 `NUMERIC`, 음수는 `CHECK`가 막는다

어제 만든 수강 신청 표 `enrollments`를 다시 볼게요. 오늘 정리에서 새로 짚은 건 맨 아래 두 줄이에요.

```sql
-- 수강 신청 테이블
CREATE TABLE enrollments
(
    member_id     INT            NOT NULL REFERENCES members (member_id),
    course_id     INT            NOT NULL REFERENCES courses (course_id),
    enroll_month  CHAR(7)        NOT NULL,
    status        VARCHAR(10)    NOT NULL,
    pay_amount    NUMERIC(10,2)  NOT NULL CHECK (pay_amount >= 0),
    PRIMARY KEY (member_id, course_id, enroll_month)
);
```

`enrollments` 한 행은 **누가, 어떤 강좌를, 몇 월에** 들었는지예요. 회원과 강좌는 N:M이라 어느 한쪽 표에 외래 키를 두면 한 칸에 값이 여러 개 들어가야 해요. 그래서 가운데 표를 두고, 세 값을 합친 복합 기본 키로 같은 조합이 두 번 들어오는 것만 막아요.

```sql
INSERT INTO enrollments VALUES (1, 1, '2026-11', '수료', 50000);
INSERT INTO enrollments VALUES (2, 2, '2026-10', '수료', 70000);
INSERT INTO enrollments VALUES (2, 2, '2026-10', '수료', 90000);   -- 금액만 다르고 세 값이 같음
```

```text
ERROR:  duplicate key value violates unique constraint "enrollments_pkey"
DETAIL:  Key (member_id, course_id, enroll_month)=(2, 2, 2026-10) already exists.
```

금액이 달라도 회원, 강좌, 월 세 값이 같으면 같은 신청으로 봐요. 셋 중 하나라도 다르면(예: 11월) 들어가요.

### `NUMERIC(10,2)`: 전체 10자리 중 소수 2자리

`NUMERIC(10,2)`는 숫자를 **글자 그대로 정확하게** 저장해요. 앞의 10은 전체 자릿수, 뒤의 2는 그중 소수점 아래 자릿수예요. 그래서 정수 부분은 8자리(99,999,999)까지 담을 수 있어요.

  <Boxes

왜 금액에 `NUMERIC`을 쓸까요? 실수 타입(`float`)은 컴퓨터 안에서 2진수 근삿값으로 저장돼요. PostgreSQL에서 직접 더해 보면 차이가 보여요.

```sql
SELECT 0.1::float8 + 0.2::float8 AS f, 0.1::numeric + 0.2::numeric AS n;
```

```text
          f          |  n
---------------------+-----
 0.30000000000000004 | 0.3
(1 row)
```

`::`는 값을 그 타입으로 바꾸라는 표시예요. 돈 계산에서 0.00000000000000004원이 쌓이면 곤란하니 금액은 `NUMERIC`에 담아요.

### `CHECK`: 조건이 거짓인 값은 문 앞에서 돌려보낸다

`CHECK (pay_amount >= 0)`은 "이 조건이 참인 값만 받는다"는 규칙이에요. 음수를 넣어 보면 막혀요.

```sql
INSERT INTO enrollments VALUES (1, 2, '2026-11', '수강중', -1000);
```

```text
ERROR:  new row for relation "enrollments" violates check constraint "enrollments_pay_amount_check"
DETAIL:  Failing row contains (1, 2, 2026-11, 수강중, -1000.00).
```

제약 조건은 표 앞에 선 문지기 여럿이라고 보면 쉬워요. `INSERT`로 들어오는 행은 문지기를 차례로 지나야 하고, 한 명에게라도 걸리면 행은 한 칸도 들어가지 않아요. 어제 본 기본 키, 외래 키 문지기에 오늘 `CHECK`가 더해졌어요.

<Figure label="enrollments 앞의 문지기들 (먼저 확인하는 순서, PostgreSQL에서 직접 확인)">
  <GateFlow
    gates={[
      { q: "비어 있는 필수 칸이 있나?", code: "NOT NULL", out: "`violates not-null constraint`" },
      { q: "`CHECK` 조건이 거짓인가?", code: "CHECK (pay_amount >= 0)", out: "`violates check constraint`" },
      { q: "같은 (회원, 강좌, 월)이 이미 있나?", code: "PRIMARY KEY (member_id, course_id, enroll_month)", out: "`duplicate key value`" },
      { q: "없는 회원이나 강좌를 가리키나?", code: "REFERENCES", out: "`violates foreign key constraint`" },
    ]}
    pass={{ text: "통과: 행이 들어가요", code: "INSERT 0 1" }}
  />
</Figure>

규칙을 둘 이상 어기면 먼저 확인하는 문지기 하나만 알려 줘요. 예를 들어 없는 회원 99번으로 음수 금액을 넣으면 외래 키가 아니라 `CHECK` 오류가 나와요.

`CHECK`에 따로 이름을 안 붙이면 PostgreSQL이 **표\_열\_check**로 지어요. 어제 본 `_pkey`, `_key`, `_fkey`와 같은 규칙이에요. 이름을 직접 붙이고 싶으면 `CONSTRAINT 이름`을 앞에 써요.

```sql
pay_amount NUMERIC(10,2) CONSTRAINT amount_not_negative CHECK (pay_amount >= 0)
```

그러면 오류에도 `violates check constraint "amount_not_negative"`처럼 내가 지은 이름이 나와요.

<Hint>
`CHECK`와 `UNIQUE`는 **NULL을 막지 않아요.** NULL은 "모르는 값"이라 조건이 거짓이라고도, 겹친다고도 판단하지 않거든요. 별점 열에 `CHECK (rating BETWEEN 1 AND 5)`만 걸고 `NULL`을 두 번 넣어 보면 두 행 다 들어가요. 빈 값도 막으려면 `NOT NULL`을 같이 붙여요. 그래서 `pay_amount`에는 `NOT NULL`과 `CHECK`가 둘 다 있어요.
</Hint>

## 3. 강사 표는 `DROP TABLE IF EXISTS`로 깨끗하게 다시 만든다

정리 파일에서는 강사 표를 만들기 전에 이 줄을 먼저 썼어요.

```sql
DROP TABLE IF EXISTS instructors;
CREATE TABLE instructors
(
    instructor_id  SERIAL       PRIMARY KEY,
    name           VARCHAR(20)  NOT NULL,
    sport_id       INT          NOT NULL REFERENCES sports (sport_id),
    phone          VARCHAR(20),
    hire_date      DATE         NOT NULL
);

INSERT INTO instructors (name, sport_id, phone, hire_date)
VALUES
('홍길동', 1, '010-1234-1234', '2025-01-01'),
('손흥민', 2, '010-1234-8080', '2025-01-10');
```

`VALUES` 뒤에 괄호를 쉼표로 이어 쓰면 `INSERT` 한 번에 여러 행이 들어가요. 번호 `instructor_id`는 `SERIAL`이 채우니 열 목록에서 뺐어요.

그냥 `DROP TABLE instructors`는 표가 없으면 `ERROR:  table "instructors" does not exist`로 멈춰요. `IF EXISTS`를 붙이면 **있으면 지우고, 없으면 오류 없이 넘어가요.** 없을 때는 `NOTICE:  table "instructors" does not exist, skipping`이라는 알림만 남겨요. 같은 파일을 몇 번이고 다시 실행할 수 있게 해 주는 장치예요.

다만 다른 표가 가리키는 표는 `IF EXISTS`를 붙여도 못 지워요.

```text
ERROR:  cannot drop table sports because other objects depend on it
DETAIL:  constraint courses_sport_id_fkey on table courses depends on table sports
HINT:  Use DROP ... CASCADE to drop the dependent objects too.
```

`IF EXISTS`는 "없을 때"만 봐 주는 거라, 강좌가 가리키는 `sports`는 여전히 지킬 대상이에요. 그래서 표는 **가리키는 쪽(자식)부터** 지워요.

그다음 이미 있는 강좌 표에 강사 번호 열을 붙였어요.

```sql
ALTER TABLE courses
ADD COLUMN instructor_id INT REFERENCES instructors (instructor_id);
```

`ALTER TABLE ... ADD COLUMN`은 데이터는 그대로 두고 열만 더해요. 이미 있던 강좌 행의 새 칸에는 **NULL**이 들어가요. 강사가 아직 없는 강좌를 NULL로 둘 수 있게 `NOT NULL`을 일부러 안 붙였어요.

## 4. 컨테이너 안의 psql은 내 Mac의 파일을 못 본다

시드 파일 `sportscenter_seed.sql`을 받으면 `docker-compose.yml`이 있는 실습 폴더에 넣어요.

```text
SportsCenter/
    docker-compose.yml
    sportscenter_seed.sql     ← 받은 파일
```

여기서 함정이 하나 있어요. psql은 **컨테이너 안에서** 돌아요. 컨테이너는 내 Mac과 따로 떨어진 작은 컴퓨터라서, 내 폴더에 있는 파일을 psql이 바로 열 수 없어요. 그래서 파일을 먼저 컨테이너 안으로 복사해요.

<Figure>
  <Boxes
    row={[
      { title: "내 Mac", tone: "neutral", lines: ["`SportsCenter/`", "`sportscenter_seed.sql`"] },
      { arrow: "cp" },
      { title: "컨테이너 db", tone: "blue", lines: ["`/tmp/sportscenter_seed.sql`", "`/tmp`는 임시 폴더"] },
      { arrow: "\\i" },
      { title: "psql", tone: "rust", lines: ["파일 안 SQL을", "위에서부터 차례로 실행"] },
    ]}
  />
</Figure>

```bash
docker compose up -d
docker compose cp sportscenter_seed.sql db:/tmp/sportscenter_seed.sql
```

`docker compose cp`의 모양은 `cp 보낼파일 서비스이름:받을경로`예요. 서비스 이름 `db`는 `docker-compose.yml`의 `services:` 아래 이름이에요. 아무 말 없이 끝나면 복사가 된 거예요.

그다음 psql에 들어가서 psql 명령 `\i`(include)로 파일을 실행해요.

```bash
docker compose exec db psql -U postgres
```

```sql
\i /tmp/sportscenter_seed.sql
```

<Hint>
지금 어느 터미널에 있는지는 줄 맨 앞(프롬프트)으로 알아요. Mac 터미널은 줄이 `%`로 끝나고, psql 안에서는 `postgres=#`나 `sportscenter=#`이에요. `docker compose ...`는 `%`에서, `\i`와 SQL은 `=#`에서 쳐요. psql에서 Mac 터미널로 나올 때는 `\q`예요. 손에 익을 때까지 명령을 치기 전에 프롬프트부터 보는 습관을 들이면 덜 헷갈려요.
</Hint>

SQL 파일을 psql에 넣는 방법은 `docker compose cp` 뒤 `\i`와, `exec -i`에 `<`로 흘려 넣는 것 두 가지가 있어요. 오늘은 `cp`를 썼어요. 파일을 컨테이너에 남겨 두니 `\i`로 몇 번이고 다시 돌릴 수 있어요.

## 5. 시드는 DB를 처음 상태로 되돌린다: 다시 짓거나, 비우거나

처음 상태로 되돌리는 방법은 두 가지예요. 수업에서 받은 시드는 DB를 통째로 다시 지었고, 교안의 시드는 표를 비우고 다시 채워요.

<Figure>
  <Boxes
    row={[
      { title: "수업 시드: 통째로 다시 짓기", tone: "rust", lines: ["`DROP DATABASE sportscenter`", "`CREATE DATABASE sportscenter`", "`\\c sportscenter`", "표 6개 `CREATE` → `INSERT`", "접속: `psql -U postgres`"] },
      { title: "교안 시드: 비우고 다시 채우기", tone: "blue", lines: ["`TRUNCATE ... RESTART IDENTITY`", "`INSERT` 6번", "표 구조는 그대로 둬요", "접속: `psql -U postgres -d sportscenter`"] },
    ]}
  />
</Figure>

### 통째로 다시 짓는 시드는 `postgres` DB에서 돌린다

수업 시드는 `sportscenter`를 지우는 것부터 시작해요. 그런데 **지금 접속해 있는 DB는 지울 수 없어요.** 내가 앉아 있는 방을 통째로 철거할 수는 없는 것과 같아요.

```text
ERROR:  cannot drop the currently open database
```

`-d sportscenter`로 들어가서 돌리면 이 오류가 나요. 그래서 기본 DB `postgres`로 들어가(`-d` 없이) 실행하고, 시드 안의 `\c sportscenter`가 새로 지은 DB로 옮겨 줘요.

### 비우는 시드는 `TRUNCATE`로 행만 지운다

교안 시드를 `sportscenter` 안에서 돌리면 이렇게 나와요.

```text
TRUNCATE TABLE
INSERT 0 4
INSERT 0 8
INSERT 0 14
INSERT 0 60
INSERT 0 18
INSERT 0 200
```

`INSERT 0 4`의 4가 넣은 행 수예요. 종목 4, 강사 8, 강좌 14, 회원 60, 사물함 18, 수강 기록 200건이에요. 어제 손으로 넣은 김하늘, 이준호는 지워지고, 같은 사람이 시드의 1번, 2번 행으로 다시 들어가요.

행을 모두 지우는 방법은 셋이고, 다음 번호가 달라요(엔진에서 확인).

| 명령 | 지우는 것 | 다음 번호 |
| --- | --- | --- |
| `DELETE FROM 표;` | 행을 하나씩 (`WHERE`로 고를 수 있어요) | 이어서 |
| `TRUNCATE 표;` | 표 안을 통째로 | 이어서 |
| `TRUNCATE 표 RESTART IDENTITY;` | 표 안을 통째로 | 1부터 다시 |

`TRUNCATE`도 외래 키를 지켜요. 누가 가리키는 표만 비우려 하면 막혀요.

```text
ERROR:  cannot truncate a table referenced in a foreign key constraint
DETAIL:  Table "enrollments" references "members".
HINT:  Truncate table "enrollments" at the same time, or use TRUNCATE ... CASCADE.
```

그래서 이어진 표를 **한 줄에 같이** 적어요. 적는 순서는 상관없어요.

```sql
TRUNCATE enrollments, lockers, courses, instructors, sports, members RESTART IDENTITY;
```

## 6. `SELECT`는 열을, `WHERE`는 행을 고른다

데이터가 찼으니 먼저 작은 표부터 통째로 봐요. `*`는 "모든 열"이에요.

```sql
SELECT * FROM sports;
SELECT * FROM instructors;
```

## 7. `AS`는 결과 열의 이름표, 계산식도 열이 된다

`AS`는 결과에 나오는 열 이름을 바꿔요. 표의 열 이름은 그대로고, 이번 결과에서만 붙는 이름표(별칭)예요. 열 자리에 계산식을 써도 돼요.

```sql
SELECT course_name AS 강좌명,
       fee         AS 수강료,
       fee * 3     AS "3개월 수강료"
FROM courses
LIMIT 5;
```

```text
      강좌명      | 수강료 | 3개월 수강료
------------------+--------+--------------
 수영 초급 새벽반 |  70000 |       210000
 헬스 자유이용    |  50000 |       150000
 수영 중급 저녁반 |  75000 |       225000
 수영 상급 저녁반 |  80000 |       240000
 아쿠아로빅       |  65000 |       195000
(5 rows)
```

별칭에 띄어쓰기가 있으면 **큰따옴표**로 감싸요. 감싸지 않은 `AS 회원 이름`은 `syntax error at or near "이름"`이 나요. `강좌명`처럼 한 단어면 그대로 써도 돼요.

오늘 정리에는 행 수를 세는 `COUNT(*)`도 한 번 나왔어요. 자세한 집계는 다음 강의(2강)에서 배워요.

```sql
SELECT COUNT(*) AS "이메일 미기재" FROM members WHERE email IS NULL;
```

```text
 이메일 미기재
---------------
            15
(1 row)
```

## 9. `WHERE`의 글자는 작은따옴표, 큰따옴표는 열 이름

```sql
SELECT member_id, name, gender, birth_year
FROM members
WHERE region = '용산구';
```

```text
 member_id |  name  | gender | birth_year
-----------+--------+--------+------------
         7 | 조수아 | F      |       1999
        12 | 강지훈 | M      |       1978
        17 | 신성민 | M      |       2007
        23 | 류민재 | M      |       1968
        24 | 오은찬 | M      |       1978
        28 | 조동현 | M      |       1974
        29 | 권서현 | F      |       1955
(7 rows)
```

같은 조건을 마포구로 바꾸면 17행이에요. 작은따옴표 대신 큰따옴표로 쓰면 오류가 나요.

```sql
SELECT name FROM members WHERE region = "용산구";
```

```text
ERROR:  column "용산구" does not exist
LINE 1: SELECT name FROM members WHERE region = "용산구";
                                                ^
```

SQL에서 **큰따옴표는 열 이름**이에요. 그래서 PostgreSQL은 `용산구`라는 열을 찾다가 없다고 해요. 글자와 날짜 값은 작은따옴표, 띄어쓰기 있는 별칭은 큰따옴표라고 나눠 기억해요.

숫자, 날짜, 시각은 비교 연산자 `=`, `<>`(같지 않다), `<`, `<=`, `>`, `>=`로 비교해요. 수강료가 10만 원 이상인 강좌예요.

```sql
SELECT course_name, fee
FROM courses
WHERE fee >= 100000;
```

```text
  course_name   |  fee
----------------+--------
 헬스 PT 그룹반 | 150000
 골프 입문반    | 120000
 골프 중급반    | 130000
(3 rows)
```

## 10. 빈 칸은 `=`로 못 찾는다, `IS NULL`로 찾는다

이메일이 없는 회원을 찾아 연락 수단을 점검해 봐요.

```sql
SELECT member_id, name, phone
FROM members
WHERE email IS NULL
LIMIT 5;
```

```text
 member_id |  name  |     phone
-----------+--------+---------------
         2 | 이준호 | 010-2345-6789
         5 | 정유진 | 010-5678-9012
        13 | 서승현 | 010-3849-3947
        15 | 황은지 | 010-6197-8541
        18 | 최준서 | 010-5544-2914
(5 rows)
```

`= NULL`로 쓰면 어떻게 될까요?

```sql
SELECT member_id, name FROM members WHERE email = NULL;
```

```text
 member_id | name
-----------+------
(0 rows)
```

오류는 아닌데 **0행**이에요. 직접 세어 보면 `email = NULL`은 0건, `email IS NULL`은 15건이었어요.

NULL은 "값이 0"이나 "빈 글자"가 아니라 "**모르는 값**"이에요. 모르는 값이 무엇과 같은지 물으면 답도 "모른다"가 되고, `WHERE`는 참인 행만 남기니 아무것도 남지 않아요. 그래서 빈 칸은 `IS NULL`, 값이 있는 칸은 `IS NOT NULL`로 물어요.

## 11. 범위는 `BETWEEN`, 목록은 `IN`, 모양은 `LIKE`

| 연산자 | 뜻 | 예 |
| --- | --- | --- |
| `BETWEEN a AND b` | a 이상 b 이하 (양 끝 포함) | `birth_year BETWEEN 1995 AND 2000` |
| `IN (...)` | 목록 중 하나와 정확히 같음 | `course_id IN (1, 5, 10)` |
| `LIKE` | 모양(패턴)에 맞음. `%`는 0글자 이상, `_`는 정확히 1글자 | `name LIKE '김%'` |

수업에서 직접 돌린 결과예요.

```sql
SELECT member_id, name, birth_year, region
FROM members WHERE birth_year BETWEEN 1995 AND 2000;
```

```text
 member_id |  name  | birth_year |  region
-----------+--------+------------+----------
         1 | 김하늘 |       1995 | 마포구
         7 | 조수아 |       1999 | 용산구
        16 | 권유나 |       1998 | 은평구
        35 | 서가은 |       1997 | 서대문구
        43 | 조하은 |       1997 | 서대문구
        45 | 오서현 |       1997 | 서대문구
        53 | 권은지 |       1998 | 은평구
(7 rows)
```

1995년생 김하늘이 들어온 게 양 끝 포함이라는 증거예요. `BETWEEN 2000 AND 1995`처럼 큰 값을 앞에 쓰면 0행이니, 작은 값을 앞에 써요.

```sql
SELECT course_id, course_name, instructor_id
FROM courses WHERE course_id IN (1, 5, 10);
```

```text
 course_id |    course_name     | instructor_id
-----------+--------------------+---------------
         1 | 수영 초급 새벽반   |             1
         5 | 아쿠아로빅         |             1
        10 | 골프 타석 자유이용 |
(3 rows)
```

10번 강좌의 강사 칸이 빈 게 보여요. 3절의 `ALTER TABLE`로 붙인 열에서 강사가 아직 없는 강좌예요.

```sql
SELECT member_id, name, birth_year, region
FROM members WHERE name LIKE '김%';
```

```text
 member_id |  name  | birth_year | region
-----------+--------+------------+--------
         1 | 김하늘 |       1995 | 마포구
         9 | 김정우 |       1981 | 은평구
(2 rows)
```

교안에서는 `LIKE '%자유이용'`으로 "자유이용"으로 끝나는 강좌(헬스 자유이용, 골프 타석 자유이용)를 찾았어요. `%`를 어디에 두느냐로 "시작", "끝", "포함"이 갈려요.

`IN`과 `LIKE`는 헷갈리기 쉬워요. `IN`은 패턴을 모르고 **글자 그대로** 같은지만 봐요. 그래서 `region IN ('%구')`는 이름이 정말로 `%구`인 동네를 찾다가 0행이 나와요.

## 13. `CASE WHEN`은 위에서부터 처음 맞는 값을 고른다

체육관은 65세 이상(2026년 기준 1961년 이전 출생) 회원에게 경로 할인을 줘요. `CASE WHEN`으로 조건에 따라 값이 바뀌는 새 열을 만들어요.

```sql
SELECT name, birth_year,
       CASE WHEN birth_year <= 1961 THEN '경로'
            WHEN birth_year >= 2000 THEN '청년'
            ELSE '일반'
       END AS 요금구분
FROM members
LIMIT 7;
```

```text
  name  | birth_year | 요금구분
--------+------------+----------
 김하늘 |       1995 | 일반
 이준호 |       1988 | 일반
 박서윤 |       1972 | 일반
 최민준 |       2001 | 청년
 정유진 |       1960 | 경로
 강도윤 |       1983 | 일반
 조수아 |       1999 | 일반
(7 rows)
```

파이썬의 `if`, `elif`, `else`와 같아요. 위에서부터 조건을 보다가 **처음 참인 곳**의 값을 쓰고 나머지는 보지 않아요. 아무것도 안 맞으면 `ELSE` 값이고, `ELSE`가 없으면 NULL이에요.

## 14. `ORDER BY`는 `SELECT` 다음에 돈다

`ORDER BY`는 결과를 정렬해요. 기본은 오름차순(`ASC`)이고, `DESC`를 붙이면 내림차순이에요.

```sql
SELECT course_name, fee
FROM courses
ORDER BY fee DESC, course_name
LIMIT 5;
```

```text
    course_name     |  fee
--------------------+--------
 헬스 PT 그룹반     | 150000
 골프 중급반        | 130000
 골프 입문반        | 120000
 골프 타석 자유이용 |  90000
 수영 마스터즈반    |  90000
(5 rows)
```

기준을 여러 개 쓰면 **앞의 기준이 같을 때만** 다음 기준을 봐요. 9만 원인 두 강좌는 이름 가나다순으로 섰어요. `DESC`는 바로 앞의 기준 하나에만 붙어요.

### 글자 정렬은 사전 순서다

```sql
SELECT course_name, level, fee
FROM courses
WHERE sport_id = 1
ORDER BY level, fee DESC;
```

```text
   course_name    | level |  fee
------------------+-------+-------
 수영 마스터즈반  | 상급  | 90000
 수영 상급 저녁반 | 상급  | 80000
 수영 중급 저녁반 | 중급  | 75000
 수영 초급 새벽반 | 초급  | 70000
 아쿠아로빅       | 초급  | 65000
(5 rows)
```

상급이 맨 위예요. 글자는 가나다순이라 `'상급' < '중급' < '초급'`이에요. 난이도 순서가 아니에요. 난이도 순으로 세우려면 15절 미션처럼 `CASE WHEN`으로 숫자를 만들어 그걸로 정렬해요.

### NULL은 가장 큰 값처럼 선다

```sql
SELECT name, email
FROM members
WHERE member_id <= 7
ORDER BY email DESC, name;
```

```text
  name  | email
--------+--------
 이준호 |
 정유진 |
 조수아 | sua
 박서윤 | seoyun
 최민준 | minjun
 김하늘 | haneul
 강도윤 | doyun
(7 rows)
```

이메일은 `@` 앞부분만 적었어요(순서는 같아요). PostgreSQL은 NULL을 **가장 큰 값처럼** 다뤄요. 그래서 `DESC`에서는 맨 앞, `ASC`에서는 맨 뒤에 와요.

### 별칭은 `ORDER BY`에서는 쓸 수 있다

어제 `SELECT`의 별칭을 `WHERE`에서 쓰면 오류가 났죠. `ORDER BY`에서는 돼요. 실행 순서가 다르기 때문이에요.

<Figure label="적는 순서가 아니라 실행 순서">
  <Trail values={["FROM", "WHERE", "SELECT (별칭이 생겨요)", "ORDER BY", "LIMIT"]} />
</Figure>

`WHERE`는 `SELECT`보다 먼저 돌아서 별칭을 몰라요. `ORDER BY`는 `SELECT` 다음이라 이미 생긴 별칭을 쓸 수 있어요. `LIMIT`은 정렬이 끝난 뒤에 앞에서부터 잘라요.

SELECT name, birth_year AS 출생 FROM members ORDER BY 출생 LIMIT 3;   -- 됨

## 오늘 꼭 기억할 주의점

- 금액은 정확한 `NUMERIC(전체, 소수)`에 담고, 말이 안 되는 값은 `CHECK`로 막아요. `CHECK`와 `UNIQUE`는 NULL을 통과시키니 `NOT NULL`을 같이 붙여요.
- 제약 이름은 `표_열_check`, `_pkey`, `_key`, `_fkey` 규칙으로 지어져요. 오류에서 이름과 `DETAIL:`을 읽어요.
- psql은 **컨테이너 안**에서 돌아요. 내 Mac의 파일은 `docker compose cp`로 넣고 `\i`로 실행해요.
- 지금 접속한 DB는 못 지워요. DB를 다시 짓는 시드는 `postgres`로 들어가 돌려요.
- `TRUNCATE ... RESTART IDENTITY`는 비우고 번호를 1부터 다시 세요. 이어진 표는 한 줄에 같이 적어요.
- **`SELECT`는 열, `WHERE`는 행**을 골라요. `DISTINCT`는 적은 열의 조합으로 겹침을 판단해요.
- 글자 값은 작은따옴표, 큰따옴표는 열 이름과 띄어쓰기 별칭이에요.
- 빈 칸은 `IS NULL`로 찾아요. `= NULL`은 오류 없이 0행이라 더 위험해요.
- `IN`은 글자 그대로, `LIKE`는 `%`와 `_`로 모양을 봐요. `BETWEEN`은 양 끝을 포함해요.
- `AND`가 `OR`보다 먼저 묶여요. 섞을 때는 괄호를 쳐요.
- `CASE WHEN`은 처음 맞는 줄에서 멈춰요. 좁은 조건을 위에 둬요.
- `ORDER BY`는 `SELECT` 다음에 돌아서 별칭을 쓸 수 있어요. 글자는 사전 순, NULL은 가장 큰 값처럼 서요.
