## 1. 클래스(Class)와 인스턴스(Instance)

클래스는 **붕어빵 틀**, 인스턴스는 그 틀로 찍어 낸 **붕어빵**이에요. 틀은 하나여도 붕어빵은 몇 개든 만들 수 있고, 붕어빵마다 속 재료가 달라도 돼요.

```python
# 클래스 정의(선언)
class User:
    def __init__(self, name):  # 생성자: 인스턴스가 처음 만들어질 때 자동으로 호출
        self.name = name       # 인스턴스 안의 변수를 초기화

    def show(self):            # 메서드(Method)
        return f"회원 이름 : {self.name}"

# 인스턴스 생성: 붕어빵 만들기
user_a = User("손흥민")
user_b = User("이강인")

# 인스턴스 변수
print(user_a.name)
print(user_b.name)

# 메서드 호출
print(user_a.show())
print(user_b.show())

print(type(user_a))
print(user_a is user_b)
print(id(user_a))
print(id(user_b))
```

```text
손흥민
이강인
회원 이름 : 손흥민
회원 이름 : 이강인
<class '__main__.User'>
False
(id 값)
(위와 다른 id 값)
```

| 비유 | 파이썬 |
| --- | --- |
| 붕어빵 틀 | 클래스 `User` (설계도) |
| 붕어빵 | 인스턴스 `user_a`, `user_b` |
| 틀에 넣는 속 재료 | `User("손흥민")`에서 넘기는 값 |

- `class User:`로 클래스를 선언해요. 콜론과 들여쓰기가 범위인 건 어제 배운 `def`와 같아요.
- 클래스 이름은 단어 첫 글자를 대문자로 붙여 써요(`User`, `BankAccount`). 이런 표기를 **PascalCase**라고 해요. 함수와 변수의 snake_case와 일부러 다르게 써서 이름만 봐도 클래스인지 알 수 있어요.
- `User("손흥민")`처럼 클래스를 함수처럼 부르면 인스턴스가 하나 만들어져요.
- `user_a.name`, `user_a.show()`처럼 인스턴스 뒤에 점(`.`)을 붙여 안에 든 값과 메서드를 꺼내 써요.

### 같은 틀이어도 다른 붕어빵

`user_a is user_b`는 `False`예요. 같은 클래스로 만들었어도 서로 다른 객체예요. `id()`도 두 값이 달라요.

`id()`는 객체가 메모리 어디에 있는지 나타내는 번호예요. 실행할 때마다 숫자가 바뀌니 값 자체보다 **같은지 다른지**를 보면 돼요.

`type(user_a)`는 `<class '__main__.User'>`예요. `__main__`은 "지금 직접 실행한 파일"이라는 뜻이라, 이 파일에서 만든 `User` 클래스라는 말이에요.

## 2. 생성자 `__init__`

`__init__`은 **인스턴스가 만들어지는 순간 파이썬이 알아서 불러 주는 메서드**예요. 이런 메서드를 생성자(Constructor)라고 불러요. 이름 앞뒤에 밑줄이 두 개씩 붙어요.

```python
class User:
    def __init__(self, name):
        print("생성:", name)
        self.name = name

u = User("손흥민")
```

```text
생성: 손흥민
```

`__init__`을 직접 부르지 않았는데 출력이 나와요. `User("손흥민")`이 인스턴스를 만들면서 `__init__`을 불렀기 때문이에요.

- `User("손흥민")`에 넘긴 `"손흥민"`이 `__init__`의 `name`으로 들어가요.
- `self.name = name`은 받은 값을 **인스턴스 안에 담아 두는** 줄이에요. 이렇게 담아 둔 값을 인스턴스 변수(속성)라고 해요. 인스턴스마다 자기 `name`을 따로 가져요.
- 생성자가 받는 값을 빠뜨리면 인스턴스가 만들어지지 않아요.

```python
User()
# TypeError: User.__init__() missing 1 required positional argument: 'name'
```

어제 배운 함수의 매개변수 규칙이 그대로예요. 필요한 인수가 모자라면 `TypeError`가 나요.

## 3. `self`: 점 앞의 그 인스턴스

메서드의 첫 매개변수 `self`는 **지금 메서드를 부른 인스턴스 자기 자신**이에요. `monitor.display_info()`라고 부르면 점 앞의 `monitor`가 `self`로 들어가요.

```python
class Monitor:
    def display_info(self):  # self는 메서드를 부른 인스턴스(호출할 때 점 앞의 것)
        self.resolution = "1920X1080"
        self.size = "27인치"
        print(f"모니터 정보\n해상도: {self.resolution}\n크기: {self.size}\n객체 ID: {id(self)}")

monitor = Monitor()  # 인스턴스 생성
print(id(monitor))   # 인스턴스의 ID 출력

monitor.display_info()
```

```text
(id 값)
모니터 정보
해상도: 1920X1080
크기: 27인치
객체 ID: (위와 같은 id 값)
```

`id(monitor)`와 메서드 안의 `id(self)`가 같은 숫자예요. 이름만 다를 뿐 같은 객체라는 증거예요.

### 속성은 그 줄이 실행된 뒤에 생겨요

이 예제는 `__init__` 없이 메서드 안에서 속성을 만들어요. 그래서 `display_info()`를 부르기 전에는 속성이 아직 없어요.

```python
monitor = Monitor()
print(monitor.resolution)
# AttributeError: 'Monitor' object has no attribute 'resolution'
```

`self.resolution = ...` 줄이 실행돼야 비로소 `resolution`이 생겨요. 이 문제는 8절에서 생성자가 왜 필요한지 이야기할 때 다시 나와요.

<TwistBox title="메서드에 self를 빼먹으면 어떻게 될까요?">

```python
class Bad:
    def hi():
        return "hi"

Bad().hi()
# TypeError: Bad.hi() takes 0 positional arguments but 1 was given
```

괄호 안에 아무것도 안 넘겼는데 "1개를 받았다"고 해요.

`Bad().hi()`처럼 인스턴스로 메서드를 부르면 파이썬이 점 앞의 인스턴스를 **첫 번째 인수로 몰래 넘겨요**. 그런데 `hi()`는 매개변수가 하나도 없으니 받을 자리가 없어요. 그래서 메서드에는 늘 `self` 자리를 맨 앞에 만들어 둬요.

</TwistBox>

## 4. 속성(Attribute)과 메서드(Method)

```python
class SmartPhone:
    def __init__(self, model):
        self.model = model  # 속성(Attribute)
        self.battery = 50   # 속성

    def charge(self, amount):
        self.battery += amount
        if self.battery > 100:
            self.battery = 100
            print(f"배터리 충전 완료 : {self.battery}%")
        else:
            print(f"배터리 충전 중 ... : {self.battery}%")

phone_a = SmartPhone("아이폰")
print(phone_a.model)
phone_a.charge(30)
phone_a.charge(30)

phone_b = SmartPhone("갤럭시")
```

```text
아이폰
배터리 충전 중 ... : 80%
배터리 충전 완료 : 100%
```

| 이름 | 무엇 | 예 |
| --- | --- | --- |
| 속성 (attribute) | 인스턴스가 가진 데이터 | `self.model`, `self.battery` |
| 메서드 (method) | 인스턴스가 할 수 있는 동작 | `charge()` |

메서드는 **클래스 안에 만든 함수**예요. 어제 배운 `def`를 클래스 안에 들여 쓰고, 첫 매개변수로 `self`를 받는다는 점만 달라요.

- `self.battery = 50`: 인수로 받지 않은 속성도 만들 수 있어요. 모든 인스턴스가 `50`에서 시작해요.
- `charge(30)` 첫 번째: 50 + 30 = `80`이에요. 100을 넘지 않아 `else`로 가요.
- 두 번째: 80 + 30 = 110이라 100을 넘어요. 그래서 `100`으로 맞추고 "충전 완료"를 출력해요.
- 메서드가 `self.battery`를 바꾸면 그 인스턴스 안의 값이 바뀌어 다음 호출까지 남아 있어요. 함수 안의 지역 변수가 함수가 끝나면 사라지는 것과 달라요.

`phone_b`는 새 인스턴스라 배터리가 다시 `50`에서 시작해요. 직접 실행하면 `phone_a.battery`는 `100`, `phone_b.battery`는 `50`이에요. 붕어빵 하나를 베어 물어도 다른 붕어빵은 그대로인 것과 같아요.

## 5. 실습: 은행 계좌 클래스

```python
class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner      # 예금주
        self.balance = balance  # 잔액

    def __str__(self):
        return f"예금주 : {self.owner}, 잔액: {self.balance:,}원"

    def __repr__(self):
        return f"예금주 : {self.owner}, 잔액: {self.balance:,}원"

    # 입금 처리 메서드
    def deposit(self, amount):
        self.balance += amount
        print(f"{amount:,}원 입금 완료 / 잔액 : {self.balance:,}원")

    # 출금 처리 메서드
    # 잔액 확인 => 잔액 부족 메시지 출력
    def withdraw(self, amount):
        # Pseudo Code
        # 잔액 확인
        if self.balance < amount:
            print(f"출금 잔액이 부족합니다. 잔액 : {self.balance:,}원 || 출금 요청액 : {amount:,}원")
            return
        self.balance -= amount
        print(f"{amount:,}원 출금 완료")
        return self.balance  # 출금 후 잔액 리턴

account_a = BankAccount("김민지", 100000)
print(account_a)
account_a.deposit(500000)
account_a.withdraw(1000000)
print(f"잔액 : {account_a.withdraw(200000):,}원")
print(f"잔액 : {account_a.withdraw(300000):,}원")

account_c = BankAccount("홍길동", 200000)
print([account_a, account_c])
```

```text
예금주 : 김민지, 잔액: 100,000원
500,000원 입금 완료 / 잔액 : 600,000원
출금 잔액이 부족합니다. 잔액 : 600,000원 || 출금 요청액 : 1,000,000원
200,000원 출금 완료
잔액 : 400,000원
300,000원 출금 완료
잔액 : 100,000원
[예금주 : 김민지, 잔액: 100,000원, 예금주 : 홍길동, 잔액: 200,000원]
```

### 어떻게 흐르나

| 줄 | 동작 | 잔액 |
| --- | --- | --- |
| `BankAccount("김민지", 100000)` | 계좌 생성 | 100,000 |
| `deposit(500000)` | 입금 | 600,000 |
| `withdraw(1000000)` | 잔액 부족 메시지, `return`으로 끝남 | 600,000 |
| `withdraw(200000)` | 출금 | 400,000 |
| `withdraw(300000)` | 출금 | 100,000 |

- **먼저 막고 나가기:** `withdraw`는 잔액이 모자라면 메시지만 찍고 `return`으로 바로 끝나요. 아래 `self.balance -= amount`까지 가지 않으니 잔액은 그대로예요. 어제 나누기 전에 0인지 먼저 검사하고 `return`으로 내보낸 것과 같은 모양이에요.
- **Pseudo Code:** 코드를 치기 전에 "잔액 확인" 같은 할 일을 주석으로 먼저 적어 두는 것을 의사 코드(Pseudo Code)라고 해요. 주석을 보며 한 줄씩 코드로 바꾸면 길을 잃지 않아요.
- `{self.balance:,}`: 천 단위 쉼표예요. 앞 회차에서 배운 포맷이 여기서 쓰여요.

<PredictPrompt />

`print(f"잔액 : {account_a.withdraw(200000):,}원")`에서 무엇이 먼저 찍힐지 예측해 보세요.

직접 실행하면 `200,000원 출금 완료`가 먼저, `잔액 : 400,000원`이 나중이에요. `print`는 괄호 안의 문장을 다 만든 뒤에 찍어요. 문장을 만들려면 f-string 안의 `withdraw(200000)`부터 실행해야 하고, 그 메서드 안의 `print`가 먼저 돌아요. 그다음 돌려받은 잔액 `400000`이 문장에 들어가요.

<TwistBox title="잔액이 부족한 출금을 f-string 안에서 부르면?">

```python
print(f"잔액 : {account_a.withdraw(999999):,}원")
```

```text
출금 잔액이 부족합니다. 잔액 : 100,000원 || 출금 요청액 : 999,999원
TypeError: unsupported format string passed to NoneType.__format__
```

잔액이 부족하면 `withdraw`는 값 없이 `return`해요. 어제 배운 대로 값 없는 `return`은 `None`을 돌려줘요. `None`에는 천 단위 쉼표(`:,`)를 붙일 수 없어서 `TypeError`가 나요.

수업 예제는 부족한 출금 `withdraw(1000000)`을 f-string 밖에서 따로 불러서 이 에러를 피했어요.

</TwistBox>

## 6. `__str__`과 `__repr__`

둘 다 **객체를 글자로 보여 줄 때 쓰는 모양**을 정하는 메서드예요. 은행 계좌 예제는 두 메서드가 같은 문자열을 돌려줘서 어느 쪽이 쓰였는지 출력만으로는 알 수 없어요. 그래서 일부러 다르게 만들어 봐요.

```python
class T:
    def __str__(self):
        return "STR"

    def __repr__(self):
        return "REPR"

t = T()
print(t)
print([t])
```

```text
STR
[REPR]
```

| 어떻게 출력하나 | 쓰이는 메서드 |
| --- | --- |
| `print(객체)`, `f"{객체}"` | `__str__` |
| `print([객체, 객체])`처럼 리스트 안에 든 객체 | `__repr__` |

`__str__`은 사람이 읽기 좋은 모양, `__repr__`은 개발자가 확인하기 좋은 모양이라고 생각하면 돼요. 그래서 은행 계좌 예제의 `print([account_a, account_c])`는 `__repr__`이 돌려준 문자열로 찍혔어요.

두 메서드가 없으면 파이썬이 정한 기본 모양으로 나와요.

```python
class Item:
    def __init__(self, name, price):
        self.name = name
        self.price = price

print(Item("새우깡", 2000))
# <__main__.Item object at 0x000001C2120F0C20>
```

"이 파일의 `Item` 객체가 메모리 어디에 있다"는 뜻이에요. 뒤의 주소는 실행할 때마다 달라요. 무엇이 든 객체인지 알 수 없으니, 출력해 볼 클래스에는 `__str__`을 만들어 두면 좋아요.

## 7. 실습: 쇼핑 카트

요구사항(파일 맨 위 주석):

- `shopping cart` 클래스 선언, 상품 목록 저장 기능
- 메서드: 장바구니 담기, 장바구니 빼기, 상품 목록 조회
- `상품` 클래스: 속성은 제품명, 가격

```python
class ShoppingCart:
    # 저장 기능
    def __init__(self):
        self.bucket = []

    # 장바구니 담기
    def add_item(self, item):
        self.bucket.append(item)

    # 장바구니 빼기
    def remove_item(self, item):
        self.bucket.remove(item)

    # 상품 목록 조회
    def show_items(self):
        return self.bucket

# 상품 클래스
class Item:
    def __init__(self, name, price):
        self.name = name
        self.price = price

# 쇼핑 카트 생성
cart = ShoppingCart()

# 상품 3개 생성
item_a = Item("초코파이", 5000)
item_b = Item("새우깡", 2000)
item_c = Item("빅파이", 3000)

# 장바구니 담기
cart.add_item(item_a)
cart.add_item(item_b)
cart.add_item(item_c)
# 장바구니에서 빼기
cart.remove_item(item_b)
# 장바구니에 담긴 상품 목록 조회
for item in cart.show_items():
    print(item.name, item.price)
```

```text
초코파이 5000
빅파이 3000
```

| 클래스 | 속성 | 메서드 |
| --- | --- | --- |
| `ShoppingCart` | `bucket` (빈 리스트에서 시작) | `add_item`, `remove_item`, `show_items` |
| `Item` | `name`, `price` | 없음 |

- `self.bucket = []`: 카트마다 자기 리스트를 하나씩 가져요. 직접 실행해 보면 한 카트에 담아도 새로 만든 카트의 `bucket`은 `[]`예요.
- `add_item`은 리스트의 `append`, `remove_item`은 리스트의 `remove`를 감싸요. 이미 있는 기능에 "장바구니 담기" 같은 알아보기 쉬운 이름을 붙인 거예요.
- `Item`은 데이터만 담는 클래스라 메서드가 없어요. `__init__`으로 `name`, `price`를 받아 속성으로 저장해요.
- `for item in cart.show_items():`로 꺼낸 `item`은 `Item` 인스턴스라 `item.name`, `item.price`로 속을 볼 수 있어요.
- `remove_item(item_b)`로 `새우깡`이 빠져 `초코파이`와 `빅파이`만 출력돼요.

클래스 하나가 다른 클래스의 인스턴스를 리스트에 담아 다루고 있어요. 카트는 "담고 빼는 일", 상품은 "이름과 가격"만 맡아요. 일을 나눠 맡기는 것이 클래스를 여러 개 만드는 이유예요.

<TwistBox title="똑같은 상품을 새로 만들어 빼면 빠질까요?">

```python
cart.remove_item(Item("초코파이", 5000))
# ValueError: list.remove(x): x not in list
```

이름도 가격도 같은데 "리스트에 없다"고 해요.

1절에서 본 것처럼 같은 클래스로 같은 값을 넣어 만들어도 **서로 다른 객체**예요. `Item("초코파이", 5000)`은 방금 새로 찍어 낸 붕어빵이라, 카트에 담긴 `item_a`와 다른 객체예요. 그래서 `remove`가 찾지 못해요.

카트에서 빼려면 담을 때 쓴 그 객체(`item_a`)를 넘겨야 해요. 이미 뺀 `item_b`를 한 번 더 빼도 같은 `ValueError`가 나요.

</TwistBox>

<TwistBox title="self.bucket = [] 를 클래스 바로 아래에 쓰면?">

```python
class SharedCart:
    bucket = []  # __init__ 밖, 클래스 바로 아래

    def add_item(self, item):
        self.bucket.append(item)

x = SharedCart()
y = SharedCart()
x.add_item("초코파이")
print(y.bucket)
# ['초코파이']
```

`x`에만 담았는데 `y`에도 초코파이가 들어 있어요.

클래스 바로 아래에 쓴 변수는 **틀 자체에 붙은 하나뿐인 값**이라 모든 인스턴스가 같은 리스트를 나눠 써요. `__init__` 안에서 `self.bucket = []`로 만들어야 인스턴스마다 새 리스트가 생겨요. 수업 코드가 `__init__` 안에 둔 이유예요.

</TwistBox>

## 8. 생성자는 왜 있을까

오늘 셀프 체크 질문은 "클래스에 생성자 함수가 존재하는 이유가 뭐야?"였어요. 오늘 본 예제들로 답할 수 있어요.

**1. 인스턴스가 태어나는 순간 꼭 필요한 값을 받으려고**

`BankAccount("김민지", 100000)`처럼 만들 때 예금주와 잔액을 바로 넣어요. 빠뜨리면 2절처럼 `TypeError`가 나서 **예금주 없는 계좌는 아예 만들어지지 않아요.**

**2. 모든 속성을 처음부터 준비해 두려고**

3절의 `Monitor`는 `__init__`이 없어서 `display_info()`를 부르기 전에는 `resolution`이 없었어요(`AttributeError`). 생성자에서 속성을 다 만들어 두면 어떤 메서드를 먼저 부르든 속성이 이미 있어요.

**3. 인스턴스마다 자기 값을 따로 가지게 하려고**

`SmartPhone`의 `self.battery = 50`, 쇼핑 카트의 `self.bucket = []`는 인스턴스가 생길 때마다 새로 만들어져요. 그래서 `phone_a`를 충전해도 `phone_b`는 그대로이고, 카트끼리 상품이 섞이지 않아요.

한 문장으로 줄이면 이래요. **생성자는 인스턴스가 쓸 수 있는 상태로 태어나게 해 주는 시작 준비**예요. 생성자가 자동으로 불리니, 준비를 깜빡하는 일도 없어요.

## 오늘 꼭 기억할 주의점

- 클래스는 설계도, 인스턴스는 그 설계도로 만든 객체예요. `User("손흥민")`처럼 클래스를 부르면 인스턴스가 생겨요.
- 클래스 이름은 PascalCase(`BankAccount`), 함수와 변수는 snake_case로 지어요.
- `__init__`은 인스턴스가 만들어질 때 자동으로 실행돼요. 받는 값을 빠뜨리면 `TypeError`예요.
- `self`는 메서드를 부른 그 인스턴스예요. 점 앞의 객체가 `self`로 들어가요.
- 메서드에는 맨 앞에 `self` 자리를 꼭 만들어요. 빼먹으면 "인수를 1개 받았다"는 `TypeError`가 나요.
- 속성은 `self.이름 = 값`이 실행된 뒤에 생겨요. 그 전에 쓰면 `AttributeError`예요.
- 같은 클래스, 같은 값으로 만들어도 서로 다른 객체예요(`is`는 `False`, `id()`도 달라요).
- 메서드가 바꾼 속성은 인스턴스 안에 남아요. 다른 인스턴스에는 영향이 없어요.
- 값 없는 `return`은 `None`을 돌려줘요. 그 값을 `f"{...:,}"`에 넣으면 `TypeError`예요.
- f-string 안의 메서드 호출이 먼저 실행되고, 바깥 `print`가 나중에 찍혀요.
- `print(객체)`는 `__str__`, 리스트 안의 객체는 `__repr__`로 보여요. 둘 다 없으면 `<__main__.클래스 object at 0x...>`예요.
- 리스트에서 객체를 빼려면 담을 때 쓴 그 객체를 넘겨요. 같은 값으로 새로 만든 객체는 `ValueError`예요.
- 인스턴스마다 따로 가져야 하는 리스트는 클래스 바로 아래가 아니라 `__init__` 안에서 `self.이름 = []`로 만들어요.
