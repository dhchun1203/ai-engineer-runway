14회차부터 16회차까지 docker 명령을 스무 개 넘게 배웠어요. 회차마다 흩어져 있어서 막힐 때 찾기 어려워요. 이 페이지는 교안의 정리 챕터를 따라 명령을 묶음별로 다시 보고, 마지막에 **치트시트 두 장**으로 모아요.

예시 이름은 15회차 그대로예요. 폴더 `pg_lab`, 파일 `my_shop.sql`, 컨테이너 `my-pg`, 비밀번호 `admin`, 볼륨 `pg-data`예요. 명령은 맥 터미널 기준이에요. 아래 출력은 실제로 실행한 결과예요(긴 줄은 `…`로 줄였어요).

## 1. 명령은 이미지, 컨테이너, 볼륨, 내 폴더 사이를 오간다

명령마다 **무엇을 움직이는지** 보면 덜 헷갈려요. `pull`은 Docker Hub에서 이미지를 받고, `run`은 이미지로 컨테이너를 찍어요. 컨테이너를 켜고 끄는 명령, 안에 들어가는 명령, 볼륨 명령, compose 명령이 각자 다른 곳을 건드려요.

## 2. `docker` 다음은 할 일, 그 뒤에 옵션과 이름이 온다

docker 명령은 모양이 정해져 있어요. `docker` 다음에 **할 일**, 그 뒤에 **옵션**, 마지막에 **이름**이 와요. 할 일이 `volume create`, `compose up`처럼 두 단어일 때도 있어요.

| 할 일 | 옵션 | 이름 | 그 뒤에 붙는 것 |
| --- | --- | --- | --- |
| `docker run` | `-d --name my-pg -e ... -p ...` | `postgres:18` (이미지) | |
| `docker volume create` | | `pg-data` | |
| `docker exec` | `-it` | `my-pg` | `psql -U postgres` (안에서 실행할 명령) |
| `docker logs` | `--tail 3` | `my-pg` | |
| `docker compose up` | `-d` | | |
| `docker cp` | | `my_shop.sql` | `my-pg:/tmp/my_shop.sql` |

옵션은 대부분 글자 하나짜리예요. 아래 세 줄(`-i`, `--tail`, `-f`)은 15회차 실습 저장소에서 새로 나왔어요.

| 옵션 | 뜻 | 언제 |
| --- | --- | --- |
| `-d` | 뒤에서 켜기 | 터미널을 계속 쓰고 싶을 때 |
| `--name 이름` | 컨테이너 이름 붙이기 | 긴 ID 대신 이름으로 부를 때 |
| `-p 5432:5432` | 포트 잇기 (내 컴퓨터:컨테이너) | 밖에서 접속할 때 |
| `-e 이름=값` | 환경 변수 넘기기 | 비밀번호를 정할 때 |
| `-v pg-data:경로` | 볼륨 붙이기 | 지워도 데이터를 남길 때 |
| `-it` | 들어가서 직접 치기 | `psql`, `bash`를 열 때 |
| `-i` | 파일 내용을 넘기기 | `< 파일`로 SQL을 넣을 때 |
| `--tail 3` | 마지막 3줄만 | 기록이 길 때 |
| `-f` | 계속 보기 (`Ctrl + C`로 멈춤) | 새 기록을 기다릴 때 |

### 긴 명령은 줄 끝에 `\`를 붙여 나눈다

`\`는 "다음 줄도 같은 명령"이라는 표시예요. `Enter`를 쳐도 실행하지 않고 `>`를 띄워 다음 줄을 기다려요. 한 줄로 친 것과 똑같이 실행돼요.

```bash
docker run -d --name my-pg \
  -e POSTGRES_PASSWORD=admin \
  -p 5432:5432 postgres:18
```

그런데 `\` **뒤에 띄어쓰기가 하나라도 있으면** 줄이 끊겨요. 첫 줄이 따로 실행되고, 둘째 줄은 엉뚱한 명령이 돼요.

```text
docker: invalid reference format

Run 'docker run --help' for more information
bash: line 2: -e: command not found
```

## 3. 이미지와 컨테이너: 켜고, 끄고, 보고, 지운다

### 이미지는 `pull`로 받고 `images`로 보고 `rmi`로 지운다

```bash
docker pull postgres:18     # 받기. 층마다 한 줄씩 나오고 Status 줄이 나오면 끝
docker images               # 받은 목록
docker rmi postgres:18      # 지우기 (쓰는 컨테이너가 없을 때)
```

태그 `18`은 PostgreSQL 18이에요. 숫자로 적어 두면 모두 같은 버전을 받아요.

### `run`으로 켜고 `ps`로 본다

```bash
docker run -d --name my-pg -e POSTGRES_PASSWORD=admin -p 5432:5432 postgres:18
docker ps
```

```text
CONTAINER ID   IMAGE         COMMAND                  CREATED         STATUS         PORTS                    NAMES
b64cc6816076   postgres:18   "docker-entrypoint.s…"   2 seconds ago   Up 2 seconds   0.0.0.0:5432->5432/tcp   my-pg
```

맨 앞은 컨테이너 ID 앞 12자리, `STATUS`가 `Up`이면 켜져 있어요. `NAMES`는 `--name`으로 붙인 이름이에요. `docker ps`는 켜진 것만, `docker ps -a`는 꺼진 것까지 보여 줘요.

### `stop`, `start`, `restart`는 상태만 바꾸고 `rm`이 지운다

<Figure label="컨테이너가 오가는 상태">
  <Boxes
    row={[
      { title: "켜짐 Up", tone: "ok", lines: ["`docker run`으로 만들어 켜요", "`docker restart`: 껐다가 바로 켜기"] },
      { arrow: "`docker stop`" },
      { title: "꺼짐 Exited", tone: "amber", lines: ["`ps`에는 없고 `ps -a`에 남아요", "`docker start`로 다시 켜면 안의 데이터도 그대로"] },
      { arrow: "`docker rm`" },
      { title: "없어짐", tone: "red", lines: ["컨테이너가 지워져요", "볼륨에 둔 데이터는 남아요"] },
    ]}
  />
</Figure>

```bash
docker stop my-pg       # 끄기
docker ps -a            # STATUS: Exited (0) ...
docker start my-pg      # 다시 켜기, STATUS: Up
docker restart my-pg    # 껐다가 바로 켜기. 설정을 다시 읽게 할 때
```

### `logs --tail`은 마지막 몇 줄만, `-f`는 계속 따라간다

PostgreSQL은 기록이 길어서 `docker logs my-pg`만 치면 화면이 넘쳐요. 14회차에서 `ready to accept connections`를 찾을 때처럼 끝만 보면 돼요.

```bash
docker logs --tail 3 my-pg       # 마지막 3줄만 보여 주고 끝나요
docker logs -f --tail 1 my-pg    # 마지막 1줄부터 계속 따라가요. Ctrl + C로 멈춰요
```

```text
… LOG:  database system is ready to accept connections
^C
```

### 켜진 컨테이너는 못 지우고, 쓰는 이미지도 못 지운다

```text
$ docker rm my-pg
Error response from daemon: cannot remove container "my-pg": container is running: stop the container before removing or force remove

$ docker rmi postgres:18
Error response from daemon: conflict: unable to delete postgres:18 (must be forced) - container b64cc6816076 is using its referenced image b9f6b8ff03b6
```

첫 번째는 켜진 채로 `rm`을 쳐서 먼저 끄라는 뜻이에요. 두 번째는 컨테이너가 그 이미지를 쓰고 있다는 뜻이에요. **꺼진 컨테이너가 남아 있어도** 같은 오류가 나요. 지울 때는 끄고(`docker stop my-pg`), 컨테이너를 지우고(`docker rm my-pg`), 이미지를 지워요(`docker rmi postgres:18`).

## 4. 컨테이너 안에서 작업하기: `cp`, `exec`, 그리고 파일 넣기 두 길

15회차의 `my_shop.sql`은 DB `my_shop`을 지웠다 다시 만들고(`DROP DATABASE IF EXISTS`), `\c my_shop`으로 옮겨 가서, 표 `product`를 만들고 상품 다섯 개를 넣어요. `IF EXISTS` 덕분에 몇 번을 실행해도 같은 결과가 나와요.

### `docker cp`는 내 폴더와 컨테이너 사이에서 복사한다

쓰는 모양은 리눅스의 `cp`와 같아요. **보낼 것을 먼저, 받을 곳을 뒤에** 써요. 컨테이너 안 경로는 `컨테이너 이름:경로`로 적어요. 방향은 양쪽 다 돼요.

```bash
docker exec my-pg ls /tmp                          # 비어 있어요
docker cp my_shop.sql my-pg:/tmp/my_shop.sql       # 내 폴더 → 컨테이너
docker exec my-pg ls /tmp                          # my_shop.sql
docker cp my-pg:/tmp/my_shop.sql ./copy.sql        # 컨테이너 → 내 폴더
ls                                                 # copy.sql  my_shop.sql
```

보낼 파일 이름이 틀리면 `lstat …/my_shop.sq: no such file or directory`가 나와요. `ls`로 이름과 지금 폴더를 확인해요.

<Hint>

윈도우 Git Bash에서는 컨테이너 안 경로(`:/tmp`)가 바뀌지 않게 `export MSYS_NO_PATHCONV=1`을 먼저 쳐요(15회차). 맥 터미널은 필요 없어요.

</Hint>

### 컨테이너 안을 보는 방법은 세 가지

| 명령 | 하는 일 | 나오기 |
| --- | --- | --- |
| `docker exec -it my-pg bash` | 안의 `bash`를 열어 여러 명령을 차례로 쳐요. 앞 표시가 `root@...`로 바뀌어요 | `exit` |
| `docker exec my-pg ls /tmp` | 명령 하나만 실행하고 바로 끝나요(14회차 `nginx -t`처럼) | 자동 |
| `docker exec -it my-pg psql -U postgres -d my_shop` | `psql`을 바로 열어요. `\dt`로 표 목록 | `\q` |

### 방법 1: 복사해 둔 파일을 `psql -f`로 실행

```bash
docker exec -it my-pg psql -U postgres -f /tmp/my_shop.sql
```

```text
psql:/tmp/my_shop.sql:2: NOTICE:  database "my_shop" does not exist, skipping
DROP DATABASE
CREATE DATABASE
You are now connected to database "my_shop" as user "postgres".
CREATE TABLE
INSERT 0 5
```

`-f`는 file이에요. 파일 안의 SQL을 위에서부터 차례로 실행하고 문장마다 결과를 한 줄씩 보여 줘요. 첫 줄 `NOTICE`는 `my_shop`이 아직 없어서 `DROP`을 건너뛰었다는 알림이지 오류가 아니에요. 파일은 **컨테이너 안에** 있어야 해요.

### 방법 2: 내 폴더의 파일을 `<`로 바로 넘기기

```bash
docker exec -i my-pg psql -U postgres < my_shop.sql
```

`<`는 파일 내용을 키보드 대신 명령에 흘려 넣어요. 그 내용은 내 컴퓨터에 있고 `psql`은 컨테이너 안에 있으니, `-i`가 내 쪽 입력을 컨테이너 안까지 이어 줘요. 복사할 필요가 없어요.

### `<`로 넘길 때 `-it`를 쓰면 거절된다

```text
$ docker exec -it my-pg psql -U postgres < my_shop.sql
cannot attach stdin to a TTY-enabled container because stdin is not a terminal
```

`psql`을 열 때 늘 `-it`를 써서 습관처럼 붙이기 쉬워요. `-it`는 두 옵션을 붙여 쓴 거예요.

<Figure label="-i와 -t는 다른 줄을 잇는다">
  <Boxes
    row={[
      { title: "-i", note: "입력을 이어요", tone: "blue", lines: ["키보드든 파일이든 받아요", "`< my_shop.sql`에 필요해요"] },
      { title: "-t", note: "화면(터미널)을 이어요", tone: "rust", lines: ["키보드로 직접 칠 때만 써요", "파일을 넘기면 \"터미널이 아니다\"라며 거절해요"] },

직접 칠 때는 `-it`, 파일을 넘길 때는 `-i`예요.

## 5. 볼륨: 만들고, 보고, 붙이고, 지운다

```bash
docker volume create pg-data      # 이름 붙여 만들기 (run에 -v만 써도 저절로 생겨요)
docker volume ls                  # 목록
docker volume inspect pg-data     # 자세히 보기
```

```text
[
    {
        "CreatedAt": "2026-11-13T04:44:54Z",
        "Driver": "local",
        "Labels": null,
        "Mountpoint": "/var/lib/docker/volumes/pg-data/_data",
        "Name": "pg-data",
        "Options": null,
        "Scope": "local"
    }
]
```

`Mountpoint`는 Docker가 실제로 데이터를 두는 곳이에요. 직접 열지 않고 컨테이너로 읽어요(맥과 윈도우는 Docker Desktop의 리눅스 VM 안이라 열 수도 없어요).

### 볼륨을 붙이면 컨테이너를 지워도 상품이 남는다

```bash
docker run -d --name my-pg -e POSTGRES_PASSWORD=admin -p 5432:5432 \
  -v pg-data:/var/lib/postgresql postgres:18
docker exec -i my-pg psql -U postgres < my_shop.sql    # 마지막 줄 INSERT 0 5
docker stop my-pg && docker rm my-pg                   # 컨테이너를 지웠어요
docker run -d --name my-pg -e POSTGRES_PASSWORD=admin -p 5432:5432 \
  -v pg-data:/var/lib/postgresql postgres:18           # 같은 볼륨으로 새로 켜요
docker exec -it my-pg psql -U postgres -d my_shop -c "SELECT * FROM product"   # (5 rows)
```

붕어빵(컨테이너)은 새로 찍었지만 보관함(`pg-data`)은 그대로라 상품 다섯 개가 다시 보여요. PostgreSQL 18은 데이터를 `/var/lib/postgresql`에 둬요.

### 쓰고 있는 볼륨은 지울 수 없다

```text
$ docker volume rm pg-data
Error response from daemon: remove pg-data: volume is in use - [1bb2985a5357…]
```

대괄호 안 긴 글자는 그 볼륨을 쓰는 컨테이너 ID예요. `docker stop my-pg`, `docker rm my-pg` 뒤에 다시 지우면 돼요.

`-v` 뒤에는 두 가지가 올 수 있어요(14회차). `-v pg-data:/var/lib/postgresql`처럼 **이름**이면 Docker가 관리하는 볼륨이고, `-v ./site:/usr/share/nginx/html`처럼 **경로**면 내가 직접 고치는 내 폴더예요.

## 6. YAML: 칸이 누구 안에 있는지 정한다

`compose.yaml`은 "이름: 값"을 한 줄에 하나씩 적는 YAML 파일이에요. 파이썬 들여쓰기처럼, **같은 칸에서 시작하는 줄끼리 형제**이고 한 단계 더 들어가면 위 줄의 안쪽이에요.

```yaml
services:                         # 실행할 컨테이너(서비스) 목록, 꼭 있어야 해요
  db:                             # 서비스 이름, 직접 정해요
    image: postgres:18            # 쓸 이미지:태그
    container_name: my-pg         # 컨테이너 이름(--name), 안 적으면 자동
    environment:
      POSTGRES_PASSWORD: admin    # 환경 변수(-e)
    ports:
      - "5432:5432"               # 포트(-p), 따옴표로 감싸요
    volumes:
      - pg-data:/var/lib/postgresql   # 볼륨(-v)
volumes:
  pg-data:                        # 쓸 볼륨 이름 적어 두기(맨 바깥)
```

`이름: 값`은 쌍점 뒤에 한 칸, `- 값`은 목록의 한 칸, `#` 뒤는 주석이에요.

### 2칸이든 4칸이든 같은 단계끼리 맞으면 된다

위 파일을 한 단계에 **4칸**씩 들어가게 바꿔도 `docker compose config`가 그대로 읽고 `up -d`도 켜져요. YAML이 보는 건 칸 수가 아니라 **같은 단계끼리 칸이 맞는지**예요. 다만 compose 파일은 Docker 공식 문서와 수업 자료처럼 **2칸**으로 적어요. 그리고 **탭은 못 써요.**

### 오류는 세 가지가 가장 많다

`docker compose config`로 직접 돌려 본 메시지예요. `L3.C1`은 3번째 줄 1번째 칸이에요.

```text
# 1. 3번째 줄을 탭으로 들여썼어요
go-yaml load error in scanner (while scanning for the next token) at L3.C1: found character that cannot start any token

# 2. 4번째 줄만 2칸이라 어긋났어요
go-yaml load error in scanner at L5.C16: mapping values are not allowed in this context

# 3. 3번째 줄이 image:postgres:18 (쌍점 뒤 띄어쓰기 없음)
go-yaml load error in scanner at L4.C19: mapping values are not allowed in this context
```

뒤의 둘은 **실수한 다음 줄**을 가리켜요. 앞줄이 값 하나로 읽혀서 다음 줄에서 막히기 때문이에요. 메시지 줄 번호의 바로 위 줄도 같이 봐요.

## 7. compose: `docker run`의 옵션이 파일의 칸으로 옮겨 간다

| `docker run` | `compose.yaml`의 `db` 안 |
| --- | --- |
| `--name my-pg` | `container_name: my-pg` |
| `-e POSTGRES_PASSWORD=admin` | `environment:` 아래 `POSTGRES_PASSWORD: admin` |
| `-p 5432:5432` | `ports:` 아래 `- "5432:5432"` |
| `-v pg-data:/var/lib/postgresql` | `volumes:` 아래 `- pg-data:/var/lib/postgresql` |
| `postgres:18` | `image: postgres:18` |
| `-d` | `docker compose up -d`에 붙여요 |

### `compose config`는 파일을 읽은 그대로 펼쳐 보여 준다

`up` 하기 전에 쳐 봐요. 파일에 오류가 있으면 여기서 나고, 없으면 Docker가 알아들은 내용을 빠짐없이 펼쳐 보여 줘요.

```text
$ docker compose config
name: pg_lab
services:
  db:
    container_name: my-pg
    environment:
      POSTGRES_PASSWORD: admin
    image: postgres:18
    networks:
      default: null
    volumes:
      - type: volume
        source: pg-data
        target: /var/lib/postgresql
        volume: {}
    ports:
      - mode: ingress
        target: 5432
        published: "5432"
        protocol: tcp
networks:
  default:
    name: pg_lab_default
volumes:
  pg-data:
    name: pg_lab_pg-data
```

눈여겨볼 곳은 두 군데예요. 맨 위 `name: pg_lab`은 **폴더 이름이 프로젝트 이름**이 된다는 뜻이고, 맨 아래 볼륨의 진짜 이름은 앞에 `pg_lab_`가 붙은 `pg_lab_pg-data`예요. 안 적은 칸이 기본값으로 채워지고 순서가 바뀌어도 괜찮아요.

### `up`, `ps`, `exec`, 그리고 `logs`, `stop`, `start`, `restart`

```bash
docker compose up -d        # 네트워크, 볼륨, 컨테이너를 한 번에 만들고 켜기
docker compose ps           # 이 폴더의 compose로 켠 것만. SERVICE 칸에 db
docker compose exec db psql -U postgres -d my_shop -c "SELECT * FROM product"
docker compose logs --tail 3     # 줄 앞에 컨테이너 이름이 붙어요 (my-pg  | ...)
docker compose stop         # 끄기 (지우지 않아요)
docker compose ps -a        # 꺼진 것까지
docker compose start        # 다시 켜기
docker compose restart      # 껐다가 바로 켜기
```

`compose exec` 뒤에는 **서비스 이름**(`db`)을 써요. `docker exec`에는 컨테이너 이름(`my-pg`)을 써요. `logs`, `stop`, `start`, `restart`는 3절 명령 앞에 `compose`만 붙인 거예요. 이름을 안 적으면 이 폴더 `compose.yaml`의 서비스 전부에 적용돼요.

### `down`은 볼륨을 남기고, `down -v`는 볼륨까지 지운다

```bash
docker compose down       # 컨테이너와 네트워크만 지워요
docker volume ls          # pg_lab_pg-data가 남아 있어요
docker compose up -d      # 다시 켜면 상품이 그대로
docker compose down -v    # 볼륨까지 지워요. 상품도 사라져요
```

### `container_name`을 빼면 이름이 "폴더-서비스-1"이 된다

`container_name` 한 줄을 지우고 켜면 컨테이너 이름이 `pg_lab-db-1`이 돼요. 폴더 이름, 서비스 이름, 첫 번째라는 번호를 이은 거예요. 그래서 `docker exec my-pg ...`를 치면 이렇게 나와요.

```text
Error response from daemon: No such container: my-pg
```

이름이 기억 안 나면 `docker compose ps`의 `NAME` 칸을 봐요. 서비스 이름으로 들어가는 `docker compose exec db ...`는 이름과 상관없이 돼요.

### 그 밖의 compose 명령 둘

| 명령 | 하는 일 |
| --- | --- |
| `docker compose ls` | compose로 켠 프로젝트 목록. `pg_lab  running(1)`처럼 나와요 |
| `docker compose pull` | `compose.yaml`에 적힌 이미지를 미리 받기 |

## 8. 오류 여덟 가지를 한 장에

| 이런 글이 보이면 | 왜 | 이렇게 해요 |
| --- | --- | --- |
| `Conflict. The container name "/my-pg" is already in use` | 같은 이름의 컨테이너가 있어요 | `docker rm my-pg` 뒤 다시 |
| `Bind for 0.0.0.0:5432 failed: port is already allocated` | 5432번을 다른 컨테이너가 써요 | 하나 끄거나 `-p 5433:5432` |
| `invalid reference format` / `-e: command not found` | 줄 끝 `\` 뒤에 띄어쓰기 | `\`로 줄을 끝내기 |
| `cannot attach stdin to a TTY-enabled container` | `< 파일`과 `-it`를 같이 썼어요 | `-i`만 쓰기 |
| `lstat …/my_shop.sq: no such file or directory` | 보낼 파일 이름이 틀렸거나 다른 폴더 | `ls`로 이름 확인 |
| `No such container: my-pg` | `container_name`을 안 적어서 이름이 달라요 | `docker compose ps`로 이름 보기 |
| `volume is in use` | 그 볼륨을 쓰는 컨테이너가 있어요 | `stop`, `rm` 뒤 `volume rm` |
| `go-yaml load error … at L3.C1` | YAML에 탭, 어긋난 칸, 쌍점 뒤 띄어쓰기 | `docker compose config`로 확인 |

## 9. 실제 상황 세 가지

### 수업 흐름 그대로: 켜고, 넣고, 실행하고, 확인한다

```bash
# 1. 켜기
docker run -d --name my-pg \
  -e POSTGRES_PASSWORD=admin \
  -p 5432:5432 postgres:18

# 2. 넣기
docker cp my_shop.sql my-pg:/tmp/my_shop.sql

# 3. 실행하기
docker exec -it my-pg psql -U postgres -f /tmp/my_shop.sql

# 4. 확인하기: (5 rows)로 끝나요
docker exec -it my-pg psql -U postgres -d my_shop \
  -c "SELECT * FROM product"
```

2, 3단계는 `docker exec -i my-pg psql -U postgres < my_shop.sql` 한 줄로 바꿔도 돼요.

### compose로 같은 일: 파일 두 개, 명령 세 줄

폴더에 `my_shop.sql`과 6절의 `compose.yaml`을 두고 세 줄이면 끝나요.

```bash
docker compose up -d
docker exec -i my-pg psql -U postgres < my_shop.sql
docker exec -it my-pg psql -U postgres -d my_shop -c "SELECT * FROM product"
```

다음 날은 `docker compose up -d` 한 줄이면 돼요. `down`만 했다면 상품도 그대로 있어요.

### 다 쓴 것은 컨테이너, 볼륨, 이미지 순서로 지운다

| compose로 켰다면 | `docker run`으로 켰다면 |
| --- | --- |
| `docker compose down -v` | `docker stop my-pg` → `docker rm my-pg` → `docker volume rm pg-data` |
| `docker rmi postgres:18` | `docker rmi postgres:18` |

빈 `docker ps -a`, 빈 `docker volume ls`, 빈 `docker images`가 다 지운 모습이에요. 이미지는 다음 수업에 또 쓸 거라면 남겨 둬요. 지우면 다음에 `pull`부터 다시 해요.

## 10. 긴 이름과 `--help`

인터넷 치트시트나 공식 문서에는 같은 명령이 **긴 이름**으로 나오기도 해요. 무엇에 대한 명령인지 `container`, `image`를 앞에 붙인 거라 결과가 똑같아요.

| 수업에서 쓰는 이름 | 같은 명령 (긴 이름) |
| --- | --- |
| `docker ps` | `docker container ls` |
| `docker images` | `docker image ls` |
| `docker rm my-pg` | `docker container rm my-pg` |
| `docker rmi postgres:18` | `docker image rm postgres:18` |
| `docker exec -it my-pg bash` | `docker container exec -it my-pg bash` |
| `docker cp ...` | `docker container cp ...` |

옵션이 기억 안 나면 명령 뒤에 `--help`를 붙여요. 맨 위 `Usage`에 쓰는 모양이 나와요. `[OPTIONS]`처럼 대괄호는 "넣어도 되고 빼도 되는 것"이에요.

```text
$ docker cp --help
Usage:  docker cp [OPTIONS] CONTAINER:SRC_PATH DEST_PATH|-
        docker cp [OPTIONS] SRC_PATH|- CONTAINER:DEST_PATH

Copy files/folders between a container and the local filesystem
```

첫 줄은 컨테이너에서 꺼내기, 둘째 줄은 컨테이너로 넣기예요.

## 치트시트 1: docker 명령 한 장

| 묶음 | 명령 | 하는 일 |
| --- | --- | --- |
| 이미지 | `docker pull postgres:18` | Docker Hub에서 받기 |
| | `docker images` | 받은 이미지 목록 |
| | `docker rmi postgres:18` | 지우기 (쓰는 컨테이너 먼저 지우기) |
| 컨테이너 | `docker run -d --name my-pg -e POSTGRES_PASSWORD=admin -p 5432:5432 postgres:18` | 뒤에서 켜기, 이름, 환경 변수, 포트 |
| | `docker ps` / `docker ps -a` | 켜진 것 / 꺼진 것까지 |
| | `docker stop my-pg` / `docker start my-pg` | 끄기 / 다시 켜기 |
| | `docker restart my-pg` | 껐다가 바로 켜기 |
| | `docker logs --tail 3 my-pg` | 마지막 3줄 (`-f`는 계속, `Ctrl + C`) |
| | `docker rm my-pg` | 지우기 (끈 다음에) |
| 안에서 작업 | `docker exec -it my-pg bash` | 들어가기, `exit`로 나오기 |
| | `docker exec my-pg ls /tmp` | 명령 하나만 실행 |
| | `docker exec -it my-pg psql -U postgres -d my_shop` | `psql` 열기, `\q`로 나오기 |
| | `docker cp my_shop.sql my-pg:/tmp/my_shop.sql` | 내 파일을 컨테이너로 (반대 방향도 돼요) |
| | `docker exec -i my-pg psql -U postgres < my_shop.sql` | 파일 내용 넘기기 (`-it` 말고 `-i`) |
| 볼륨 | `docker volume create pg-data` | 만들기 |
| | `docker volume ls` | 목록 |
| | `docker volume inspect pg-data` | 자세히 보기 |
| | `-v pg-data:/var/lib/postgresql` | `run`에 붙여 연결 |
| | `docker volume rm pg-data` | 지우기 (쓰는 컨테이너 먼저) |

## 치트시트 2: docker compose 명령 한 장

모든 compose 명령은 `compose.yaml`이 있는 폴더(`pg_lab`)에서 쳐요. 파일은 2칸 들여쓰기, 쌍점 뒤 한 칸, 탭 금지예요.

| 묶음 | 명령 | 하는 일 |
| --- | --- | --- |
| 켜고 보기 | `docker compose config` | 파일을 읽은 그대로 보기, YAML 오류 확인 |
| | `docker compose up -d` | 만들고 켜기 (뒤에서) |
| | `docker compose ps` / `ps -a` | 이 폴더의 컨테이너 / 꺼진 것까지 |
| | `docker compose ls` | compose 프로젝트 목록 |
| | `docker compose pull` | 이미지 미리 받기 |
| 다루고 끄기 | `docker compose exec db psql -U postgres -d my_shop` | 서비스 이름 `db`로 들어가기 |
| | `docker compose logs --tail 3` | 마지막 3줄 (`-f`는 계속) |
| | `docker compose stop` / `start` | 끄기 (지우지 않아요) / 다시 켜기 |
| | `docker compose restart` | 껐다가 바로 켜기 |
| | `docker compose down` | 지우기, 볼륨은 남아요 |
| | `docker compose down -v` | 볼륨까지 지우기 |

`container_name`을 빼면 컨테이너 이름은 `pg_lab-db-1`이에요.

## 꼭 기억할 주의점

- 명령은 `docker` + 할 일 + 옵션 + 이름 순서예요. 막히면 명령 뒤에 `--help`를 붙여요.
- 줄 끝 `\` 뒤에는 띄어쓰기를 두지 않아요.
- 직접 칠 때는 `-it`, `< 파일`로 넘길 때는 `-i`만 써요.
- 지우는 순서는 컨테이너, 볼륨, 이미지예요. 쓰고 있는 것은 지울 수 없어요.
- `docker compose down`은 볼륨을 남기고, `down -v`는 볼륨까지 지워요.
- `compose exec`에는 서비스 이름(`db`), `docker exec`에는 컨테이너 이름(`my-pg`)을 써요.
- YAML은 탭 금지, 같은 단계는 같은 칸, 쌍점 뒤 한 칸이에요. `up` 전에 `docker compose config`로 확인해요.
