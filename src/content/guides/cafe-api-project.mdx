[1부](/class/cafe-mini-project)에서는 파이썬이 DB에 직접 접속해서 데이터를 꺼냈어요. 그런데 실제 서비스에서는 앱이나 웹 화면이 DB에 직접 붙지 않아요. 가운데에 **API 서버**를 두고, "판교점 주문 보여 줘" 같은 부탁을 HTTP로 보내요.

## 3. 첫 창구: GET /stores에 함수 하나를 건다

VS Code에서 새 파일 `server.py`를 만들어요. 먼저 지점 목록을 돌려주는 창구 하나만 열어요.

```python
import psycopg
from fastapi import FastAPI
from psycopg.rows import dict_row

DSN = "host=localhost port=5433 dbname=cafe_db user=postgres password=admin"

app = FastAPI(title="카페 주문 API")


def fetch_all(sql, params=None):
    """SQL을 보내고 행마다 딕셔너리 하나인 리스트를 돌려준다."""
    with psycopg.connect(DSN, row_factory=dict_row) as conn:
        return conn.execute(sql, params).fetchall()


@app.get("/stores")
def list_stores():
    return fetch_all("SELECT store_id, name, region, opened_on FROM stores ORDER BY store_id")
```

새로 나온 것은 세 가지예요.

- `app = FastAPI(...)`: API 서버 한 개예요. 창구를 이 `app`에 하나씩 달아요.
- `@app.get("/stores")`: 바로 아래 함수에 붙는 표시(데코레이터)예요. "`GET /stores` 요청이 오면 이 함수를 불러"라는 뜻이에요.
- `row_factory=dict_row`: 1부에서는 행이 튜플 `(1, '성수점', ...)`이었어요. 이렇게 열면 행이 `{"store_id": 1, "name": "성수점", ...}` 딕셔너리로 와요. 열 이름이 붙어 있어서 FastAPI가 그대로 JSON으로 바꿀 수 있어요.

## 5. 경로 파라미터와 404: /stores/3, /stores/9

지점 하나만 받는 창구를 더해요. 주소 안의 `{store_id}` 자리가 함수 인자로 들어와요. 이것을 **경로 파라미터**라고 해요. `server.py` 첫 줄의 `import`도 고쳐요.

```python
from fastapi import FastAPI, HTTPException
```

```python
@app.get("/stores/{store_id}")
def get_store(store_id: int):
    rows = fetch_all(
        "SELECT store_id, name, region, opened_on FROM stores WHERE store_id = %s",
        (store_id,),
    )
    if not rows:
        raise HTTPException(status_code=404, detail="그런 지점이 없어요")
    return rows[0]
```

저장하면 서버가 다시 켜져요. 있는 지점과 없는 지점을 불러 봐요.

```bash
curl -i http://127.0.0.1:8000/stores/9
```

```text
HTTP/1.1 404 Not Found
date: Fri, 20 Nov 2026 09:51:04 GMT
server: uvicorn
content-length: 39
content-type: application/json

{"detail":"그런 지점이 없어요"}
```

`rows`가 빈 리스트면 `raise HTTPException(...)`으로 함수를 멈추고 404를 돌려줘요. 그냥 `None`을 돌려주면 FastAPI는 `200 OK`에 본문 `null`을 보내요. 부른 쪽은 성공인 줄 알게 돼요.

이번엔 숫자 자리에 글자를 넣어요.

```bash
curl -i http://127.0.0.1:8000/stores/abc
```

```text
HTTP/1.1 422 Unprocessable Content
...
{"detail":[{"type":"int_parsing","loc":["path","store_id"],"msg":"Input should be a valid integer, unable to parse string as an integer","input":"abc"}]}
```

`store_id: int`라고 타입을 적어 두어서 FastAPI가 함수를 부르기도 전에 막았어요. `loc`은 어느 칸이 틀렸는지(`path`의 `store_id`), `msg`는 왜 틀렸는지예요.

상태 코드는 첫 숫자만 봐도 누구 잘못인지 알 수 있어요.

| 코드 | 뜻 | 이 프로젝트에서 언제 |
| --- | --- | --- |
| `200 OK` | 잘 됐어요 | 창구가 있고 함수가 끝까지 돌았을 때. 결과가 빈 배열이어도 200이에요 |
| `404 Not Found` | 찾는 것이 없어요 | 없는 지점 번호(`/stores/9`), 없는 창구 주소(`/nothing`) |
| `422 Unprocessable Content` | 보낸 값의 모양이 틀렸어요 | 숫자 자리에 글자(`/stores/abc`) |
| `500 Internal Server Error` | 서버 안에서 터졌어요 | 서버가 켜진 채 DB 컨테이너가 꺼졌을 때 |

4로 시작하면 부른 쪽이 고칠 일, 5로 시작하면 서버 쪽이 고칠 일이에요.

<Hint>
`500`이 나오면 본문에는 `Internal Server Error` 한 줄뿐이에요. 진짜 이유는 서버 터미널에 길게 찍혀요. DB 컨테이너가 꺼져 있으면 맨 아래에 `psycopg.OperationalError: connection failed: ...`가 보여요. `docker compose up -d`로 켜면 다시 200이 와요.
</Hint>

<Hint>
고친 창구가 `/docs`에 안 보이거나 `{"detail":"Not Found"}`가 나오면, 서버가 다시 켜지지 않았거나 저장(`Cmd + S`)을 안 한 거예요. 서버 터미널에서 `Ctrl + C`로 끄고 `uv run fastapi dev server.py`로 다시 켜요.
</Hint>

## 6. 쿼리 파라미터: /order-lines?store=판교점

분석 재료인 주문 상세 창구를 열어요. 주소 `?` 뒤에 `이름=값`으로 붙이는 것이 **쿼리 파라미터**예요. 함수 인자 중 주소 안에 자리가 없는 인자는 FastAPI가 쿼리 파라미터로 받아요.

```python
ORDER_LINES_SQL = """
    SELECT o.order_id, o.ordered_at, o.store_id, s.name AS store, o.member_id,
           m.name AS menu, m.category, oi.qty, m.price, m.cost
    FROM order_items oi
    JOIN orders o ON o.order_id = oi.order_id
    JOIN stores s ON s.store_id = o.store_id
    JOIN menus  m ON m.menu_id  = oi.menu_id
"""


@app.get("/order-lines")
def list_order_lines(store: str | None = None):
    if store is None:
        return fetch_all(ORDER_LINES_SQL + " ORDER BY oi.order_id, oi.menu_id")
    return fetch_all(
        ORDER_LINES_SQL + " WHERE s.name = %s ORDER BY oi.order_id, oi.menu_id",
        (store,),
    )
```

SQL은 1부 9절의 `JOIN`과 같아요. `store: str | None = None`은 "글자를 받을 수 있지만, 안 줘도 돼"라는 뜻이에요. 안 주면 `store`가 `None`이라 전체 1,104줄, 주면 그 지점만 돌려줘요.

브라우저에서 `http://127.0.0.1:8000/order-lines?store=판교점`을 열면 판교점 주문 상세만 와요. 없는 지점(`?store=강남점`)은 404가 아니라 `200 OK`에 빈 배열 `[]`이에요. 창구는 있고, 찾아본 결과가 없을 뿐이니까요.

<Hint>
SQL에 값을 넣을 때는 19회차처럼 `%s` 자리 채우기만 써요. `f"... WHERE s.name = '{store}'"`처럼 글자를 이어 붙이면, 누군가 `?store=판교점' OR '1'='1`을 보냈을 때 그 글자가 SQL 문법이 되어 버려요. `%s`로 넘기면 그 글자 전체를 지점 이름 하나로 다뤄서, 실제로 보내 보면 빈 배열이 돌아와요.
</Hint>

## 7. 서버에서 계산하는 창구: /reports/stores

창구가 꼭 표를 통째로 줄 필요는 없어요. 서버가 SQL로 계산까지 해서 답만 돌려줄 수도 있어요. 1부 12절의 지점 성적표를 창구로 만들어요.

```python
@app.get("/reports/stores")
def store_report():
    return fetch_all("""
        SELECT s.name AS store,
               SUM(oi.qty * m.price) AS revenue,
               COUNT(DISTINCT o.order_id) AS orders
        FROM order_items oi
        JOIN orders o ON o.order_id = oi.order_id
        JOIN stores s ON s.store_id = o.store_id
        JOIN menus  m ON m.menu_id  = oi.menu_id
        GROUP BY s.name
        ORDER BY revenue DESC
    """)
```

```bash
curl http://127.0.0.1:8000/reports/stores
```

```text
[{"store":"판교점","revenue":2305700,"orders":249},{"store":"성수점","revenue":2200000,"orders":253},{"store":"연남점","revenue":2009700,"orders":212}]
```

`COUNT(DISTINCT o.order_id)`는 1부에서 pandas로 쓴 `nunique`와 같은 일이에요. 상세 줄이 아니라 주문 번호를 겹치지 않게 세요.

**여기까지 되면:** `/docs`에 창구 네 개(`/stores`, `/stores/{store_id}`, `/order-lines`, `/reports/stores`)가 보여요.

```python
import pandas as pd

print(r.headers["content-type"])
```

딕셔너리 리스트는 20회차에서 본 대로 바로 DataFrame이 돼요. 딕셔너리의 키가 열 이름이에요.

## 10. 실패를 먼저 잡는다: raise_for_status와 get_json()

요청이 늘 성공하지는 않아요. 없는 지점을 불러 봐요.

```python
r = requests.get(f"{BASE}/stores/9")
print(r.status_code)
r.json()
```

```text
404
{'detail': '그런 지점이 없어요'}
```

`requests`는 404가 와도 오류를 내지 않아요. 응답을 받는 데는 성공했으니까요. 이 본문을 모르고 표로 바꾸면 엉뚱한 곳에서 터져요.

```python
pd.DataFrame(r.json())
```

```text
ValueError: If using all scalar values, you must pass an index
```

진짜 원인(404)과 상관없어 보이는 오류예요. 그래서 본문을 쓰기 전에 `raise_for_status()`로 상태부터 확인해요. 4나 5로 시작하는 코드면 그 자리에서 이유가 분명한 오류를 내요.

```python
r.raise_for_status()
```

```text
HTTPError: 404 Client Error: Not Found for url: http://127.0.0.1:8000/stores/9
```

앞으로는 부를 때마다 이 확인을 하도록 함수 하나에 담아요. 1부의 `export_csv()`처럼 반복되는 일을 묶는 거예요.

```python
def get_json(path, params=None):
    """API를 호출해 JSON을 돌려준다. 실패하면 그 자리에서 오류를 낸다."""
    r = requests.get(f"{BASE}{path}", params=params, timeout=5)
    r.raise_for_status()
    return r.json()
```

```python
@app.get("/menus")
```

## 꼭 기억할 주의점

- `@app.get("/주소")` 아래 함수 하나가 창구 하나예요. 주소 안의 `{store_id}`는 경로 파라미터, 주소에 없는 함수 인자는 쿼리 파라미터가 돼요.
- 인자에 타입(`store_id: int`)을 적으면 FastAPI가 값을 검사해서 틀리면 함수를 부르기 전에 `422`를 돌려줘요.
- 찾는 것이 없으면 `raise HTTPException(status_code=404, ...)`로 알려요. `None`을 돌려주면 `200`에 `null`이 가요.
- 결과가 비었다는 것(`200`, `[]`)과 창구나 대상이 없다는 것(`404`)은 달라요.
- SQL에 값을 넣을 때는 늘 `%s` 자리 채우기예요. f-string으로 이어 붙이지 않아요.
- `requests`는 404, 500이 와도 오류를 내지 않아요. `raise_for_status()`로 먼저 확인하고, `timeout`을 꼭 줘요.
- JSON에는 날짜 타입이 없어요. 받은 날짜 열은 `pd.to_datetime`으로 바꿔야 `.dt`를 쓸 수 있어요. `null`은 `NaN`이 돼요.
- `fastapi dev`는 서버가 터미널을 붙잡고 있어요. 다른 명령은 새 터미널에서 쳐요. `500`의 진짜 이유는 서버 터미널에 찍혀요.
