수업 1~16회차는 윈도우의 Git Bash로 진행했어요. 맥으로 옮겨도 **명령은 거의 그대로**예요. `git`, `uv`, `docker`, `psql`, SQL은 글자 하나 안 바뀌어요.

[수업 복습](/class)의 모든 회차 레슨은 이제 맥 기준으로 고쳐 두었어요. 이 페이지는 윈도우에서 하던 것과 달라진 점을 한곳에 모으고, 새 맥을 처음 세팅하는 순서를 담았어요.

바뀌는 건 프로그램을 까는 방법, 터미널 이름, 그리고 몇몇 키예요. 위에서부터 차례로 한 번만 따라 하면 다음 수업을 맥에서 바로 이어 갈 수 있어요.

이 페이지에서 `Ctrl`은 맥 키보드의 **control** 키, `Cmd`는 **command** 키, `Option`은 **option** 키예요.

## 1. 바뀌는 것은 생각보다 적다

| 하는 일 | 윈도우에서 | 맥에서 |
| --- | --- | --- |
| 프로그램 설치 | `winget` | `brew` (Homebrew) |
| 터미널 | Git Bash (bash) | 터미널 앱 (zsh) |
| 터미널 설정 파일 | `~/.bashrc` | `~/.zshrc` |
| GitHub 로그인 | 첫 push 때 뜨는 로그인 창 | `gh auth login` 한 번 |
| 가상환경 활성화 | `source .venv/Scripts/activate` | `source .venv/bin/activate` |
| 경로 변환 막기 | `MSYS_NO_PATHCONV=1`, `//tmp` | **필요 없음** (`/tmp` 그대로) |
| Docker 밑바탕 | Docker Desktop + WSL 2 | Colima (터미널로 켜는 작은 리눅스 VM, 12절) |
| 내 폴더 | `/c/Users/<이름>` | `/Users/<이름>` (`~`) |
| 탐색기로 열기 | `explorer .` | `open .` |
| 주피터, VS Code 키 | `Alt` | `Option` |

15회차에서 `~/.bashrc`에 넣은 경로 변환 줄은 Git Bash만의 문제를 막던 거예요. 맥 터미널은 `/`로 시작하는 글자를 몰래 바꾸지 않아서 아무것도 넣지 않아도 돼요.

## 2. 터미널 열기와 맥 키보드 길들이기

`Cmd + Space`로 Spotlight를 열고 "터미널"을 쳐서 열어요. 1회차에서 배운 `echo $SHELL`을 치면 맥은 `/bin/zsh`가 나와요. 셸 이름만 다를 뿐 `ls -al`, `cd -`, `mkdir`, `rm -r`, `chmod +x`, `>`, `>>`는 똑같이 동작해요.

터미널 단축키도 그대로예요. `Ctrl + c`(멈추기), `Ctrl + u`, `Ctrl + w`, `Ctrl + a / Ctrl + e`, `Ctrl + l`, `Ctrl + r` 모두 **control** 키로 눌러요. command 키로 바뀌는 건 복사(`Cmd + C`)와 붙여넣기(`Cmd + V`)뿐이에요.

### 한영 전환은 Caps Lock으로

시스템 설정 > 키보드 > 텍스트 입력의 **편집**을 누르고, Caps Lock으로 ABC(영문) 입력 소스를 전환하는 옵션을 켜요. 짧게 누르면 한영이 바뀌고, 길게 누르면 대문자 고정이에요.

### 한글 상태에서 백틱이 ₩로 나온다

맥의 한글 입력기는 숫자 1 왼쪽 키를 누르면 `₩`를 넣어요. 코드 블록, 마크다운, 셸에서 백틱이 자주 필요하니 아래를 한 번 실행해 두면 한글 상태에서도 백틱이 나와요.

```bash
mkdir -p ~/Library/KeyBindings
cat > ~/Library/KeyBindings/DefaultKeyBinding.dict <<'EOF'
{
    "₩" = ("insertText:", "`");
}
EOF
```

이미 열려 있던 앱은 껐다 켜야 바뀌어요. 원래대로 돌리려면 그 파일을 지우면 돼요.

### 숨김 파일과 명령 기록

- **Finder에서 숨김 파일 보기:** `Cmd + Shift + .`을 누르면 `.git`, `.venv`, `.gitignore`가 보여요. 한 번 더 누르면 다시 숨어요.
- **`history`는 최근 16개만:** zsh의 `history`는 마지막 16줄만 보여 줘요. 전부 보려면 `history 1`을 쳐요. `!번호`, `!!`는 그대로 돼요.

## 3. 맥 필수 초기 세팅: 처음 한 번만

새 맥을 받으면 개발 도구를 깔기 전에 이것부터 해 둬요. 한 번 해 두면 다시 할 일이 없고, 안 해 두면 코드를 칠 때마다 조금씩 걸려요.

### 시스템 설정에서 손으로

| 할 일 | 어디서 | 왜 |
| --- | --- | --- |
| 최신 macOS로 업데이트 | 일반 > 소프트웨어 업데이트 | 4절 Homebrew와 12절 Colima가 최신 macOS 기준이에요 |
| Touch ID 손가락 등록 | Touch ID 및 암호 | 잠금 해제, 아래 `sudo` 지문 허용에 써요 |
| FileVault 켜기 | 개인정보 보호 및 보안 > FileVault | 맥을 잃어버려도 디스크를 못 읽어요. 새 맥은 보통 이미 켜져 있어요 |
| 탭하여 클릭하기 | 트랙패드 > 포인트 및 클릭 | 꾹 누르지 않고 톡 쳐서 클릭해요 |
| 키 반복 빠르게 | 키보드 > 키 반복 속도, 반복 지연 시간 | 화살표, 지우기, `vim`의 `j`를 꾹 누를 때 빨라요 |
| AirPlay 수신 모드 끄기 | 일반 > AirDrop 및 Handoff | 맥이 5000번, 7000번 포트를 먼저 차지해요. 뒤 수업에서 웹 서버를 5000번에 띄우면 부딪혀요 |
| Caps Lock 한영 전환 | 키보드 > 텍스트 입력 > 편집 | 2절에서 본 그것이에요 |

### `sudo`를 지문으로

Homebrew를 깔 때나 시스템 파일을 고칠 때 `sudo`가 비밀번호를 물어요. 아래 한 줄을 실행해 두면 그때마다 Touch ID로 넘어가요.

```bash
sed "s/^#auth/auth/" /etc/pam.d/sudo_local.template | sudo tee /etc/pam.d/sudo_local
```

이 명령 자체도 `sudo`라 비밀번호를 한 번 물어요. 이 파일은 macOS 업데이트에도 지워지지 않아요. 되돌리려면 `sudo rm /etc/pam.d/sudo_local`을 실행해요.

### 글자 자동 고침 끄기: 코드가 몰래 바뀌지 않게

맥은 글을 쓸 때 곧은 따옴표를 둥근 따옴표로, `--`를 긴 줄표로 바꾸고, 맞춤법을 고치고, 문장 첫 글자를 대문자로 바꿔요. 메모 앱이나 메신저에 적어 둔 코드를 터미널에 붙이면 이 바뀐 글자 때문에 명령이 깨져요.

```bash
defaults write NSGlobalDomain NSAutomaticQuoteSubstitutionEnabled -bool false
defaults write NSGlobalDomain NSAutomaticDashSubstitutionEnabled -bool false
defaults write NSGlobalDomain NSAutomaticSpellingCorrectionEnabled -bool false
defaults write NSGlobalDomain NSAutomaticCapitalizationEnabled -bool false
defaults write NSGlobalDomain NSAutomaticPeriodSubstitutionEnabled -bool false
defaults write NSGlobalDomain ApplePressAndHoldEnabled -bool false
```

위에서부터 둥근 따옴표, 긴 줄표, 맞춤법 고침, 첫 글자 대문자, 스페이스 두 번에 마침표를 꺼요. 마지막 줄은 **키를 꾹 누르면 악센트 글자 고르는 창이 뜨는 것**을 끄고 키 반복으로 바꿔요. 2회차의 `vim`에서 `j`를 꾹 눌러 내려가려면 꼭 필요해요.

로그아웃했다가 다시 들어오면 적용돼요. 시스템 설정 > 키보드 > 텍스트 입력 > 편집에서 같은 항목을 손으로 꺼도 돼요. 되돌리려면 `false`를 `true`로 바꿔 실행해요.

### Finder: 확장자, 경로, 상태 막대

```bash
defaults write NSGlobalDomain AppleShowAllExtensions -bool true
defaults write com.apple.finder ShowPathbar -bool true
defaults write com.apple.finder ShowStatusBar -bool true
killall Finder
```

이제 `main.py`, `compose.yaml`처럼 확장자가 늘 보이고, 창 아래에 지금 폴더의 경로와 남은 디스크 용량이 보여요. 경로 막대의 폴더를 우클릭하면 **경로 이름 복사**로 터미널에 붙일 경로를 얻어요.

### 스크린샷은 한 폴더로

맥은 스크린샷을 바탕화면에 쌓아요. 따로 모아 두면 TIL에 붙일 그림을 찾기 쉬워요.

```bash
mkdir -p ~/Pictures/Screenshots
defaults write com.apple.screencapture location ~/Pictures/Screenshots
killall SystemUIServer
```

| 키 | 하는 일 |
| --- | --- |
| `Cmd + Shift + 4` | 끌어서 고른 영역을 파일로 |
| `Cmd + Shift + 4` 뒤 `Space` | 창 하나를 통째로 |
| `Cmd + Shift + Ctrl + 4` | 파일 대신 클립보드로, 글에 바로 붙여 넣기 |
| `Cmd + Shift + 5` | 화면 녹화와 저장 위치 고르기 |

### 창 나란히 놓기

터미널은 왼쪽, 브라우저나 교안은 오른쪽에 두고 따라 하면 편해요. 창을 화면 왼쪽이나 오른쪽 끝으로 끌어다 놓으면 반쪽 크기로 붙어요. 키보드로는 `Fn + Ctrl + ←` 또는 `→`(지구본 키가 `Fn`)예요.

## 4. Homebrew: 맥의 winget

1회차의 winget이 맥에서는 **Homebrew**(명령 이름 `brew`)예요. 먼저 Homebrew 자체를 깔아요.

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

중간에 맥 로그인 비밀번호를 물어요. 쳐도 화면에 글자가 안 보이는 게 정상이니 그대로 치고 `Enter`를 눌러요. Git이 들어 있는 Xcode Command Line Tools도 이때 함께 깔려요.

<Note title="끝에 나오는 Next steps를 꼭 실행해요">

설치가 끝나면 화면 아래에 **Next steps**와 함께 명령 두세 줄이 나와요. 그 줄을 그대로 복사해 실행해야 `brew` 명령이 잡혀요. 애플 칩 맥에서는 보통 이런 모양이에요.

```bash
echo >> ~/.zprofile
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"
```

그다음 `brew --version`이 나오면 성공이에요. 안 나오면 터미널을 새로 열어 다시 확인해요.

</Note>

winget에서 쓰던 명령은 이렇게 바뀌어요.

| winget | brew | 하는 일 |
| --- | --- | --- |
| `winget search <검색어>` | `brew search <검색어>` | 패키지 검색 |
| `winget show <ID>` | `brew info <이름>` | 상세 정보 |
| `winget install <ID>` | `brew install <이름>` | 설치 |
| `winget list` | `brew list` | 설치된 목록 |
| `winget upgrade` | `brew outdated` | 업그레이드할 수 있는 목록 |
| `winget upgrade <ID>` | `brew upgrade <이름>` | 업그레이드 |
| `winget uninstall <ID>` | `brew uninstall <이름>` | 삭제 |

창이 뜨는 앱(VS Code, DBeaver 같은 것)은 `--cask`를 붙여 깔아요. 터미널에서만 쓰는 도구는 그냥 `brew install`이에요.

## 5. 수업 도구 한 번에 깔기

지금까지 수업에서 쓴 도구를 두 줄로 깔아요. 터미널을 편하게 해 주는 도구는 6절에서 따로 깔아요.

```bash
brew install git gh uv colima docker docker-compose
brew install --cask visual-studio-code dbeaver-community
```

| 이름 | 무엇 | 몇 회차 |
| --- | --- | --- |
| `git` | Git 최신 버전 | 1~4회차 |
| `gh` | GitHub 로그인 도우미 (8절) | 1, 2회차 push |
| `uv` | 파이썬 버전, 패키지, 가상환경 관리 | 5회차부터 |
| `visual-studio-code` | VS Code, `code` 명령도 함께 | 전체 |
| `colima` | Docker 엔진(작은 리눅스 VM)을 켜고 끄는 도구 (12절) | 14회차부터 |
| `docker` | `docker` 명령 (엔진에 일을 시키는 쪽) | 14회차부터 |
| `docker-compose` | `docker compose` 명령 (12절에서 한 번 연결) | 15회차부터 |
| `dbeaver-community` | DB 화면 도구 | 16회차 |

다 깔렸는지 확인해요. 넷 다 버전이 나오면 돼요.

```bash
git --version
gh --version
uv --version
code --version
```

<Hint>

`code --version`이 안 나오면 VS Code를 열고 `Cmd + Shift + P`에서 **Shell Command: Install 'code' command in PATH**를 실행해요.

</Hint>

## 6. 터미널을 개발자처럼: `~/.zshrc` 한 장으로

맥 터미널은 처음엔 거의 빈 상태예요. Git Bash가 기본으로 해 주던 브랜치 표시와 자동 완성을 `~/.zshrc`에 직접 적어 줘야 해요. 15회차에서 `~/.bashrc`를 고치던 것과 같은 일이에요.

여기에 개발자들이 맥에 거의 빠짐없이 까는 네 가지를 더해요. 치는 동안 전에 친 명령을 미리 보여 주고, 틀린 명령은 `Enter` 전에 빨갛게 알려 주고, 기록과 폴더를 몇 글자로 찾아요.

### 먼저 도구 깔기

```bash
brew install zsh-autosuggestions zsh-syntax-highlighting fzf zoxide
brew install --cask font-d2coding
```

| 이름 | 하는 일 |
| --- | --- |
| `zsh-autosuggestions` | 지금 치는 글자로 시작하는 지난 명령을 회색으로 이어 보여 줘요 |
| `zsh-syntax-highlighting` | 치는 동안 명령 이름이 맞으면 초록, 없는 명령이면 빨강으로 칠해요 |
| `fzf` | 기록, 파일을 글자 몇 개로 좁혀 고르는 검색 창이에요 |
| `zoxide` | 다녀간 폴더를 기억했다가 `z 이름 일부`로 바로 가요 |
| `font-d2coding` | 한글과 영문 폭이 딱 맞는 코딩 글꼴이에요 |

### `~/.zshrc`를 통째로 이걸로

```bash
code ~/.zshrc
```

파일이 없으면 VS Code가 새로 만들어요. 전에 이 페이지를 보고 붙여 넣은 내용이 있으면 **모두 지우고** 아래로 바꿔요. 저장한 뒤 터미널 창을 새로 열면 적용돼요.

```bash
# ~/.zshrc  맥 수업 실습용

# 0. 붙여 넣은 명령의 # 뒤를 주석으로 읽기 (zsh는 기본으로 꺼져 있어요)
setopt INTERACTIVE_COMMENTS

BREW_PREFIX="$(brew --prefix)"

# 1. 프롬프트에 폴더와 브랜치: ~/dev/my-project (main) %
autoload -Uz vcs_info
precmd() { vcs_info }
zstyle ':vcs_info:git:*' formats ' (%b)'
setopt PROMPT_SUBST
PROMPT='%F{blue}%~%f%F{green}${vcs_info_msg_0_}%f %# '

# 2. Tab 자동 완성: git, gh, docker, uv 하위 명령까지
FPATH="$BREW_PREFIX/share/zsh/site-functions:${FPATH}"
autoload -Uz compinit
compinit
zstyle ':completion:*' matcher-list 'm:{a-z}={A-Z}'
zstyle ':completion:*' menu select

# 3. 명령 기록: 넉넉하게, 탭끼리 같이, 중복은 한 번만
HISTFILE=~/.zsh_history
HISTSIZE=10000
SAVEHIST=10000
setopt SHARE_HISTORY
setopt HIST_IGNORE_ALL_DUPS

# 4. 줄임말
alias ll='ls -alh'
alias gs='git status'
alias glog='git log --oneline --graph --all'
alias dps='docker ps -a'

# 5. 회색 추천: 전에 친 명령을 미리 보여 주고 → 로 받기
source "$BREW_PREFIX/share/zsh-autosuggestions/zsh-autosuggestions.zsh"

# 6. fzf: Ctrl + r 기록 검색, Ctrl + t 파일 찾기
source <(fzf --zsh)

# 7. zoxide: z 폴더이름 으로 바로 가기
eval "$(zoxide init zsh)"

# 8. 색 검사: 꼭 맨 마지막 줄에
source "$BREW_PREFIX/share/zsh-syntax-highlighting/zsh-syntax-highlighting.zsh"
```

<Note title="0번 줄이 없으면 이 페이지의 명령이 깨져요">

zsh는 터미널에 직접 친 줄의 `#`을 주석으로 읽지 않아요. 그래서 `#` 설명이 붙은 명령을 복사해 붙이면 `#` 뒤 글자까지 명령에 넘어가요.

```text
% echo hi # 주석
hi # 주석
```

0번 줄을 넣은 뒤에는 `hi`만 나와요. Git Bash는 처음부터 켜져 있던 설정이라 윈도우에서는 몰랐던 차이예요.

</Note>

번호마다 하는 일이에요.

- **1. 브랜치 표시:** Git Bash는 프롬프트 끝에 `(main)`을 늘 보여 줬어요. 맥 기본 프롬프트에는 이게 없어서 3회차처럼 브랜치를 오갈 때 지금 어디 있는지 놓치기 쉬워요.
- **2. 자동 완성:** `git sw`까지 치고 `Tab`을 누르면 `git switch`로, `git switch `에서 `Tab`을 누르면 브랜치 이름이 나와요. 후보가 여럿이면 `Tab`을 한 번 더 눌러 화살표로 골라요. 소문자로 쳐도 `Desktop`, `Documents`가 잡혀요.
- **3. 기록:** 2절에서 본 `history`가 짧은 문제를 덜고, 탭 여러 개에서 친 명령을 함께 찾아요.
- **4. 줄임말:** `ll`은 1회차 `ls -al`에 크기를 KB, MB로 붙인 것, `glog`는 2회차의 브랜치 그래프예요. 다만 수업 중에는 **원래 명령을 손으로 치는 게 먼저**예요. 시험이나 다른 컴퓨터에는 줄임말이 없어요.
- **5. 회색 추천:** `docker com`까지 치면 어제 친 `docker compose up -d`가 회색으로 이어 보여요. `→` 또는 `Ctrl + e`로 받고, 무시하려면 그냥 계속 쳐요.
- **6. fzf:** `Ctrl + r`을 누르고 `compose`처럼 기억나는 글자만 치면 그 글자가 든 지난 명령이 좁혀져요. `Ctrl + t`는 지금 폴더 아래 파일 이름을 찾아 명령 줄에 넣어 줘요.
- **7. zoxide:** 한 번 `cd ~/dev/my-project`로 가 봤다면 다음부터 어디서든 `z my`만 쳐도 그 폴더로 가요. 원래 `cd`도 그대로 돼요.
- **8. 색 검사:** `gti status`처럼 오타를 내면 `Enter` 전에 빨갛게 보여요. 이 줄은 다른 설정이 다 끝난 뒤에 읽어야 제대로 칠해서 **맨 마지막**에 둬요.

<Hint>

`compinit`이 `insecure directories`라고 경고하면 `compaudit | xargs chmod g-w`를 한 번 실행하고 터미널을 새로 열어요. 많이 쓰는 Oh My Zsh는 이런 설정을 묶어 둔 꾸러미예요. 위 파일과 같이 깔면 설정이 겹치니 둘 중 하나만 써요.

</Hint>

### 터미널 앱 설정 (터미널 > 설정)

- **프로파일 > 텍스트:** 서체를 **D2Coding**으로 바꾸고 글자 크기를 키운 뒤 **기본값**을 눌러요. 기본값으로 정하지 않으면 새 창은 예전 모양으로 열려요.
- **프로파일 > 키보드:** **Option 키를 Meta 키로 사용**을 켜요. 그러면 `Option + b`, `Option + f`로 단어 단위로 커서를 옮기고, fzf의 `Option + c`(폴더 골라 이동)도 돼요.
- **프로파일 > 셸:** 셸이 종료될 때 창을 닫도록 고르면 `exit`로 창까지 정리돼요.
- **일반 > 새 탭 열기:** 같은 작업 디렉터리로 열게 하면 `Cmd + T`로 연 새 탭이 지금 폴더에서 시작해요. 한 탭은 `docker compose logs -f`, 다른 탭은 `psql`처럼 나눠 쓸 때 편해요.

<Note title="VS Code 안의 터미널도 같은 설정을 써요" tone="info">

VS Code의 `` Ctrl + ` `` 터미널도 zsh라서 `~/.zshrc`를 그대로 읽어요. 글꼴만 따로예요. `Cmd + ,`로 설정을 열고 `Terminal Integrated Font Family`를 찾아 `D2Coding`을 넣어요.

</Note>

### 맥에만 있는 편한 명령

- **`open .`:** 지금 폴더를 Finder로 열어요. `open main.py`는 그 파일을 기본 앱으로 열어요.
- **`pbcopy`:** 받은 글을 클립보드에 넣어요. `git diff | pbcopy`나 `pbcopy < main.py`로 출력이나 파일을 바로 복사해 TIL에 붙여요.
- **`pbpaste`:** 클립보드 내용을 내보내요. `pbpaste > notes.md`로 복사해 둔 글을 파일로 저장해요.
- **`Cmd + K`:** 터미널 화면을 지워요. `Ctrl + l`과 달리 위로 올려도 안 보이게 깨끗해져요.

<Hint>

터미널 앱을 바꾸고 싶다면 `brew install --cask iterm2`나 `brew install --cask ghostty`로 깔아요. 개발자들이 많이 쓰는 두 앱인데, 어느 쪽이든 같은 `~/.zshrc`를 읽어서 위 설정이 그대로 따라가요. 기본 터미널로도 수업에는 충분해요.

</Hint>

## 7. Git 설정: 윈도우 설치 화면에서 고른 것을 명령으로

1회차에 `winget install -i Git.Git`의 설치 화면에서 기본 에디터와 기본 브랜치 이름을 골랐어요. 맥에는 그 화면이 없어서 명령으로 정해요. 2회차의 사용자 정보도 새 컴퓨터라 다시 넣어요.

```bash
git config --global user.name "내 이름"
git config --global user.email "GitHub 계정 이메일"
git config --global init.defaultBranch main
git config --global core.editor "code --wait"
git config --global --list
```

- **`user.email`:** 2회차에서 본 대로 **GitHub 계정에 등록한 이메일**과 같아야 커밋이 내 계정으로 잡혀요.
- **`init.defaultBranch main`:** `git init`할 때 첫 브랜치 이름이 `main`이 돼요.
- **`core.editor "code --wait"`:** 커밋 메시지나 병합 메시지를 VS Code에서 써요. `--wait`가 있어야 탭을 닫을 때까지 Git이 기다려요. 2회차처럼 `vim`이 편하면 이 줄은 빼도 돼요(맥 Git의 기본이 `vim`이에요).

윈도우 Git은 줄 끝 문자(CRLF, LF)를 알아서 바꿔 주는 설정이 켜져 있었어요. 맥과 리눅스는 원래 LF라서 따로 켤 필요가 없어요.

### 맥이 폴더마다 만드는 `.DS_Store` 무시하기

Finder는 열어 본 폴더마다 보기 설정을 담은 숨김 파일 `.DS_Store`를 만들어요. 그냥 두면 `git status`에 `?? .DS_Store`로 뜨고, 실수로 `git add .`하면 저장소에 올라가요.

```bash
mkdir -p ~/.config/git
echo ".DS_Store" >> ~/.config/git/ignore
```

`~/.config/git/ignore`는 Git이 따로 설정하지 않아도 **모든 저장소에서** 읽는 무시 목록이에요. 한 번 넣으면 저장소마다 `.gitignore`에 적지 않아도 돼요. `.DS_Store`와 `a.txt`가 있는 폴더에서 `git status --short`를 치면 `?? a.txt`만 나와요.

## 9. 윈도우에서 하던 프로젝트 옮기기

옮기는 길은 **GitHub를 거치는 것**이에요. 폴더를 USB로 통째로 복사하지 않아요.

1. **윈도우에서 마지막으로:** 각 저장소에서 `git status`로 남은 변경이 없는지 보고, 아직 안 올린 커밋은 `git push`해 둬요.
2. **맥에서 받기:**

```bash
mkdir -p ~/dev && cd ~/dev
git clone https://github.com/my-id/my-project.git
cd my-project
uv sync
```

<Note title="따라오지 않는 세 가지">

- **`.venv`:** `.gitignore`에 들어 있어서 저장소에 없어요. 5회차에 본 대로 `uv sync` 한 번이면 맥용으로 새로 만들어져요. 윈도우의 `.venv`를 복사하면 안에 윈도우용 `python.exe`가 들어 있어서 맥에서 돌지 않아요.
- **`.git/hooks`의 훅:** 2회차에서 본 대로 훅은 내 컴퓨터에만 있어요. 맥에서 다시 만들고 `chmod +x .git/hooks/<훅 이름>`으로 실행 권한을 줘요.
- **Docker 볼륨의 데이터:** 볼륨은 윈도우 Docker Desktop 안에 남아요. compose 파일과 SQL 파일만 저장소로 옮기고, 맥에서 다시 띄워 SQL을 다시 실행해요(12절).

</Note>

## 10. 파이썬과 uv: Scripts 대신 bin

5회차의 uv 명령은 하나도 안 바뀌어요. `uv init --no-package`, `uv python pin 3.12`, `uv python install`, `uv add`, `uv sync`, `uv run main.py` 그대로 쳐요.

바뀌는 건 세 가지예요.

- **활성화 경로:** 맥의 `.venv` 안에는 `Scripts` 폴더가 없고 `bin` 폴더가 있어요.

```bash
source .venv/bin/activate
which python      # /Users/<이름>/.../my-project/.venv/bin/python
deactivate
```

- **맥에는 `python` 명령이 없어요.** 시스템에는 오래된 `python3`만 있어요. 그래서 가상환경 밖에서 `python`을 치면 `command not found`가 나와요. 5회차의 `python -c "import dis; dis.dis('...')"` 같은 건 `uv run python -c "..."`로 치거나, 위처럼 활성화한 뒤에 쳐요.
- **대괄호가 든 이름은 따옴표로:** zsh는 `[ ]`를 파일 이름 패턴으로 읽어요. 19회차의 `uv add psycopg[binary]`를 그대로 치면 `zsh: no matches found: psycopg[binary]`가 나요. `uv add "psycopg[binary]"`처럼 감싸요.

### `docker compose` 연결하기 (처음 한 번만)

brew로 깐 `docker-compose`는 `docker` 명령이 바로 찾지 못해요. `docker`는 `~/.docker/cli-plugins` 폴더에 있는 부품만 `docker 부품이름`으로 불러 주거든요. 그 폴더에 바로가기(심볼릭 링크)를 하나 넣어요.

```bash
mkdir -p ~/.docker/cli-plugins
ln -sfn "$(brew --prefix)/opt/docker-compose/bin/docker-compose" ~/.docker/cli-plugins/docker-compose
docker compose version
```

`Docker Compose version v2...`처럼 버전이 나오면 연결된 거예요. Colima 공식 문서가 같은 방식으로 `buildx` 부품을 연결해요.

- `ln -sfn 원본 바로가기`: 원본 파일을 가리키는 바로가기를 만들어요. `-f`는 이미 있으면 바꿔 끼우기, `-s`는 심볼릭 링크예요.
- `"$(brew --prefix)/opt/..."`: `brew --prefix`가 brew 설치 폴더(애플 칩 맥은 `/opt/homebrew`)로 바뀌어 들어가요. 그 아래가 brew가 깐 `docker-compose`의 자리예요.

### 켜기: colima start

```bash
colima start
```

처음 한 번은 리눅스 VM을 내려받아 만드느라 1~2분 걸려요. 다음부터는 금방 켜져요. 켜졌는지 확인해요.

```bash
colima status          # colima is running 이 보이면 켜진 거예요
docker context ls      # colima 줄 옆에 * 가 붙어 있어요
docker run --rm hello-world
```

`Hello from Docker!`가 나오면 준비 끝이에요. `docker context`는 "`docker` 명령이 어느 엔진에 말을 걸지"를 정하는 설정이에요. `colima start`가 스스로 `colima`를 기본으로 정해 줘서 따로 할 일은 없어요.

Colima는 처음에 CPU 2개, 메모리 2GiB, 디스크 100GiB로 VM을 만들어요. 수업 실습(PostgreSQL, nginx, Redis)에는 충분해요. 컨테이너를 여러 개 띄워 느려지면 끄고 크기를 바꿔 다시 켜요.

```bash
colima stop
colima start --cpu 4 --memory 4   # CPU 4개, 메모리 4GiB
```

### 켜고 끄는 명령

| 명령 | 하는 일 | 컨테이너, 이미지, 볼륨 |
| --- | --- | --- |
| `colima start` | 엔진 켜기 | 지난번 그대로 돌아와요 |
| `colima status` | 켜졌는지 보기 | |
| `colima stop` | 엔진 끄기. 맥 메모리를 돌려받아요 | 남아요 |
| `colima restart` | 껐다 켜기. 엔진이 이상할 때 | 남아요 |
| `colima delete` | VM 지우기 | 최근 버전(0.9.0부터)은 데이터를 남기고, `--data`를 붙이면 다 지워요 |

맥을 다시 켜면 Colima는 꺼져 있어요. 실습 전에 `colima start`부터 쳐요. 맥에 로그인할 때 저절로 켜지게 하려면 한 번만 이렇게 해 둬요.

```bash
brew services start colima   # 로그인할 때마다 자동으로 켜기
brew services stop colima    # 자동 켜기 그만
```

### 맥에서 달라지는 것과 그대로인 것

- **포트는 그대로 `localhost`예요.** 컨테이너에서 `-p 8080:80`이나 compose의 `ports:`로 연 포트를 Colima가 맥의 `localhost`로 이어 줘요. 브라우저, DBeaver, 파이썬 모두 `localhost`로 접속해요.
- **수업 이미지는 다 맥용이 있어요.** `nginx`, `ubuntu:24.04`, `mysql:8.4`, `redis`, `postgres:18` 모두 애플 칩용 이미지가 있어서 받는 명령도 그대로예요.
- **Git Bash 우회는 전부 버려요.** 15회차의 `//tmp`는 `/tmp`로 쓰면 되고, `MSYS_NO_PATHCONV` 줄은 넣지 않아요. 14회차의 `docker exec -i my-pg psql -U postgres < products.sql`도 맥 터미널에서 그대로 돼요.
- **데이터는 다시 넣어요.** 16회차 `SportsCenter` 폴더를 받아 `docker compose up -d`로 띄우고, SQL 파일을 다시 실행하면 표와 데이터가 돌아와요.

<Hint>
`Cannot connect to the Docker daemon`이 나오면 Colima가 꺼져 있는 거예요. `colima start` 뒤에 다시 쳐요. `docker compose`가 "그런 명령이 없다"고 나오면 위의 연결하기를 빠뜨린 거예요. 이미지를 받을 때 `docker-credential-desktop`을 찾을 수 없다고 나오면 Docker Desktop이 남긴 설정 때문이에요. `code ~/.docker/config.json`으로 열어 `"credsStore": "desktop"` 줄을 지우고 저장해요.
</Hint>

## 13. DBeaver: 접속 정보는 같고 실행 키만 다르다

16회차와 똑같이 Host `localhost`, Port `5432`, Database `sportscenter`, Username `postgres`, Password는 compose 파일의 값으로 연결해요.

커서가 있는 SQL 문장을 실행하는 키는 맥에서 `Cmd + Enter`예요. 안 되면 예전 버전이라서 `Ctrl + Enter`예요.

프롬프트가 `~ %`처럼 파란 폴더 이름으로 바뀌었고, `gi`까지 쳤을 때 회색 글씨가 이어 보이면 6절 설정도 잘 들어간 거예요.

## 맥으로 옮길 때 꼭 기억할 주의점

- 명령은 그대로예요. 바뀌는 건 설치 도구 `brew`, 셸 `zsh`, 설정 파일 `~/.zshrc`예요.
- 새 맥이면 도구보다 먼저 3절의 초기 세팅을 해요. 특히 글자 자동 고침을 꺼야 붙여 넣은 코드의 따옴표가 바뀌지 않아요.
- `~/.zshrc`의 첫 줄 `setopt INTERACTIVE_COMMENTS`가 없으면 `#` 설명이 붙은 명령이 깨져요. 색 검사(`zsh-syntax-highlighting`) 줄은 늘 맨 마지막이에요.
- zsh에서 `psycopg[binary]`처럼 대괄호가 든 이름은 `"psycopg[binary]"`로 따옴표를 쳐요.
- `.DS_Store`는 `~/.config/git/ignore`에 한 번 넣어 두면 모든 저장소에서 무시돼요.
- 웹 서버를 5000번 포트에 띄웠는데 이미 쓰는 중이라고 나오면 AirPlay 수신 모드를 꺼요.
- 프로젝트는 GitHub로 옮기고 `uv sync`로 `.venv`를 새로 만들어요. `.venv`, 훅, Docker 볼륨은 따라오지 않아요.
- 가상환경 활성화는 `source .venv/bin/activate`, 맥에는 `python` 명령이 없으니 `uv run python`을 써요.
- 터미널 단축키는 control, 복사와 붙여넣기는 command, 윈도우의 `Alt`는 option이에요.
- 15회차의 경로 변환 설정(`MSYS_NO_PATHCONV`, `//tmp`)은 Git Bash 전용이라 맥에서는 넣지 않아요.
- 인터넷에서 찾은 `sed -i` 명령은 맥에서 `sed -i ''`처럼 빈 따옴표를 하나 더 넣어야 돼요. 맥의 `sed`는 리눅스 것과 조금 달라요.
- 맥의 Docker 엔진은 Colima예요. 맥을 다시 켠 뒤에는 `colima start`부터, 다 쓰면 `colima stop`이에요. `Cannot connect to the Docker daemon`은 Colima가 꺼져 있다는 뜻이에요.
- brew로 깐 `docker compose`는 `~/.docker/cli-plugins`에 바로가기를 한 번 넣어야 불려요(12절).
