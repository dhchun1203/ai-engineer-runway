지금까지 배운 것을 한 줄로 잇는 작은 프로젝트예요. Docker로 데이터베이스를 켜고, SQL로 표와 데이터를 넣고, 파이썬으로 꺼내서 pandas와 NumPy로 분석해요. 마지막에는 분석 결과를 다시 데이터베이스에 저장해요.

재료는 동네 카페 세 지점(성수점, 연남점, 판교점)의 2주 치 주문이에요. 사장님이 "다음 주에 어느 지점, 어느 시간에 사람을 더 넣을까?"를 묻는다고 생각하고 숫자로 답을 찾아요.

이 레슨은 맥 터미널(zsh) 기준이에요. 맥 준비가 아직이라면 [맥 실습 환경](/class/mac-setup)을 먼저 끝내고 오세요. Colima(맥의 Docker 엔진), `uv`, VS Code가 깔려 있으면 돼요.

아래 명령과 출력은 모두 `postgres:18`, Python 3.14, pandas 3.1.1, NumPy 2.5.5, psycopg 3.3.9에서 직접 실행해 확인했어요. 노트북에서는 DataFrame이 예쁜 표로 보이지만, 여기서는 같은 내용을 글자로 옮겼어요.

## 2. 프로젝트 폴더와 compose.yaml: 켜는 법을 파일 한 장에 적는다

Docker 엔진부터 켜요. 맥에서는 Colima가 엔진이에요.

```bash
colima start            # Docker 엔진 켜기 (이미 켜져 있다고 나와도 괜찮아요)
colima status           # colima is running 이면 준비 완료
docker compose version  # 버전이 나오면 compose도 준비 완료
```

프로젝트 폴더를 만들고 VS Code로 열어요. 이 폴더 하나에 DB 설정, 시드 파일, 파이썬 코드가 모두 들어가요.

```bash
mkdir -p ~/dev/cafe-analysis
cd ~/dev/cafe-analysis
code .
```

VS Code 왼쪽 탐색기에서 새 파일 `compose.yaml`을 만들고 아래를 적어요. 15회차에 배운 `docker run` 옵션이 한 자리씩 옮겨진 모양이에요.

```yaml
services:
  db:
    image: postgres:18          # 사용할 이미지
    container_name: cafe-pg     # docker ps 에 보일 이름
    environment:
      POSTGRES_PASSWORD: admin  # postgres 계정 비밀번호
    ports:
      - "5433:5432"             # 내 맥 5433 -> 컨테이너 5432
    volumes:
      - cafe-data:/var/lib/postgresql   # 데이터를 볼륨에 보관

volumes:
  cafe-data:                    # 이 프로젝트 전용 볼륨
```

## 3. 컨테이너 켜기: docker compose up -d 한 줄

`compose.yaml`이 있는 폴더에서 켜요. `-d`는 "뒤에서 돌려 두고 터미널은 돌려줘"라는 뜻이에요.

```bash
docker compose up -d
```

```text
 Network cafe-analysis_default Created
 Volume cafe-analysis_cafe-data Created
 Container cafe-pg Created
 Container cafe-pg Started
```

맥에서 `postgres:18`을 처음 쓰면 이미지를 내려받는 줄(`Pulling`)이 먼저 지나가요. 한 번 받아 두면 다음부터는 바로 켜져요.

```bash
docker compose ps
```

```text
NAME      IMAGE         COMMAND                   SERVICE   CREATED         STATUS         PORTS
cafe-pg   postgres:18   "docker-entrypoint.s…"   db        6 seconds ago   Up 5 seconds   0.0.0.0:5433->5432/tcp, [::]:5433->5432/tcp
```

**여기까지 되면:** `STATUS`가 `Up`이고 `PORTS`에 `5433->5432`가 보여요.

<Hint>
`Cannot connect to the Docker daemon`이 나오면 Colima가 꺼져 있는 거예요. `colima start` 뒤에 다시 쳐요. `docker compose`가 없는 명령이라고 나오면 [맥 실습 환경](/class/mac-setup) 12절의 compose 연결을 먼저 해요. `port is already allocated`가 나오면 맥의 5433을 다른 프로그램이 쓰는 중이에요. `compose.yaml`의 왼쪽 숫자를 `"5434:5432"`처럼 바꾸고, 뒤에 나오는 접속 주소의 포트도 같이 바꿔요.
</Hint>

## 4. 데이터베이스 만들기: 빈 서버에 cafe_db 하나

컨테이너 안의 `psql`로 들어가요. `-it`는 "내 키보드로 대화하겠다"는 뜻이에요.

```bash
docker exec -it cafe-pg psql -U postgres
```

프롬프트가 `postgres=#`로 바뀌면 SQL을 칠 수 있어요. 데이터베이스를 만들고 목록에서 확인해요.

```sql
CREATE DATABASE cafe_db;
\l
```

**여기까지 되면:** 목록 맨 위에 `cafe_db`가 있어요. `\q`로 나와요. 목록이 길어 `:`에서 멈추면 `q`를 누르면 돼요.

<Hint>
`CREATE DATABASE`의 세미콜론(`;`)을 빠뜨리면 프롬프트가 `postgres-#`로 바뀌고 아무 일도 안 일어나요. 문장이 안 끝났다는 표시예요. `;`만 치고 Enter를 누르면 실행돼요.
</Hint>

## 5. 시드 파일 읽기: 표 다섯 개와 그 사이의 줄

시드 파일을 내려받아요.

넣기 전에 VS Code에서 열어 읽어 봐요. 위에서부터 **지우기, DDL(표 만들기), DML(행 넣기)** 순서예요. 16회차와 17회차에 배운 것이 그대로 들어 있어요.

DDL 부분은 이래요. 열 하나하나가 왜 그 타입과 제약 조건인지 읽어 보세요.

```sql
CREATE TABLE stores (
    store_id  SERIAL PRIMARY KEY,
    name      VARCHAR(20) NOT NULL UNIQUE,
    region    VARCHAR(30) NOT NULL,
    opened_on DATE NOT NULL
);

CREATE TABLE menus (
    menu_id  SERIAL PRIMARY KEY,
    name     VARCHAR(30) NOT NULL UNIQUE,
    category VARCHAR(10) NOT NULL CHECK (category IN ('커피', '음료', '디저트')),
    price    INTEGER NOT NULL CHECK (price > 0),
    cost     INTEGER NOT NULL CHECK (cost > 0 AND cost < price)
);

CREATE TABLE members (
    member_id SERIAL PRIMARY KEY,
    nickname  VARCHAR(20) NOT NULL,
    joined_on DATE NOT NULL
);

CREATE TABLE orders (
    order_id   SERIAL PRIMARY KEY,
    store_id   INTEGER NOT NULL REFERENCES stores (store_id),
    member_id  INTEGER REFERENCES members (member_id),  -- 비회원 주문은 NULL
    ordered_at TIMESTAMP NOT NULL
);

CREATE TABLE order_items (
    order_id INTEGER NOT NULL REFERENCES orders (order_id),
    menu_id  INTEGER NOT NULL REFERENCES menus (menu_id),
    qty      INTEGER NOT NULL CHECK (qty > 0),
    PRIMARY KEY (order_id, menu_id)
);
```

`orders.member_id`에만 `NOT NULL`이 없어요. 비회원 주문을 받아야 해서예요. 이 빈칸이 10절에서 pandas의 `NaN`으로 다시 나타나요.

돈은 `NUMERIC`이 아니라 `INTEGER`(원 단위)로 두었어요. 원화는 소수점이 없고, 파이썬으로 꺼냈을 때 그냥 정수로 받아져서 pandas 계산이 쉬워요.

DML 부분은 기준 데이터(지점, 메뉴, 회원)를 먼저 넣고, 그걸 참조하는 주문과 주문 상세를 나중에 넣어요.

```sql
INSERT INTO stores (name, region, opened_on) VALUES
    ('성수점', '서울 성동구', '2023-04-01'),
    ('연남점', '서울 마포구', '2024-09-14'),
    ('판교점', '성남 분당구', '2025-03-03');

INSERT INTO menus (name, category, price, cost) VALUES
    ('아메리카노', '커피', 4500, 900),
    ('카페라테', '커피', 5000, 1400),
    ('바닐라라테', '커피', 5500, 1700),
    ('콜드브루', '커피', 5000, 1100),
    ('자몽에이드', '음료', 6000, 2100),
    ('말차라테', '음료', 5800, 1900),
    ('레몬티', '음료', 5000, 1300),
    ('크루아상', '디저트', 4000, 1600),
    ('소금빵', '디저트', 3500, 1200),
    ('바스크치즈케이크', '디저트', 6500, 2600);

-- members 20명 (하늘, 바다, 우주, ...)

-- 4. DML: 주문 714건. 시간 순서대로 넣어서 order_id 1번이 가장 이른 주문이다.
INSERT INTO orders (store_id, member_id, ordered_at) VALUES
    (3, 1, '2026-11-02 08:14'),
    (3, NULL, '2026-11-02 08:19'),
    (1, NULL, '2026-11-02 08:22'),
    ...

-- 5. DML: 주문 상세 1104줄. (주문 번호, 메뉴 번호, 수량)
INSERT INTO order_items (order_id, menu_id, qty) VALUES
    (1, 7, 1),
    (2, 8, 1),
    (2, 1, 1),
    ...
```

`orders`에는 `order_id`를 적지 않았어요. `SERIAL`이 넣는 순서대로 1, 2, 3을 매겨요. 그래서 `order_items`의 `(2, 8, 1)`은 "두 번째로 넣은 주문에 메뉴 8번(크루아상) 1개"예요.

<Hint>
파일 맨 위의 `DROP TABLE IF EXISTS`는 "있으면 지우고, 없으면 넘어가라"예요. 참조하는 표(`order_items`)부터 지워야 참조받는 표(`stores`)를 지울 수 있어요. 이 줄들 덕분에 시드를 몇 번 다시 넣어도 늘 같은 714건으로 돌아가요.
</Hint>

## 6. 시드 넣기: 파일 하나를 psql에 흘려 넣는다

이번엔 `-it` 대신 `-i`만 써요. 키보드가 아니라 파일을 `<`로 흘려 넣기 때문이에요. 맥은 경로 변환 문제가 없어서 윈도우 때처럼 `docker cp`를 거치지 않아도 돼요.

```bash
docker exec -i cafe-pg psql -U postgres -d cafe_db < cafe-seed.sql
```

```text
NOTICE:  table "store_daily_sales" does not exist, skipping
DROP TABLE
NOTICE:  table "order_items" does not exist, skipping
DROP TABLE
...
CREATE TABLE
CREATE TABLE
CREATE TABLE
CREATE TABLE
CREATE TABLE
INSERT 0 3
INSERT 0 10
INSERT 0 20
INSERT 0 714
INSERT 0 1104
```

처음 넣을 때는 지울 표가 없어서 `NOTICE`가 나와요. 오류가 아니라 안내예요. `-d cafe_db`를 빠뜨리면 표가 `postgres` 데이터베이스에 들어가니 꼭 붙여요.

다시 `psql`로 들어가서 표와 행 수를 확인해요. 이번엔 처음부터 `cafe_db`로 들어가요.

```bash
docker exec -it cafe-pg psql -U postgres -d cafe_db
```

```sql
\dt
SELECT (SELECT COUNT(*) FROM stores)      AS stores,
       (SELECT COUNT(*) FROM menus)       AS menus,
       (SELECT COUNT(*) FROM members)     AS members,
       (SELECT COUNT(*) FROM orders)      AS orders,
       (SELECT COUNT(*) FROM order_items) AS order_items;
```

```text

--------+-------------+-------+----------

 public | stores      | table | postgres
(5 rows)

--------+-------+---------+--------+-------------
      3 |    10 |      20 |    714 |        1104
(1 row)
```

**여기까지 되면:** 표 5개, 숫자 `3 | 10 | 20 | 714 | 1104`가 똑같이 나와요. `\q`로 나와요. 이제 DB 쪽 준비는 끝났어요.

## 7. 파이썬 준비: 같은 폴더를 uv 프로젝트로

같은 `cafe-analysis` 폴더를 파이썬 프로젝트로 만들어요. 이미 폴더 안에 있으니 `uv init` 뒤에 이름을 붙이지 않아요. 폴더 이름이 곧 프로젝트 이름이 돼요.

```bash
cd ~/dev/cafe-analysis
uv init --no-package --python 3.14
rm main.py
uv add pandas numpy "psycopg[binary]"
uv add --dev ipykernel
```

```text
Initialized project `cafe-analysis`
...
 + numpy==2.5.5
 + pandas==3.1.1
 + psycopg==3.3.9
 + psycopg-binary==3.3.9
...
```

`psycopg[binary]`는 19회차에 쓴 PostgreSQL 드라이버예요. 대괄호 안의 `binary`는 "맥에 PostgreSQL 프로그램이 없어도 되게 접속 부품을 같이 넣어 줘"라는 뜻이에요. zsh는 대괄호를 특별한 글자로 읽어서 따옴표로 감싸야 해요.

## 9. query() 함수: 결과를 DataFrame으로 받는 통로 하나

SQL을 보낼 때마다 연결하고, 열 이름 챙기고, 표로 바꾸는 일을 함수 하나에 담아요. 앞으로 모든 데이터는 이 통로로 들어와요.

```python
def query(sql, params=None):
    """SQL을 보내고 결과를 DataFrame으로 돌려준다."""
    with psycopg.connect(DSN) as conn:
        cur = conn.execute(sql, params)
        columns = [col.name for col in cur.description]
        return pd.DataFrame(cur.fetchall(), columns=columns)

query("SELECT * FROM stores")
```

## 16. 미션 6. 회원과 단골: 평균과 중앙값을 같이 본다

**질문:** 회원이 비회원보다 많이 쓰나? 단골은 누구인가?

`isna()`는 칸마다 "비었나?"를 True/False로 답해요. True는 1로 세지니 `sum()`이 빈칸 수예요.

```python
print(orders["member_id"].isna().sum())
orders["who"] = np.where(orders["member_id"].isna(), "비회원", "회원")
orders.groupby("who")["total"].agg(["count", "mean", "median"]).round()
```

```text

     count    mean  median
who
비회원    398  8931.0  7500.0
회원     316  9369.0  8500.0
```

`agg`에 이름 목록을 주면 계산마다 열이 하나씩 생겨요. 평균(`mean`)은 아주 큰 값 하나에도 끌려가요. 중앙값(`median`)은 금액 순으로 세웠을 때 한가운데 값이라 덜 흔들려요. 둘 다 회원이 1,000원쯤 높아요.

이제 `member_id`를 정수로 되돌려요. 대문자로 시작하는 `"Int64"`는 빈칸을 품을 수 있는 정수 타입이에요. 빈칸은 `<NA>`로 보여요.

## 18. SQL로 맞춰 보기: 같은 질문, 같은 답

pandas로 낸 지점 성적표가 맞는지, 같은 질문을 SQL로 DB에 직접 물어봐요. 터미널에서 `psql`로 들어가요.

```bash
docker exec -it cafe-pg psql -U postgres -d cafe_db
```

```sql
SELECT s.name AS store, SUM(oi.qty * m.price) AS revenue, COUNT(DISTINCT o.order_id) AS orders
FROM order_items oi
JOIN orders o ON o.order_id = oi.order_id
JOIN stores s ON s.store_id = o.store_id
JOIN menus  m ON m.menu_id  = oi.menu_id
GROUP BY s.name
ORDER BY revenue DESC;
```

```text
 store  | revenue | orders
--------+---------+--------
 판교점 | 2305700 |    249
 성수점 | 2200000 |    253
 연남점 | 2009700 |    212
(3 rows)
```

12절의 `by_store`와 숫자가 똑같아요. 두 도구가 이렇게 짝을 이뤄요.

| 하는 일 | SQL | pandas |
| --- | --- | --- |
| 묶기 | `GROUP BY s.name` | `groupby("store")` |
| 합계 | `SUM(oi.qty * m.price)` | `("amount", "sum")` |
| 서로 다른 값 세기 | `COUNT(DISTINCT o.order_id)` | `("order_id", "nunique")` |
| 정렬 | `ORDER BY revenue DESC` | `sort_values("revenue", ascending=False)` |
| 표 붙이기 | `JOIN ... ON` | `merge(..., on=...)` |

원본 데이터를 많이 줄이는 집계는 SQL로, 여러 각도로 돌려 보는 분석은 pandas로 하면 편해요. 결과가 중요하면 이렇게 두 길로 한 번씩 맞춰 봐요.

## 19. 결과를 DB에 저장: DataFrame을 표로 돌려보낸다

마지막으로 "지점별 하루 매출" 표를 만들어 DB에 저장해요. 다른 사람이 분석을 다시 돌리지 않고도 SQL로 바로 꺼내 볼 수 있게요.

```python
orders["sales_date"] = orders["ordered_at"].dt.date
daily = orders.groupby(["sales_date", "store_id"]).agg(
    order_count=("order_id", "count"),
    revenue=("total", "sum"),
).reset_index()
print(daily.shape)
daily.head(3)
```

```text

   sales_date  store_id  order_count  revenue
0  2026-11-02         1           16   141000
1  2026-11-02         2           11    87900
2  2026-11-02         3           24   191800
```

14일 × 3지점 = 42행이에요. `orders`는 주문 하나가 한 행이라 이번엔 `count`가 주문 건수예요. `reset_index()`는 묶음 이름(날짜, 지점)을 다시 보통 열로 내려요. 저장할 표와 모양을 맞추는 거예요.

표를 만들고 42행을 한 번에 넣어요. 19회차의 `INSERT`와 `%s` 자리 채우기를 행 여러 개에 반복하는 것이 `executemany`예요.

```python
with psycopg.connect(DSN) as conn:
    conn.execute("""
        CREATE TABLE IF NOT EXISTS store_daily_sales (
            sales_date  DATE    NOT NULL,
            store_id    INTEGER NOT NULL REFERENCES stores (store_id),
            order_count INTEGER NOT NULL,
            revenue     INTEGER NOT NULL,
            PRIMARY KEY (sales_date, store_id)
        )
    """)
    conn.execute("DELETE FROM store_daily_sales")
    with conn.cursor() as cur:
        cur.executemany(
            "INSERT INTO store_daily_sales VALUES (%s, %s, %s, %s)",
            daily.itertuples(index=False),
        )
        print(cur.rowcount, "행 저장")
```


## 꼭 기억할 주의점

- `compose.yaml`의 `ports:`는 **내 맥:컨테이너** 순서예요. 파이썬 `DSN`과 DBeaver는 왼쪽 숫자(5433)로 접속해요.
- 키보드로 대화할 때는 `docker exec -it`, 파일을 `<`로 흘려 넣을 때는 `docker exec -i`예요. 시드를 넣을 때 `-d cafe_db`를 빠뜨리면 다른 데이터베이스에 들어가요.
- zsh에서는 `uv add "psycopg[binary]"`처럼 대괄호를 따옴표로 감싸요.
- DB의 `NULL`은 pandas에서 `NaN`이 되고, 정수 열이 `float64`로 바뀌어요. 빈칸을 품는 정수가 필요하면 `astype("Int64")`예요.
- JOIN한 상세 표에서 주문 수를 셀 때는 `count`가 아니라 `nunique`예요. 주문 단위 질문(시간대, 객단가)은 주문 하나가 한 행인 표로 접은 뒤에 세요.
- `idxmax()`는 같은 최댓값이 여럿이어도 첫 번째 하나만 돌려줘요. 표를 직접 보고 확인해요.
- 평균은 튀는 값에 끌려가요. 결론을 내기 전에 중앙값과 가장 큰 값들을 같이 봐요.
- 요일은 `.dt.day_of_week`(월요일 0)예요. 밑줄 없는 `dayofweek`는 pandas 3.1.1에서 경고가 나요.
- DataFrame을 DB에 넣을 때는 `CREATE TABLE IF NOT EXISTS`, `DELETE`, `executemany`를 한 `with` 블록에 두면 몇 번을 다시 실행해도 같은 결과가 돼요.
- 중요한 숫자는 SQL과 pandas 두 길로 한 번씩 맞춰 봐요.
