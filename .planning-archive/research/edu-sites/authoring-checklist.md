# 레슨 저작 체크리스트 (2026-09-01)

리서치 라운드에서 확정된 저작 기준의 통합본. 레슨을 새로 쓰거나 고칠 때 이 문서만
보고 검사한다. 각 항목 끝에 출처 라운드를 표기했다. 자동 게이트(L1~L7,
`scripts/check-lesson-structure.mjs`)가 잡는 것은 여기 다시 적지 않는다 — 이 문서는
사람이 판단해야 하는 기준만 담는다.

## 1. 문장·설명

- [ ] **정의-먼저 금지** — 소제목 첫 1~2문장은 구체 상황·경험으로 시작하고, 용어
      정의는 그 뒤에. 혼란 패턴 13(Julia Evans) 중 1번 "추상부터 시작"이 최다 위반.
      (R1-B, R2-I 실측)
- [ ] **'왜'가 있는가** — "무엇을 한다"만 있고 "왜 그렇게 한다"가 없는 단락은 혼란
      패턴. 코드 블록 주석도 동작 설명이 아니라 이유를 적는다. (R1-B)
- [ ] **틀린 방법은 틀렸다고 라벨** — 순진한 첫 시도를 보여줄 때는 "흔한 첫 시도",
      "✗" 같은 표시를 반드시 붙인다. 표시 없는 오답 노출은 혼란 패턴 12번. (R1-B, R2-F)
- [ ] **인과 사슬 (Therefore/But)** — 소제목 사이 전환이 "그런데 문제가 생긴다 →
      그래서 X가 등장한다" 형태로 이어지는가. 끊긴 목록이 아니라 연결된 이야기.  (R2-F)
- [ ] **"왜 배우나"는 구체 장면으로** — 2장 첫 문단은 구체적 실패 장면·퍼즐 하나로
      시작. 효용 나열은 한 문장으로 축소. (R2-F)

## 2. 비유

- [ ] **비유 1개 = 오개념 1개** — 비유 하나가 잡는 오해는 하나. (R1-B)
- [ ] **두 문단 이상 끌고 가지 않기** — 관통 비유(예제 세계)는 예외, 설명 비유는
      짧게. (R1-B)
- [ ] **한계 명시** — 비유가 깨지는 지점을 한 줄로 적는다("이 비유가 안 맞는 부분은
      ~"). 35편 실측 0건이던 항목. (R1-B, R2-I)

## 3. 용어

- [ ] **병기는 첫 등장 1회** — 지배 관례: `한글(영어, 한줄설명)` 첫 등장에만, 이후
      한글 단독. 매번 병기 금지, 무병기 금지. (R2-I, R1-C)
- [ ] **학습 목표는 can-do 동사** — "~할 수 있다 / 말할 수 있다"로 끝낸다.
      "~를 안다"형 금지(측정 불가). (R3-N)

## 4. 그림 (SVG)

- [ ] **그림-본문 호흡** — 본문 2~4문단당 그림 1개, 그림 없이 5문단 연속 금지.
      논증 자체는 글이 담당한다. (R2-F)
- [ ] **텍스트 밀도** — 그림 하나에 제목 1 + 요소 레이블 + "핵심 한 줄" 주석 최대 1.
      그 외 텍스트 금지, 범례 대신 직접 레이블. (R4-P)
- [ ] **색 의미 계약** — 색 상한 3개. 사이트 전역에서 같은 색은 같은 의미
      (강조 accent=주의·핵심, soft=면·보통), 실선=흐름/점선=참조. (R4-P, R2-F)
- [ ] **그림-본문 색 일치** — 다이어그램의 색과 본문 해당 용어 하이라이트를 맞춘다
      (그림 주변 1~2문단만). (R2-F)
- [ ] **질문 유형에 맞는 도식** — 구조=해부도, 순서=타임라인, 상태 전이=상태도,
      비교=대비 그리드, 과정=흐름도. 상태 전이 개념을 흐름도로 그리지 않기. (R4-P)
- [ ] **흐름형 그림엔 번호 경로** — ①②③ 배지로 읽기 순서를 강제하고 본문이 같은
      번호를 부른다. (R4-P)

## 5. 6장 스스로 점검 문항

- [ ] **"왜"형으로 묻기** — "~가 맞나요?"(예/아니오·단답 재인) 금지. "왜 그런가 /
      무슨 일이 일어나나 / 어떻게 고치나"로 묻는다. 정답에도 '왜'까지 설명. (R4-O)
- [ ] **4장 예제의 변형** — 두 문항 중 최소 하나는 4장 예제의 고장·확장 변형
      ("이 코드에서 ~를 바꾸면?"). (R3-N)
- [ ] **목표와 1:1 정렬** — 모든 문항이 1장 학습 목표 중 하나를 겨냥한다. 어느
      목표도 안 건드리는 문항(예제 제작 의도를 묻는 메타 질문 등) 금지. (R3-N)

## 6. 구조 슬롯 (있으면 좋은 장치 — 신규·리워크 시 검토)

- [ ] **빈칸 버전 예제 (backward fading)** — 4장 완성 코드 뒤에 핵심 1~3줄을
      `# ___ 채워보세요`로 비운 블록 + 정답 접기. (R3-N)
- [ ] **반전(轉) 박스** — 배운 규칙이 어긋나 보이는 경계 사례 1개 + 해설
      ("어라?" 슬롯 — 예: `==` 강제 변환, NULL=NULL). (R6)
- [ ] **안테피스 예고** — 다음 레슨 예고를 요약이 아니라 "지금 도구로는 안 풀리는
      미니 문제"로 보여준다. (R6)
- [ ] **북엔드** — 전체 그림을 앞에서 보여줬다면 끝에서 재등장시켜 "이제 모든
      화살표를 설명할 수 있는지" 묻는다. (R2-F)
- [ ] **슬라이더 대신 스몰 멀티플** — 값 하나만 다른 변형 3개를 같은 레이아웃으로
      나란히 (temperature 0/0.7/1.5 등). (R2-F)
