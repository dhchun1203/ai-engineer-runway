## 한 일

우측 하단에 '맨 위로' 버튼. 480px 이상 스크롤하면 나타나고 위로 돌아가면 사라진다.
루트 레이아웃에 한 번만 두어 전 페이지 공통이다.

레슨이 길어서(그림 확장 후 더) 아이패드에서 위로 돌아가려면 계속 쓸어 올려야 했다.

## 바닥 사정 — 메모장을 피해야 했다

레슨 페이지 하단에는 메모장 시트가 이미 고정돼 있다(좌우 전체 폭, 손잡이 44px, z-40).
버튼을 그냥 두면 손잡이를 가린다.

`body:has(.note-sheet) .scroll-top`으로 메모장이 있는 페이지에서만 손잡이 높이만큼
올라서게 했다. 페이지가 버튼에게 자기 사정을 알려주는 배선을 만들지 않는다 — 메모장이
다른 화면에 생겨도 이 규칙이 저절로 따라간다.

기준을 `[data-notepad]`가 아니라 `.note-sheet`로 잡은 건, 메모가 도착하기 전 자리표시자도
같은 `.note-sheet` 기하를 쓰기 때문이다. 그래야 로딩 중에 버튼이 내려앉았다 올라오지 않는다.

z-index는 30 — 헤더(20)·구간 테이프(10) 위, 메모장(40) 아래. 메모를 펼치면 버튼이 그
뒤로 가려지는 게 맞다.

## 도중에 잡은 것 — 레이어 밖 규칙이 호버를 죽였다

`.btn`을 재사용하면서 진입 애니메이션에 `transform: translateY(0.5rem)`을 썼다. 그런데
`.btn`은 `@layer components` 안에 있고 이 블록은 레이어 밖이다 — **레이어 밖은 명세성과
무관하게 항상 이긴다.** 그래서 호버할 때 그림자만 3px→4px로 커지고 버튼이 떠오르지
않았다(디자인 시스템이 "누를 수 있다"를 색이 아니라 깊이로 말하는 그 신호의 절반이 죽었다).

브라우저에서 실측해 확인했다: 호버 시 `transform: matrix(1,0,0,1,0,0)` — 이동 없음.

진입에서 transform을 빼고 페이드만 남겼다. 다시 재니 `matrix(1,0,0,1,-1,-1)` — 살아났다.
슬라이드 인 하나보다 디자인 시스템의 호버가 사는 쪽이 낫다.

## 검증 — 브라우저로 직접

아이패드 세로(768×1024) 프로덕션 빌드 실측.

| 확인 | 결과 |
|---|---|
| 맨 위에서 | `visibility: hidden` — 안 보임 |
| 480px 넘게 스크롤 | 나타남, 44×44, 우측 하단 |
| 눌렀을 때 | 2500 → 0, 페이지 이동 없음, 버튼 다시 숨음 |
| 메모장 있을 때 | 시트 위 15px, 겹침 없음 (z 30 vs 40) |
| 호버 | −1px 떠오름 + 그림자 3→4px |
| 숨은 상태 탭 포커스 | 안 들어감 (visibility) |
| 보이는 상태 탭 포커스 | 들어감 |
| 짧은 페이지(커리큘럼) | 끝까지 안 나타남 — 스크롤이 문턱에 못 미침 |
| 라이트/다크 | 양쪽 확인 |
| 인쇄 | `data-print-hide` 부착, 인쇄 규칙이 이 속성을 걷어감 |

게이트: `check-design-tokens` · `check-brand` · `e2e-mobile-overflow`(21조합) ·
`next build` — 전부 통과.
