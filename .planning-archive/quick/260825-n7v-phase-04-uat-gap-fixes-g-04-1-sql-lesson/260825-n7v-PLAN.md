# Quick Task: Phase 04 UAT 결함 2건 수정

`/gsd-verify-work 04`가 진단한 두 결함을 닫는다. 원인·재현·수정 방향은
`.planning/phases/04-step-1/04-UAT.md`의 `## Gaps`에 이미 확정돼 있다.

## Task 1 — G-04-1 (major): 2편 준비 블록의 스키마 충돌

**파일:** `src/content/lessons/step-1/1-4-sql-queries-and-joins.mdx`

**문제:** 준비 블록이 `CREATE TABLE IF NOT EXISTS`로 선언돼 있다. 1편
(`1-4-relational-db-basics`)이 만든 `score` 없는 `practice.enrollments`가 남아 있으면
이 문장이 아무 일도 하지 않고 지나가고, 뒤이은 `INSERT ... score`가
`ERROR: 42703: column "score" of relation "enrollments" does not exist`로 죽는다.
Supabase MCP로 실제 재현 확인.

**조치:** 준비 블록을 `DROP SCHEMA IF EXISTS practice CASCADE;`로 시작하게 바꾼다.
이어지는 `CREATE TABLE`에서 `IF NOT EXISTS`를 뗀다 (서랍을 방금 비웠으므로 무의미하고,
남겨두면 "표 이름만 보고 모양은 안 본다"는 바로 그 오해를 다시 부른다).

`DROP` 우선 방식을 고른 이유: 본문이 이미 약속한 "앞 레슨을 건너뛰었어도 이 블록 하나로
준비가 끝납니다"와 "두 번 실행해도 안전합니다"를 **실제로 참으로 만든다**. 문장을 약화시켜
현실에 맞추는 것보다 낫다. 1편의 정리 SQL을 필수로 격상하는 대안은 채택하지 않는다 —
학습자가 그 한 줄을 건너뛰는 순간 다시 깨지므로 근본 수정이 아니다.

**같이 고칠 서술:**
- 52행 `IF NOT EXISTS`를 쓰기 때문에 두 번 실행해도 안전합니다 → `DROP` 선행 근거로 교체
- 94행 `CREATE SCHEMA/TABLE IF NOT EXISTS`가 있어 이미 표가 있으면 건드리지 않습니다 …
  `INSERT`는 실행할 때마다 새 행이 추가되니 → 새 동작에 맞게 교체 (중복 INSERT 문제도 함께 사라짐)

**verify:** `DROP SCHEMA` 선행 상태에서 1편 7블록 → 2편 준비 블록 순서로 Supabase에 실제 실행,
42703이 나오지 않고 이어지는 9블록의 행 수가 본문 주장과 일치할 것.

**done:** 1편 → 2편 순서로 이어서 실습해도 준비 블록이 성공한다.

## Task 2 — G-04-2 (cosmetic): 복사 버튼이 코드 첫 줄을 가림

**파일:** `src/content/lessons/step-1/1-4-sql-queries-and-joins.mdx`

**문제:** 코드 블록 복사 버튼(44×44, `position: absolute`, 항상 표시)이 첫 줄 위에 겹친다.
첫 줄이 버튼 앞 여유 폭(측정값 655px)을 넘으면 그만큼 글자가 가려진다. Step 1 전체
34개 블록 중 이 파일 첫 블록 1건만 해당 (첫 줄 714px, 59px 가려짐).

**조치:** 첫 줄 주석을 655px 안으로 줄인다. 잘려나간 설명은 둘째 줄로 내린다.
Task 1에서 어차피 이 블록을 다시 쓰므로 같은 편집에 포함된다.

**범위 밖 (의도적):** 근본 원인인 "첫 줄에 버튼 폭만큼의 우측 여유가 없다"는
`globals.css`의 코드 블록 전역 문제다. Step 1 34블록 중 1건만 걸리는 현 상황에서
전역 CSS를 건드리는 건 Phase 06(site-wide-design-polish)의 일이다.
UAT G-04-2의 `missing` 2번 항목으로 남겨둔다.

**verify:** Playwright로 아이패드 세로(820×1180)·가로(1180×820) 양쪽에서 Step 1 10편
전체 코드 블록의 첫 줄 폭을 재측정 — 버튼과 겹치는 블록 0건일 것.

**done:** 10편 34블록 어디에서도 첫 줄이 복사 버튼에 가리지 않는다.
