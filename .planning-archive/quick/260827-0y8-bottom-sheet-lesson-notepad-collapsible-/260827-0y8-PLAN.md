<research_findings>
계획 수립 중 확인한 것 — 실행자는 이 결론을 다시 조사하지 말고 그대로 쓴다.

**R-1 `env(keyboard-inset-height)`는 아이패드 Safari에서 쓸 수 없다.** MDN 확인 결과
`keyboard-inset-*` 환경 변수는 VirtualKeyboard API가 정의하는 값이고, 그 API는
`navigator.virtualKeyboard.overlaysContent`를 요구하는 Chromium 전용 기능이다. iOS/iPadOS
Safari(WebKit)는 구현하지 않으므로 이 사이트에서는 항상 폴백값 `0px`로 해석된다. CSS 우선
해법을 먼저 검토했으나 소유자의 1순위 기기에서 동작하지 않는다 — 채택하지 않는다.
신뢰도: 높음(MDN 1차 확인).

**R-2 viewport meta의 `interactive-widget=resizes-content`도 쓸 수 없다.** Chrome 108+ 전용
확장이며 문서가 iOS/iPadOS를 명시적으로 제외한다(WebKit 기반이라). iOS Safari는 기본적으로
`resizes-visual`처럼 동작한다 — 즉 키보드가 열려도 **레이아웃 뷰포트는 줄지 않고**
`position: fixed` 하단 요소가 키보드 뒤로 들어간다. 이것이 이 작업의 최대 리스크다.
신뢰도: 높음.

**R-3 따라서 `window.visualViewport`가 유일하게 실제로 동작하는 메커니즘이다.** Baseline
widely available(2021-08~). `height` / `offsetTop` + `resize` / `scroll` 이벤트로 실제 보이는
영역을 추적한다. 보정량은 `document.documentElement.clientHeight - (vv.height + vv.offsetTop)`
이며 0 미만으로 내려가지 않게 clamp한다. 신뢰도: 높음(MDN 정식 예제와 동형).

**R-4 헤드리스로 증명 불가능한 것.** Playwright Chromium에는 iOS 소프트 키보드가 없다. 시트가
"진짜 키보드 위에" 앉는지, 핀치 줌 상태에서 어떻게 보이는지는 게이트로 증명할 수 없다 —
Task 4의 실기기 점검표로 보낸다. 게이트는 `visualViewport` 리스너가 붙었는지·CSS 변수가
갱신되는지까지만 기계적으로 확인한다.

**R-5 옥스포드/괘선 노트 실측 기준.** 미국 college ruled 줄 간격 7.1mm, wide ruled 8.7mm,
narrow 6.4mm이고 세로 여백선은 왼쪽 가장자리에서 약 32mm 지점이다(Ruled paper 표준). 이
사이트 본문 토큰 `--text-body`는 1rem(16px)이고, 화면에서 편안한 줄 간격은 1.75rem(28px) —
28px ≈ 7.4mm로 college ruled에 가장 가깝다. 따라서 **줄 간격 1.75rem을 채택**한다. 세로
여백선은 화면 폭이 종이보다 좁으므로 32mm를 그대로 쓰지 않고 2.75rem(44px)로 축소한다 —
375px 폭에서도 본문 영역이 충분히 남는다.

**R-6 상대 명도(가장 흔한 실패는 괘선을 너무 진하게 만드는 것).** 종이가 가장 밝고, 괘선은
겨우 보일 정도, 세로 여백선이 그보다 한 단계 진하다. 이 순서를 라이트/다크 양쪽에서 동일하게
유지한다.

**(1) 마이그레이션 기록.** `supabase/migrations/20260827000000_create_lesson_note.sql`을 만든다.

security;` 만 담는다. `create policy`는 단 하나도 쓰지 않는다. 파일 상단 한국어 주석은

**(2) 데이터 계층** `src/lib/note-store.ts`. 첫 import는 `import 'server-only';`. `progress-store.ts`의
형태를 그대로 미러링한다: `export type NoteRead = { ok: true; body: string } | { ok: false; error: string }`,

`supabaseAdmin.from('lesson_note').select('body').eq('lesson_id', slug).maybeSingle()`이며 **행이 없으면
빈 문자열로 성공**을 반환한다(조회 실패와 "아직 메모 없음"을 타입 수준에서 구분 — 실패를 빈 메모로
오인해 화면에 보여주면 사용자는 메모가 사라졌다고 느낀다). 저장은
`upsert({ lesson_id, body, updated_at })`. 저장 전에 본문 길이가 50,000자를 넘으면 한국어 메시지로
