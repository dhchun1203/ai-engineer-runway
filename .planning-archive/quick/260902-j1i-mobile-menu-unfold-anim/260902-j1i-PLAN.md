# Quick Task 260902-j1i — 모바일 메뉴 펼침 애니메이션

## 문제

640px 미만 햄버거 메뉴 패널(`#site-nav-panel`)은 현재 `nav-panel-reveal`이
opacity + translateY(-4px)만 적용해 "살짝 페이드인"만 된다. 요청: 실제로 **아래로
펼쳐지는(unfold)** 느낌 — 높이가 0에서 열리는 애니메이션. 단 성능 문제 없이.

## 접근 (성능 판단)

- **grid-template-rows: 0fr → 1fr** 트릭 + opacity 키프레임.
  - 콘텐츠 실측 높이(auto)를 JS로 재지 않고도 순수 CSS로 진짜 높이 펼침을 낸다.
    max-height 하드코딩(콘텐츠가 잘리거나 이징이 튐)보다 정확하다.
  - transform: scaleY는 컴포지터 전용이라 가장 싸지만 텍스트가 눌려 찌그러진다 —
    메뉴 항목 가독성을 해쳐 채택 안 함.
  - grid-rows 애니메이션은 프레임마다 레이아웃을 유발하나, 대상이 작은 내비 패널
    하나(≤7행)이고 지속이 ~200ms라 체감/실측 비용이 무시할 수준. 이것이 JS 없이
    auto 높이를 부드럽게 펴는 현대 표준 기법.
- 조건부 렌더(`{open && …}`) 유지 → 마운트 시 키프레임이 발화(스타팅 스타일 불필요).
- `prefers-reduced-motion: reduce`에서 `animation: none`으로 즉시 표시(기존 규칙 계승).

## 변경

1. `src/app/globals.css` — `@keyframes nav-panel-reveal`를 grid-rows 0fr→1fr +
   opacity로 교체, `.nav-panel-reveal`를 grid 컨테이너로, 새 `.nav-panel-clip`
   (overflow:hidden; min-height:0) 추가. reduced-motion 블록 유지.
2. `src/components/site-nav.tsx` — 패널 내부에 `.nav-panel-clip` 래퍼 한 겹 추가
   (grid 자식이 클립되도록). 마크업 외 로직 변경 없음.

## 검증

- 내장 브라우저 아이패드/모바일 폭에서 햄버거 → 패널이 위에서 아래로 펼쳐지는지.
- reduced-motion 에뮬레이션에서 즉시 표시되는지.
- 데스크톱(sm:) 드롭다운·헤더 높이/구간 테이프에 회귀 없는지.
