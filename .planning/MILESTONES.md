**핵심 성과 6가지:**

1. **학습 루프 전체가 배포된 URL 위에서 동작한다** — Step→모듈→레슨 탐색, 완료 토글(Supabase 저장, 기기 간 유지), 모듈·Step·전체 진행률까지. 진도 저장은 Supabase Auth 없이 공유 시크릿 쿠키 + 서버 전용 `service_role` 경로 + RLS 기본 차단(정책 0개)으로 1인용 최소 마찰을 지켰다. (Phase 1~2)
2. **레슨 35편을 eli5 표준으로 집필했다** — 파일럿 1편으로 톤·6단 구조를 먼저 굳히고 승인받은 뒤 나머지를 그 표준에 맞춰 썼다. Step 1·2 핵심은 심화, Step 3는 개념 훑기로 깊이를 나누고 레슨마다 배지로 표시했다. SQL 2편은 Supabase SQL 에디터에서 실제 실행해 확인했고(발견된 스키마 충돌 1건 수정), 실습 프로젝트 5종은 재현이 아니라 준비 가이드로 제공했다. (Phase 4~5)
3. **일정과 오늘의 학습이 매니페스트에서 자동으로 파생된다** — 35레슨 하루 1개 배정, D-day, 시간 가중 3단계 페이스 판정(ahead/on-track/behind), 밀린 레슨 목록, 오늘 행 자동 스크롤. 경계값은 순수 모듈로 분리해 게이트가 상시 검증한다. (Phase 3)
4. **콘텐츠 라우트를 완전 정적으로 전환했다** — `/curriculum`·`/step/*`·`/lesson/*`(35개)가 빌드 시점에 확정되고, 진도·완료·메모만 `GET /api/progress` 한 곳에서 클라이언트가 따로 가져온다. 프로덕션 TTFB 33.59~39.93ms로 정적 대조군(`/about` 34.86ms)과 같은 구간. ISR은 쓰지 않았다 — 하루 한 번 여는 사이트에서는 재검증 창 만료 후 첫 요청이 곧 그날의 유일한 방문이라, 날짜 의존 값은 브라우저 재계산으로 풀었다. (Phase 8)
5. **첫 방문 전송량을 측정해서 줄였다** — 폰트가 전송량의 76%(2.06MB)라는 실측을 근거로 서브셋을 결정하고, KS X 1001 완성형 2,350자를 Unicode.org 1차 자료에서 받아 교차검증해 448KB(-78.21%)로 줄였다. 글리프 커버리지 게이트가 이후 콘텐츠 증가로 인한 누락을 상시 잡는다. (Phase 8)
6. **자동 게이트 20종이 회귀를 막는다** — 브랜드·디자인 토큰·매니페스트 불변식·레슨 구조·진도 수학·일정·라우트 렌더 모드·폰트 커버리지에 더해, 실 Supabase 왕복을 도는 e2e 8종. 다만 자동 게이트가 실기기를 대체하지 못한다는 것도 두 번 확인했다 — Phase 6과 8 모두 게이트 전부 초록불 상태에서 사용자가 실기기 결함을 찾았고, 그래서 페이즈 마지막에 실기기 UAT를 두는 설계를 유지한다.
