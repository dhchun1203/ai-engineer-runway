**(1) 한국어 장문 줄바꿈.** `body`의 `word-break: keep-all`과 `overflow-wrap: break-word` 조합이 파일럿 본문에서 실제로 어떻게 동작하는지 좁은 폭(375px)과 아이패드 폭 양쪽에서 확인한다. 한국어 어절이 중간에서 끊기거나, 영어 기술 용어가 컨테이너를 넘치거나, 제목이 말줄임으로 잘리는 경우가 있으면 규칙을 고친다. 말줄임(`text-overflow: ellipsis`)은 제목에도 본문에도 쓰지 않는다 — 넘치면 줄바꿈한다(UI-SPEC long-text 결정). `prose` 래퍼의 본문 line-height를 UI-SPEC의 1.6으로 맞춘다(1.5 기본값이 아니다 — keep-all 한국어 장문에 수직 여백이 더 필요하다는 것이 UI-SPEC의 근거다).

**(2) 코드 블록.** `pre`의 가로 스크롤이 실제 예제의 긴 줄에서 동작하는지, 줄바꿈이나 클리핑으로 대체되지 않는지 확인한다. 컨테이너 폭과 코드 줄 폭이 정확히 같은 경계에서는 스크롤바가 생기지 않고 마지막 글자도 잘리지 않아야 한다 — 실제로 넘칠 때만 스크롤이 생긴다. 빈 코드 블록이나 한 줄짜리 코드 블록에서도 높이가 무너지지 않게 최소 높이/패딩을 준다. `code`와 `pre`가 한국어 본문 폰트를 상속하지 않고 monospace 스택을 쓰는지, 인라인 `code`가 주변 한국어 텍스트와 베이스라인이 어긋나지 않는지 확인한다.

**(3) 복사 버튼 터치 타깃.** rehype-pretty-code가 만든 복사 버튼 클래스에 최소 44px의 히트 영역과 명확한 대비를 준다 — 아이패드에서 손가락으로 누를 수 있어야 하고, hover 상태가 없는 기기이므로 항상 보여야 한다(RESEARCH Pitfall 3). 코드 블록 우상단에 겹쳐 놓되 첫 줄 코드를 가리지 않도록 배치한다. 라이트·다크 두 테마 모두에서 버튼이 배경에 묻히지 않는지 확인한다.

**(4) 다크 테마 대비.** 파일럿 두 편의 본문·코드·배지·버튼을 다크 테마에서 훑고, UI-SPEC이 정한 다크 색값 위에서 텍스트 대비가 읽기 불편한 곳이 있으면 UI-SPEC 토큰 범위 안에서 조정한다. UI-SPEC에 없는 새 색값을 만들지 않는다 — 필요하면 UI-SPEC을 먼저 갱신해야 한다.

**(5) 범위 제한.** 이 태스크는 타이포·코드 블록·터치 규칙을 실콘텐츠 기준으로 맞추는 일이다. 색값 미세조정, 아코디언 애니메이션, 새 컴포넌트 추가는 하지 않는다 — RESEARCH Pitfall 6이 지목한 시간 잠식 지점이다.
