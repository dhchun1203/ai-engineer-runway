  <action>
진행률 계산의 심장을 어디에도 의존하지 않는 파일 하나에 격리한다. 격리하는 이유는 미학이 아니라 검증 가능성이다 — import가 없는 `.ts` 파일은 Node가 그대로 로드할 수 있어서, 저장소에 테스트 러너를 새로 들이지 않고도(PITFALLS Pitfall 1) 실제 실행 단위 검증을 붙일 수 있다.

**(1) `src/lib/progress-math.ts`.** import 문을 하나도 쓰지 않는다. `export type ProgressCounts = { completed: number; total: number; percent: number }`와 위 `<behavior>`가 규정한 두 함수를 named export한다. 퍼센트는 `total`이 0이면 0, 아니면 `Math.round(completed / total * 100)`을 0~100으로 클램프한 값이다(UI-SPEC #22: 바 fill이 트랙을 넘지 않아야 한다). 완료 수는 **주어진 slug 목록을 순회하며 집합 포함 여부를 세는 방식**으로 구한다 — 집합 크기를 그대로 쓰면 다른 Step의 완료가 이 모듈 진행률에 섞인다. `firstIncompleteSlug`는 순서 배열을 앞에서부터 훑어 집합에 없는 첫 값을 돌려주고, 없으면 null이다. 함수형 스타일과 명시적 반환 타입은 `curriculum-helpers.ts`의 기존 관례를 그대로 따른다. enum·namespace·매개변수 프로퍼티 같은 소거 불가능한 TypeScript 문법은 쓰지 않는다 — Node의 타입 제거 로더가 이 파일을 그대로 읽어야 한다.
