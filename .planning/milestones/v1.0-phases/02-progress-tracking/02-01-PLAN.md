진도 데이터가 흐를 서버 쪽 통로를 만든다. 이 태스크는 아직 DB에 스키마를 적용하지 않는다 — 적용은 Task 3의 블로킹 단계다.

**(1) 패키지 설치.** `npm install @supabase/supabase-js@2.112.3 server-only@0.0.1`. 버전을 고정해 설치하고 `package.json`의 `dependencies`에 두 항목이 들어간 것을 확인한다. `@supabase/ssr`는 설치하지 않는다 — D-17이 Supabase Auth를 배제해 이 패키지가 관리할 세션 자체가 없다 (RESEARCH Standard Stack). 테스트 러너·dotenv·Supabase CLI 등 다른 패키지도 추가하지 않는다 (PITFALLS Pitfall 1: 플랫폼 과잉 엔지니어링).

**(2) `src/lib/supabase/admin.ts`.** 첫 줄이 `import 'server-only';`다 — 클라이언트 컴포넌트가 실수로 import하면 빌드가 실패하게 만드는 마커다. 그 다음 `@supabase/supabase-js`의 `createClient`로 모듈 스코프 상수 `supabaseAdmin`을 하나 만들어 named export한다. 인자는 `process.env.SUPABASE_URL`, `process.env.SUPABASE_SERVICE_ROLE_KEY`, 그리고 세 번째 옵션으로 `{ auth: { persistSession: false, autoRefreshToken: false } }`다(서버에는 유지할 세션이 없다). 두 환경 변수가 비어 있으면 모듈 로드 시점에 파일명과 변수 이름을 담은 서술적 Error를 던진다 — `curriculum-helpers.ts`의 `findModule`이 쓰는 것과 같은 "조용히 undefined로 넘어가지 않는다" 관례다. 환경 변수 이름에 `NEXT_PUBLIC_` 접두사를 절대 붙이지 않는다: 붙이는 순간 service_role 키가 브라우저 번들에 인라인된다. 이 파일 외의 어떤 곳에서도 `createClient`를 호출하지 않는다 — 앱 전체에서 Supabase 클라이언트는 이 하나뿐이다.

**(3) `src/lib/progress-store.ts`.** 첫 줄은 역시 `import 'server-only';`. `supabaseAdmin`을 상대 경로(`./supabase/admin`)로 import한다. 두 개의 함수와 한 개의 타입을 named export한다.
- `export type ProgressRead = { ok: true; completedIds: Set<string> } | { ok: false; error: string }` — 조회 실패와 "완료 0건"이 타입 수준에서 구분되어야 D-31(조회 실패 시 진행률 대신 에러 배너)이 성립한다. 이 구분이 이 파일의 존재 이유 절반이다.
- `readCompletedLessonIds(): Promise<ProgressRead>` — `progress` 테이블에서 `lesson_id` 컬럼만 select하고, 오류가 있으면 `{ ok: false, error: <supabase 오류 메시지> }`를, 없으면 행들의 `lesson_id`를 모은 `Set<string>`을 `{ ok: true, completedIds }`로 반환한다. 예외를 삼켜 빈 Set으로 반환하지 않는다.
- `setLessonCompletion(lessonSlug: string, completed: boolean): Promise<void>` — `completed`가 true면 `{ lesson_id: lessonSlug, completed_at: new Date().toISOString() }`을 upsert하고(D-30: 재완료 시 시각 갱신), false면 `lesson_id`가 일치하는 행을 delete한다. Supabase가 오류를 반환하면 그 메시지를 담아 throw한다 — 호출자(Server Action)가 실패를 감지해야 낙관적 UI를 되돌릴 수 있다(D-28).
집계·퍼센트 계산은 이 파일에 넣지 않는다 — 순수 집계는 02-03이 만드는 `src/lib/progress.ts`의 몫이다(ARCHITECTURE 책임 맵: DB 접근과 % 계산 분리).

**(4) `supabase/migrations/20260824120000_create_progress.sql`.** 저장소에 커밋되는 단일 마이그레이션 파일이다(RESEARCH Open Question 1 권고 — 대시보드 전용 변경 금지). 내용은 세 가지다: `public.progress` 테이블 생성(`lesson_id text primary key`, `completed_at timestamptz not null default now()`), 그 테이블에 대한 `alter table public.progress enable row level security;`, 그리고 정책을 하나도 만들지 않는 것이 의도된 설계임을 설명하는 SQL 주석. `create policy` 문을 쓰지 않는다 — 정책 0개가 곧 anon/authenticated 완전 차단이고, `using (true)` 같은 "편의 정책"을 넣는 순간 테이블이 세상에 열린다(RESEARCH Pitfall 3). 인덱스·트리거·뷰·집계 컬럼을 만들지 않는다(ARCHITECTURE Anti-Pattern 3). 파일 상단 주석에 "정책 0개는 버그가 아니라 기본 차단 설계"라는 사실과 그 근거를 한국어로 남긴다 — 미래의 나 자신이 이걸 고장난 것으로 오해하고 되돌리는 게 이 스키마의 가장 큰 회귀 위험이다.
