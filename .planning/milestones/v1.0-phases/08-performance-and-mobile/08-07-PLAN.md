- **D8-Q: 탭 피드백을 Tailwind `active:` 유틸리티가 아니라 `globals.css`의 클래스 규칙으로 구현한다.**
  (reversibility: reversible) 스킬 원문은 `-translate-y-[1px]`/`scale-[0.98]`를 예로 든다. 그런데
  `scripts/check-design-tokens.mjs`의 `findArbitraryValueTokens`(228~247행)는 `word-[...]` 형태의
  **모든** Tailwind 임의값 대괄호를 위반으로 잡는다 — 색·타이포에 국한되지 않는다. CSS 클래스로
  구현하면 (1) 게이트를 건드리지 않고 (2) 스킬이 지정한 정확한 수치(1px, 0.98)를 그대로 쓸 수 있고
  (3) `prefers-reduced-motion` 오버라이드를 같은 파일의 기존 패턴으로 나란히 둘 수 있고
  (4) 이미 5곳에 붙어 있는 `.card-interactive`에 규칙 한 줄을 더하는 것만으로 카드·행 전부가
  한 번에 적용된다. allowlist 등록(`ARBITRARY_ALLOWLIST_TOKENS`)은 쓰지 않는다 — 우회보다 정공법이다.

- **D8-R: Motion(구 Framer Motion) 라이브러리를 도입하지 않는다.** (reversibility: reversible)
  이 프로젝트는 "새 패키지 없이"를 지켜왔고 의존성이 매우 적다. 이 플랜이 필요로 하는 움직임은
  눌림 변형, 스켈레톤 펄스, 순차 등장 셋뿐이고 전부 CSS `transform`/`opacity`와 `animation-delay`
  cascade로 된다. 스킬의 5.C 스켈레톤이 `motion/react`를 전제하지만 같은 효과를 CSS 변수 기반
  `animation-delay: calc(var(--reveal-index) * 80ms)`로 낼 수 있고, 이 방식은 서버 컴포넌트에서도
  동작해 `staggerChildren`이 요구하는 "부모·자식이 같은 클라이언트 트리" 제약이 없다.
  **재론 조건:** 스크롤 연동 물리(scrub)나 라우트 간 공유 요소 전환이 실제로 필요해지면 그때
  이유와 함께 도입한다. 5.A(sticky-stack)·5.B(horizontal-pan)는 스킬이 GSAP+ScrollTrigger를
  전제하고 학습 대시보드의 콘텐츠 탐색을 방해하므로 적용 대상에서 제외한다.

- **D8-S: `section-tape.tsx`는 재작성하지 않고 스로틀만 추가한다.** (reversibility: reversible)
  문제는 메커니즘(스크롤 위치로 현재 구간을 판정)이 아니라 스로틀 부재다. `IntersectionObserver`
  전면 재작성은 `scroll-margin-top` 임계값과 정확히 일치해야 하는 정밀도 요구(G-06-9 재발 방지
  조항, 116~126행)를 새로 만족시켜야 해서 리스크가 스로틀 추가보다 크다.

**(a) `src/components/section-tape.tsx` 스로틀.**
`useEffect` 안에 rAF 핸들 참조 변수를 하나 두고, 스크롤 핸들러가 이미 예약된 프레임이 있으면

예약하고, 콜백 안에서 참조를 비운다. cleanup에서 리스너 제거와 함께 예약된 프레임도 취소한다

갱신을 써서 이전 값과 같으면 같은 값을 그대로 반환하는 형태가 가장 안전하다 — 별도의 ref 미러를
두면 그 미러가 상태와 어긋날 여지가 생긴다.

`ResizeObserver` 콜백은 지금처럼 `measure()` + `updateCurrent()`를 직접 부른다 — 크기 변화는
스크롤만큼 자주 일어나지 않고, 여기서 지연시키면 `<details>` 펼침 직후 테이프가 한 박자 늦는다.
