<objective>
SC1이 명시한 세 라우트 중 마지막인 `/curriculum`을 정적으로 전환하고, 나머지 두 라우트(`/`, `/schedule`)를
**동적으로 유지한다는 결정을 근거와 함께 확정한다.**

리서치는 `/`·`/curriculum`·`/schedule` 세 라우트가 `todayInSeoul()`에 의존하므로 ISR(`revalidate`)을
붙이라고 권고했다. 이 플랜은 그 권고를 그대로 따르지 않는다 — **ISR이 이 사이트의 "오늘"을 실제로
망가뜨리기 때문이다.**

설치된 Next.js 16.3.2 문서가 직접 말한다: 재검증 창이 만료된 뒤 **다음 요청은 여전히 캐시된(이제
낡은) 페이지를 받고**, 새 버전은 백그라운드에서 생성된다
(`node_modules/next/dist/docs/01-app/02-guides/incremental-static-regeneration.md` 100~102행, 238행).
즉 ISR을 붙이면 **매일 첫 방문이 어제의 "오늘의 학습"을 본다.** 홈은 SCHED-02가 "오늘 배정된 레슨을
보여주는 기본 랜딩 화면"이라고 못박은 화면이다. 이미 통과된 요구사항을 성능 최적화가 깨는 것은
받아들일 수 없다.

세 라우트를 하나로 묶지 않고 성질에 따라 셋으로 가른다:
  - `/curriculum` — 날짜 의존이 **D-day 배지 하나뿐**이다. 그 배지를 브라우저 계산으로 옮기면
    ISR 없이 완전 정적이 되고, 낡은 날짜를 보여줄 창 자체가 사라진다. ISR보다 정확하다.
  - `/` — 오늘 날짜가 곧 페이지 본문 전체다(오늘 배정 레슨, 상태 머신, 페이스, 밀린 레슨, 내일).
    정적으로 만들려면 화면 대부분이 클라이언트 렌더가 되고, 그러면 정적 셸의 이득이 사라진다.
  - `/schedule` — 오늘 행 강조와 자동 스크롤 앵커가 날짜에서 나온다. 위와 같은 이유.

`/`와 `/schedule`은 icn1 리전 이동으로 이미 TTFB 59~68ms이고, SC1이 명시한 세 라우트에 포함되지도
않는다. 동적 유지를 **측정된 결정으로 기록**한다 — 조용히 빼놓는 것이 아니다.

Purpose: SC1을 닫고, 남은 두 라우트의 처리를 근거와 함께 확정한다.
Output: 정적 `/curriculum`, 브라우저 계산 D-day, 초록불이 된 라우트 렌더 계약.

- **D8-N: ISR(`export const revalidate`)을 어느 라우트에도 쓰지 않는다.** (reversibility: reversible)
  리서치 권고(`revalidate = 3600`)에서 벗어나는 결정이므로 근거를 명시한다. ISR은 창 만료 후
  **첫 요청에 낡은 페이지를 그대로 내보내고** 백그라운드에서 재생성한다
  (설치된 Next 16.3.2 문서 `incremental-static-regeneration.md` 100~102행·238행 직접 확인).
  하루 한 번 여는 1인 학습 사이트에서는 "창 만료 후 첫 요청"이 곧 "그날의 유일한 방문"이 되기 쉬워,
  사실상 매일 어제를 보게 된다. 리서치 Assumptions Log A3이 이 위험을 이미 플래그했다.
  **재론 조건:** 방문 빈도가 하루 여러 번으로 바뀌거나, Next가 만료 시 동기 재생성 옵션을 제공하면
  다시 본다.

- **D8-O: `/curriculum`의 D-day를 브라우저에서 계산한다.** (reversibility: reversible)
  `todayInSeoul()`은 `Intl.DateTimeFormat('en-CA', { timeZone: 'Asia/Seoul' })` 기반이라 브라우저에서
  동일하게 동작하고, `src/lib/today.ts`는 import 0 순수 모듈(G18)이라 클라이언트 컴포넌트에서
  그대로 쓸 수 있다. 정적 셸에는 **빌드 시점 값**을 초기값으로 심어 마크업 형태를 확정하고,
  마운트 후 브라우저 값으로 정정한다 — 빈 자리에서 숫자가 튀어나오는 레이아웃 시프트가 없다.

- **D8-P: `/`와 `/schedule`은 `force-dynamic`을 유지한다.** (reversibility: reversible)
  근거는 objective에. 두 파일의 기존 선언 주석을 이 근거로 갱신하고, 이 페이즈에서 왜 전환하지
  않았는지를 코드에 남긴다. `check-progress-gates.mjs`의 `DYNAMIC_GATED_PAGES`(08-02가 이 둘로
  좁혔다)가 이 결정을 상시로 지킨다.
</recorded_decisions>
