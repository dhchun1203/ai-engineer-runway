# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn stays declined (continuation of Phase 1/2 decision) |
| Preset | not applicable |
| Component library | none — native HTML (`<a>`/`next/link` rows, `<details>` reused pattern where relevant) + custom Tailwind-styled components, same as Phase 1/2. Phase 3's new surface (today card, D-day badge, pace panel, behind list, 36-row schedule table) is all display/link state — no dialog/overlay/dropdown primitives are needed, so a headless-UI dependency stays unjustified. |
| Icon library | `lucide-react` (already installed, Phase 1) — new usages: `TrendingUp` (ahead-state pace icon), `Clock` (behind-state pace icon), `CalendarDays` (D-day countdown decorative icon, optional), `PartyPopper` (today-complete celebration state, same icon Phase 2 already reserved for the 100%-complete case — reused here for the daily version of that moment). All four are decorative (`aria-hidden="true"`) — if any icon name doesn't resolve in the installed `lucide-react` version, drop the icon and keep the text-only state; comprehension never depends on the icon. |
| Font | Pretendard (unchanged, D-06) — no new font needs |
| New client island | `ScheduleAutoScroll` (or an inline effect in `schedule/page.tsx`'s row) — the only new client-side JS this phase introduces: `scrollIntoView` on mount to land on today's row (D-46). No state, no event handlers beyond the one-time scroll — keeps the "client components are minimal islands" convention (RESEARCH.md Established Patterns). |

**shadcn gate re-check:** `components.json` still absent (confirmed via filesystem scan of repo root). Re-declining for the same reasons as Phase 1/2: this phase explicitly avoids a calendar/drag-drop library (RESEARCH.md "Don't Hand-Roll" — a plain vertical list beats `react-big-calendar` since rebalancing/drag-drop is out of scope, D-33/CONV-03), and the remaining surface (badges, a list, a table-like row set) is well within hand-styled Tailwind + native HTML.

**Access-gated visibility (PLAT-02, D-17/D-18/D-20) — extended by D-37 for this phase.** Two different gates now coexist, and every element below states which one it uses:
- **Public, no cookie needed:** the schedule itself (all 36 rows: date, lesson title, depth badge, estimated time), today's assigned lesson identity, and the D-day countdown. These render identically for every visitor — D-37 explicitly keeps the schedule a public portfolio artifact (same spirit as D-14).
- **Cookie-gated (renders only with the secret unlock cookie, DOM-absent otherwise — not visually hidden):** completion checkmarks on schedule rows, the today-lesson-card's done/not-done state and its celebration variant, the pace panel (ahead/on-track/behind), and the 밀린 레슨 (behind lessons) section. Without the cookie, the page looks exactly like the public schedule/today view with no progress signal at all — same DOM-absence principle as Phase 2's `ProgressSummary`/`ProgressBadge`.
- **Read-failure fallback (reuses Phase 2's `ProgressReadError` component verbatim, no new copy):** if `readCompletedLessonIds()` fails after the cookie is present, do not guess or show 0%. Render the existing `진행률을 불러오지 못했어요. 새로고침 후 다시 확인해주세요.` banner in place of the pace panel and the behind-lessons section; the today-lesson-card falls back to its "not unlocked" visual (lesson identity shown, no complete/incomplete marker); schedule rows fall back to no-checkmark (same as logged-out view).

## Spacing Scale

Inherited unchanged from Phase 1/2 (`01-UI-SPEC.md`, `02-UI-SPEC.md`) — no new tokens needed for Phase 3.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inline padding |
| sm | 8px | Compact element spacing (badge-to-text, row-internal gaps) |
| md | 16px | Default element spacing (card padding, schedule row padding, section gaps) |
| lg | 24px | Section padding (today-lesson-card internal padding, week-group header spacing) |
| xl | 32px | Layout gaps (homepage section breaks: D-day → today card → pace → behind list) |
| 2xl | 48px | Major section breaks (between week groups on `/schedule`, generous enough that the eye can find "오늘" quickly while scanning) |
| 3xl | 64px | Page-level spacing |

Exceptions:
- **44px minimum touch target (UX-01)** — every schedule row is a single `<Link>` wrapping the full row (D-45); the row's `min-height` must be 44px even when its content (single-line date + short lesson title) would naturally be shorter. Today-lesson-card's CTA and the celebration state's "내일 레슨 미리 보기" link follow the same rule as all existing Phase 1/2 CTAs.
- No other new exceptions.

## Typography

Inherited unchanged from Phase 1/2 — exactly 4 sizes / 2 weights, no additions.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 (regular) / 600 (semibold for badge/pace values) | 1.4 |
| Body | 16px | 400 (regular) / 600 (semibold for primary CTA) | 1.6 |
| Heading | 20px | 600 (semibold) | 1.3 |
| Display | 28px | 600 (semibold) | 1.2 |

**Phase 3 application map (new elements only):**
- Home page H1 → **"오늘의 학습"**, Display (28px/600) — replaces the old "AI Engineer Runway" H1 (D-36); the brand name stays visible via the nav bar's existing `Link` (`site-nav.tsx`), so it is not lost, just no longer duplicated on the page body.
- D-day countdown number ("D-36" / "D-DAY") → Display (28px/600), reusing the Display role outside `<h1>` — same precedent as Phase 2's big percentage number in `ProgressSummary`.
- D-day countdown caption ("개강까지" / "9/30 개강") → Label, regular (14px/400)
- Today-lesson-card lesson title → Body, regular (16px/400) — same role as lesson titles elsewhere (`module-accordion.tsx`), not Heading; this keeps the card visually consistent with how lesson titles read across the site instead of inventing new emphasis
- Today-lesson-card CTA ("레슨 시작하기" / "다시 보기") → Label, semibold (14px/600) — identical treatment to the existing `module-accordion.tsx` list-item CTA it's modeled on
- Celebration heading ("오늘 학습을 모두 마쳤어요!") → Heading (20px/600)
- Pace panel status word ("앞서가고 있어요" / "순항 중이에요" / "밀렸어요") → Heading (20px/600)
- Pace panel quantified/guidance body (behind state's "약 N시간 분량…" + "하루 30분씩…") → Body, regular (16px/400)
- 밀린 레슨 section heading ("밀린 레슨 {M}개") → Heading (20px/600)
- 밀린 레슨 list rows → same Body/Label split as existing lesson list rows (`module-accordion.tsx`) — title Body 16/400, minutes/depth Label 14
- `/schedule` page H1 ("학습 일정표") → Display (28px/600)
- `/schedule` week-group label ("1주차" … "6주차") → Heading (20px/600)
- `/schedule` row (date, lesson title, minutes, depth badge) → same Body/Label split as every other lesson row on the site (Body 16/400 for title, Label 14 for date/minutes/badge) — no new size introduced for density
- `/schedule` buffer-day row (9/29) and course-start row (9/30) copy → Body, regular (16px/400), visually distinguished by color/border only (see Color section), not by a new type size

No new sizes or weights — do not introduce a 3rd weight or 5th size for any Phase 3 element.

## Color

Inherited unchanged from Phase 1/2 — same hex values, **no new color tokens introduced this phase.** Phase 3 reuses the existing accent, Step-identity, neutral, and destructive tokens only — this is a deliberate constraint: pace status (ahead/on-track/behind) is informational, not alarming (D-43's "안내 톤, 압박 아님"), so it must not reach for a new "warning" or "danger" hue.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Light `#F8FAFC` / Dark `#0B1220` | Page background, base surface |
| Secondary (30%) | Light `#E7ECF3` / Dark `#131B2E` | Today-lesson-card panel, pace panel, behind-list panel, schedule row background |
| Accent (10%) | Light `#0D9488` / Dark `#2DD4BF` | See "Accent reserved for" below (extended from Phase 1/2) |
| Destructive | Light `#DC2626` / Dark `#F87171` | Still **unused**. The `behind` pace state is explicitly NOT destructive-colored — D-43 requires a calm, actionable tone, and a "you're behind" state is informational, not a data-loss/irreversible warning. Token stays reserved. |

**Accent reserved for (explicit list — extends Phase 1/2's list, never "all interactive elements"):**
- *(Phase 1/2, unchanged)* Progress bar fills, primary CTA buttons, focus ring/active nav underline, link hover in lesson prose, complete-button checked state, "이어서 학습하기" CTA
- *(Phase 3, new)* D-day countdown number
- *(Phase 3, new)* Today's row highlight on `/schedule` (border/background tint, D-46) — the one row that should visually "pop" out of 36
- *(Phase 3, new)* Ahead-state pace panel (status word, `TrendingUp` icon, and the numeric detail if shown) — reuses accent as the positive-feedback signal (D-42's "긍정 피드백"), consistent with how accent already marks "good/complete" states elsewhere on the site
- *(Phase 3, new)* Today-lesson-card CTA ("레슨 시작하기" / "다시 보기"), reusing the exact existing lesson-row CTA treatment
- *(Phase 3, new)* Course-start day row (9/30) on `/schedule` — accent border-left, marking it as the destination of the whole table (distinct from the neutral buffer-day row)

**On-track and behind states deliberately do NOT use accent** (only ahead does) — this keeps accent meaningful as "ahead of / exceeding plan," not diluted into "everything progress-related." On-track uses neutral text (it is the expected default, nothing to celebrate or flag). Behind uses neutral text + `Clock` icon (a calm signal, not destructive red) — the quantified gap and catch-up guidance text carry the information, not the color.

**Step identity colors (D-04)** — unchanged, still used for the depth badge on every schedule row and today-lesson-card (via the existing `DepthBadge` component, reused verbatim):

| Step | Color |
|------|-------|
| Step 1 | Light `#3B82F6` / Dark `#60A5FA` |
| Step 2 | Light `#8B5CF6` / Dark `#A78BFA` |
| Step 3 | Light `#F59E0B` / Dark `#FBBF24` |

**Past schedule rows tone-down (mirrors D-24's existing pattern, no new color):** past dates switch title/date text to `text-badge-neutral-text`/`dark:text-badge-neutral-text-dark` (existing neutral token), no strikethrough, no opacity trick — same rule Phase 2 already established for completed lesson list items.

**Buffer day (9/29) and course-start day (9/30) rows:** both use the existing neutral surface token (`bg-badge-neutral-bg` light border or similar), NOT a new "special row" color — the course-start row's accent border-left (above) is the only visual differentiator, keeping the palette closed.
