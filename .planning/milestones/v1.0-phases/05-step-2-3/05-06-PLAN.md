- **③ 개념 설명** — `###` 소제목 3~4개, 각 앞에 이모지 하나. 비유 먼저 정의 뒤. 다룰 것: 프롬프트의 네 부분(역할·지시·예시·제약 — 비유: 신입에게 일 시킬 때 주는 안내문), 예시 제공(few-shot, 답을 몇 개 보여 주고 나머지를 맡기기)과 언제 필요한가, 구조화 출력(structured output, 자연어 대신 정해진 틀로 받기)과 왜 파싱이 아니라 스키마로 강제해야 하는가, 검증 실패 시의 선택지(재시도·기본값·사람에게 넘기기). 프롬프트 → 응답 → 검증 → 사용 흐름을 `요청 조립 → 모델 호출 → 스키마 검증 → 통과하면 사용 / 실패하면 재시도` 한 줄 도식으로 그린다(D-48).
