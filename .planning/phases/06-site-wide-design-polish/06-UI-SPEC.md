# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**이 Phase의 성격:** 그린필드 디자인이 아니라 **이미 배포된 6종 화면의 정리**다. 대부분의 값은
이미 `06-CONTEXT.md`(D-R4K-1~8, D-88~D-99)와 `06-RESEARCH.md`의 실측이 확정했다. 아래 계약은
그 결정들을 executor가 드리프트 없이 구현할 수 있도록 못박고, 실제로 미결이던 항목(토큰 이름,

**출처 표기 규칙:** 아래 모든 값은 `file:line` 실측 또는 `D-XX` 결정 ID로 추적 가능하다.
근거가 없는 값은 이 문서에 없다.

## Spacing Scale

Phase 1이 선언한 8-point 스케일을 그대로 승계한다 — `06-RESEARCH.md` 실측(간격 임의값 대괄호
1건뿐, `about/page.tsx:25`의 `top-[0.4em]` 장식용 마이크로 오프셋)이 "간격층은 이미 토큰만 쓴다"를
확인했으므로 이 Phase는 스케일 자체를 바꾸지 않는다.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | 아이콘 간격, 배지 내부 padding |
| sm | 8px | 촘촘한 요소 간격(배지-텍스트, 브레드크럼 구분자), Section Tape `scroll-margin-top` 여유값의 일부 |
| md | 16px | 기본 요소 간격, **Card Contract의 표준 padding**(아래) |
| lg | 24px | 섹션 padding, 아코디언/레슨 콘텐츠 블록 |
| xl | 32px | 레이아웃 gap — **6화면 컨테이너 `gap-8`의 근거값**(D-99) |
| 2xl | 48px | 주요 섹션 구분 |
| 3xl | 64px | 페이지 레벨 여백(데스크톱 상단 padding) |

Exceptions:
- **44px 최소 터치 타깃(UX-01)** — Phase 1과 동일 규칙, `min-h-11 min-w-11`을 클릭 가능 요소 자체에 적용(아이콘/라벨이 아니라).
- **Section Tape 셀의 폭(width) 방향은 44px 최소를 강제하지 않는다** — 아래 `## Section Tape 계약` "터치 타깃 예외" 참고. 44px는 셀의 **높이**에만 적용된다(D-R4K-1 원문: "높이 44px, 시각적 막대는 3px").

## Typography

**네임스페이스 정정이 핵심 산출물이다(D-95).** `globals.css:35-38`의 `--font-size-*` 토큰은
Tailwind v4가 `text-{name}` 유틸리티를 생성하는 네임스페이스가 `--text-*`이기 때문에
(`node_modules/tailwindcss/theme.css:347-372`) 죽은 코드였다. 아래 5종은 **올바른 네임스페이스**로
선언한다.

### `@theme` 토큰 선언 (globals.css)

```css
@theme {
  --text-display: 1.875rem;        /* 30px */
  --text-display--line-height: 1.2;
  --text-heading: 1.375rem;        /* 22px */
  --text-heading--line-height: 1.3;
  --text-subhead: 1.0625rem;       /* 17px */
  --text-subhead--line-height: 1.4;
  --text-body: 1rem;               /* 16px */
  --text-body--line-height: 1.6;
  --text-label: 0.875rem;          /* 14px */
  --text-label--line-height: 1.4;
}
```

기존 `--font-size-label/body/heading/display`(죽은 코드, `globals.css:35-38`)와
`--font-weight-regular/semibold`(`globals.css:39-40`, `--font-weight-semibold`만 `.prose summary`
1곳에서 참조됨, `globals.css:204`)는 삭제한다 — 굵기는 Tailwind 기본 유틸리티(`font-normal`=400,
`font-semibold`=600, `font-bold`=700, `node_modules/tailwindcss/theme.css:374-382`)로 충분하므로
재선언이 불필요하다.

### 역할별 표 (D-R4K-4, 01-UI-SPEC의 4종/2굵기를 대체)

| 역할 | 유틸리티 클래스 | 크기 | 굵기 | Line Height | 용도 |
|------|----------------|------|------|-------------|------|
| display | `text-display font-bold` | 30px | 700 | 1.2 (tracking `-0.02em` 별도 적용) | 레슨 제목(`<h1>`), Step 페이지 제목, 홈 히어로 |
| heading | `text-heading font-bold` | 22px | 700 | 1.3 | `.prose h2`(레슨 구간 제목), 모듈 아코디언 헤더, Step 카드 제목, 사이트 로고(내비) |
| subhead | `text-subhead font-bold` | 17px | 700 | 1.4 | `.prose h3` — 크기 차이(body 대비 +1px)보다 굵기·여백·색으로 구분 |
| body | `text-body font-normal` | 16px | 400 | 1.6 (`.prose` 내부는 아래 참고) | 카드 설명, 레슨 목록 항목 제목, 페이저 라벨 |
| label | `text-label font-normal` 또는 `text-label font-semibold` | 14px | 400/600 | 1.4 | 배지, 표 셀, 브레드크럼, 내비 항목, Section Tape 번호(mono와 결합) |
| inline code | (토큰화 안 함, `.prose code` 단일 규칙) | 15px (`0.9375rem` **절대값**) | 400 | 상속 | `.prose` 안 인라인 코드 — rem 절대값이라 표 셀 안에서도 축소되지 않음(12.25px 재발 방지, 04-UI-REVIEW Pillar 4) |

**`.prose` 본문 line-height는 이 표의 body 행(1.6)과 별개다.** `globals.css:163`의
`.prose { line-height: 1.8 }` + `.prose > p { margin-block: 2.4em }`(D-79/05-13, 01-UI-SPEC 승계)는
그대로 유지 — MDX 프로즈 문단은 상속된 1.8을 쓰고, `text-body` 유틸리티는 프로즈 밖(카드 설명,
목록 항목 등)에서 명시적으로 쓰일 때만 1.6을 적용한다. 이 Phase는 body line-height를 바꾸지 않는다.

**`code`의 `font-weight: 600` 기본값을 명시적으로 덮어써야 한다(Pitfall 2, 06-RESEARCH.md).**
`@tailwindcss/typography`(`node_modules/@tailwindcss/typography/src/styles.js:1541-1543`)는
`code`에 기본 `font-weight: 600`을 지정한다 — `font-size`만 오버라이드하고 굵기를 그대로 두면
D-R4K-4의 inline code 400이 반영되지 않는다:

```css
.prose code::before,
.prose code::after {
  content: none;              /* D-R4K-5: 리터럴 백틱 글리프 제거 */
}
.prose code {
  font-size: 0.9375rem;       /* D-R4K-4 */
  font-weight: 400;           /* 반드시 함께 지정 — 플러그인 기본값 600이 새는 것을 막는다 */
  background-color: var(--color-surface);
  padding-inline: 0.25em;
  border-radius: 0.25rem;
}
.dark .prose code {
  background-color: var(--color-surface-dark);
}
```

### `.prose h1–h4` 오버라이드 (플러그인 기본값 봉쇄)

```css
.prose h1 { font-size: var(--text-display); font-weight: 700; line-height: 1.2; }
.prose h2 { font-size: var(--text-heading); font-weight: 700; line-height: 1.3; }
.prose h3 { font-size: var(--text-subhead); font-weight: 700; line-height: 1.4; }
.prose h4 { font-size: var(--text-body); font-weight: 700; line-height: 1.6; }
```

평범한 클래스 선택자로 충분하다 — `@tailwindcss/typography`의 모든 선택자가 `:where()`로 감싸져
명세성 0이므로(`node_modules/@tailwindcss/typography/src/index.js:20-45`), `!important`나
`@layer`가 필요 없다. `globals.css:163-215`가 이미 이 패턴으로 5곳(`.prose > p`, `.prose > h2`,
`.prose > h3`, `.prose details`, `.prose summary`)을 성공적으로 오버라이드했다 — 새 CSS 아키텍처
불필요.

## Color

**새 토큰 0개(D-R4K-2) — 04-UI-REVIEW Pillar 3이 이미 4/4(양쪽 테마 AAA 실측)를 줬으므로 이
Phase는 색을 손대지 않는다.** 아래는 `globals.css:5-33`의 기존 18토큰을 그대로 인용한다.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Light `#F8FAFC` / Dark `#0B1220` | 페이지 배경 |
| Secondary (30%) | Light `#E7ECF3` / Dark `#131B2E` | 카드(`bg-surface`), 아코디언, 내비 바 |
| Accent (10%) | Light `#0D9488` / Dark `#2DD4BF` | 아래 "Accent reserved for" 참고 |
| Destructive | Light `#DC2626` / Dark `#F87171` | 파괴적 액션 확인용 — 이 Phase에도 사용처 없음(01-UI-SPEC 승계) |

**Accent reserved for (명시적 목록 — Phase 6이 추가하는 것 없음, D-R4K-2가 확장을 명시적으로 금지):**
- 진행률 바 채움, Primary CTA, 활성/포커스 상태(포커스 링, 활성 내비 밑줄), 프로즈 링크 hover
- **Section Tape에는 accent를 쓰지 않는다** — D-R4K-2가 명시적으로 금지: "테이프에 accent를 쓰면
  Step 1 파랑과 인접해 '청록 = 상호작용'이라는 기존 의미가 흐려진다." Section Tape의 색은 아래
  Step 색을 쓴다.

**Step identity colors (D-04, 승계) — Section Tape까지 확장(D-R4K-2):**

| Step | Value | 기존 용도 | Phase 6 신규 용도 |
|------|-------|----------|-------------------|
| Step 1 | Light `#3B82F6` / Dark `#60A5FA` | Step 카드 좌측 테두리, 아코디언 헤더 틴트, 진행률 바 | **Section Tape 막대색**(해당 레슨이 Step 1 소속일 때) |
| Step 2 | Light `#8B5CF6` / Dark `#A78BFA` | 동일 | 동일 |
| Step 3 | Light `#F59E0B` / Dark `#FBBF24` | 동일 | 동일 |

**D-88(a)/D-96 게이트 스코프(리터럴 색 판정):** `check-design-tokens.mjs`는 hex/rgb/hsl 리터럴 +
Tailwind 임의값 대괄호(`bg-[#abc]`) + **Tailwind 기본 팔레트 색 유틸리티**(`text-white` 등)까지
위반으로 검사한다(D-96). 06-RESEARCH.md 실측: `text-white` 4곳(`not-found.tsx:12`,
`today-lesson-card.tsx`의 `CTA_CLASS`, `unlock/done/page.tsx:37`, `progress-summary.tsx:72`)이
CTA 버튼 텍스트색으로 쓰이는데, 대비되는 배경이 항상 `bg-accent`/`bg-accent-dark`이므로
`text-white`를 유지해도 실질 문제는 없지만 게이트 취지("토큰만 쓴다")를 지키려면 4곳 모두
CTA 텍스트를 위한 명시적 대응이 필요하다 — 계획 단계에서 다음 중 하나로 처리:
(a) 이미 흰색과 동등한 대비를 내는 기존 토큰이 없으므로 새 토큰 도입 없이 `color-mix` 없이
`text-white` 자체를 게이트 예외 목록(allowlist)에 명시적으로 등록하거나, (b) CTA 배경이 항상
accent이므로 `text-white`를 그대로 두되 주석으로 "accent 배경 전용 흰색, 새 색 아님"을 명시.
**이 문서의 권고: (a) 게이트 allowlist에 `text-white`를 등록** — 4곳뿐이고 전부 accent 배경 위
고정 대비용이라 토큰화해도 값이 항상 `#ffffff`로 동일해 실질 이득이 없다. `check-design-tokens.mjs`
실패 메시지에 이 allowlist 이유를 주석으로 남길 것.

## Section Tape 계약 (D-R4K-1)

### 구조

- 상단 `sticky` 6칸 바, `article h2` 개수만큼(이 사이트의 6단 척추 표준 — `06-DESIGN-INPUT.md` 근거) 칸이 생긴다. `hasContent: false`이거나 렌더된 `h2`가 2개 미만이면 아예 렌더하지 않는다(D-R4K-1).
- 폭 = 다음 `h2.offsetTop` − 이 `h2.offsetTop`(비례), `ResizeObserver`로 `<details>` 토글 시 재계산.
- 색 = 해당 레슨의 Step 색(`lesson.stepId`, 이미 페이지에서 사용 가능 — `lesson/[lessonId]/page.tsx:50`). accent는 쓰지 않는다(D-R4K-2).
- 번호는 `ui-monospace`(계기 목소리, D-R4K-3), `text-label`(14px) 크기.

### 인터랙션 상태 (신규 정의 — CONTEXT.md에 없던 항목)

| 상태 | 시각 처리 |
|---|---|
| **idle**(비-현재 칸) | 3px 시각 막대, Step 색 배경 불투명도 40%(`bg-step-N/40 dark:bg-step-N-dark/40`) — 번호/제목 텍스트 없음(D-R4K-1 원문: "나머지는 무표시") |
| **current**(현재 칸) | 3px 막대 불투명도 100%, 칸 안에 번호+제목 텍스트 표시(`text-label` mono 번호 + `text-label` 제목, 굵기 600) |
| **hover**(마우스 환경) | 배경 불투명도 idle 대비 +20%p(`/60`) — 새 색 없이 같은 Step 색의 불투명도만 이동 |
| **focus-visible**(키보드 탭) | `outline: 2px solid var(--color-accent)` (다크 `--color-accent-dark`), `outline-offset: 2px` — Section Tape는 이 Phase의 신규 컴포넌트라 기존 코드베이스에 focus-visible 관례가 없었다(전역 grep 확인, `globals.css`에 `focus-visible` 0건) → 이 Phase가 처음 도입하는 명시적 규칙. accent를 쓰는 이유: "활성/포커스 상태"는 이미 Accent reserved-for 목록에 있는 용도(색 의미 재사용, 새 규칙 아님) |
| **tap/active** | 클릭 즉시 해당 `h2`로 스크롤. `prefers-reduced-motion: reduce`면 `scrollIntoView({ behavior: "auto" })`, 그 외에는 `{ behavior: "smooth" }` — 코드베이스가 이미 완료 애니메이션에서 이 패턴을 지킨다(`globals.css:283-287`, `@media (prefers-reduced-motion: reduce)`로 `complete-check-icon` 애니메이션 제거) |

### 하이드레이션·초기 렌더

- SSR/최초 렌더: `sections === null` 상태 — 6칸 **균등 폭**(각 16.67%), Step 색은 이미 서버에서 알 수 있으므로(색은 하이드레이션 불필요) idle 불투명도(40%)로 렌더. 라벨/번호는 아직 없음.
- `useEffect` 완료 후: 실제 비례 폭 + 현재 칸 라벨로 전환.
- **폭 전환에 애니메이션을 걸지 않는다**(discretion) — 균등 폭 → 실제 폭 전환은 reflow를 동반하는 레이아웃 변화라, 트랜지션을 걸면 오히려 어색한 "튐"으로 보일 위험이 있고 `prefers-reduced-motion`을 매번 분기해야 하는 비용도 든다. 대신 현재 칸의 라벨 등장에는 `opacity` 150ms 트랜지션만 허용(reflow 없는 순수 페인트 변화라 안전).

### 터치 타깃 예외

- **높이**: 44px, 시각 막대는 3px(D-R4K-1 원문 그대로) — 얇은 막대로 44px 히트 영역을 확보하는 방식.
- **폭**: 44px 최소를 강제하지 않는다. 비례 폭이 44px보다 좁아지는 짧은 구간이 있을 수 있다(예: 375px 뷰포트, 6칸, 한 구간이 유난히 짧으면 그 칸의 실제 폭이 이론상 375px/6=62.5px 평균보다 훨씬 작아질 수 있음). 대신 **폭 하한 24px**을 CSS `min-width`로 둔다: 비례 계산 결과가 24px 미만이면 24px로 바닥을 두고 나머지 칸에서 그 차이를 흡수한다. 24px는 "완전히 눌리지 않을 만큼의 최소 폭"이며 44px 규칙의 예외로 명시한다 — Section Tape는 파괴적 액션이 아닌 내비게이션 보조 UI라 오탭의 대가가 낮다(잘못 눌러도 인접 구간으로 이동할 뿐이다).
- 이 예외는 01-UI-SPEC의 "44px 최소 터치 타깃… 기능적 하한선이지 스페이싱 토큰이 아니다"는 문구와 같은 결의 예외다 — 새 원칙이 아니라 그 문서가 이미 열어둔 "예외는 명시하라"는 여지를 채운 것이다.

### `scroll-margin-top`

```css
.prose h2 {
  scroll-margin-top: 52px; /* 44px(테이프 높이) + 8px(spacing sm 토큰) 여유 */
}
```

`.prose h2` 자체 폰트 크기·굵기 규칙(위 Typography 섹션)과 병기 가능 — 선택자가 겹치므로 같은
규칙 블록에 넣거나 별도 규칙으로 분리해도 무방(계획 재량).

## UI Considerations

> ui-phase UI-consideration probe가 생성했다(`ui-consideration-probe.cjs`, 8 elements x 8-category
> shape-rooted state taxonomy). 한국어 산문이라 휴리스틱 분류기가 8개 중 6개를 `unclassified`로
> 남겼으므로, 워크플로가 규정한 kind 오버라이드(propose-then-confirm)를 저자가 적용해 재실행했다.
> empty / loading / error / populated / partial / overflow / zero-one-many / long-text 축을 다룬다.
> 빈 상태·에러 상태의 **문구**는 `## Copywriting Contract`가 소유한다 — 이 절은 문구를 재기술하지 않고 참조만 한다.

**커버리지: applicable 44 / resolved 44 / unresolved 0** (explicit 27 · backstop 6 · dismissed 11)

| Element | Category | Status | Resolution / Reason |
|---|---|---|---|
| Section Tape | empty | resolved (explicit) | 렌더된 article h2가 2개 미만이거나 lesson.hasContent === false이면 Section Tape 컴포넌트는 null을 반환한다 — 빈 테이프가 존재할 수 없다 (D-R4K-1) |

**플래너 lift 규칙:** `resolved (explicit)` 행은 `must_haves.truths`에 평문 문자열로,
`resolved (backstop)` 행은 `{ statement: <the check>, verification: backstop }` 플랫 스칼라 마커로 올린다.
`dismissed` 행은 올리지 않는다(사유가 이 표에 남아 있다). `unresolved` 행은 0건이다.
