실습 방식은 D-57로 고정한다: **PC 터미널의 git 명령 + GitHub 웹에서 PR.** 연습용 새 저장소(1-1 레슨에서 만든 빈 저장소)를 대상으로 clone → branch → 파일 수정 → commit → push → PR 열기 → merge → 로컬 동기화까지 **한 바퀴 전체**를 명령 순서대로 돌게 한다. 중간에 끊기는 안내를 만들지 않는다 — 학습자가 PR이 머지되는 것까지 눈으로 봐야 이 레슨이 끝난다.

비유의 방향은 **갈래길에서 새 가지를 뻗었다가 다시 원줄기에 붙이는 것**이다. 브랜치=가지, 커밋=가지에 남긴 표식, PR=합쳐 달라는 요청, 머지=원줄기에 붙이기.

절별 목표:
- ① 학습 목표 — "브랜치를 만들어 원본을 건드리지 않고 작업할 수 있다", "변경을 커밋으로 묶고 원격 저장소에 올릴 수 있다", "PR을 열어 변경 내용을 설명하고 머지할 수 있다", "머지 후 로컬을 최신 상태로 되돌릴 수 있다" 계열 4개.
- ② 왜 배우나 — 협업에서 브랜치·PR이 왜 기본 단위인지, 그리고 이 사이트 자체도 같은 방식으로 만들어진다는 것. 4문장 이내.
- ③ 개념 설명 — 이모지 `###` 소제목 3~4개.
  - "저장소·커밋·브랜치" — 원격 저장소와 로컬 저장소가 각각 무엇인지, 커밋이 무엇을 저장하는지. "일상 비유" 열이 있는 3열 표(개념 · 하는 일 · 일상 비유)로 정리한다.

  - "왜 원줄기에서 바로 고치지 않나" — 브랜치가 막아 주는 사고(되돌리기, 리뷰 없이 배포되는 것)를 한 문단.
