# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn stays declined (continuation of Phase 1 decision) |
| Preset | not applicable |
| Component library | none — native HTML (`<button>` for the complete toggle, `<a>`/`next/link` for CTAs) + custom Tailwind-styled components, same as Phase 1. Phase 2's new surface (complete button, progress bars/badges, `/unlock` page) is all simple toggle/display state — a native `<button>` already gives correct a11y semantics (`aria-pressed`) without a headless-UI dependency. |
| Icon library | `lucide-react` (already installed, Phase 1) — new usages: `CheckCircle2` (complete button checked state + completed lesson list item marker), `RefreshCw` (inline retry after save failure, D-29), `PartyPopper` (optional decorative accent on the "커리큘럼 완료" celebratory state only — not required, omit if it complicates the build) |
| Font | Pretendard (unchanged, D-06) — no new font needs |

**shadcn gate re-check:** `components.json` still absent (confirmed via filesystem scan of repo root). Re-declining for the same reasons as Phase 1 (`01-UI-SPEC.md`): PITFALLS.md Pitfall 1 explicitly warns against platform/tooling polish crowding out the content-writing timeline, and Phase 2's actual component surface — one toggle button, a handful of progress bars/badges, one unlock page — is well within what hand-styled Tailwind + native HTML already covers without a new dependency. Revisit only if a later phase (schedule/calendar, Phase 3) needs real overlay/dialog primitives.

**Access-gated visibility (PLAT-02, D-18/D-20) — applies to every element below:** All progress UI — complete button, progress bars/percentages, module/Step progress badges, the homepage progress summary block, and the "이어서 학습하기" CTA — renders **only** when the request carries the secret unlock cookie. Without the cookie, none of these elements exist in the DOM (not just visually hidden) — the page renders exactly as it did in Phase 1 (pure static content). This is a server-side render condition, not a client-side show/hide, and every component spec below assumes "cookie present" unless stated otherwise.

## Spacing Scale

Inherited unchanged from Phase 1 (`01-UI-SPEC.md`) — no new tokens needed for Phase 2.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inline padding |
| sm | 8px | Compact element spacing (badge-to-text, progress badge to lesson count) |
| md | 16px | Default element spacing (card padding, list item gaps, complete button internal padding) |
| lg | 24px | Section padding (progress summary block internal padding) |
| xl | 32px | Layout gaps (homepage section breaks) |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- **44px minimum touch target (UX-01)** — the complete button (D-21) and the `/unlock` page's confirmation button both must meet `min-h-11 min-w-11`, same rule as all Phase 1 interactive elements. No new exceptions introduced.

## Typography

Inherited unchanged from Phase 1 — exactly 4 sizes / 2 weights, no additions.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 (regular) / 600 (semibold for badge values) | 1.4 |
| Body | 16px | 400 (regular) / 600 (semibold for primary CTA) | 1.6 |
| Heading | 20px | 600 (semibold) | 1.3 |
| Display | 28px | 600 (semibold) | 1.2 |

**Phase 2 application map (new elements only):**
- Complete button label → Body size, **semibold** (16px/600) — deliberately heavier than the existing prev/next pager buttons (16px/400, `lesson-nav.tsx`) so the primary action of the page reads as more prominent than secondary navigation.
- Progress summary block heading ("전체 진행률") → Heading (20px/600)
- Progress summary block big percentage number → Display (28px/600) — reusing the Display role outside `<h1>` is acceptable per Phase 1's role-based (not tag-based) typography system
- Module/Step progress badge label ("완료 X/Y") → Label, regular (14px/400)
- Module/Step progress badge percentage ("Z%") → Label, semibold (14px/600), accent-colored when >0%, neutral when 0%
- `/unlock` page confirmation/error copy → Body (16px/400), heading → Heading (20px/600)

No new sizes or weights — do not introduce a 3rd weight or 5th size for any Phase 2 element.

## Color

Inherited unchanged from Phase 1 — same hex values, no new color tokens. Phase 2 reuses the existing accent, Step-identity, neutral, and destructive tokens only.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Light `#F8FAFC` / Dark `#0B1220` | Page background, base surface |
| Secondary (30%) | Light `#E7ECF3` / Dark `#131B2E` | Cards, progress summary block panel, module accordion panels |
| Accent (10%) | Light `#0D9488` / Dark `#2DD4BF` | See "Accent reserved for" below (extended from Phase 1) |
| Destructive | Light `#DC2626` / Dark `#F87171` | Still **unused** — Phase 2 has no destructive action (toggling a lesson back to incomplete is a normal reversible toggle, not a destructive one per D-24/TRACK-02). Token stays reserved for a future "진도 초기화"-style feature, not introduced here. |

**Accent reserved for (explicit list — extends Phase 1's list, never "all interactive elements"):**
- *(Phase 1, unchanged)* Progress bar fill on Step cards, primary CTA buttons, focus ring/active nav underline, link hover in lesson prose
- *(Phase 2, new)* Complete button's checked-state fill/border and the `CheckCircle2` icon color
- *(Phase 2, new)* Progress summary block's progress bar fill and the big percentage number
- *(Phase 2, new)* Module/Step progress badge's percentage number, only when >0%
- *(Phase 2, new)* "이어서 학습하기" CTA button
- *(Phase 2, new)* The completion celebration ring/glow effect (see Copywriting Contract → completion animation note) — reuses the accent hex, does not introduce a new color

**Step identity colors (D-04)** — unchanged, still used for per-Step progress bars/badges so Step 2/3 progress reads in that Step's own color rather than the global teal accent:

| Step | Color |
|------|-------|
| Step 1 | Light `#3B82F6` / Dark `#60A5FA` |
| Step 2 | Light `#8B5CF6` / Dark `#A78BFA` |
| Step 3 | Light `#F59E0B` / Dark `#FBBF24` |

**Completed lesson list item tone-down (D-24):** text color switches from default foreground to `text-badge-neutral-text`/`dark:text-badge-neutral-text-dark` (existing neutral token, no new color), no strikethrough, no opacity trick beyond the color swap itself — the `CheckCircle2` icon in front of the title is accent-colored and is what signals "done," not a dimmed/greyed-out treatment of the whole row.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Complete button — unchecked state | 레슨 완료하기 (aria-label same) |
| Complete button — checked state | 완료했어요 ✓ (aria-label: "완료 취소하기" — re-clicking toggles back to incomplete, D-24) |
| Save error (inline, D-29) | 저장하지 못했습니다. 다시 시도해주세요. |
| Save error — retry button | 다시 시도 |
| Progress summary — empty state heading (0 완료) | 학습을 시작해볼까요? |
| Progress summary — empty state body | 완료한 레슨이 아직 없어요. |
| Progress summary — populated heading | 전체 진행률 |
| Progress summary — populated body | {완료}/{전체} 레슨 완료 · {percent}% |
| Progress summary — all-complete heading (100%) | 커리큘럼을 모두 완료했어요! |
| Progress summary — all-complete body | 축하합니다. 처음부터 다시 볼 수도 있어요. |
| Primary CTA (progress summary, not yet 100%) | 이어서 학습하기 — 커리큘럼 순서상 첫 미완료 레슨으로 이동 |
| Primary CTA (progress summary, 100% complete) | 커리큘럼 처음으로 — Step 1 페이지로 이동 (교체, "이어서 학습하기" 문구는 이 상태에서 쓰지 않음) |
| Module/Step progress badge | 완료 {n}/{total} · {percent}% |
| Completed lesson list item secondary CTA (module accordion) | 다시 보기 (미완료 레슨의 "레슨 시작하기"를 대체) |
| `/unlock` success heading | 잠금 해제됐어요 |
| `/unlock` success body | 이제 이 기기에서도 진도가 저장돼요. |
| `/unlock` success CTA | 커리큘럼 홈으로 |
| `/unlock` invalid-key heading | 유효하지 않은 링크예요 |
| `/unlock` invalid-key body | 링크를 다시 확인해주세요. |
| `/unlock` invalid-key CTA | 홈으로 돌아가기 |
| 진행률 조회 실패 배너 (읽기 장애, D-31) | 진행률을 불러오지 못했어요. 새로고침 후 다시 확인해주세요. — 홈에서는 진행률 요약 블록 자리, 레슨 페이지에서는 완료 버튼 자리에 렌더. 인라인 배지/바/완료 마커는 이 상태에서 렌더하지 않음 |
| Destructive confirmation | 해당 없음 — Phase 2에 파괴적 액션 없음 (완료 취소는 되돌릴 수 있는 일반 토글이지 삭제가 아님, D-24). Destructive 토큰은 계속 미사용 예약 상태. |
| Completion animation note (D-23, Claude's Discretion) | CSS-only 연출: 체크 아이콘 fade+scale-in(0 → 1.15 → 1, ~450ms) + 버튼 주변 accent 색 ring/glow가 한 번 확장하며 사라짐. 새 라이브러리(Framer Motion 등) 도입 없이 Tailwind `@keyframes`로 구현. `prefers-reduced-motion: reduce`에서는 트랜지션 없이 즉시 상태만 바뀐다. |
