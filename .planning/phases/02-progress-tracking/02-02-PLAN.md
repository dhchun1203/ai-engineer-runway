한 레슨의 완료 토글을 UI부터 Postgres까지 실제로 관통시킨다. 다른 호출 지점(모듈 목록·Step·홈)은 이 태스크에서 손대지 않는다 — 경로 하나만, 대신 그 하나는 프로덕션 품질로 만든다.

**(1) `src/lib/unlock-secret.ts`.** 어떤 것도 import하지 않는 순수 모듈이다(그래야 게이트 스크립트가 Node에서 직접 로드해 단위 검증할 수 있다). `export const UNLOCK_COOKIE_NAME = 'runway_unlock';`와 `export function isValidUnlockValue(candidate: string | undefined, secret: string | undefined): boolean`를 둔다. 판정 규칙: `secret`이 비어 있거나 길이가 16 미만이면 **무조건 false**를 반환한다. 이 가드가 이 파일의 존재 이유다 — 가드가 없으면 시크릿이 설정되지 않은 서버에서 쿠키 없는 요청의 `undefined`와 환경 변수의 `undefined`가 서로 같아져 모든 방문자가 잠금 해제 상태로 판정된다. 가드를 통과한 뒤에만 `candidate === secret` 엄격 비교를 한다. 타이밍 안전 비교는 쓰지 않는다 — 1인용·단일 정적 시크릿의 위협 모델에서 과설계이며 RESEARCH가 이를 명시적으로 수용했다(A3). 그 판단 근거를 한 줄 주석으로 남긴다.

**(2) `src/lib/auth.ts`.** `next/headers`의 `cookies()`와 위 두 심볼을 import해 `export async function hasUnlockCookie(): Promise<boolean>` 하나만 둔다. 본문은 쿠키 스토어에서 `UNLOCK_COOKIE_NAME` 값을 꺼내 `isValidUnlockValue(value, process.env.UNLOCK_SECRET)`를 반환하는 것뿐이다. 페이지·Server Action이 각자 `cookies()`를 직접 다루지 않고 이 함수 하나만 부르게 해서 게이트를 빠뜨릴 경로를 줄인다. `middleware.ts`는 만들지 않는다 — 콘텐츠는 공개여야 하므로(D-18) 미들웨어로 요청을 사전 차단하면 오히려 D-18과 충돌하고, Server Action 내부 재검증이 어차피 필수라 중복 대비 이득이 작다(RESEARCH Anti-Patterns, A4를 이 계획이 검토 후 채택).

**(3) `src/app/lesson/[lessonId]/actions.ts`.** 파일 첫 줄 `'use server';`. `toggleLessonComplete(lessonId: string, currentlyDone: boolean): Promise<void>`를 named export한다. 본문 순서가 중요하다 — 이 순서 자체가 보안 계약이다:
  1. `await hasUnlockCookie()`가 false면 즉시 throw한다. 페이지가 버튼을 렌더하지 않았다는 사실은 보호가 아니다: Server Action은 컴파일된 POST 엔드포인트로 존재하므로 캡처된 요청을 재전송할 수 있다(RESEARCH Pitfall 1). 이 검사는 재량 사항이 아니라 PLAT-02 성공 기준 5의 필수 구현이다.
