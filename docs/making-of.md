## 🗂 단계별 기록

### 1️⃣ 자료 모으기 — 무엇을 공부할지 정리했다 ✅ (2026-08-24)

- 커리큘럼 원문(3 Steps, 19개 모듈, 프로젝트 5종)을 구조화해 "원본 자료(source of truth)"로 보존했다
- 핵심 결정 4가지를 먼저 정했다: 구현 형태는 Next.js + Supabase + Vercel / 콘텐츠 깊이는 Step 1·2 핵심은 심화, Step 3는 개념 훑기 / 일정 기준은 하루 4~6시간 × 5주 → 3단계 이후 실제 레슨 분량을 재보고 하루 3시간 이내(하루 1레슨, 평균 약 2시간)로 낮췄다 / 예제 스택은 커리큘럼과 동일: Python, SQL, TS/React, Express, Prisma, LLM API, LangGraph/n8n
- GSD(작업 방식) 프로젝트를 초기화했다 — PROJECT.md(제품 정의·제약·핵심 가치), config.json(자동 진행 모드, 병렬 실행, 조사·계획 검토·검증을 맡는 보조 도구를 모두 켬)

### 2️⃣ 조사하기 — 남들은 어떻게 만들었나 ✅ (2026-08-24)

AI 리서치 에이전트(자동으로 자료를 조사해 주는 프로그램) 4개를 동시에 돌려, 네 가지 관점에서 조사했다.

| 관점 | 핵심 발견 |
|------|-----------|
| **무엇으로 만들까(Stack)** | Next.js 16 + React 19 정적 생성(SSG: 방문할 때 만들지 않고 미리 다 만들어 두는 방식), Velite(글 파일을 검사·변환해 주는 도구) 기반 MDX 파이프라인, Shiki 코드 색칠, Tailwind v4 + Pretendard 폰트, Supabase 익명 로그인 + RLS(데이터 접근 규칙) |
| **무엇을 어디에 둘까(Architecture)** | 커리큘럼 구조와 레슨 본문은 코드 저장소에 파일로, 데이터베이스에는 **진도만** 저장한다. 값을 바꾸는 일은 Server Action(브라우저가 아니라 서버에서 도는 함수) 한 경로로 통일했다 |
| **비슷한 서비스는 뭘 하나(Features)** | LMS·roadmap.sh·freeCodeCamp 모두 "콘텐츠 계층 → 완료 토글 → 진행률" 3단 구조가 핵심 루프다. 즉 이 사이트 요구사항이 곧 업계 표준이다. 다만 "개강일에서 거꾸로 계산한 학습 일정표"는 어디에도 없는 이 프로젝트만의 차별점이다. 일정 계산에는 레슨별 예상 소요시간 값이 필요하다 |
| **가장 위험한 함정(Pitfalls)** | 플랫폼 다듬기에 빠져 진짜 작업인 콘텐츠 집필(60~100시간+)을 미루는 범위 역전이 가장 위험하다. 대응: 1단계를 며칠로 타임박스, 배포를 맨 앞으로, 진도의 단일 진실 원천은 데이터베이스로(브라우저 저장소는 임시 표시용만) |

## 🧰 무엇으로 만들었나 — 그리고 왜 그걸 골랐나

판단 기준은 세 가지였다.

- ① 수업에서 배울 것과 같은 도구인가 — 짓는 게 곧 예습이 되도록
- ② 혼자 쓰고 5주 안에 끝낼 수 있나
- ③ 나중에 손이 덜 가나

| 선택 | 이유 | 검토했지만 안 쓴 대안 |
|------|------|----------------------|
| **Next.js(앱 라우터) + React** — 화면을 만들어 주는 프로그램 뼈대 | 커리큘럼 Step 2에서 배울 것과 같은 도구다. 사이트를 만드는 일 자체가 예습이 된다. 콘텐츠가 안 바뀌니 SSG(방문 전에 미리 다 만들어 두는 방식)로 빠르게 띄운다 | SPA(CRA/Vite) — 검색 노출과 첫 로딩이 불리하고 커리큘럼과도 안 맞는다. ISR(주기적으로 다시 만드는 방식) — 콘텐츠는 git push로만 바뀌니 필요 없다 |
| **Supabase(PostgreSQL)** — 내 진도를 대신 기억해 주는 온라인 창고 | 진도(완료 체크)처럼 "바뀌는 값"만 여기 저장한다. 커리큘럼 Step 2에서 배울 데이터베이스와 같아서 실전 연습이 된다 | 브라우저 저장소(localStorage)만 쓰기 — 기기를 바꾸면 진도가 사라진다(아이패드+PC 병행에 치명적). 직접 서버 만들기 — 혼자 쓰는 사이트엔 과하다 |
| **콘텐츠 = MDX(글과 코드 예제를 한 파일에 같이 쓰는 문서 형식) 파일 — 데이터베이스 아님** | 레슨 글을 "코드처럼" 저장소 파일로 버전 관리한다 — 되돌리기·검색이 쉽고, 글 편집 화면(CMS)을 따로 안 만들어도 된다. 저장 전에 형식을 자동 검사(Velite)해 오타나 빠진 항목을 미리 잡는다 | 데이터베이스에 글 저장 — 결국 편집 화면을 또 만들어야 한다. Contentlayer — 더 이상 관리되지 않는 도구다 |
| **Shiki(코드 색칠 도구, rehype-pretty-code로 연결)** | 실무 예제 언어가 Python·SQL·TS·React 등 다양하다. 코드 색칠을 미리(사이트를 만들 때) 끝내 두면, 방문자 화면에서는 색칠 프로그램이 따로 돌지 않아 아이패드에서도 빠르다 | Prism/highlight.js — 방문자 화면에서 색칠 프로그램이 돌아 느려지고, 정확도도 낮다 |
| **Tailwind CSS v4 + Pretendard(한글 글꼴)** | 태블릿 화면을 빠르게 맞추는 꾸미기 도구다. Pretendard는 한글이 화면에서 가장 자연스럽게 보이는 글꼴 중 하나다 | CSS를 하나하나 직접 쓰기 — 5주 안에 끝내기엔 느리다. Noto Sans KR만 쓰기 — 본문 가독성이 조금 떨어진다 |
| **진도 보호 방식** — 내 진도를 남이 못 보고 못 바꾸게 막는 방법 | 혼자 쓰는 사이트라 회원가입·비밀번호는 번거롭기만 하다. 로그인 화면 없이 진도만 안전하게 지키는 방법을 쓰기로 했다 → 실제 구현(2단계)에서는 로그인 자체를 아예 없애고, 비밀 링크를 한 번 열면 남는 쿠키로 본인을 확인하는 방식으로 바뀌었다. 데이터베이스는 서버에서만 열 수 있고, 바깥에서는 기본 차단(RLS 정책 0개)이다 | 완전한 로그인(OAuth·매직링크) — 혼자 쓰는데 과한 설계다. 로그인도 잠금도 없음 — 공개된 접속 정보로 아무나 진도를 볼 수 있는 구멍이 생긴다 |
| **Vercel 배포(1단계부터)** — 만든 사이트를 인터넷에 공개해 주는 서비스 | 커리큘럼에서 마지막에 배울 배포 서비스와 같다. 맨 처음부터 실제 주소로 확인해 두면 "내 컴퓨터에선 됐는데" 문제를 일찍 찾는다 | 맨 마지막에 배포 — 몇 주간 문제를 숨겨 두는 시한폭탄이 된다 |

### 3️⃣ 할 일 정하기 — 20가지로 못 박았다 ✅ (2026-08-24)

- 리서치 결과와 커리큘럼을 바탕으로 v1 요구사항 20개를 정했다. 5개 카테고리로 나눴다: 콘텐츠(CONT) / 진도(TRACK) / 일정(SCHED) / 플랫폼(PLAT) / 사용 경험(UX)
- 각 요구사항은 "사용자가 ~할 수 있다"처럼 눈으로 확인 가능한 문장 + 고유 번호로 적었다. 이후 로드맵의 각 단계에 100% 연결됐다
- 여유 있을 때로 미룬 것 4가지: 검색·필터, 레슨 노트, 일정 자동 재조정, 앱처럼 설치하기(PWA)
- 일부러 뺀 것 9가지와 그 이유를 문서로 남겼다. 예를 들어 게임식 보상은 뺐다 — 혼자 공부하는 사람에겐 D-day와 진도 표시로 충분하기 때문이다. 퀴즈 채점도 뺐다 — 기간이 부족해서다. 할 일이 슬금슬금 늘어나는 걸 막는 장치다

### 4️⃣ 뼈대 잡기 — 5개 덩어리로 나눴다 ✅ (2026-08-24)

- 5단계 로드맵을 확정했다. 요구사항 20개를 전부 연결했고, 전략은 "플랫폼은 1주, 콘텐츠에 4주"였다
- 5개 덩어리: ① 배포된 커리큘럼 뼈대 ✅ ② 진도 체크와 진행률 ✅ ③ 학습 일정과 오늘의 학습 ✅ ④ Step 1 심화 콘텐츠(아직) ⑤ Step 2·3 콘텐츠 + 프로젝트 가이드(아직)
- 모든 단계는 기술 계층이 아니라 "사용자가 할 수 있는 일" 단위로 잘랐다
- 단계마다 눈으로 확인 가능한 성공 기준을 4~5개씩 미리 정했다. 검증할 때 그대로 썼다
- 위험 대응을 구조에 미리 심어 뒀다: 배포를 1단계에 둬서 환경 문제를 일찍 발견하고, 1~3단계가 커지면 자동으로 나중 버전으로 밀어내 콘텐츠 집필 시간을 지켰다

### 5️⃣ 만들기 — 실제로 돌아가게 했다 ✅ (2026-08-24 ~ 08-25)

## 🏗️ 1단계 — 뼈대와 배포 (2026-08-24)

- Walking Skeleton(전체를 관통하는 가장 얇은 한 줄기를 먼저 끝까지 연결해 보는 방식)으로 Next.js 16 + React 19 + TypeScript + Tailwind v4 기본 골격을 만들었다
- 문서 파일 한 개가 Velite → 코드 색칠(라이트/다크 두 테마, 항상 보이는 복사 버튼) → 화면 렌더러 → 실제 레슨 주소까지 끝까지 이어지는 걸 확인하고 빌드도 통과시켰다
- 파일럿 레슨 1편(Python 변수·자료형)을 6단 구성(학습 목표 → 왜 배우나 → 개념 설명 → 실무 예제 → 실무 팁 → 핵심 정리)으로 실제 글을 써서 파이프라인을 진짜 콘텐츠로 검증했다
- Pretendard 자체 호스팅 가변 폰트, 딥블루/청록 테마, 다크모드(화면이 그려지기 전에 도는 스크립트로 깜빡임을 없앰)를 적용했다
- 공개 GitHub 저장소 [`ai-engineer-runway`](https://github.com/dhchun1203/ai-engineer-runway)를 만들고 첫 커밋을 올렸다 — 코드 자체가 포트폴리오라 처음부터 공개로 열었다. 기본 브랜치는 로컬 설정을 따라 `main`이 아니라 `master`로 만들어졌다(기능은 같고, 차이만 기록한다)
- Vercel(만든 사이트를 인터넷에 올려 주는 서비스)에서 이 저장소를 불러와 첫 실서비스 배포에 성공했다. 주소는 **https://ai-engineer-runway.vercel.app**이다 — 첫 화면과 파일럿 레슨 주소 모두 정상 응답했고, 배포된 환경에서도 코드 색칠·복사 버튼이 그대로 나왔다
- 두 가지 자동 배포 경로가 실제로 도는 것도 확인했다: `master`에 올리면 사람 손 없이 실서비스가 갱신된다 / 수정 제안(Pull Request)을 열면 미리보기 주소가 자동으로 생긴다
- 이 시점엔 비밀값이 하나도 없었다 — 환경 변수를 비운 채 배포에 성공시켜 "비밀값 없는 배포"라는 기준선을 먼저 세웠다
- 배포를 마지막이 아니라 맨 앞에서 한 이유: 조사 단계가 지목한 가장 큰 위험은 "플랫폼 다듬기가 진짜 작업인 콘텐츠 집필(60~100시간+)을 잠식하는 것"이고, 그 아래 위험은 "내 컴퓨터에선 됐는데 배포하면 터지는 문제를 콘텐츠 4주치 뒤에야 발견하는 것"이다. 처음에 실주소로 파이프라인을 검증해 둔 덕분에, 이후 모든 커밋은 사람 손 없이 실서비스에 반영된다

## ✅ 2단계 — 진도 체크 (2026-08-24)

- 레슨 페이지의 완료 버튼을 누르면 저장되고, 새로고침해도 아이패드↔데스크톱을 오가도 그대로 남는다. 다시 누르면 미완료로 되돌아간다
- 모듈·Step·전체 진행률(완료 개수와 %)이 표시되고, 첫 화면에 전체 요약과 "이어서 학습하기" 버튼이 생겼다
