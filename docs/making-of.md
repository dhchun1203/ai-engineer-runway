# Making-of: 이 사이트가 만들어진 과정

> 이 문서는 사이트의 "소개(Making-of)" 페이지의 원천 문서다. 자료 수집부터 배포까지 각 단계가 끝날 때마다 업데이트되며, 사이트 구축 후에는 MDX 페이지로 렌더링된다.
> 이 사이트는 학습 도구이자 **AI 엔지니어링 프로세스를 그대로 적용해 만든 포트폴리오**다.

## 프로젝트 한눈에 보기

- **무엇**: AI Engineer 교육과정(2026-09-30 개강, 총 1,056h) 사전학습 사이트
- **왜**: 개강 전 5주(8/25~9/29, 하루 4~6시간)를 체계적으로 쓰기 위해 — 개념 설명 + 실무 예제 + 진도 추적 + 학습 일정표
- **어떻게**: GSD(Get Stuff Done) 워크플로우로 리서치 → 요구사항 → 로드맵 → 단계별 계획/실행/검증을 거쳐 구축
- **스택**: Next.js(App Router) + Supabase + Vercel, 콘텐츠는 MDX — 커리큘럼에서 배울 스택과 동일하게 선택해 구축 과정 자체가 학습이 되도록 함
- **주 기기**: iPad (태블릿 우선 반응형)

## 단계별 기록

### 1단계 — 기획 & 자료 수집 ✅ (2026-08-24)

- 커리큘럼 원문(3 Steps, 19개 모듈, 프로젝트 5종)을 구조화해 `source of truth` 문서로 보존
- 핵심 결정 4가지를 먼저 확정:
  - **구현 형태**: Next.js + Supabase + Vercel 배포 (커리큘럼 동일 스택 = 구축이 곧 학습)
  - **콘텐츠 깊이**: Step 1·2 핵심은 심화, Step 3는 개념 훑기 (개강 후 깊게 배울 내용에 과투자 금지)
  - **일정 기준**: 하루 4~6시간 × 5주
  - **예제 스택**: 커리큘럼과 동일 (Python, SQL, TS/React, Express, Prisma, LLM API, LangGraph/n8n)
- GSD 프로젝트 초기화: PROJECT.md(제품 정의·제약·핵심 가치), config.json(YOLO 모드, 병렬 실행, 리서치/플랜체크/검증 에이전트 전부 활성화)

### 2단계 — 도메인 리서치 ✅ (2026-08-24)

AI 리서치 에이전트 4개를 병렬로 실행해 4개 관점에서 조사:

| 관점 | 핵심 발견 |
|------|-----------|
| **Stack** | Next.js 16 + React 19 정적 생성(SSG), Velite 기반 MDX 파이프라인, Shiki(rehype-pretty-code) 코드 하이라이팅, Tailwind v4 + Pretendard 폰트, Supabase 익명 로그인 + RLS |
| **Architecture** | 콘텐츠(커리큘럼 구조·레슨 본문)는 코드 저장소의 MDX/매니페스트로, Supabase에는 **진도 테이블만** — 변경(mutation)은 Server Action으로 일원화 |
| **Features** | 모든 유사 제품(LMS, roadmap.sh, freeCodeCamp)의 핵심 루프는 "콘텐츠 계층 → 완료 토글 → 진행률 산출" 3단 구조 — 이 사이트의 요구사항이 곧 업계 표준. 단, "개강일 역산 학습 일정표"는 어떤 제품에도 없는 이 프로젝트만의 차별점. 일정 매핑에는 레슨별 예상 소요시간 필드가 필요 |
| **Pitfalls** | 최대 함정은 "플랫폼 다듬기에 빠져 콘텐츠 집필(진짜 작업, 60~100h+)을 미루는 범위 역전" — Phase 1을 며칠로 타임박스하고 배포를 첫 단계에 배치, 진도의 단일 진실 원천은 Supabase(localStorage는 낙관적 오버레이만) |

## 기술 스택 — 무엇을, 왜 골랐나

각 선택은 ① 커리큘럼과의 일치(구축 = 학습), ② 1인 사용자 + 5주 데드라인, ③ 유지보수 최소화라는 세 기준으로 내렸다.

| 선택 | 이유 | 검토했지만 안 쓴 대안 |
|------|------|----------------------|
| **Next.js (App Router) + React** | 커리큘럼 Step 2에서 배울 스택 그대로 — 사이트를 만드는 과정이 곧 React/Next.js 예습이 된다. 콘텐츠가 고정이므로 정적 생성(SSG)으로 빌드 시점에 페이지를 만들어 iPad에서도 즉시 로드 | SPA(CRA/Vite): SEO·초기 로드 불리, 커리큘럼과 불일치. ISR: 콘텐츠가 git push로만 바뀌므로 불필요 |
| **Supabase (PostgreSQL)** | 진도(완료 체크)처럼 "변하는 상태"만 DB에 저장. 커리큘럼 Step 2의 DB 스택과 동일해 RLS·클라이언트 연동을 실전으로 익힘 | 브라우저 localStorage 단독: 기기 간 동기화 불가(iPad+PC 병행에 치명적). 자체 백엔드 구축: 1인용에 과함 |
| **콘텐츠 = MDX 파일 (DB 아님)** | 레슨 본문은 "코드처럼" git으로 버전 관리 — 리뷰·롤백·검색 가능, 관리자 화면(CMS) 구축 비용 0. 타입 검증(Velite)으로 오타·구조 오류를 빌드 시점에 잡음 | DB 저장 마크다운: 편집 UI를 또 만들어야 함(범위 역전 함정). Contentlayer: 유지보수 중단된 라이브러리 |
| **Shiki (rehype-pretty-code)** | 실무 예제가 Python·SQL·TS·React 등 언어가 다양 — VS Code와 동일한 문법 강조를 빌드 타임에 처리해 런타임 JS 0으로 iPad 성능 확보 | Prism/highlight.js: 클라이언트 런타임 부담, 강조 정확도 낮음 |
| **Tailwind CSS v4 + Pretendard** | 태블릿 우선 반응형을 유틸리티로 빠르게. Pretendard는 한국어 웹에서 OS 네이티브에 가장 가까운 가독성 | CSS 직접 작성: 5주 데드라인에 속도 불리. Noto Sans KR 단독: 본문 가독성 열세 |
| **Supabase 익명 로그인 + RLS** | 1인용이라 회원가입/비밀번호는 마찰만 추가 — 익명 세션으로 로그인 화면 없이 진도 저장, RLS로 내 데이터만 접근 가능하게 보호 | 풀 인증(OAuth/매직링크): 과설계. 인증 생략 + RLS 해제: anon key가 공개되는 구조상 보안 구멍 |
| **Vercel 배포 (1단계부터)** | 커리큘럼 최종 배포 스택과 동일. 처음부터 실제 URL로 검증해 "로컬에선 됐는데" 문제와 환경변수 드리프트를 조기 차단 | 마지막에 배포: 다주간 콘텐츠 집필 기간 동안 문제를 숨기는 시한폭탄 |

### 3단계 — 요구사항 정의 ✅ (2026-08-24)

- 리서치 결과 + 커리큘럼을 바탕으로 **v1 요구사항 20개**를 5개 카테고리(콘텐츠 CONT / 진도 TRACK / 일정 SCHED / 플랫폼 PLAT / UX)로 확정
- 각 요구사항은 "사용자가 ~할 수 있다" 형태의 검증 가능한 문장 + REQ-ID로 관리 — 이후 로드맵의 각 Phase에 100% 매핑되어 추적됨
- v2(여유 시)로 미룬 것: 검색/필터, 레슨 노트, 일정 자동 리밸런싱, PWA
- 의도적으로 제외한 것 9가지와 그 이유를 명문화 (예: 게이미피케이션 — 1인 학습자에게는 D-day/on-track 표시로 충분, 퀴즈 엔진 — 기간 제약) → 범위 확장(scope creep) 방지 장치

### 4단계 — 로드맵 & 아키텍처 설계 ✅ (2026-08-24)

- **5 Phase 로드맵** 확정, 요구사항 20개 100% 매핑 — 전략은 "플랫폼은 1주, 콘텐츠에 4주"
  1. **배포된 커리큘럼 뼈대** — Vercel 배포 + 3단 구조 탐색 + 파일럿 레슨 + iPad 기준 확립
  2. **진도 체크와 진행률** — 완료 토글 → Supabase 저장 → 모듈/Step/전체 진행률
  3. **학습 일정과 오늘의 학습** — 8/25~9/29 일정표, "오늘의 학습" 랜딩, D-day·on-track
  4. **Step 1 심화 콘텐츠** — 완성 즉시 실제 사전학습 시작
  5. **Step 2·3 콘텐츠 + 프로젝트 가이드** — 나머지 집필은 학습과 병행
- 모든 Phase는 Vertical MVP 슬라이스 — 기술 계층이 아니라 "사용자가 할 수 있는 일" 단위로 완성
- 각 Phase에 관찰 가능한 성공 기준(4~5개)을 정의해 검증 단계에서 그대로 사용
- 리스크 대응이 구조에 반영됨: 배포를 Phase 1에 배치(환경 문제 조기 발견), Phase 1~3 범위 증가분은 자동으로 v2로 밀어냄(콘텐츠 집필 시간 보호)

### 5단계 — 구현 ✅ (2026-08-24)

**Walking Skeleton (Phase 1 Plan 1):**

- Next.js 16(App Router) + React 19 + TypeScript + Tailwind v4 스캐폴드 생성
- Velite → rehype-pretty-code(라이트/다크 이중 Shiki 테마, 항상 보이는 복사 버튼) → MDX 런타임 렌더러 → `/lesson/[lessonId]` 정적 라우트까지 한 줄기 파이프라인을 끝까지 연결하고 `npm run build` 통과 확인
- 파일럿 레슨 1편(Python 변수·자료형)을 6단 구성(학습 목표 → 왜 배우나 → 개념 설명 → 실무 예제 → 실무 팁 → 핵심 정리) 실콘텐츠로 작성해 파이프라인을 실제 콘텐츠로 검증
- Pretendard 자체 호스팅 가변 폰트, 딥블루/청록 테마 토큰, 다크모드(하이드레이션 이전 인라인 스크립트) 적용
- **공개 GitHub 저장소** [`ai-engineer-runway`](https://github.com/dhchun1203/ai-engineer-runway) 생성 및 첫 커밋 push — 코드 자체가 포트폴리오라는 판단(D-14)에 따라 처음부터 공개로 개설. 기본 브랜치는 로컬 git 설정을 그대로 이어받아 `main`이 아닌 `master`로 생성됨 (기능적으로 동등, 편차로 기록)

**배포 파이프라인 연결 (Phase 1 Plan 2):**

- Vercel 대시보드에서 위 저장소를 Import해 프로젝트 `ai-engineer-runway`를 생성하고 첫 프로덕션 배포 성공
- 프로덕션 URL: **https://ai-engineer-runway.vercel.app** — 루트 경로와 파일럿 레슨 경로 모두 HTTP 200 확인, 배포 환경에서도 코드 하이라이팅·복사 버튼 마크업이 그대로 렌더됨을 확인
- Vercel ↔ GitHub 연동으로 두 배포 경로가 실제로 동작함을 확인:
  - `master`(프로덕션 브랜치) 푸시 → 사람 개입 없이 새 프로덕션 배포 생성
  - Pull Request 오픈 → 고유 프리뷰 URL 자동 생성, HTTP 200 확인
- 이 단계에는 비밀값이 하나도 없음 — Vercel 프로젝트 환경변수를 비워 둔 채로 배포 성공을 확인해, Phase 2의 Supabase 키 도입 이전 "무비밀 배포"라는 기준선을 세움

**배포를 마지막이 아니라 지금 한 이유:** 리서치가 지목한 최대 리스크는 "플랫폼 다듬기가 콘텐츠 집필(진짜 작업, 60~100h+)을 잠식하는 것"이고, 그 하위 리스크는 "로컬에선 됐는데 배포에서 터지는 문제를 콘텐츠 4주치 뒤에야 발견하는 것"이다. Phase 1 초반에 실제 프로덕션 URL로 빌드·배포 파이프라인을 검증해 둔 덕분에, 이후 모든 Phase의 커밋은 사람 개입 없이 프로덕션에 반영된다.
