# TIL 학습기록 시스템 — 설계 스펙

작성일 2026-09-10

## 1. 목적과 철학

사이트에 TIL(Today I Learned) 메뉴를 추가한다. 목적은 **상기(recall)와 핵심 기록**이다. 내가 공부한 것을 내 말로 다시 정리해 기억에 남기는 것이 전부이고, 남에게 보여주는 포트폴리오가 아니다.

근거로 삼은 것:

1. 능동적 인출(active recall)이 재독보다 파지율이 높다(24시간 뒤 재독 30~40% 대 인출 75~85%).
2. 파인만 기법: 개념을 내 말로 쉽게 재구성하면 이해가 생긴다.
3. 코넬 노트: 단서(질문), 본문, 요약의 3단 구조.
4. 개발자 TIL 관행 조사 결과, "TIL은 일기가 아니다"라는 원칙이 반복된다(감정, 오늘 하루 잡담 같은 학습 무관 내용은 배제).

이 설계는 2026-09-08에 정했던 "GitHub TIL 레포 우선, 나중에 자체 사이트 이관" 결정을 대체한다. 사용자가 자체 사이트에 Velog식 시스템(에디터, 태그, 깔끔한 읽기)을 바로 붙이기로 방향을 바꿨다. 다만 글의 톤은 여전히 "나를 위한 정리 노트"이지 완성글이 아니다.

## 2. Non-goals (YAGNI)

- 소셜 기능 없음: 좋아요, 댓글, 팔로우, 트렌딩.
- 일일 감정 회고 없음.
- 다중 사용자 없음(1인 사용). 쓰기는 소유자 전용, 읽기는 발행글만 공개.

## 3. 콘텐츠 포맷 (엔트리 템플릿)

글 한 편은 개념 하나(또는 버그 하나)를 다룬다. 칸이 많으면 그게 마찰이 되어 습관을 죽이므로 항목을 최소화한다.

### 3.1 템플릿 2종

새 글을 시작하면 먼저 템플릿을 고른다.

**A. 개념 노트 (기본)**

본문 스켈레톤(마크다운 소제목으로 미리 채움):
- 왜 / 언제 쓰나 (맥락 1~2줄)
- 핵심 정리 (내 말로) — 재구성 + 코드/예시, 깊이는 중요도 따라

**B. 버그 해결**

본문 스켈레톤:
- 문제 상황 (무슨 에러/증상)
- 시도한 것들
- 해결 (어떻게 풀렸나 + 왜 그게 원인이었나)
- 다음에 또 만나면 (재발 방지, 일반화한 교훈)

### 3.2 공통 구조화 항목 (템플릿 무관)

- 제목
- 한 줄 요약: "이 글을 한 문장으로"
- 셀프 체크 질문: "3일 뒤 나에게: ___?" (답은 적지 않는다). **발행 필수**
- 이해도: 1~5
- 🔴 아직 막힌/헷갈리는 곳 (선택)
- 태그

### 3.3 작성 가이드 방식

- **골격 자동 채움**: 새 글을 열면 고른 템플릿의 소제목과 회색 힌트가 미리 들어가 있다. 타이핑하면 힌트는 사라진다. 매번 빈 화면과 싸우지 않게 한다.
- **강제하지 않음**: 셀프 체크 질문 하나만 발행 게이트로 두고, 나머지 항목은 비어도 발행된다. 원칙 "형식은 버리고 내용은 챙긴다". 깊이는 그날 중요도 따라 다르게.
- **부드러운 체크리스트(넛지)**: 에디터 옆에 "요약 있나? 셀프 체크 질문 있나?" 정도만 표시. 막지 않는다.

## 4. 시스템 아키텍처

### 4.1 데이터 모델 (Supabase)

기존 progress/lesson_note 테이블과 같은 규율을 따른다. RLS를 켜되, 쓰기와 초고 읽기는 서버 전용 `supabaseAdmin`(service_role)으로만 접근한다.

**`til_post`**
- `id` uuid primary key default gen_random_uuid()
- `slug` text unique not null (URL 식별자)
- `template` text not null check in ('concept', 'bug')
- `title` text not null
- `summary` text (한 줄 요약)
- `body_md` text not null default '' (본문 마크다운 원문, 편집용)
- `body_html` text not null default '' (저장 시 컴파일된 HTML, 표시용)
- `self_check` text (셀프 체크 질문, 발행 시 필수)
- `understanding` smallint check between 1 and 5
- `blocked_points` text (🔴)
- `tags` text[] not null default '{}'
- `series_id` uuid null (til_series 참조)
- `cover_image_url` text null
- `status` text not null default 'draft' check in ('draft', 'published')
- `published_at` timestamptz null
- `created_at` timestamptz not null default now()
- `updated_at` timestamptz not null default now()

설계 결정: 본문(핵심 정리 또는 문제/시도/해결/다음에또)은 컬럼으로 쪼개지 않고 `body_md` 한 덩어리에 마크다운으로 둔다. 템플릿에 따라 소제목만 다르게 프리셋하고, 깊이는 자유롭게 한다. 반면 질의/검증이 필요한 항목(요약, 셀프 체크, 이해도, 🔴, 태그, 상태)은 별도 컬럼으로 둔다. 이렇게 하면 "셀프 체크 필수"를 컬럼 non-empty 검증으로 단순하게 강제하고, 태그/이해도 질의도 쉽다.

**`til_series`**
- `id` uuid pk, `slug` text unique, `title` text, `description` text, `created_at` timestamptz

**태그**: 별도 조인 테이블 없이 `til_post.tags text[]`. 1인 사용이라 이게 가장 단순하다.

**RLS**
- 기존 progress/lesson_note와 동일하게, RLS를 켜되 **정책은 하나도 만들지 않는다(default-deny)**. anon/authenticated 역할의 모든 접근이 거부되고, 이 앱은 오직 서버 전용 `supabaseAdmin`(service_role, RLS 우회)으로만 접근한다. 공개 발행글 노출은 anon 정책이 아니라 서버 쿼리의 `status = 'published'` 필터가 담당한다(4.2, 5절). anon 키로 조회하면 빈 결과가 나오는 것이 고장이 아니라 이 설계의 증거다. `using (true)` 편의 정책을 넣어 "고치지" 않는다.
- `til_post`, `til_series` 모두 이 규율을 따른다.

**스토리지**: 커버/본문 이미지는 Supabase Storage 버킷 하나(`til-image`).

### 4.2 라우트

공개(발행글):
- `/til` 목록(최신순 카드). 카드에 제목, 요약, 태그, 이해도, 날짜, 커버 이미지. 상단에 잔디/streak 캘린더.
- `/til/[slug]` 상세. 발행글은 공개, 초고 상세는 소유자일 때만.
- `/til/series/[slug]` 시리즈 묶음(연재 순서대로).
- `/til/tags/[tag]` 태그별 목록.

소유자 전용:
- `/til/new` 템플릿 선택 화면 → 에디터
- `/til/[slug]/edit` 편집
- `/til/drafts` 초고함

렌더링 모드: 발행 글은 DB에서 오고 재배포 없이 바뀌므로 정적 생성이 맞지 않는다. 다른 DB 페이지(홈, 노트)처럼 `force-dynamic`으로 둔다.

### 4.3 마크다운 렌더링 (컴파일 온 세이브)

사용자가 마크다운으로 쓰지만, 저장/발행하는 순간 서버에서 HTML로 한 번 컴파일해 `body_html`에 저장한다. 코드 하이라이트는 프로젝트가 이미 쓰는 rehype-pretty-code + Shiki 설정을 재사용한다(Velite 설정과 같은 플러그인 구성). 읽을 때는 `body_html`을 `.prose` 컨테이너에 주입만 한다. 클라이언트 하이라이팅 JS 0을 유지하는 사이트 철학과 일치한다.

- 에디터 미리보기는 가벼운 클라이언트 마크다운 렌더로 충분하다(하이라이트는 저장 후 최종본에서만 정확히).
- 새니타이즈: 단일 신뢰 저자라 XSS 위험은 낮지만, 컴파일 파이프라인은 통제된 마크다운만 처리한다(임의 raw HTML 삽입은 허용하지 않는다).

### 4.4 에디터

- `/til/new`: 카드 2개(개념 노트 / 버그 해결) 중 선택 → `template` 프리셋을 들고 에디터로.
- 에디터 구성: 제목, 한 줄 요약, 본문 마크다운(스켈레톤 프리셋) + 미리보기 토글, 셀프 체크 질문(필수 표시), 이해도 1~5, 🔴 막힌 곳, 태그. 하단에 [초고 저장] / [발행].
- 발행 검증: `self_check`가 비면 발행을 막고 인라인 안내. 초고 저장은 허용.
- 아이패드: 터치 타깃 44px 이상, 세로/가로 모두. 마크다운 textarea가 iPad Safari에서 편하게.
- 이미지 삽입: 파일 선택 → 스토리지(`til-image`) 업로드 → 본문에 마크다운 이미지 링크 삽입. 커버 이미지도 같은 경로.
- 시리즈: 글을 기존/새 시리즈에 지정(til_series).

### 4.5 보안과 브랜딩

- 쓰기/초고 읽기: `hasUnlockCookie()` 게이트 + `supabaseAdmin`. 진도/노트와 동일한 계약.
- Server Action은 렌더 여부와 무관하게 스스로 재검증한다(basecamp/actions.ts 패턴). 알려진 값 검증 후에만 DB 접근.
- RLS default-deny, 공개는 발행글만.
- 브랜딩 하드룰: 교육기관명 "KANT"를 어디에도 쓰지 않는다. 페이지 제목/메타/OG 포함 "AI Engineer 교육과정" 표기.

### 4.6 네비게이션

`site-nav.tsx`의 `NAV_ITEMS`에 단독 링크 "TIL"을 추가한다. 매일 쓰는 핵심 동선이라 소메뉴에 숨기지 않고 상위 단독 링크로 둔다. 위치는 "채널톡 로드맵" 다음.

## 5. 데이터 흐름

**쓰기**: 에디터(client) → Server Action → `hasUnlockCookie()` 재검증 → 입력 검증(발행이면 self_check 필수) → `body_md`를 HTML로 컴파일 → `supabaseAdmin.upsert(til_post)` → 목록/상세로 리다이렉트.

**공개 읽기**: `/til`, `/til/[slug]` Server Component → `supabaseAdmin`으로 읽되 서버 쿼리에 `status = 'published'` 필터를 건다(기존 페이지들이 admin으로 서버에서 읽는 방식과 일관). 초고 상세는 `hasUnlockCookie()`가 참일 때만 노출.

## 6. 에러 처리

- DB 조회 실패는 "빈 목록/안내"로 강등한다(진도 패턴처럼 성공과 실패를 타입으로 구분, 실패를 "0건"으로 오인하지 않는다).
- 발행 검증 실패는 에디터 인라인 메시지.
- slug 충돌은 저장 시 접미사를 붙여 유일하게 만든다.

## 7. 테스트

기존 `scripts/*.mjs` 게이트 방식을 따른다.
- RLS: anon 키로는 초고가 보이지 않고 발행글만 보이는지.
- 발행 필수 검증: self_check 없이 발행 시도가 거부되는지.
- 컴파일 온 세이브: 저장 후 `body_html`이 채워지고 코드 블록이 하이라이트되는지.
- 접근 게이트: 소유자 전용 라우트가 비로그인에서 막히는지.

## 8. 범위와 권장 구현 순서

전체가 하나의 범위다(단계로 미루지 않는다). 다만 구현은 아래 순서로 쌓아 올리는 것을 권장한다. 각 묶음이 끝날 때마다 동작하는 상태가 되도록, 그리고 핵심 쓰기 루프가 먼저 돌도록 하기 위함이다(게이트가 아니라 순서일 뿐).

포함 범위 전체:
- `til_post` + `til_series` 테이블 + RLS(default-deny) + 스토리지 버킷(`til-image`) 마이그레이션/설정
- 라우트: `/til`, `/til/[slug]`, `/til/series/[slug]`, `/til/tags/[tag]`, `/til/new`, `/til/[slug]/edit`, `/til/drafts`
- 템플릿 2종 + 선택 화면, 스켈레톤/힌트, 셀프 체크 필수 발행 게이트
- 마크다운 컴파일 온 세이브 + 렌더
- 이해도, 🔴, 태그
- 시리즈, 커버/본문 이미지 업로드, 잔디/streak 캘린더
- 네비 "TIL" 메뉴

권장 순서:
1. 데이터/보안 토대: 테이블, RLS, 스토리지 버킷, 접근 게이트
2. 핵심 쓰기 루프: 템플릿 선택 → 에디터 → 컴파일 온 세이브 → 초고/발행 → 목록/상세 렌더(이해도·🔴·태그·셀프체크 포함). 네비 메뉴. 여기까지면 매일 쓸 수 있다.
3. 확장: 시리즈, 커버/본문 이미지, 잔디 캘린더, 태그 필터 페이지
4. (선택, 후속) 셀프 체크 질문을 기존 복습/자가진단 흐름과 연동

## 9. 확정한 기본값

- 네비 이름/위치: 단독 "TIL", "채널톡 로드맵" 다음.
- 공개 읽기 렌더: `force-dynamic`.
- 본문 저장: `body_md` + `body_html`(컴파일 온 세이브) 두 컬럼.
- 한 줄 요약, 셀프 체크, 이해도, 🔴, 태그는 구조화 컬럼. 본문 소제목은 템플릿 프리셋.
