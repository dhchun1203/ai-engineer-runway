# 아티클 섹션 + 매주 자동 수집 설계

- 날짜: 2026-09-23
- 상태: 사용자 승인 (브레인스토밍 완료)
- 범위: 새 격리 컬렉션 `articles`, 목록/상세 페이지, 하단 메모장, 공용 용어 사전과 AI 뜯어보기 "용어 사전" 층, 작성 스킬, 매주 클라우드 예약 실행

## 1. 목적

현업 엔지니어링 기사(예: Linear "AI coding has made CI a bottleneck")를 우리 말로 풀어 쌓아 두고, **공부**(모르는 개념 풀이)와 **취업**(면접 포인트) 양쪽에 쓴다.

**연결은 억지로 만들지 않는다(사용자 원칙).** 우리 레슨이나 채널톡 로드맵과 자연스럽게 이어질 때만 연결하고, 이어지지 않으면 연결 부분을 통째로 뺀다. 기사를 고를 때도 "우리 레슨과 이어지는가"는 기준이 아니다. 기사 자체의 가치로만 고른다.

기사는 두 경로로 들어온다.

1. 사용자가 링크를 주면 Claude가 작성해 올린다(수동 경로).
2. 매주 월요일 08:00(KST) 클라우드 예약 실행이 출처 목록에서 2편을 골라 작성하고 **바로 게시**한다(자동 경로).

두 경로 모두 같은 작성 스킬(`.claude/skills/article-scrap/SKILL.md`)을 따른다.

## 2. 비목표

- 원문 전문 저장 또는 번역 게재 (저작권, 아래 7절)
- 사이트 안 입력 폼, DB 저장 (글은 Claude가 저장소에 파일로 쓴다)
- 진도, 일정, 복습, 용어집 집계 (격리 컬렉션)
- 읽음 체크 (사용자가 제외함. 필요해지면 나중에 추가)

## 3. 콘텐츠 모델

### 3.1 위치와 컬렉션

- 파일: `src/content/articles/<slug>.mdx`
- velite 컬렉션 `articles` (concepts, roadmapLessons, basecampLessons와 같은 격리 패턴). 진도, 일정, 복습은 `lessons`만 소비하므로 자동으로 집계되지 않는다.
- permalink: `/articles/<slug>`
- slug 규칙: `<출처 약칭>-<주제 영문 kebab>` (예: `linear-ci-bottleneck`). 영문 소문자, 숫자, 하이픈만 쓴다.

### 3.2 frontmatter 스키마

| 필드 | 형식 | 설명 |
| --- | --- | --- |
| `title` | string | 우리 말 제목 |
| `originalTitle` | string | 원문 제목 그대로 |
| `source` | string | 출처 표시명 (예: "Linear 블로그") |
| `author` | string, 선택 | 원문 글쓴이 |
| `publishedAt` | `YYYY-MM-DD` | 원문 발행일 |
| `addedAt` | `YYYY-MM-DD` | 우리 사이트에 올린 날. 목록 정렬 기준 |
| `url` | URL | 원문 링크. 중복 판별 키 (컬렉션 전체에서 유일) |
| `tags` | enum 배열 (1~3개) | 아래 3.3 목록에서만 |
| `summary` | string 배열 (정확히 3개) | 세 줄 요약 |
| `related` | `{ label, href }` 배열, 선택 | 우리 레슨, 로드맵 단계 등 사이트 내부 링크 |
| `origin` | `"manual"` 또는 `"auto"` | 수동 경로인지 자동 수집인지 |
| `slug` | slug | 파일과 같은 값 |

- `url` 중복, `summary` 개수, `tags` 범위 위반은 **velite 빌드 실패**로 막는다(스키마 + transform 검사).
- `related.href`는 `/`로 시작하는 내부 경로만 허용한다.

### 3.3 분야 태그 (고정 목록)

`AI 코딩`, `LLM`, `RAG`, `에이전트`, `평가`, `DevOps`, `백엔드`, `프론트엔드`, `데이터`, `제품`, `커리어`

새 태그가 필요하면 스키마의 enum과 이 문서를 함께 고친다. 표기 흔들림(예: "Devops", "데브옵스")을 빌드에서 막는 것이 목적이다.

### 3.4 본문 구조 (h2 필수 네 개 + 선택 한 개)

본문은 아래 h2를 이 순서로 가진다. 4번은 **선택**이고 나머지는 정확히 한 번씩 필수다. 빌드 transform이 존재와 순서를 검사하고 어긋나면 실패시킨다.

1. `## 먼저 알아 둘 개념`: 기사를 읽는 데 필요한 용어를 eli5 비유로 푼다 (3~6개).
2. `## 핵심 내용 정리`: 기사의 문제, 해결책, 수치 효과를 우리 말로 재서술한다. 번역이 아니다.
3. `## 취업과 면접 포인트`: 면접에서 쓸 수 있는 한 마디, 현업이 원하는 역량. 채널톡 로드맵은 실제로 맞닿을 때만 언급한다.
4. `## 내 학습과 연결` (선택): 관련 레슨이나 로드맵이 **실제로 같은 내용을 다룰 때만** 쓴다. 없으면 이 h2를 빼고 frontmatter `related`도 비운다.
5. `## 스스로 확인하기`: 질문 2~3개와 `<details>` 정답 접기.

세 줄 요약은 본문이 아니라 frontmatter `summary`로 두고 페이지 머리의 카드로 렌더한다.

### 3.5 공용 용어 사전과 AI 뜯어보기 연동 (2026-09-23 추가, 사용자 승인)

- 기존 `src/content/roadmap-terms.ts`(로드맵 레슨의 `<Term>` 패널 사전, 64항목)를 **공용 용어 사전** `src/content/terms.ts`로 옮긴다. 로드맵 레슨과 기사가 같은 정의를 쓴다. 기존 항목 내용은 바꾸지 않는다.
- 항목 형식: `{ title, body, concept? }`. `concept`는 AI 뜯어보기 편의 slug이고, **그 편이 실제로 같은 개념을 다룰 때만** 채운다(억지 연결 금지).
- 기사 본문의 "먼저 알아 둘 개념"은 기사 맥락에 맞춘 설명을 그대로 쓰고, 용어를 처음 쓸 때 `<Term id="...">`로 감싼다. 누르면 설명 패널이 열린다.
- 사전에 없는 용어는 기사를 쓸 때 사전에 한 항목 추가한다. 이미 있거나 같은 뜻의 다른 표기(예: 할루시네이션과 환각)가 있으면 기존 항목을 쓴다.
- 빌드(velite `prepare`)가 막는 것: 기사, 로드맵 레슨에 쓴 `<Term id>`가 사전에 없음. 사전 항목의 `concept`가 존재하지 않는 편을 가리킴.
- 정규 레슨 용어집(/glossary)은 별개로 그대로 둔다.


## 4. 페이지

### 4.1 목록 `/articles`

- 서버 컴포넌트. `searchParams`(태그 필터)를 읽으므로 요청마다 렌더링된다(Next 16 규칙). DB 조회는 없다. 카드: 제목, 출처, 원문 발행일, 태그 칩, 세 줄 요약의 첫 줄, 자동 수집 여부 표시(작은 라벨 "자동 수집").
- 정렬: `addedAt` 내림차순, 같은 날이면 `publishedAt` 내림차순.
- 태그 필터: 쿼리스트링 `?tag=DevOps`. 목록 위에 태그 칩 줄(전체 + 실제 쓰인 태그만). 필터는 링크 이동이라 클라이언트 JS가 필요 없다. 존재하지 않는 태그 값이면 전체를 보여 준다.
- 빈 상태: "아직 모은 기사가 없어요" 문구.

### 4.2 상세 `/articles/[slug]`

- `basecamp/[slug]/page.tsx`의 셸을 따른다: 뒤로 가기, 제목, 칩("아티클"), 읽는 시간, 클로드에 물어보기(`BasecampCopyPrompt` 재사용 또는 동형), PDF 저장 두 종, 본문 `prose`, 독서 도우미(`ReadingAssistant`), 하단 메모장.
- 머리에 추가: 출처와 글쓴이, 원문 발행일, 태그 칩, **원문 열기** 버튼(새 탭, `rel="noopener noreferrer"`, 외부 링크 아이콘은 lucide `ExternalLink`), 세 줄 요약 카드.
- `related`가 있으면 본문 아래 "함께 보기" 링크 목록.
- `generateStaticParams`로 정적 생성, `generateMetadata`는 `title`과 `summary[0]`.

### 4.3 하단 메모장

- 기존 `lesson_note` 저장소 재사용. 키는 `article:<slug>` (`src/lib/article-note.ts`의 `articleNoteId()` 단일 지점, `basecampNoteId()`와 동형).
- 읽기: `app/api/article-note/route.ts` (basecamp-note 라우트와 대칭), 쓰기: `app/articles/[slug]/note-actions.ts` (hasUnlockCookie 재검증, 슬러그 존재 검증, 저장 순서 동일).
- 컴포넌트: `ArticleNote` (`BasecampNote`와 동형, `LessonNotepad` 재사용).
- DB 마이그레이션 없음.

### 4.4 AI 뜯어보기 "용어 사전" 층

- `/concepts` 첫 화면: 깊은 10편 목록 아래에 "용어 사전" 구역(용어 수, 입구 링크).
- `/concepts/terms`: 전체 용어 목록(제목 가나다순, 첫 문단 한 줄).
- `/concepts/terms/[id]`: 용어 카드. 설명 문단, `concept`가 있으면 "AI 뜯어보기에서 자세히" 링크, **"이 용어가 나온 곳"**(이 용어를 쓴 기사와 로드맵 레슨, 빌드 시 본문의 `<Term id>`에서 자동 계산).
- 설명 패널(`term-panel.tsx`)에 "용어 페이지 열기" 링크와, `concept`가 있으면 "AI 뜯어보기에서 자세히" 링크를 더한다.
- 모두 정적 생성.

### 4.5 네비

- `site-nav.tsx` "더보기"의 "AI 뜯어보기" 아래에 `{ label: "아티클", href: "/articles" }` 추가.
- 로그인 게이트는 기존 proxy 정책을 그대로 따른다(다른 콘텐츠 페이지와 동일).

## 5. 작성 스킬 `.claude/skills/article-scrap/SKILL.md`

수동, 자동 두 경로가 공유하는 유일한 작성 절차서.

1. 원문 확보: 브라우저로 본문을 읽는다(JS 렌더 페이지 대응). 발행일, 글쓴이, 원제를 확인한다.
2. 중복 확인: `src/content/articles/*.mdx`의 `url`과 비교해 이미 있으면 중단한다.
3. 작성: 3.2 스키마, 3.4 구조, 3.5 용어 사전(새 용어 추가, `<Term>` 감싸기), 7절 저작권 규칙, 사이트 글쓰기 규칙(가운데점과 긴하이픈 금지, 2~3문장마다 문단 끊기, 교육기관명 금지, UI 이모지 금지)을 따른다.
4. 검사 (6.3의 자동 검사와 같은 목록).
5. `npx velite build`와 `npx tsc --noEmit` 통과 확인.
6. 수동 경로는 화면(아이패드 크기) 확인 후 커밋, push. 자동 경로는 6절.

## 6. 매주 자동 수집

### 6.1 실행

- 클라우드 예약 실행(schedule 스킬의 routine), cron: 매주 월요일 08:00 KST.
- 저장소를 받아 작성 스킬대로 2편을 만든다.

### 6.2 출처와 선정

출처 목록은 스킬 파일 안의 표로 관리한다(사용자가 "여기 추가해 줘"로 고친다).

- 국내 기술 블로그: 토스, 당근, 우아한형제들, 카카오, 네이버 D2, 채널톡 등
- 해외 엔지니어링 블로그: Anthropic, OpenAI, Vercel, Linear, Stripe, GitHub, Cloudflare 등
- AI 실무 큐레이션: Simon Willison, Latent Space, Hacker News 상위 글 등

선정 기준:

- 최근 14일 안에 발행된 글
- 기사 자체의 가치로 고른다: 현업의 설계 판단, 수치, 시행착오가 분명하고 AI Engineer 실무에 의미 있는 글. 우리 레슨과 이어지는지는 선정 기준이 아니다.
- 2편 중 국내와 해외를 섞는다(한쪽에 적합한 글이 없으면 예외)
- 광고, 채용 공고, 행사 홍보, 내용이 얕은 글 제외
- 이미 올린 `url` 제외

적합한 글이 2편 미만이면 있는 만큼만 올린다. 억지로 채우지 않는다.

### 6.3 게시 전 자동 검사 (하나라도 실패하면 그 글은 버린다)

1. frontmatter 스키마, 본문 h2 구조, `<Term id>`가 사전에 있는지 (velite 빌드가 검사)
2. 원문 `url`이 열리는지 (HTTP 2xx 또는 브라우저 로드 성공)
3. 금지 표기 없음: 교육기관명, 가운데점(·), 긴하이픈(—)
4. 원문 인용은 한 문장 이하, 원문 문단을 옮긴 흔적 없음 (작성자 자기 점검)
5. `npx velite build`, `npx tsc --noEmit` 통과

### 6.4 게시와 알림

- 통과한 글만 커밋해 `origin/master`에 push한다. push 전에 `git pull --rebase`로 로컬 작업과의 충돌을 피한다.
- Vercel이 자동 배포한다.
- 실행 결과(올린 글 제목과 링크, 버린 글과 이유)는 예약 실행의 세션 기록으로 남는다.
- 사용자가 "내려 줘"라고 하면 해당 파일을 삭제하고 push한다.

### 6.5 선행 조건

- 클라우드 실행 환경이 GitHub 저장소 `dhchun1203/ai-engineer-runway`에 push할 권한. 2단계 시작 시 확인하고, 막히면 사용자에게 연결 방법을 안내한다.
- 첫 예약 전 1회 수동 실행으로 결과를 확인한 뒤 예약을 켠다.

## 7. 저작권 규칙

- 원문 전문, 문단 단위 번역을 싣지 않는다. 모든 서술은 우리 말로 새로 쓴다.
- 직접 인용은 기사당 한 문장 이하, 따옴표와 출처 표기.
- 원문 이미지, 도표를 가져오지 않는다. 필요하면 우리가 새로 그린다.
- 수치와 사실은 "기사에 따르면" 식으로 출처를 밝혀 적는다.
- 원문 링크는 항상 머리의 "원문 열기"로 제공한다.

## 8. 만드는 순서

1. 컬렉션, 공용 용어 사전과 용어 사전 페이지, 목록, 상세, 메모장, 네비를 만들고 첫 글(Linear CI 기사, `origin: manual`)을 올린다. 작성 스킬 파일을 쓴다.
2. 예약 실행을 만들고 1회 수동 실행으로 확인한 뒤 매주 예약을 켠다.

## 9. 검증

- 빌드: 스키마 위반(태그 오타, 요약 2줄, url 중복, h2 누락)을 일부러 만든 임시 파일로 빌드 실패를 확인한 뒤 되돌린다.
- 화면: 아이패드 크기(768px)에서 목록, 태그 필터, 상세, 원문 열기, 용어 패널과 용어 페이지 이동, `/concepts/terms` 목록과 용어 카드의 "이 용어가 나온 곳", 메모 저장 후 새로고침 유지, 가로 넘침 없음. 로드맵 레슨의 용어 패널이 전과 똑같이 동작.
- 자동 수집: 1회 수동 실행의 결과물이 6.3 검사를 모두 통과하고 배포 사이트에 보이는지.
