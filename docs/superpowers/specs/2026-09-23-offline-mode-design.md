# 오프라인 모드 설계

- 날짜: 2026-09-23
- 상태: 사용자 승인 (브레인스토밍 완료)
- 선행: 아티클 섹션 작업(`2026-09-23-articles-section-design.md`)을 먼저 끝낸다. 아티클과 용어 사전 페이지도 오프라인 대상에 넣기 위해서다.

## 1. 목적

비행기 안처럼 인터넷이 없을 때도 아이패드에서 학습을 이어 간다. 학습 콘텐츠를 읽고, 완료 체크와 메모를 남기고, 인터넷이 돌아오면 자동으로 서버와 맞춘다.

## 2. 범위

**된다 (오프라인)**
- 읽기: 정규 레슨(/lesson), 스텝 목차(/step), 커리큘럼(/curriculum), 베이스캠프 레슨(/basecamp/[slug]), AI 뜯어보기(/concepts, 용어 사전 /concepts/terms 포함), 로드맵 레슨(/roadmap/[slug]), 아티클 목록과 글(/articles, /articles/[slug]. 목록은 태그 필터 없는 기본 화면을 저장하고, 오프라인에서 필터 링크는 기본 목록으로 대신한다), 용어집(/glossary), 소개(/about)
- 쓰기(대기열 후 동기화): 레슨 완료 체크, 베이스캠프 항목 체크, 메모(레슨, 베이스캠프 레슨, 아티클)
- 내 진도와 메모 보기: 마지막으로 서버에서 받은 사본 + 대기열 변경분

**안 된다 (오프라인이면 "인터넷 연결 후 가능" 안내)**
- 로그인, 가입, 관리자, 슬랙, TIL, 복습 세션, 북마크, 다시 보기 표시, 질문함
- 코드 실행기(Python, SQL): 실행 엔진을 CDN에서 받기 때문
- 개인 화면(홈 대시보드 /, 베이스캠프 허브 /basecamp, 노트 /notes, 북마크 /bookmarks, 질문함 /inbox, 복습 /review, TIL /til처럼 사용자별로 서버가 그리는 화면): 오프라인 목차 화면으로 대신한다

**비목표**
- 코드 실행기 오프라인화(사용자가 제외)
- 여러 기기 동시 편집의 정교한 병합(마지막 변경이 이김)
- 외부 라이브러리(Serwist 등) 도입. 서비스 워커를 직접 작성한다(저장소의 외부 의존성 0 원칙, 로그인과 사용자별 화면 통제 필요)

## 3. 구성 요소

### 3.1 서비스 워커 `public/sw.js`

- 루트 레이아웃의 작은 클라이언트 컴포넌트가 로그인 상태일 때만 등록한다(`navigator.serviceWorker.register('/sw.js', { scope: '/' })`).
- `/sw.js` 응답 헤더: `Cache-Control: no-cache, no-store, must-revalidate`, `Content-Type: application/javascript; charset=utf-8` (Next PWA 가이드 권장, `next.config.ts` headers).
- 캐시 이름에 빌드 id를 넣는다(`offline-<buildId>`). 새 배포면 새 캐시로 갈아타고 옛 캐시를 지운다.
- **요청 처리 규칙**
  - 허용 목록(2절 "읽기" 경로)의 문서 요청(navigate): 네트워크 먼저, 성공하면 캐시에 갱신 저장, 실패하면 캐시, 캐시도 없으면 오프라인 안내 페이지.
  - 개인 화면 경로(/, /basecamp, /notes 등)의 문서 요청: 네트워크 먼저, 실패하면 **오프라인 목차 페이지**(`/offline`)를 캐시에서 준다.
  - 같은 출처의 `/_next/static/**`, `/fonts/**`, `/static/**`, 아이콘: 캐시 먼저(해시 파일명이라 불변).
  - `/api/**`, Server Action(POST), 로그인 관련, 외부 출처: **서비스 워커가 손대지 않는다**(항상 네트워크).
- 허용 목록 밖의 문서는 저장하지 않는다(다른 사람 정보가 기기에 남지 않게).

### 3.2 전체 받기 목록 `/offline-manifest.json`

- 라우트 핸들러가 velite 데이터로 오프라인 대상 URL 전부를 JSON으로 돌려준다(레슨, 스텝, 커리큘럼, 베이스캠프 레슨, 개념, 용어 사전 목록과 카드, 로드맵 레슨, 아티클 목록과 글, 용어집, 소개, `/offline`). 빌드 id도 함께.
- "전체 받기"는 이 목록의 각 URL을 받아 캐시에 넣고, 받은 HTML에서 같은 출처의 `/_next/static/` 스크립트와 스타일 주소를 뽑아 함께 캐시한다. 진행률(n/N)과 받은 용량을 보여 준다.

### 3.3 오프라인 저장 화면 `/offline` (목차 겸용)

- 온라인일 때: "전체 받기" 버튼, 진행률, 저장된 페이지 수와 대략 용량, 마지막 받은 시각, "저장본 지우기", 아이패드 안내("Safari에서 공유 → 홈 화면에 추가로 설치한 앱으로 써야 저장본이 오래 유지돼요").
- 오프라인일 때(개인 화면 대신 보여 주는 목차): 저장된 콘텐츠를 분류별(레슨, 베이스캠프, AI 뜯어보기, 로드맵, 아티클)로 링크, "이어서 읽기"(마지막 읽던 레슨, 기존 LastLessonRecorder 값), 동기화 대기 중인 체크와 메모 개수.
- 목차 내용은 캐시에 실제로 있는 URL만 보여 준다(Cache Storage를 조회). 제목은 `/offline-manifest.json`의 제목 필드에서.
- 네비의 "더보기"에 "오프라인 저장" 항목.

### 3.4 내 데이터의 마지막 사본과 대기열 (IndexedDB `offline-db`)

- 저장소: `progressSnapshot`(마지막 `/api/progress` 응답 전체), `noteSnapshots`(메모 키별 마지막 본문), `queue`(대기 중인 쓰기), `meta`(userId, 마지막 동기화 시각).
- 온라인에서 진도와 메모를 불러올 때마다 사본을 갱신한다.
- 오프라인에서 진도와 메모 읽기는 사본에 대기열 변경분을 얹어 보여 준다.
- **대기열 항목**: `{ id, kind: "lessonComplete" | "basecampItem" | "note", key, value, at }`
  - `lessonComplete`: key=레슨 slug, value=목표 상태(true/false). 같은 key는 마지막 것만 남긴다.
  - `basecampItem`: key=항목 id, value=목표 상태.
  - `note`: key=메모 키(`<slug>`, `basecamp:<slug>`, `article:<slug>`), value=본문. 같은 key는 마지막 것만.
- **쓰기 경로**: 기존 Server Action 호출부(완료 버튼, 베이스캠프 체크, 메모장)를 얇은 래퍼로 감싼다. 오프라인이거나 네트워크 오류면 대기열에 넣고 화면은 낙관적으로 바꾼다. 온라인이면 지금처럼 바로 호출한다.
- **동기화**: `online` 이벤트, 앱 시작, 화면이 다시 보일 때(visibilitychange) 대기열을 순서대로 기존 Server Action으로 재생한다. 성공한 항목만 지운다. 인증 실패(unauthorized)면 멈추고 "다시 로그인하면 동기화돼요"를 표시한다.
- 완료 토글 재생은 "목표 상태"로 보낸다. 기존 `toggleLessonComplete(lessonId, currentlyDone)`는 `!currentlyDone`을 저장하므로 `currentlyDone = !목표`로 부른다(서버 계약 변경 없음).
- 충돌: 마지막으로 재생된 쓰기가 이긴다.

### 3.5 "ON AIR" 상태 표시

- 헤더(네비) 오른쪽에 작은 램프 표시. 온라인 "ON AIR", 오프라인 "OFF AIR".
- 온라인: 느리고 부드럽게 숨 쉬는 빛(약 3초 주기, 밝기만 변화). 오프라인: 또렷한 깜빡임(약 1초 주기)으로 한눈에 구별.
- `prefers-reduced-motion: reduce`면 깜빡임 없이 켜진 상태로 고정.
- 대기열이 있으면 램프 옆에 작은 숫자(동기화 대기 개수). 누르면 `/offline`.
- 상태 판단: `navigator.onLine` + `online`/`offline` 이벤트, 그리고 오프라인일 때 짧은 주기로 가벼운 연결 확인(같은 출처 HEAD 요청)해 실제 복구를 감지.
- 색은 디자인 토큰으로만(`check-design-tokens.mjs` 규칙). 이모지 금지, 글자와 도형으로 램프를 그린다. 터치 타깃 44px.
- `aria-live="polite"`로 상태 변화를 알린다.

### 3.6 로그아웃과 계정 전환

- 로그아웃 버튼은 서버 로그아웃 전에 기기의 오프라인 캐시(Cache Storage)와 IndexedDB를 모두 지운다.
- `meta.userId`가 현재 로그인 사용자와 다르면(다른 계정으로 로그인) 즉시 모두 지운다.
- 로그인하지 않은 상태에서는 서비스 워커를 등록하지 않는다(이미 있으면 해제).

### 3.7 코드 실행기와 기타 온라인 전용 기능

- RunPython, RunSQL: 오프라인이면 실행 버튼 대신 "인터넷 연결 후 실행할 수 있어요" 안내.
- 북마크, 다시 보기 표시, TIL 버튼: 오프라인이면 비활성과 안내.

## 4. 확인이 필요한 기술 위험 (계획의 첫 단계에서 검증)

1. **오프라인에서 링크 이동**: Next 클라이언트 이동은 HTML이 아니라 RSC 데이터를 받는다. 오프라인에서 이 요청이 실패할 때 전체 페이지 이동으로 바뀌어 서비스 워커의 캐시된 HTML이 쓰이는지 확인한다. 안 되면 대안: 오프라인일 때 서비스 워커가 RSC 요청을 즉시 실패시키고, 클라이언트가 오프라인 상태에서의 링크 클릭을 `location.assign`으로 처리.
2. **로그인 제한과 캐시**: proxy가 쿠키로 막는 페이지를 서비스 워커가 받아 둘 때 쿠키가 함께 가는지(같은 출처 fetch의 credentials 기본값) 확인.
3. **iPad Safari 저장 한도와 유지**: 홈 화면 앱에서 수십 MB 저장, 오프라인 시작(비행기 모드로 앱 실행) 동작 확인.
4. **Vercel 배포와 빌드 id**: 캐시 버전 전환 시 옛 JS 조각을 참조하는 캐시 HTML이 깨지지 않는지(같은 빌드의 HTML과 조각을 한 캐시에 묶어 보관).

## 5. 검증

- 데스크톱 크롬 개발자 도구 오프라인 모드와 내장 브라우저로: 전체 받기 → 오프라인 전환 → 각 분류 페이지 열림, 링크 이동, 개인 화면이 목차로 대체, 저장 안 된 페이지 안내, 완료 체크와 메모 대기열 적재, 온라인 복귀 후 동기화와 서버 반영, ON AIR 표시 전환과 대기 개수, 로그아웃 후 저장본 삭제.
- 아이패드: 홈 화면 앱에서 비행기 모드로 실행해 읽기, 체크, 메모, 복귀 후 동기화(사용자 확인, 구체적 단계 안내 제공).
- 기존 게이트(`check-design-tokens`, `check-brand`, 글리프, lint, build) 통과.
