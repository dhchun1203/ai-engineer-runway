# 수업 복습 레슨 "훑기" 형태 설계

2026-11-24, 사용자 승인.

## 왜

수업 복습(/class) 회차 레슨이 한 편 1만 4천~7만 자(보통 3만 자, 절 10~20개)라 다시 복습하기 힘들다. 사용자가 원하는 것은 빠르게 훑으면서 그날의 핵심을 다시 떠올리는 복습이다.

## 목표, 비목표

- 목표: 펼친 상태로 보이는 분량을 지금의 1/5 정도로 줄여 한 편을 3~5분에 훑게 한다.
- 목표: 원래 내용(직접 실행해 확인한 출력, 오류 재현, 그림)은 지우지 않고 접어 둔다.
- 비목표: 퀴즈, 명령어, 용어(`review.yml`)는 손대지 않는다. 퀴즈 id는 오답 기록 키라 절대 바꾸지 않는다.
- 안티 목표: 접힌 칸이 너무 많아 훑는 흐름이 끊기는 것. 절마다 접힌 칸은 하나만 둔다.

## 접근

- A. 완전히 교체: 가장 짧지만 긴 설명이 git 기록에만 남는다.
- B. "자세히 보기"로 접기 (사용자 선택): 핵심만 펼쳐 두고 나머지는 같은 페이지 안에 접어 둔다.
- C. 긴 판을 별도 페이지로: 왔다 갔다 해야 해서 훑기에 맞지 않아 뺐다.

## 형태 (21편 공통)

```
도입 2~3줄: 오늘 배운 것 한눈에 (+ 퀴즈 안내 한 줄)
## N. 요점을 말하는 절 제목        (회차당 5~8개로 묶는다)
   핵심 설명 1~2문장
   핵심 코드나 명령 한 블록 (출력은 꼭 필요한 줄만)
   회차 대표 그림이면 그림 1장 (회차 전체 1~3장)
   <details><summary>자세히 보기</summary> 원래 긴 설명, 전체 출력, 나머지 그림, 오류 재현 </details>
## 오늘 꼭 기억할 주의점           (펼친 채 그대로)
```

- 접기는 사이트에 이미 있는 `.prose details` 스타일을 그대로 쓴다(인쇄 시 자동으로 펼쳐짐, print-mode.tsx). 새 부품은 만들지 않는다.
- 접힌 칸 안에는 h2를 두지 않는다(목차 막대, 책갈피가 h2 기준). 원래의 소제목은 `###`로 내린다.
- 시뮬레이터는 회차의 핵심이면 펼친 쪽, 아니면 접힌 칸으로.
- 순서 표, 가운데점, 긴 하이픈, ─ 글리프, 이모지 금지 규칙과 맥 기준은 그대로.

## 진행

1. 21회차를 파일럿으로 바꿔 배포, 사용자가 아이패드로 확인.
2. 승인 후 나머지 20편을 병렬로 바꾼다.
3. `.claude/skills/class-lesson/SKILL.md`를 이 형태로 고친다.

## 빌더에게 남긴 것

절을 어떻게 묶을지, 무엇을 펼친 쪽 핵심으로 둘지는 회차마다 내용을 보고 판단한다. 기준은 "복습할 때 이것만 보면 그날이 떠오르는가".
