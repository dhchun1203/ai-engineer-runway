# 번외 실습 "파이썬 손풀기" 설계

작성일: 2026-10-31
상태: 승인됨 (뼈대 + 파일럿 1단원 착수)

## 배경 / 목표

정규 커리큘럼, 수업 복습과 **별개로**, 파이썬을 일주일 동안 손에 익히는 실습 묶음을
만든다. 원칙은 "개념은 필요한 것만 짧게, 치는 시간은 길게"다. 읽고 이해한 느낌이 아니라
빈 화면 앞에서 손이 움직이는 상태가 목표다.

- 편집기: VS Code
- 프로젝트: 저장소 하나에서 **가계부 CLI**를 단원마다 키운다
- 분량: 하루 2~3시간, 7단원 (하루 한 단원, 일주일에 완성)
- git: 단원 안에서 단계마다 커밋, 단원 끝에 GitHub로 push

## 하드 제약

1. **진도와 일정에 섞이지 않는다.** 홈 대시보드, 학습 일정, 진행률, 복습 어디에도 집계되지 않는다.
2. 브랜딩 규칙 유지: 공개 문안에 교육기관명 금지, "AI Engineer 교육과정"으로 표기.
3. 가운데점, 긴 하이픈, ─ 글리프, 이모지 금지. 한국어는 2~3문장마다 문단을 끊는다.
4. **레슨의 실행 결과와 에러 메시지는 실제로 돌려서 나온 값만 쓴다.** scratchpad에서 uv와
   Python 3.12로 실행하고, git은 임시 `GIT_CONFIG_GLOBAL`을 쓴다.
5. 아이패드 우선 반응형, 터치 타깃 44px 이상, 코드 칸 가로 스크롤.

## 격리 방식

- 새 Velite 컬렉션 `practiceLessons` (`src/content/practice/*.mdx`). 진행률, 일정, 복습,
  용어집은 `lessons` 컬렉션만 읽으므로 구조적으로 섞이지 않는다
  (`2026-09-07-bonus-concepts-curriculum-design.md`와 같은 근거).
- 완료 체크는 기존 progress 테이블에 `pr:<단원 slug>` 접두사로 저장한다. 베이스캠프의 `bc:`와
  같은 방식이며, 커리큘럼 진행률은 레슨 slug만 순회하므로 `pr:` 행을 무시한다.
- 들어가는 길은 메뉴 링크 하나("파이썬 손풀기")뿐이다. 홈 카드와 일정에는 넣지 않는다.

## 단원 목록

| 단원 | 필요한 개념 | 가계부에 붙는 기능 |
|---|---|---|
| 1 | VS Code 준비, uv, git, 변수, 자료형, `input`과 `print` | 금액과 메모를 받아 한 줄 출력. 첫 커밋, GitHub 저장소 만들고 push |
| 2 | 조건문, 형변환, 입력 검사 | 수입과 지출 구분, 숫자가 아니면 다시 묻기 |
| 3 | `while` 반복, 리스트 | 메뉴 반복, 여러 건 쌓기, 목록과 합계 보기 |
| 4 | 딕셔너리, 정렬 | 항목을 딕셔너리로, 분류별 합계, 큰 순서로 보기 |
| 5 | 함수, 모듈 나누기, f-string 정렬 | 기능을 함수로 쪼개고 파일 두세 개로 나누기 |
| 6 | 파일(JSON), 예외 처리, 날짜 | 껐다 켜도 남는 저장, 날짜별 기록, 망가진 파일 대응 |
| 7 | 클래스(dataclass), README | 기록 클래스, 월별 리포트, 저장소 정리와 v1.0 태그 |

단원 N의 시작 코드는 단원 N-1의 혼자 치기 정답 코드와 같다. 혼자 치기를 못 끝냈어도
다음 단원을 시작할 수 있게, 단원 첫머리에 "시작 코드" 전체를 접어서 둔다.

## 단원 하나의 구성

| 순서 | 이름 | 시간 | 내용 |
|---|---|---|---|
| 1 | 오늘 만들 것 | 2분 | 단원을 마쳤을 때의 터미널 화면(실제 실행 결과) |
| 2 | 필요한 개념만 | 15~20분 | 오늘 기능에 필요한 문법만. 2~5줄 예제를 VS Code 터미널에서 바로 쳐 본다 |
| 3 | 따라 치기 | 30분 | 완성 코드를 그대로 친다. **복사 버튼 없는 코드 칸** |
| 4 | 고쳐 치기 | 30분 | 방금 코드를 조건만 바꿔 다시 짠다. 힌트는 하나씩 펼친다 |
| 5 | 혼자 치기 | 40~60분 | 요구사항과 확인 표만 준다. 정답 코드는 접어 둔다 |
| 6 | 자주 나는 에러 | 10분 | 이 단원에서 잘 나는 에러 메시지(실제 출력)와 읽는 법 |
| 7 | 커밋하고 올리기 | 10분 | 커밋 메시지 예시, `git push`, 완료 체크 |

- **커밋 지점:** 3, 4, 5단계 끝마다 커밋한다(단원당 3개). push는 단원 끝에 한 번.
- **혼자 치기 확인 표:** "이렇게 입력하면 이렇게 나와야 한다" 표. 정답 코드와 달라도 표대로
  나오면 통과다.

## 화면

**목록 `/practice`**
- 원칙 한 문단: "개념은 짧게, 치는 시간은 길게. 복사하지 말고 직접 치기."
- 7칸 진행 막대 (`pr:` 완료 수)
- "시작 전 준비물" 카드: VS Code(Python 확장), uv, git, GitHub 계정
- 단원 카드 7장: 단원 번호, 붙는 기능, 예상 시간, 완료 표시. 카드 호버는 기존 `card-interactive panel`

**단원 `/practice/<slug>`**
- 위쪽 단계 칩 7개: 누르면 그 단계로 이동, 읽는 단계 표시
- 본문 7단계, 기존 레슨 리더 기능(책갈피 `PageBookmark`, 독서 도우미) 적용
- 맨 아래 완료 체크와 다음 단원 카드

## 부품

새로 만드는 것:
- `TypeAlong`: 복사 버튼을 숨긴 코드 칸. 기존 `code-block.tsx`의 복사 버튼을 끄는 방식으로 만든다
  (하이라이트는 그대로 빌드 시점).
- `Hints`: 힌트를 하나씩 펼치는 칸. 한 번에 하나씩만 다음 힌트가 열린다.

재사용:
- 정답 접기는 `<details>` (기존 레슨과 같은 스타일)
- `TwistBox`, `PredictPrompt`는 필요할 때만
- 완료 체크는 베이스캠프 액션 패턴(`setLessonCompletion` + 접두사)

## frontmatter

```yaml
title: "가계부에 메뉴 붙이기"
unit: 3
slug: "03-loops-lists"
summary: "목록 카드와 머리에 보일 두 줄 요약"
feature: "메뉴 반복, 여러 건 쌓기, 목록과 합계"
concepts: ["while", "리스트"]
minutes: 150
```

빌드 검사: `unit`은 1부터 빠짐없이 이어져야 하고 slug의 앞 두 자리와 같아야 한다.

## 만드는 순서

1. **뼈대:** 컬렉션, 목록과 단원 페이지, `TypeAlong`, `Hints`, 완료 체크, 메뉴 링크
2. **파일럿 1단원:** 작성, 코드 전부 실행 확인, 배포. 사용자가 아이패드로 보고 형식 승인
3. **2~7단원:** 승인 후. 단원마다 앞 단원 코드 위에 이어 실행해 확인
4. **마지막 점검:** 빈 폴더에서 1단원부터 레슨대로 다시 따라 해 가계부가 완성되는지 확인

## 하지 않는 것

- 브라우저 안 코드 실행기(Pyodide)는 넣지 않는다. 치는 곳은 VS Code다.
- 자동 채점은 넣지 않는다. 확인 표로 스스로 대조한다.
- 퀴즈, 간격 복습은 넣지 않는다(수업 복습이 이미 맡고 있다).
